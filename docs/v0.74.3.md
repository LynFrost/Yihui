# V0.74.3 需求：生图区 Provider / model 选择框与记录卡片按钮对齐

- **目标版本**：V0.74.3
- **目标分支**：`feature/v0.74`
- **状态**：需求已确认，待开发
- **文档路径**：`docs/v0.74.3.md`
- **范围**：生图操作区的 Provider / model 选择控件，以及记录卡片标签与操作按钮的底部对齐；不改变生图请求协议及其他既有业务功能

## 1. 背景与目标

当前生图操作区的 Provider 选择框占用较多横向空间，尚未在其右侧提供独立的 model 选择框。用户需要能够在生图区直接查看并切换当前 Provider 和该 Provider 使用的模型。

此外，记录卡片中标签输入框及「带入 / 复制 / 提交」按钮所在操作组，与右侧「删除」按钮的底边目前不够整齐，需要统一底部对齐。

V0.74.3 的目标是在尽量少改动现有布局的前提下，增加独立的 model 选择控件，并优化记录卡片操作区对齐。

## 2. 生图区 Provider 选择框

1. 将生图区当前 Provider 选择框的**可见控件宽度缩窄**，为右侧新增的 model 选择框腾出空间。
2. 只调整 Provider 选择框本身的显示宽度；现有 Provider 下拉菜单的宽度保持不变，避免供应商列表和状态信息变得难以阅读。
3. 保留现有 Provider 名称、状态标识、切换行为和配置入口，不改变 Provider 的 API Key、接口地址或其他配置。
4. Provider 控件与新增的 model 控件在同一行并排显示；在现有生图区空间内合理分配宽度，尽量避免挤压其他必要控件。

## 3. 新增 model 选择框

### 3.1 控件布局

1. 在 Provider 选择框右侧新增独立的 `model` 选择框，并使用清晰的「model」文字标识。
2. model 选择框的可见宽度保持紧凑，但应尽量显示当前模型名称；较长模型 ID 可在控件中按现有样式截断显示。
3. model 下拉菜单可以比 model 选择框本身更宽，以便阅读较长的模型名称或 ID。
4. Provider 下拉菜单和 model 下拉菜单允许在屏幕空间上重叠，因为两者不会同时显示；打开其中一个菜单时，应关闭另一个菜单，避免菜单内容同时出现。
5. 菜单应有足够的层级和可视区域边界处理，不应被其他控件遮挡到无法操作。

### 3.2 Provider 与 model 的关联行为

1. model 选择框始终对应当前选中的 Provider，只显示并管理该 Provider 的当前模型和候选模型。
2. 切换 Provider 后，model 选择框应同步显示新 Provider 当前配置的模型，不得沿用上一个 Provider 的模型作为当前选择。
3. 在 model 下拉菜单中选择模型后，更新该 Provider 的当前模型设置，后续生图使用该模型。
4. 只更新当前 Provider 的模型配置，不得意外修改其他 Provider 的模型。
5. Provider 和 model 选择应继续使用现有设置保存与加载机制；重新打开或刷新程序后，选择结果应按现有持久化规则保留。

### 3.3 复用现有模型管理逻辑

1. 优先复用 V0.74 已实现的模型候选管理、选择和持久化逻辑，不重复实现一套独立的模型管理机制。
2. 继续遵守现有模型候选规则，包括待验证模型、成功生图后的验证状态，以及现有添加和删除能力。
3. 若现有 model 下拉菜单支持添加候选、显示验证状态或删除候选，生图区新增控件应沿用相同规则与处理逻辑。
4. 不因新增入口而绕过现有的模型验证状态、Provider 隔离或删除保护逻辑。
5. 不改变 Provider API 调用方式、生图参数、图像输入处理或生成结果处理流程。

## 4. 记录卡片操作区底部对齐

### 4.1 对齐规则

1. 记录卡片左侧的标签输入框，以及「带入 / 复制 / 提交」按钮组成的操作组，与右侧「删除」按钮的**底边处于同一水平线**。
2. 右侧「编辑」按钮继续位于「删除」按钮上方，不要求与左侧操作组底边对齐。
3. 左侧标签输入框和操作按钮保持在现有操作行内；尽量通过调整容器对齐方式和间距实现目标。
4. 对齐调整不得因标签数量、标签文字长度或按钮状态变化而使卡片不必要地增高。

### 4.2 功能与布局约束

1. 保留「带入 / 复制 / 提交 / 编辑 / 删除」各按钮的现有功能、操作顺序和可用状态。
2. 不改变输入图和输出图的尺寸、位置或显示方式。
3. 尽量维持现有卡片高度和列布局，不进行与本需求无关的布局重构。
4. 保持 V0.74.1 / V0.74.2 已确认的标签展示、标签浮层和标签管理行为，不因本次对齐调整而回退。

## 5. 本次不包含的内容

- 不修改 Provider 的 API Key、接口地址、鉴权或其他连接配置。
- 不修改供应商的生图调用协议、请求参数、图像输入处理或结果处理。
- 不改变模型候选的验证规则、Provider 隔离规则和持久化规则。
- 不调整生图区其他无关控件的功能或顺序。
- 不调整输入图、输出图的尺寸，不主动改变记录卡片的整体高度。
- 不顺带进行无关的命名、格式或代码结构整理。

## 6. 验收标准

### Provider / model 选择框

- [ ] 生图区的 Provider 可见选择框比当前更窄，并为 model 控件腾出空间。
- [ ] Provider 下拉菜单的宽度保持原样。
- [ ] Provider 右侧出现独立的 model 选择框，并有「model」标识。
- [ ] model 下拉菜单可以比其可见选择框更宽，以便阅读较长模型名称或 ID。
- [ ] Provider 和 model 菜单不会同时打开；打开其中一个时另一个关闭。
- [ ] 当前 model 与当前 Provider 对应；切换 Provider 后，model 选择框正确更新。
- [ ] 选择模型后，后续生图使用当前 Provider 对应的已选模型。
- [ ] 模型候选的添加、删除、验证状态及持久化行为继续遵守现有逻辑。
- [ ] 选择模型不会意外修改其他 Provider 的模型配置。

### 记录卡片按钮对齐

- [ ] 标签输入框、「带入 / 复制 / 提交」操作组与右侧「删除」按钮的底边对齐。
- [ ] 「编辑」按钮仍位于「删除」按钮上方。
- [ ] 对齐后卡片高度没有不必要的增加。
- [ ] 图片尺寸和位置保持不变。
- [ ] 各操作按钮原有功能和可用状态正常。

### 回归验证

- [ ] Provider 切换、生图、模型选择和模型配置保存功能正常。
- [ ] 不同 Provider 的模型配置相互隔离。
- [ ] 原有标签浮层、标签添加/删除/清理及记录卡片操作正常。
- [ ] 现有历史记录、筛选、排序和分页等功能不受影响。

## 7. 建议实现顺序

1. 检查生图区现有 Provider 选择控件和 V0.74 模型候选管理实现，确定可复用的组件、状态和事件处理函数。
2. 缩窄 Provider 可见控件的宽度，同时保留其现有下拉菜单宽度。
3. 在 Provider 右侧增加 model 选择框，复用现有模型选择、候选管理和持久化逻辑。
4. 实现 Provider 菜单与 model 菜单互斥打开，并处理下拉菜单的宽度、层级和可视区域。
5. 调整记录卡片操作组和右侧删除按钮的容器对齐方式。
6. 按验收标准检查 Provider 切换、模型持久化、按钮对齐，以及既有标签和生图流程回归。
