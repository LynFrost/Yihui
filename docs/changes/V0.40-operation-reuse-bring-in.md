# AI 生图管理软件 V0.40 带入操作区与复用生成实施文档

文档版本：V0.40

日期：2026-05-09

## 修改目标

V0.40 的目标是提升复用能力，让保存区实例和历史记录可以更方便地带入操作区重新生成。

本版重点：

- 保存区普通列表模式中，实例增加“带入”按钮。
- 历史记录页中，历史记录增加“带入”按钮。
- 带入操作区时复制可用的提示词、输入图、TAG、尺寸、清晰度、Provider、调用方式等参数。
- 带入操作区只修改当前操作区状态，不直接生成，不直接修改原实例，不直接修改原历史记录。
- 用户检查操作区参数后，再点击“生成”或按 `Ctrl+Enter` 才会产生新的生成任务。
- 新生成任务继续按当前节点规则进入当前节点。
- 如果带入导致操作区 Provider 切换，沿用当前操作区 Provider 规则：立即保存为全局默认 Provider。
- V0.40 之后的新历史记录开始保存 TAG 快照；旧历史记录没有 TAG，不补写。
- 历史记录参数快照可以查看，但不能因为带入动作被误改。

本版不做：

- 不改变“复制提交”和“重新提交”的既有含义。
- 不在缩略图模式中增加复杂按钮。
- 不做批量带入。
- 不修改历史记录中的旧参数快照。
- 不追溯给 V0.39 及以前的历史记录补 TAG。
- 不新增 Provider 类型。
- 不重构 Provider 能力体系。
- 不改变保存区缩略图视图的主体样式。
- 不破坏 V0.39 历史记录高级查询与清理。
- 不破坏 V0.38 标签管理中心。
- 不破坏 V0.37 数据安全导出、备份、恢复。

## 术语边界

### 带入操作区

“带入操作区”只做一件事：

```text
把保存区实例或历史记录中的可用内容填回操作区。
```

它不等于生成。

它不会：

- 不会立刻调用生图 API。
- 不会新建保存区实例。
- 不会新建历史记录。
- 不会修改原保存区实例。
- 不会修改原历史记录。
- 不会删除电脑上的图片文件。

带入后用户可以继续手动修改操作区内容，然后再点“生成”。

### 复制提交

“复制提交”保持当前含义：

```text
复制当前保存区实例的输入，并立即新增一个生成任务。
```

它会新增实例。

它继续按当前操作区/全局默认 Provider、尺寸、清晰度、生成路径执行。

### 重新提交

“重新提交”保持当前含义：

```text
只用于生成失败实例，把当前失败实例再跑一遍，不新增另一个复制实例。
```

生成失败实例的按钮仍然显示为“重新提交”。

普通成功实例或正常实例仍然显示“复制提交”。

## 保存区实例带入操作区

### 按钮位置

保存区普通列表模式中，实例操作按钮增加：

```text
带入
```

按钮位置：

```text
带入 / 移动 / 复制提交
```

失败实例中：

```text
带入 / 移动 / 重新提交
```

要求：

- “带入”放到“移动”的左边。
- 不影响当前布局。
- 继续放在现有实例内联操作区。
- 不移动编辑、删除按钮。
- 不改变标签区、图片区、提示词区尺寸。
- 生成中临时实例不显示“带入”按钮。

### 普通列表模式

保存区普通列表模式支持“带入”。

带入字段：

- `prompt`：填入操作区提示词。
- `input_image_paths`：填入操作区输入图。
- `tags`：填入操作区 TAG。
- `mode`：如果存在输入图，则切换为图生图；如果没有输入图，则切换为文生图。
- `generation_path`：优先使用实例里的生成路径；如果实例没有生成路径，则保留当前操作区生成路径。
- `ratio`：优先使用实例 `generation_params` 中的 `ratio`。
- `resolution_level`：优先使用实例 `generation_params` 中的 `resolution_level`。
- `size`：优先使用实例 `generation_size` 或 `generation_params.resolved_size`。
- `n`：如果实例参数有数量，可带入；如果是图生图，仍然固定为 `1`。
- `provider`：如果实例记录的 Provider 当前仍存在，则带入并切换操作区 Provider。
- `openai_call_method`：只作为对照信息，不直接修改 Provider 设置页里的调用方式。

说明：

- 当前保存区实例的 Provider 字段可能是显示名或历史 Provider 文本，实际实现时必须优先使用可匹配的 Provider key。
- 如果实例没有可识别 Provider，则保持当前操作区 Provider，并提示用户。
- 如果带入切换了 Provider，必须调用现有 `changeOperationProvider(providerKey)` 逻辑，让它立即保存为全局默认 Provider。

### 缩略图模式

缩略图模式不新增“带入”按钮。

规则：

- 缩略图模式继续只显示输出图缩略图。
- 如果用户需要带入操作区，先切回普通列表模式。
- 不能为了“带入”破坏 V0.36 的缩略图模式极简显示。

## 历史记录带入操作区

### 按钮位置

历史记录页每条记录增加：

```text
带入
```

建议放在历史记录第一行元信息右侧。

要求：

- 不挤压提示词、参数 JSON、小字摘要三列布局。
- 不影响 V0.39 的提示词搜索、状态筛选、Provider 筛选、调用方式筛选、日期筛选和清理按钮。
- 不影响历史记录文本浮窗和点击展开复制。

### 带入字段

历史记录带入操作区时，使用历史记录自身和 `params_json` 中的参数快照。

字段规则：

- `prompt`：来自历史记录 `prompt`。
- `input_image_paths`：来自历史记录 `input_image_paths_json`。
- `mode`：优先使用历史记录 `mode`；如果 `mode` 为空，则根据输入图是否存在判断。
- `provider_key`：优先使用历史记录 `params.provider_key`，其次使用历史记录 `provider_key`。
- `adapter`：只作为历史信息显示，不直接编辑 Provider。
- `openai_call_method`：只作为历史信息显示，不直接改写当前 Provider 设置。
- `ratio`：来自 `params.ratio`。
- `resolution_level`：来自 `params.resolution_level`。
- `resolved_size`：来自 `params.resolved_size` 或历史记录 `resolved_size`。
- `n`：来自 `params.n`。
- `tags`：V0.40 之后的新历史记录可以从 `tags_json` 带入；旧历史记录没有 TAG，则带入空 TAG。

历史记录带入后：

- 操作区显示带入后的提示词、输入图、TAG、尺寸、清晰度、数量、Provider。
- 用户可以继续调整。
- 不修改该条历史记录。
- 不修改该条历史记录的参数 JSON。

## 历史记录 TAG 快照

### 数据库字段

V0.40 在 `generation_history` 表新增字段：

```sql
tags_json TEXT NOT NULL DEFAULT '[]'
```

当前 `APP_SCHEMA_VERSION` 从 `3` 升级为：

```python
APP_SCHEMA_VERSION = 4
```

迁移规则：

- 新建数据库时直接包含 `tags_json` 字段。
- 旧数据库启动时，如果 `generation_history` 缺少 `tags_json`，执行：

```sql
ALTER TABLE generation_history ADD COLUMN tags_json TEXT NOT NULL DEFAULT '[]';
```

- 旧历史记录不补 TAG，字段保持默认 `[]`。
- V0.40 之后点击生成、复制提交、重新提交产生的历史记录写入当时提交的 TAG 快照。

### 后端创建历史记录

`create_generate_history_record(...)` 增加 TAG 写入。

来源：

```text
data.tags
```

规则：

- 如果 `data.tags` 是数组，过滤空字符串后保存。
- 过滤虚拟值 `__untagged__`。
- 不自动创建新的 TAG。
- 不影响保存区实例自身的 TAG 写入逻辑。

### 历史记录列表返回

`hydrate_generation_history(...)` 返回：

```json
{
  "tags": ["tag1", "tag2"]
}
```

或：

```json
{
  "tags": []
}
```

前端历史记录带入使用 `record.tags`。

旧历史记录没有 TAG 时，前端必须按空数组处理。

## Provider 不存在时的处理

如果保存区实例或历史记录中的 Provider 当前已经不存在：

1. 不静默切换。
2. 弹窗或确认框提示：

```text
原 Provider 已不存在，请选择当前可用 Provider 后带入操作区。
```

3. 显示当前可用 Provider 下拉列表。
4. 用户选择后再带入。
5. 用户取消则不修改操作区。

说明：

- Provider 是用户自己设置的代理商名称或内部编号。
- `adapter` 才是 `openai / google / other`。
- 不能把 `adapter` 当成 Provider。

如果历史记录中的 `adapter` 是 `google` 或 `other`，但当前 Provider 不存在，也仍然按 Provider 缺失处理。

## 调用方式不一致时的处理

历史记录可能记录了当时的调用方式，例如：

```text
gpt-image-2
response
custom
```

但当前 Provider 的调用方式可能已经改变。

V0.40 规则：

- 带入操作区时，不直接改写 Provider 设置页中的调用方式。
- 操作区 Provider 一旦切换，后续生成使用当前 Provider 设置中的调用方式。
- 如果历史记录调用方式和当前 Provider 调用方式不同，显示提示：

```text
历史记录的调用方式与当前 Provider 设置不同，后续生成将按当前 Provider 设置执行。
```

原因：

- 调用方式属于 Provider 设置，不是单次操作区开关。
- 强行从历史记录改写 Provider 设置，可能影响之后所有生成。

## Provider 能力约束

带入操作区时必须以当前可用 Provider 能力为准。

规则：

- 如果目标 Provider 支持文生图，文生图可带入。
- 如果目标 Provider 不支持文生图，提示用户更换 Provider，不强行带入不可执行模式。
- 如果目标 Provider 支持图生图，图生图可带入。
- 如果目标 Provider 不支持图生图，提示用户更换 Provider或移除输入图切换文生图。
- 如果目标 Provider 不支持多图数量，则 `n` 自动降为 `1`，并提示用户。
- 图生图模式下数量始终固定为 `1`，继续沿用当前规则。
- 如果历史尺寸不在当前 Provider 支持范围内，优先尝试通过 `ratio + resolution_level` 映射；仍不合法时保留当前操作区尺寸并提示用户。
- 自定义尺寸可以填入操作区，但不要自动加入全局自定义尺寸列表，除非用户之后在操作区明确保存。

## 生成路径和节点规则

带入操作区时：

- 优先带入实例或历史记录中可用的生成路径。
- 如果没有可用生成路径，则保留当前操作区生成路径。
- 不因为带入动作创建文件夹。
- 不因为带入动作写入图片文件。

带入后再点击“生成”：

- 继续按当前操作区规则创建生成任务。
- 新实例进入当前节点选择路径。
- 不回到原实例所在节点。
- 不回到历史记录当时的节点。

原因：

- “带入”是为了复用内容。
- “生成”应该遵守当前用户正在管理的节点上下文。

## 操作区状态刷新

带入操作区后需要刷新：

- 文生图 / 图生图按钮状态。
- 提示词文本框内容。
- 输入图区域。
- TAG 区域。
- Provider 下拉。
- 长宽比。
- 清晰度。
- 数量。
- 生成路径。
- 输出图清空或保持规则。

推荐规则：

- 带入时清空操作区输出图，避免用户误以为历史输出图就是本次生成结果。
- 如果用户想查看原输出图，仍然通过保存区实例或历史记录查看。

带入成功提示：

```text
已带入操作区
```

如果 Provider 被切换并保存：

```text
已带入操作区，并已切换 Provider
```

建议修改：


说明：

## 后端文件建议

建议修改：

```text
backend/database.py
backend/api.py
backend/backup.py
```

说明：

- `database.py` 增加 `tags_json` 字段、schema version、迁移和 hydrate。
- `api.py` 在创建历史记录时写入 TAG 快照。
- `backup.py` 的导出、恢复会自动包含 `generation_history.tags_json`，但需要确认大数据导出和 JSON 恢复都兼容新增字段。

如果前端历史记录列表中已有完整记录数据，则不需要新增后端“单条历史详情”接口。

如果实现时发现历史记录列表为了性能没有返回完整 `params` 或图片路径，可新增：

```text
GET /api/generation-history/<id>
```

返回单条历史记录完整详情。

## 数据安全兼容

V0.37 的备份、导出、恢复增强必须保持有效。

新增 `generation_history.tags_json` 后：

- 手动备份必须包含新字段。
- 自动备份必须包含新字段。
- 大数据导出必须包含新字段。
- JSON 恢复必须兼容新字段。
- 恢复旧备份时，如果旧数据没有 `tags_json`，按 `[]` 写入。
- 恢复新备份时，TAG 快照必须保留。

注意：

- 历史记录 TAG 快照只是历史记录当时的文字快照。
- 它不等于 `tags` 表和 `instance_tags` 表的关系。
- 恢复历史记录 TAG 快照时，不要求这些 TAG 一定存在于当前 `tags` 表。

## 历史记录参数快照只读

历史记录中的参数 JSON 继续只读。

“带入”动作不能：

- 不能修改 `params_json`。
- 不能修改 `tags_json`。
- 不能修改 `provider_key`。
- 不能修改 `openai_call_method`。
- 不能修改 `input_image_paths_json`。
- 不能修改 `output_image_paths_json`。

历史记录是生成行为日志，不是可编辑草稿。

- 历史调用方式和当前 Provider 调用方式不一致时，显示提示但不改 Provider 设置。
- 缩略图模式下没有“带入”按钮，切回列表模式后可以带入。
- 带入后操作区输出图清空。
- 图片弹窗、缩略图缓存、保存区键盘翻页不回退。

完整回归建议运行：

```text
pytest
```

并至少手动打开页面核对：

- 生图管理页普通列表模式。
- 生图管理页缩略图模式。
- 历史记录页。
- 标签管理页。
- 数据安全页。
- 设置页 Provider 切换。

## 副作用与风险

本版可能带来的影响：

- 保存区普通列表模式中每个实例多一个“带入”按钮，会占用一点按钮行宽度，所以必须放在“移动”左边并控制按钮宽度，不能挤压图片和提示词布局。
- 历史记录每条记录多一个“带入”按钮，会增加元信息行内容，所以按钮应靠右放，不进入三列内容区。
- 带入切换 Provider 会立即保存为全局默认 Provider，这是用户确认的规则；因此带入旧记录后，后续普通生成也会使用被切换后的 Provider。
- 旧历史记录没有 TAG，带入后 TAG 为空，这是预期行为。
- 新历史记录开始保存 TAG 快照，会让 `generation_history` 表新增字段，数据库 schema 从 3 升到 4，备份、导出、恢复必须同步兼容。
- 历史记录里的调用方式可能和当前 Provider 设置不同，带入后不会复原旧调用方式，只会提示并按当前 Provider 设置执行。
- 如果历史尺寸或 Provider 能力现在已经不支持，带入时可能会自动降级或提示用户重新选择。
- 带入后清空操作区输出图，可能和用户“想对照旧结果”的直觉不同，但可以避免误把旧输出图当成本次结果。

必须避免：

- 不能把 `adapter` 当成 Provider。
- 不能因为带入历史记录而修改 Provider 设置页的调用方式。
- 不能修改原保存区实例。
- 不能修改原历史记录。
- 不能删除电脑上的图片文件。
- 不能破坏“复制提交”和“重新提交”的既有生成逻辑。
- 不能在缩略图模式中塞入复杂按钮。
- 不能破坏 V0.39 历史查询与清理。
- 不能破坏 V0.38 标签管理中心。
- 不能破坏 V0.37 数据安全备份、导出、恢复。
