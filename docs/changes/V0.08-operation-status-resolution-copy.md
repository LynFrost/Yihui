## 操作区右侧布局

修复截图 `AI生图软件/docs/bugs_v0.07/Snipaste_2026-05-01_20-37-12.png` 中操作按钮占用状态显示空间、按钮纵向位置偏低、操作区底部留白过多的问题。

操作区横向顺序固定为：

```text
模式 | 提示词 | 输入图区 | 尺寸/分辨率 | 输出图 | Provider/标签/路径 | 操作按钮 | 状态
```

实现规则：

- 在操作按钮右侧新增独立状态列。
- `清空 / 生成` 按钮从最后一列挪到倒数第二列。
- 软件状态文字从按钮列移到最后一列。
- 从尺寸/分辨率、输出图、Provider/标签/路径、操作按钮这些区域开始，整体向左收拢，右侧挪出的空间用于状态列。
- 输入图区不参与这次整体左移，输入图区右边界作为左移范围的起点。
- 操作按钮列不再包含状态文字。
- 状态列不再包含操作按钮。
- 状态列可显示短状态：

```text
生成中
已生成
生成失败
已复制提示词
```

- 状态文字较长时允许换行或省略，但不能遮挡按钮。
- 完整错误信息仍可通过 `title` 或顶部消息保留，不要求在状态列完整展示。

建议 CSS grid：

```css
.operation-area.image-record {
  grid-template-columns:
    88px
    minmax(620px, 720px)
    minmax(280px, 1fr)
    92px
    76px
    minmax(170px, .75fr)
    88px
    minmax(96px, 120px);
}
```

列含义：

```text
88px                 模式
minmax(620px,720px)  提示词
minmax(280px,1fr)    输入图区或文生图空占位
92px                 尺寸/分辨率
76px                 输出图
minmax(170px,.75fr)  Provider/标签/路径
88px                 清空/生成
minmax(96px,120px)   软件状态
```

如果实际页面宽度不足，允许微调列宽，但必须满足：

- 不出现横向滚动条。
- 操作按钮不被遮挡。
- 状态列不覆盖按钮。
- Provider/标签/路径仍可编辑。
- 输入图区被压缩可以接受，但图生图模式下仍要能放下至少 3 张标准图片位。

## 操作按钮纵向对齐

`清空 / 生成` 按钮纵向上移，和 `文生图 / 图生图` 按钮水平对齐。

实现规则：

- 操作按钮列只渲染按钮，不渲染状态消息。
- 操作按钮列顶部对齐到模式按钮行顶部。
- 去掉 V0.07 中导致按钮偏低的状态行占位。
- `.operation-actions` 不得再因为状态消息产生额外高度。
- `.operation-button-row` 保持竖向排列：

```text
清空
生成
```

- 操作区底部多余空间要去掉。
- 操作区整体高度由提示词框、输入图、输出图、标签/路径等真实内容决定。
- 如果标签很多导致操作区变高，允许自然增高。

建议 CSS：

```css
.operation-actions {
  padding-top: 22px;
  justify-content: flex-start;
}

.operation-button-row {
  display: grid;
  gap: 6px;
}
```

其中 `22px` 用于对齐左侧 `操作区` 标题下方的模式按钮行；如果实际视觉仍偏低，允许在浏览器验证时微调到 `18px` 至 `22px`。

状态列建议：

```css
.operation-status-panel {
  grid-column: 8;
  padding-top: 22px;
}
```

状态列和按钮列使用相同 `padding-top`，让状态文字与按钮行在同一视觉高度开始。

## 提示词宽度扩大

操作区提示词框宽度扩大为 V0.07 当前宽度的约 1.5 倍。

实现规则：

- V0.07 浏览器验证中提示词宽度约为 `480px`。
- V0.08 目标宽度约为 `720px`。
- 提示词 grid 列建议：

```css
minmax(620px, 720px)
```

- 操作区提示词框和聚焦浮层宽度继续保持一致。
- `.prompt-field.is-editable textarea:focus` 继续使用：

```css
width: 100%;
```

- 不得恢复固定浮层宽度，例如 `620px`。
- 文生图和图生图提示词框宽度仍然必须一致。
- 输入图区被压缩可以接受。
- 图生图输入图区宽度可低于 V0.07 的 `560px`，但不得小到无法显示 3 张标准图片位。

副作用处理：

- 输入图区会被压缩，一行可见输入图数量会减少。
- 输出图、尺寸/分辨率、Provider/标签/路径和操作按钮优先保持可用。
- 页面不能出现横向滚动条。

## 分辨率控件样式

分辨率控件样式和尺寸控件保持一致。

实现规则：

- 分辨率不再使用原生 `select`。
- 分辨率改成按钮式下拉，结构和尺寸按钮一致。
- 当前分辨率按钮显示：

```text
1K
2K
4K
```

- 当前值右侧显示向下箭头。
- 尺寸按钮也可以显示同样的向下箭头，两个控件视觉一致。
- 分辨率下拉选项只包含：

```text
1K
2K
4K
```

- 分辨率下拉中不需要取消按钮。
- 点击下拉框以外区域等同取消，关闭下拉但不改变当前值。
- 点击某个分辨率选项后：
  - 更新 `state.operation.resolution`。
  - 保存到全局默认 `settings.default_resolution`。
  - 关闭分辨率下拉。
- 尺寸下拉和分辨率下拉不能同时打开。

实现建议：

- `state.operation` 增加：

```js
resolution_picker_open: false
```

- 新增或改造：

```js
function renderResolutionPicker() {
  ...
}
```

使其返回类似：

```html
<div class="field record-resolution">
  <button type="button" class="option-current resolution-current" data-action="toggle-resolution-picker">
    <span>1K</span>
    <span class="select-arrow">⌄</span>
  </button>
  <div class="resolution-popover">...</div>
</div>
```

- 复用尺寸控件样式时，抽象共同 class：

```css
.option-current
.option-popover
.option-preset
```

- 保留尺寸自定义输入的原逻辑，不要把尺寸功能改坏。

点外关闭规则：

- 点击 `.resolution-popover` 以外区域时关闭分辨率下拉。
- 点击 `.size-popover` 以外区域时继续关闭尺寸下拉。
- 打开尺寸下拉时关闭分辨率下拉。
- 打开分辨率下拉时关闭尺寸下拉。
- 按 `Escape` 时关闭两个下拉。

## 保存区提示词复制按钮

保存区实例的提示词标题右侧新增复制按钮。

实现规则：

- 每个保存区实例提示词框标题行显示：

```text
提示词  [复制]
```

- 复制按钮只出现在保存区实例提示词框，不出现在操作区提示词框。
- 非编辑状态和编辑状态都显示复制按钮。
- 点击复制按钮复制该实例提示词全文。
- 复制内容来自当前显示内容：
  - 非编辑状态复制实例保存的 `item.prompt`。
  - 编辑状态复制当前编辑草稿里的 `draft.prompt`，包括尚未保存的修改。
- 点击复制按钮不得进入编辑模式。
- 点击复制按钮不得触发批量保存边界。
- 点击复制按钮不得改变提示词框高度。
- 复制成功后显示短状态：

```text
已复制提示词
```

- 复制失败时显示：

```text
复制失败：...
```

实现建议：

- `renderPromptField()` 增加可选参数：

```js
copyAction = ""
instanceId = ""
```

- 保存区实例调用：

```js
renderPromptField({
  name: "instance_prompt",
  value: item.prompt,
  readonly: !editable,
  className: "record-prompt instance-prompt",
  copyAction: "copy-instance-prompt",
  instanceId,
})
```

- 操作区继续不传 `copyAction`。
- 标题行改为独立容器：

```html
<div class="field-title-row">
  <span>提示词</span>
  <button type="button" class="field-title-action" data-action="copy-instance-prompt" data-id="...">复制</button>
</div>
```

- 复制函数：

```js
async function copyInstancePrompt(instanceId) {
  const draft = syncInstanceDraftFromDom(instanceId);
  const instance = instanceById(instanceId);
  const prompt = draft?.prompt ?? instance?.prompt ?? "";
  await navigator.clipboard.writeText(prompt);
  setMessage("已复制提示词", "success");
}
```

- 如果 `navigator.clipboard.writeText` 不可用，使用临时 `textarea` fallback：

```js
function fallbackCopyText(text) {
  const node = document.createElement("textarea");
  node.value = text;
  node.style.position = "fixed";
  node.style.left = "-9999px";
  document.body.appendChild(node);
  node.select();
  document.execCommand("copy");
  node.remove();
}
```

## 副作用处理

提示词变宽：

- 输入图区会明显变窄，这是本版本接受的取舍。
- 图生图输入图超过一行容量时继续按现有规则换行。
- 图片位尺寸不改变。

状态列：

- 状态列宽度有限，只显示短状态。
- 长错误不强塞到状态列，避免撑宽页面。
- 状态列为空时保留稳定宽度，避免生成状态出现时右侧抖动。

分辨率下拉：

- 自定义下拉比原生 `select` 多了打开/关闭状态，需要保证不会触发整页重绘导致提示词失焦。
- 分辨率下拉和标签下拉、尺寸下拉的点外关闭逻辑要互不干扰。

复制按钮：

- 复制按钮位于实例内部，必须被 `isInteractiveTarget()` 识别为交互元素。
- 复制按钮点击不能触发批量保存其他实例。
- 复制编辑草稿时要先从 DOM 同步当前 textarea 内容。
