# V0.52 历史记录与保存区筛选布局编号收口

## 目标

当前 V0.51 已完成保存区 Provider 筛选排序、历史记录 Provider/model/尺寸/模式筛选、历史编号初步对应。本版 V0.52 不新增大功能，重点继续收口历史记录页和生图管理页的筛选布局、历史编号显示、错误浮窗、标签空间利用和筛选能力一致性。

本版原则：

- 准确性优先，尤其是历史编号不能为了“看起来一致”而误匹配。
- 不改变生成主流程。
- 不改变数据库 schema，除非实现时发现已有字段完全无法支撑且必须修复。
- 不删除电脑上的图片文件。
- 不破坏 V0.51 的 Provider 排序、历史参数快照、保存区筛选、失败实例重新生成前置规则。
- 文档确认后再执行实现；本文档落成不等于直接开始改代码。

## 修改项

### 1. 历史记录错误浮窗增加最大高度滚动

当前需求：

- 历史记录页中，浮窗显示错误信息时，如果扩大到当前窗口可用最大高度后仍显示不下，需要在浮窗内部增加滚动条。

调整方案：

- 保留现有历史记录浮窗的自动定位和自动放大逻辑。
- 浮窗最大高度限制为当前视口可用高度，例如 `calc(100vh - 24px)` 或脚本计算后的可用高度。
- 当内容超出最大高度时，只在浮窗内容区域出现纵向滚动条。
- 不改变历史记录卡片里错误原因只显示后 3 行的规则。

验收标准：

- 短错误信息不出现多余滚动条。
- 长错误信息浮窗不会超出浏览器窗口。
- 长错误信息可以在浮窗内部滚动查看完整内容。
- 切页、关闭浮窗、点击其他区域关闭浮窗的现有规则不回退。

### 2. 历史记录编号继续优化，准确优先

当前问题：

- 历史记录页当前出现 `#—`。
- 用户希望历史记录编号和生图管理页保存区实例编号严格一致。
- 但旧历史记录可能没有可靠的实例 ID。

最终规则：

- 能可靠对应保存区实例的历史记录：
  - 显示该实例在“保存区当前排序规则”下的全局编号。
  - 该编号不受保存区筛选影响。
  - 该编号不受历史筛选影响。
  - 只受保存区排序影响。
- 不能可靠对应保存区实例的历史记录：
  - 仍然显示编号。
  - 但编号样式必须和保存区实例编号明显区分。
  - 建议显示为历史编号，例如 `H001`、`H002`、`H003`。
  - 历史编号只表示当前历史记录列表自身的排序编号，不伪装成保存区实例编号。
- 不再显示 `#—`。

关于用输出图路径匹配：

- 不默认使用“历史输出图路径匹配保存区实例输出图路径”作为强绑定规则。
- 原因：
  - 图片路径可能被路径替换功能批量改过。
  - 旧历史可能记录的是多输出路径，而保存区实例可能只对应其中一个。
  - 用户可能手动编辑保存区输出图路径。
  - 不同实例理论上也可能引用同一张输出图。
- 因此，只有在实现时能证明匹配是唯一且无歧义时，才可以作为辅助匹配。
- 如果不能证明唯一准确，则不用路径匹配，避免误编号。

实现建议：

- 继续优先使用历史参数快照里的：
  - `primary_instance_id`
  - `instance_ids`
  - `target_instance_id`
  - `retry_instance_id`
- 对旧历史没有实例 ID 的记录，使用历史编号 `Hxxx`。
- 历史编号应按照历史记录当前查询结果的全局顺序计算，而不是仅当前页内从 1 开始。
- 历史编号和保存区编号视觉区分：
  - 保存区对应编号：`#001`
  - 仅历史编号：`H001`

验收标准：

- 能对应实例的历史记录显示 `#001` 这类保存区编号。
- 不能对应实例的历史记录显示 `H001` 这类历史编号。
- 页面中不再出现 `#—`。
- 不发生错误匹配。
- 保存区筛选不影响历史记录里保存区编号。
- 历史筛选不影响保存区编号。
- 保存区排序变化时，能对应实例的历史编号跟随变化。

### 3. 历史记录页顶部布局重排

当前需求：

- 将“每页数量”旁边的开始日期和结束日期换行显示到下一行。
- 将“刷新”放到“每页数量”旁边。
- 将状态、Provider、尺寸、模式、调用方式、model 这些筛选按钮在当前行下面新开一行放置。
- 在状态前增加“标签”筛选。
- 下面记录和上一页/下一页等按钮的纵向间距去掉，节省空间。

调整方案：

历史记录页顶部建议分成三行：

- 第一行：
  - 提示词搜索
  - 每页数量
  - 刷新
  - 总数 / 首页 / 上一页 / 下一页 / 尾页
- 第二行：
  - 标签
  - 状态
  - Provider
  - 尺寸
  - 模式
  - 调用方式
  - model
- 第三行：
  - 开始日期
  - 结束日期

标签筛选规则：

- 历史记录页标签筛选使用历史记录自身的 `tags_json` 快照。
- 新历史从 V0.40 起已有 TAG 快照。
- 旧历史缺少 TAG 快照时，可归入“无标签/未记录”。
- 标签筛选中的虚拟“无”仍然不能写入真实 TAG。

Provider 排序：

- 历史记录页 Provider 下拉排序必须和生图管理页 Provider 下拉一致。
- 当前仍存在的 Provider 按显示名称 A-Z 排序。
- 已删除的历史 Provider 保留显示，并按历史显示名或 provider key 排序。

验收标准：

- 历史页第一行更紧凑，刷新按钮紧挨每页数量。
- 日期筛选独立到下一行。
- 标签、状态、Provider、尺寸、模式、调用方式、model 在同一筛选行。
- 历史记录列表和分页区域之间没有多余纵向空白。
- Provider 下拉顺序和生图管理页一致。

### 4. 保存区标签框空间利用修复

当前问题：

- 从截图看，标签 `d` 明显可以放到 `s` 右边，但提前换行。
- 可能原因：
  - 标签框内部仍保留了清空按钮的右侧预留空间。
  - 标签输入框 `min-width` 过大，提前占位导致 chip 换行。
  - flex 容器没有使用完整可用宽度。

调整方案：

- 检查保存区实例标签框的 CSS。
- 保存区实例标签框内部已经不放总清除 X，因此不应继续保留右侧 30px 这类预留空间。
- 只针对实例标签框修复空间利用，避免改坏操作区标签框。
- 标签输入框在有多个标签时允许更小宽度，避免过早挤走标签 chip。

验收标准：

- 标签 chip 尽量利用当前行可用空间。
- 右侧不再出现无意义空白列。
- 添加、删除、清标签、标签弹窗打开/关闭规则不回退。
- 操作区标签框不被改坏。

### 5. 生图管理页筛选布局重排

当前需求：

- 生图管理页中，将标签筛选、来源筛选、方式筛选、Provider 筛选这些筛选按钮，在当前行下面新开一行。
- 多出来的空间给到搜索提示词。
- 排序、每页数量、显示方式保留第一行。
- 筛选行新增：
  - model
  - 状态
  - 尺寸
  - 调用方式
- 筛选行按钮排序为：
  - 标签
  - 状态
  - Provider
  - 尺寸
  - 模式
  - 调用方式
  - model
  - 来源

最终布局：

- 第一行：
  - 搜索提示词
  - 排序
  - 每页数量
  - 显示方式
- 第二行：
  - 标签
  - 状态
  - Provider
  - 尺寸
  - 模式
  - 调用方式
  - model
  - 来源

命名规则：

- 原“标签筛选”改为“标签”。
- 原“来源筛选”改为“来源”。
- 原“方式筛选”改为“模式”。
- 原“Provider 筛选”改为“Provider”。
- 新增筛选按钮名称：
  - 状态
  - 尺寸
  - 调用方式
  - model

筛选含义：

- 标签：按实例 TAG 筛选，继续支持“无”。
- 状态：按实例生成状态筛选，例如全部、正常/成功、失败、生成中。
- Provider：按实例 provider 筛选。
- 尺寸：按实例 `generation_size` 或参数快照中的尺寸筛选。
- 模式：沿用当前方式筛选逻辑，区分文生图、图生图、有输出、无输出。
- 调用方式：按实例参数快照里的 `openai_call_method` 筛选。
- model：按实例参数快照里的 `model` 筛选。
- 来源：按 generated/manual 筛选。

后端要求：

- 新增筛选尽量走后端查询，不把全部实例塞到前端。
- 保存区需要可用筛选项来源：
  - Provider 当前配置 + 历史 provider key。
  - 尺寸、调用方式、model 从实例表/参数快照中统计。
  - 状态从固定状态和实际数据中合并。

验收标准：

- 搜索提示词输入框获得更多横向空间。
- 第二行筛选按钮顺序严格为：标签、状态、Provider、尺寸、模式、调用方式、model、来源。
- 下拉筛选选择后立即刷新。
- 新增筛选可与搜索、标签、来源、模式、Provider、排序、分页叠加。
- 单列/双列、缩略图视图、节点筛选不被破坏。

- 在状态前面增加标签筛选。

调整方案：

  - 尺寸
  - 模式

验收标准：

## 副作用与处理

- 历史编号对旧数据无法 100% 复原保存区编号，因为旧历史可能没有实例 ID。V0.52 不硬猜，改用明显区分的 `Hxxx` 历史编号。
- 如果实现中使用输出图路径辅助匹配，必须只在唯一无歧义时使用；否则不用。
- 保存区新增状态、尺寸、调用方式、model 筛选后，后端查询条件更多，需要注意分页总数和当前页回退逻辑。
- 历史页标签筛选依赖 `tags_json`，旧历史会归入无标签/未记录，这是可接受的数据限制。
- 标签框空间修复需要区分操作区和保存区实例，避免把操作区的清空按钮布局改坏。
- 顶部筛选栏换行会影响 CSS 布局，需要重点检查横向滚动条。
