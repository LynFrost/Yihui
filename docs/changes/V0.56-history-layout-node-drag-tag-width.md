# V0.56 历史布局、节点拖动排序与标签筛选宽度收口

## 目标

当前 V0.55 已继续修复节点下拉、尺寸排序和历史筛选布局。本版 V0.56 不新增生成能力，不改变数据核心流程，重点继续收口历史记录页顶部布局、节点下拉关闭边界、节点顺序调整和标签筛选宽度。

本版原则：

- 不新增数据库 schema。
- 不改变生成、保存、历史记录写入流程。
- 不改变 Provider 能力体系。
- 不删除电脑上的图片文件。
- 不改变 V0.55 已确定的尺寸前缀和尺寸排序规则。
- 节点拖动排序使用现有 `nodes.position` 字段保存顺序。
- 文档确认后再执行实现；本文档落成不等于直接开始改代码。

## 修改项

### 1. 历史记录页分页按钮与每页数量下边缘对齐

当前需求：

- 历史记录页中，“总数”到“尾页”之间的所有按键，下边缘要和“每页数量”框的下边缘对齐。

调整方案：

- 调整历史页日期/分页工具行的垂直对齐方式。
- “每页数量”下拉框、“总数”、首页、上一页、下一页、尾页放在同一视觉基线上。
- 按钮组不再因为文字高度、summary 高度或 flex 居中导致下边缘高低不一致。
- 保留 V0.55 的规则：每页数量仍放在总数左边挨着。

验收标准：

- “每页数量”框底边和首页、上一页、下一页、尾页按钮底边对齐。
- 总数文本与按钮组视觉上处于同一行，不向上或向下漂移。
- 每页数量切换和翻页功能不回退。

### 2. 减少第一条历史记录上方多余空间

当前需求：

- 历史记录页中，第一条记录和每页数量框的下边缘之间仍有多余空间，需要继续减小。

调整方案：

- 检查并压缩以下间距：
  - 历史页工具栏和消息区域之间的 gap。
  - 空消息区域的高度和 margin。
  - 历史列表自身的顶部间距。
  - 历史记录容器与上一行工具栏之间的 gap。
- 空消息区域没有内容时，不占明显高度。
- 保留必要呼吸空间，避免记录贴到工具栏上。

验收标准：

- 第一条历史记录更靠近顶部工具栏。
- 空消息区域不再造成明显空白。
- 历史记录之间原有可读性不变。
- 错误/加载消息出现时仍正常显示。

### 3. 节点下拉点击节点行空白也关闭

当前问题：

- 生图管理页中，节点下拉框打开后，目前只有点击节点行以外才会关闭。
- 用户希望只要点击的是下拉框以外，就关闭下拉框，即使点击位置仍在节点行内。

原因判断：

- V0.55 当前把整个节点行 `[data-node-controls]` 当作节点下拉内部区域。
- 因此点击节点行空白会被当成“内部点击”，不会触发关闭。

调整方案：

- 将节点下拉的“内部区域”判断收窄到：
  - 节点选择按钮本身。
  - 当前打开的节点下拉菜单。
  - 节点右键菜单。
  - 节点新建/重命名弹窗。
- 节点行空白不再算作内部区域。
- 节点下拉打开时：
  - 点击节点行空白关闭下拉。
  - 点击另一个节点选择框时，允许切换打开另一个下拉。
  - 点击当前下拉菜单内部不关闭。
  - 点击右键菜单内部不关闭。
  - 点击外部任意区域关闭。

验收标准：

- 打开节点下拉后，点击节点行空白，下拉关闭。
- 打开节点下拉后，点击保存区其他区域，下拉关闭。
- 打开节点下拉后，点击另一个节点框，当前下拉关闭并按预期打开目标节点框。
- 节点右键菜单、新建、重命名、删除不回退。

### 4. 自定义节点支持同层级上下拖动排序

当前需求：

- 生图管理页中，节点下拉框中，自定义节点的顺序可以上下拖动调整。

调整方案：

- 拖动范围：
  - 只允许拖动真实用户节点。
  - `新建 / 全部 / 其他` 不允许拖动。
  - 只允许在同一层级内上下排序。
  - 不支持通过拖动改变节点父级。
- 保存规则：
  - 使用现有 `nodes.position` 字段保存排序结果。
  - 需要新增后端重排接口，例如提交同一父节点下的节点 id 顺序。
  - 后端必须校验这些节点确实属于同一个父节点。
  - 排序成功后返回最新节点树。
- 前端交互：
  - 节点项可拖动时给出明确拖动状态。
  - 拖动过程中不触发节点筛选切换。
  - 拖动结束并成功保存后，保持当前已选择的节点路径不变。
  - 排序失败时恢复原顺序并显示错误。
- 与其他节点操作关系：
  - 右键菜单打开时不触发拖动排序。
  - 点击“重命名”“删除”不受拖动逻辑影响。
  - 新建节点仍默认追加到当前层级末尾。

验收标准：

- 同一层级中的用户节点可以上下拖动调整顺序。
- 刷新页面或重启软件后，节点顺序仍保持。
- `新建 / 全部 / 其他` 不可拖动。
- 不能把节点拖到另一个父节点下面。
- 拖动排序不移动任何实例，不删除任何图片文件。
- 节点筛选、移动实例、批量移动实例不回退。

### 5. 生图管理页标签筛选框继续加宽并挨着状态框

当前需求：

- 生图管理页中，筛选行的标签框改宽点，改到挨着状态框。

调整方案：

- 增大生图管理页筛选行标签框宽度。
- 标签框右边紧挨状态筛选框，不留下明显空白。
- 后续筛选项仍按当前顺序排列：
  - 标签
  - 状态
  - Provider
  - 尺寸
  - 模式
  - 调用方式
  - model
  - 来源
- 空间不足时允许筛选行自然换行，但不让控件互相挤压或遮挡。

验收标准：

- 生图管理页标签框比 V0.55 更宽。
- 标签框右侧紧挨状态框。
- 多选标签时显示更宽松。
- 标签筛选、多选、清除、“无”虚拟项不回退。

### 6. 历史记录页标签筛选框与生图管理页一致加宽

当前需求：

- 历史记录页中，筛选行的标签框也改宽点。
- 宽度和生图管理页筛选行的标签框保持一致。

调整方案：

- 使用同一标签筛选宽度变量或统一样式，保证两个页面宽度一致。
- 历史页标签框继续保持：
  - 多选。
  - 清除。
  - 搜索 TAG。
  - 虚拟“无”。
  - 选择后立即刷新。
- 标签框加宽后，不挤压开始日期、结束日期和分页工具组。

验收标准：

- 历史记录页标签筛选框与生图管理页标签筛选框宽度一致。
- 多选标签显示不拥挤。
- 历史标签筛选功能不回退。
- 开始日期和结束日期仍完整显示。

## 副作用与处理

- 节点下拉外部关闭边界收窄后，点击节点行空白会关闭下拉，但点击节点框本身仍要能正常切换下拉，事件顺序需要重点验证。
- 节点拖动排序会新增前后端交互。虽然不新增 schema，但需要新增重排 API，并校验同层级，避免错误请求把不同层级节点排到一起。
- 拖动排序可能和右键菜单、点击选择节点发生冲突，必须区分拖动和普通点击。
- 标签筛选框加宽会占用筛选行空间，窄窗口下可能换行，必须避免遮挡或挤压其他控件。
- 历史记录顶部间距压缩后，加载/错误消息仍需要有可见空间，不能被完全挤没。
- 历史分页按钮和每页数量对齐属于视觉调整，必须用页面截图或手动观察确认，不能只靠代码判断。
