## 概念命名

V0.12 起，操作区尺寸相关控件按以下概念处理：

```text
分辨率 = 宽高比，例如 1:1、16:9、9:16
清晰度 = 1K、2K、4K、自定义
实际尺寸 = 宽高比 + 清晰度 计算出的像素尺寸，例如 2048x1152
```

界面显示规则：

- 软件界面中的“分辨率”按钮只显示宽高比，例如 `16:9`。
- 软件界面中的“分辨率”按钮不显示 `2048x1152` 这类实际尺寸。
- 清晰度为 `自定义` 时，“分辨率”按钮显示 `自定义`，不显示实际尺寸。
- 实际尺寸只在分辨率下拉菜单和保存区尺寸文本中显示。
- 清晰度下拉菜单只负责选择 `1K`、`2K`、`4K`、`自定义`，不提供输入框。

生成请求继续传实际尺寸：

```js
options: {
  size: state.operation.generation_size,
  resolution: state.operation.generation_clarity,
  count: state.operation.generation_count,
}
```

说明：

- `options.size` 是实际像素尺寸。
- `options.resolution` 继续传给 provider，用作 API 的清晰度参数，值为 `1K`、`2K`、`4K` 或 `custom`。
- 保存区自动生成实例仍只显示实际尺寸，例如 `2048x1152`。
- 保存区不显示数量，不显示宽高比，不显示清晰度。

## 操作区布局

V0.11 的尺寸/分辨率区域改为：

```text
上排：分辨率按钮
下排：清晰度按钮 + 数量输入
```

布局规则：

- 上排分辨率按钮宽度等于下排 `清晰度 + 数量` 的总宽度。
- 不加宽 V0.11 的尺寸/分辨率列。
- 上排分辨率按钮只显示宽高比，例如 `16:9`。
- 上排分辨率按钮不显示实际尺寸，例如不显示 `2048x1152`。
- 清晰度为自定义时，上排分辨率按钮显示 `自定义`。
- 下排清晰度按钮显示 `1K`、`2K`、`4K`；自定义模式显示空白。
- 下排数量框只显示数字，不显示“数量”两个字。

建议 DOM 结构：

```html
<div class="field record-generation-options">
  <div class="field record-aspect-ratio">...</div>
  <div class="clarity-count-row">
    <div class="field record-clarity">...</div>
    <input name="generation_count">
  </div>
</div>
```

CSS：

- `.record-generation-options` 仍保持两行。
- `.record-aspect-ratio` 占满第一行。
- `.clarity-count-row` 第二行左右两列。
- `.record-clarity` 和 `generation_count` 各占一半宽度。

## 分辨率下拉

分辨率下拉显示宽高比选项。

当清晰度为 `1K`、`2K`、`4K` 时，下拉选项显示为：

```text
1024x1024 (1:1)
1280x1024 (5:4)
864x1536 (9:16)
2016x864 (21:9)
1536x864 (16:9)
1024x768 (4:3)
1536x1024 (3:2)
1024x1280 (4:5)
768x1024 (3:4)
1024x1536 (2:3)
```

显示规则：

- 每个选项显示 `实际尺寸 (宽高比)`。
- 主按钮只显示选中的宽高比。
- 选择某个选项后，更新：
  - `state.operation.aspect_ratio`
  - `state.operation.generation_size`
  - `state.operation.custom_generation_size`
- 同步保存默认宽高比和实际尺寸。

当清晰度为 `custom` 时，下拉选项显示自定义尺寸：

```text
1234x567 (自定义)
1600x900 (自定义)
...
```

显示规则：

- 主按钮固定显示 `自定义`，避免显示实际尺寸导致按钮变宽。
- 每个自定义选项显示 `实际尺寸 (自定义)`。
- 自定义选项只在清晰度为 `custom` 时显示。
- 自定义尺寸仍只接受 `数字x数字` 格式。
- 自定义尺寸输入区只出现在分辨率下拉中，不出现在清晰度下拉中。

## 清晰度下拉

清晰度下拉只显示选项，不显示输入框。

选项：

```text
1K
2K
4K
自定义
```

规则：

- 选择 `1K`、`2K`、`4K` 后，按照当前 `aspect_ratio` 从 `SIZE_MAP` 计算 `generation_size`。
- 选择 `自定义` 后，不在清晰度下拉里显示输入框。
- 选择 `自定义` 后，分辨率下拉切换为自定义尺寸列表和自定义尺寸输入区。
- 清晰度按钮在自定义模式下显示空白。

## 自定义尺寸保存

配置新增：

```json
{
  "custom_generation_sizes": []
}
```

规则：

- 自定义尺寸保存在共享配置，不进入数据库。
- 每次在分辨率下拉中输入并确认自定义尺寸后，将该尺寸加入 `custom_generation_sizes`。
- 已存在的尺寸不重复加入。
- 新增后自动选中该自定义尺寸。
- 自定义尺寸选项显示为 `1234x567 (自定义)`。
- 鼠标移到某个自定义尺寸选项上时，右侧出现小 `x`。
- 点击小 `x` 删除该自定义尺寸选项。
- 删除自定义尺寸只删除配置选项，不删除历史实例，不删除本地图片文件。
- 如果删除的是当前选中的自定义尺寸，回退到默认组合：

```text
aspect_ratio = 1:1
generation_clarity = 1K
generation_size = 1024x1024
```

交互细节：

- 点击自定义尺寸选项本身：选中该尺寸。
- 点击该选项右侧小 `x`：只删除该选项，不触发选中。
- 删除小 `x` 不需要二次弹窗；这是用户在设置型下拉菜单中的显式删除动作。

## 配置与默认值

`backend/config.py` 的默认配置新增：

```json
{
  "default_aspect_ratio": "1:1",
  "default_clarity": "1K",
  "custom_generation_sizes": []
}
```

保留兼容字段：

```json
{
  "default_size": "1024x1024",
  "default_resolution": "1K",
  "default_custom_resolution": ""
}
```

归一化规则：

- `default_aspect_ratio` 必须在 `SIZE_MAP` 支持的宽高比中，否则回退 `1:1`。
- `default_clarity` 必须是 `1K`、`2K`、`4K`、`custom`，否则回退 `1K`。
- `custom_generation_sizes` 必须是数组。
- `custom_generation_sizes` 只保留符合 `数字x数字` 的字符串。
- `custom_generation_sizes` 去重并保持顺序。

保存设置时：

- 选择预设宽高比/清晰度时，同步写入：
  - `default_aspect_ratio`
  - `default_clarity`
  - `default_size`
  - `default_resolution`
- 选择自定义尺寸时，同步写入：
  - `default_clarity = custom`
  - `default_size = 自定义尺寸`
  - `default_resolution = custom`
  - `custom_generation_sizes`
- `default_custom_resolution` 只保留旧配置兼容，不再通过 V0.12 界面写入新的自定义清晰度文本。

## 后端生成参数

后端 `/api/generate` 不需要理解宽高比。

前端发送：

```js
options: {
  size: state.operation.generation_size,
  resolution: activeGenerationClarity(),
  count: state.operation.generation_count,
}
```

后端继续校验：

- `size` 是 `数字x数字`。
- `resolution` 是非空字符串。
- `count` 是正整数。

Provider 继续收到：

```python
options["size"]
options["resolution"]
options["count"]
```

## 副作用处理

命名变化：

- V0.11 的“分辨率”实际是 `1K/2K/4K/custom`。
- V0.12 的“分辨率”改为宽高比。
- 代码中应尽量使用 `aspect_ratio` 和 `generation_clarity`，避免继续把 `resolution` 当作界面概念。

配置兼容：

- 旧配置仍有 `default_resolution`，不能直接删除。
- V0.12 读取旧配置时要迁移到 `default_clarity`。
- 后端仍保留 `default_resolution`，避免旧逻辑或 provider 配置读取失败。

自定义尺寸删除：

- 删除的是配置选项，不影响历史实例。
- 历史实例已经保存实际 `generation_size`，不需要迁移。

UI 宽度：

- 分辨率按钮只显示宽高比，避免挤压。
- 分辨率下拉可以显示完整 `实际尺寸 (宽高比)`。
- 自定义清晰度下，分辨率按钮只显示 `自定义`，实际尺寸只在下拉里显示为 `1234x567 (自定义)`。
- 清晰度按钮自定义模式显示空白，保持 V0.11 的紧凑风格。

自定义清晰度：

- V0.12 不在清晰度下拉中输入自定义清晰度。
- V0.11 的 `default_custom_resolution` 保留用于兼容已有配置。
- 如果后续仍需要自定义 API 清晰度字符串，应单独设计，不放在本版本。

生成保存：

- `count > 1` 的多实例保存逻辑沿用 V0.11。
- 本版本不改保存区实例结构。
