# V0.71 sysrv-google、apimart-openai 与 Provider 三态标记

## 目标

当前 V0.70 已完成生图管理页操作区 Provider 下拉菜单中的个人 `√ / X` 标记。本版 V0.71 目标是在不影响现有接口类型和布局的前提下，新增两个基于共享脚本的接口类型，并将操作区 Provider 个人标记从两态扩展为三态。

本版需求：

- 将 `google_b2_text_to_image_sysrv.py`、`google_b2_image_to_image_sysrv.py` 作为接口类型 `sysrv-google` 接入。
- 将 `openai_text_to_image_apimart.py`、`openai_image_to_image_apimart.py` 作为接口类型 `apimart-openai` 接入。
- 设置页选择 `sysrv-google` 时，连接信息区内容不变，参数区标题为 `Google API 参数`。
- 设置页选择 `apimart-openai` 时，连接信息区内容不变，参数区标题为 `Openai API 参数`。
- 参数区参数根据对应脚本实际使用的参数调整。
- 调用示例根据对应脚本代码显示。
- 软件生成流程必须按这两个接口类型运行对应共享脚本。
- 脚本里的所有实际参数值必须来自软件注入，不在脚本或软件流程中写死真实业务值。
- 以上修改不影响当前 `openai`、`openai-google`、`google`、`other` 等接口类型的运行和布局。
- 生图管理页操作区 Provider 下拉菜单中，每行最右侧个人标记从 `√ / X` 扩展为 `√ / X / -`。
- `-` 表示“当前没在用了”。
- Provider 个人标记仍只在操作区 Provider 下拉菜单中体现，不和其他地方关联。

本版原则：

- 不改变现有 Provider 配置的核心含义。
- 不破坏 Provider 能力体系。
- 不破坏现有 `openai` 和 `openai-google` 生图流程。
- 不破坏设置页现有连接信息区布局。
- 不破坏操作区、保存区、历史记录、标签、数据安全等既有功能。
- 不新增数据库 schema，除非实现时发现当前 Provider 配置字段无法保存新接口参数且必须补齐。
- 固定共享脚本优先用于默认生成流程；自定义代码仍沿用当前规则，存在自定义代码时优先使用自定义代码。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 当前状态判断

当前 V0.70 已有：

- `openai` 接口类型，使用 OpenAI-compatible 共享脚本。
- `openai-google` 接口类型，使用小云 Google B2 共享脚本。
- 设置页连接信息区已经统一包含：
  - `base_url`
  - `api_key`
  - `api_key_env`
  - `model`
  - `user_agent`
  - 代理模式
  - 自定义代理
  - 是否允许不受信代理证书
- 设置页调用示例 / 自定义代码 / 参数介绍已经在同一代码框区域切换。
- 后端已有按 adapter 选择共享脚本的入口。
- 后端已有向脚本注入 `base_url`、`api_key`、`model`、`operation_prompt`、`input_images`、`resolved_size`、`output_path`、`output_dir`、`result_json_path` 等上下文参数的机制。
- 操作区 Provider 下拉菜单已经是自定义下拉，并支持 `√ / X` 个人标记。

因此 V0.71 应优先复用现有结构，不另起一套 Provider 或脚本执行体系。

## sysrv-google 接入

### 1. 接口类型

调整方案：

- 新增 Provider adapter：`sysrv-google`。
- 设置页接口类型下拉菜单增加 `sysrv-google`。
- 前端 Provider 能力体系中将 `sysrv-google` 标记为已实现。
- `sysrv-google` 支持：
  - 文生图。
  - 图生图。
  - 自定义代码。
- `sysrv-google` 使用共享脚本：
  - 文生图：`AI生图软件/files/google_b2_text_to_image_sysrv.py`
  - 图生图：`AI生图软件/files/google_b2_image_to_image_sysrv.py`

验收标准：

- 设置页可以选择 `sysrv-google`。
- 选择后不会显示“未实现”占位提示。
- 操作区选择 `sysrv-google` Provider 后可以正常进入生成流程。
- 文生图使用 `google_b2_text_to_image_sysrv.py`。
- 图生图使用 `google_b2_image_to_image_sysrv.py`。

副作用：

- Provider adapter 枚举会增加一个值，需要前后端同时认识。
- 旧配置中不存在该 adapter，不应影响旧 Provider。

### 2. 设置页参数区

调整方案：

- 选择 `sysrv-google` 后，连接信息区保持当前样式和字段不变。
- 参数区标题显示为：`Google API 参数`。
- 参数区展示脚本实际需要的软件带入参数和可配置参数。

文生图参数：

- `生图方式`：文生图 / 图生图切换。
- `prompt / operation_prompt`：来自操作区或保存区实例。
- `保存路径 / output_path / result_json_path`：来自软件流程。
- `role / google_role`：Provider 参数，默认 `user`。
- `request_timeout_seconds`：高级容错参数，默认 300。
- `download_timeout_seconds`：高级容错参数，默认 120。
- `max_retry_attempts`：高级容错参数，默认按脚本重试列表计算。

图生图额外参数：

- `input_images`：来自操作区或保存区实例的输入图列表。

不在参数区重复展示的参数：

- `base_url`：连接信息区已有。
- `api_key` / `api_key_env`：连接信息区已有。
- `model`：连接信息区已有。
- `user_agent`：连接信息区已有。
- `use_system_proxy` / `system_proxy` / `allow_untrusted_proxy_certificate`：复用连接信息区代理配置注入。

验收标准：

- 切换到 `sysrv-google` 后参数区标题正确。
- 文生图和图生图切换时，参数区能体现 `input_images` 是否参与。
- 连接信息区没有因为 adapter 切换发生布局变化。
- `None` 或空值的处理沿用现有设置页规则，不把普通空值误当成真实字符串发送。

副作用：

- `sysrv-google` 参数比 `openai-google` 更少，需要避免继续显示当前小云脚本专用的无关参数。

### 3. 尺寸、分辨率和数量

当前脚本判断：

- `google_b2_text_to_image_sysrv.py` 不读取 `resolved_size`、`ratio`、`resolution`、`n`。
- `google_b2_image_to_image_sysrv.py` 不读取 `resolved_size`、`ratio`、`resolution`、`n`。
- 脚本 payload 使用 Google `generateContent` 风格：
  - `contents`
  - `role`
  - `parts`
  - `generationConfig.responseModalities`

调整方案：

- `sysrv-google` 不把操作区尺寸、分辨率、比例和数量强行塞入 payload。
- 如果当前操作区已有尺寸 / 分辨率值，可以保留在 UI 状态中，但实际 `sysrv-google` 脚本不使用。
- 历史参数快照中应保留 adapter、model、prompt、输入图、保存路径、脚本参数等真实参与生成的信息。

验收标准：

- `sysrv-google` 生成请求中不出现脚本不使用的尺寸参数。
- 不因为用户操作区当前有尺寸或数量就导致脚本报错。
- 不影响 `openai`、`apimart-openai` 等需要尺寸的接口继续正常使用尺寸。

副作用：

- 用户可能看到操作区中仍有尺寸相关 UI，但 `sysrv-google` 实际不使用。后续如需更强提示，可单独版本处理，不在本版扩大 UI 改动。

## apimart-openai 接入

### 4. 接口类型

调整方案：

- 新增 Provider adapter：`apimart-openai`。
- 设置页接口类型下拉菜单增加 `apimart-openai`。
- 前端 Provider 能力体系中将 `apimart-openai` 标记为已实现。
- `apimart-openai` 支持：
  - 文生图。
  - 图生图。
  - 多输出图。
  - 自定义代码。
- `apimart-openai` 使用共享脚本：
  - 文生图：`AI生图软件/files/openai_text_to_image_apimart.py`
  - 图生图：`AI生图软件/files/openai_image_to_image_apimart.py`

验收标准：

- 设置页可以选择 `apimart-openai`。
- 选择后不会显示“未实现”占位提示。
- 操作区选择 `apimart-openai` Provider 后可以正常进入生成流程。
- 文生图使用 `openai_text_to_image_apimart.py`。
- 图生图使用 `openai_image_to_image_apimart.py`。

副作用：

- `apimart-openai` 和普通 `openai` 都属于 OpenAI-compatible 风格，但脚本细节不同，不能共用同一个固定脚本入口。

### 5. 设置页参数区

调整方案：

- 选择 `apimart-openai` 后，连接信息区保持当前样式和字段不变。
- 参数区标题显示为：`Openai API 参数`。
- 参数区展示脚本实际需要的软件带入参数和可配置参数。

文生图参数：

- `生图方式`：文生图 / 图生图切换。
- `prompt / operation_prompt`：来自操作区或保存区实例。
- `size / resolved_size`：来自操作区或保存区实例尺寸参数。
- `n`：来自操作区或保存区实例数量参数。
- `保存路径 / output_dir / output_path / result_json_path`：来自软件流程。
- `quality`：Provider 参数，默认 `high`。
- `output_format`：Provider 参数，默认 `png`。
- `output_compression`：Provider 参数，默认 80，仅 `jpeg` / `webp` 有效。
- `background`：Provider 参数，默认 `auto`。
- `moderation`：Provider 参数，默认 `low`。
- `user`：Provider 参数，可为空。
- `request_timeout_seconds`：高级容错参数，默认 300。
- `download_timeout_seconds`：高级容错参数，默认 120。
- `max_retry_attempts`：高级容错参数，默认按脚本重试列表计算。
- `apimart_task_timeout_seconds`：APIMart 任务轮询超时，默认 420。
- `apimart_task_poll_interval_seconds`：APIMart 任务轮询间隔，默认 5。

图生图参数：

- 包含文生图中除 `moderation` 之外的通用参数。
- `input_images`：来自操作区或保存区实例的输入图列表。
- `input_fidelity`：Provider 参数，可为空。
- `mask_path`：Provider 参数，可为空，当前如软件没有遮罩选择入口则显示为软件未启用或空。

不在参数区重复展示的参数：

- `base_url`：连接信息区已有。
- `api_key` / `api_key_env`：连接信息区已有。
- `model`：连接信息区已有。
- `user_agent`：连接信息区已有。
- 代理相关参数：复用连接信息区代理配置注入。

验收标准：

- 切换到 `apimart-openai` 后参数区标题正确。
- 文生图显示 `moderation`。
- 图生图不显示或不发送 `moderation`。
- 图生图显示 `input_images`、`input_fidelity`、`mask_path`。
- `n`、`resolved_size` 正常从操作区或保存区实例带入脚本。
- 多输出图按脚本返回的 `output_paths` 进入软件保存流程。

副作用：

- `apimart-openai` 会引入 APIMart task 轮询参数，参数区会比普通 OpenAI 稍多。
- 需要避免这些 APIMart 专属参数污染普通 `openai` Provider。

## 调用示例和脚本路由

### 6. 调用示例切换

调整方案：

- 设置页调用示例区域根据当前 Provider adapter 和生图方式读取对应共享脚本。
- `sysrv-google`：
  - 文生图显示 `google_b2_text_to_image_sysrv.py`。
  - 图生图显示 `google_b2_image_to_image_sysrv.py`。
- `apimart-openai`：
  - 文生图显示 `openai_text_to_image_apimart.py`。
  - 图生图显示 `openai_image_to_image_apimart.py`。
- 调用示例只读，保留复制。
- 自定义代码仍然放在“自定义代码”中。

验收标准：

- 切换接口类型时，调用示例跟随切换。
- 同一接口类型下切换文生图 / 图生图时，调用示例跟随切换。
- `openai`、`openai-google` 的调用示例不被改错。
- 调用示例内容来自共享脚本文件，不手写另一份容易失真的示例。

副作用：

- 后端或前端需要扩展脚本示例加载映射。
- 如果共享脚本文件缺失，设置页应显示可理解的加载失败提示，而不是空白。

### 7. 软件生成流程

调整方案：

- 后端共享脚本路由按 adapter 增加分支：
  - `sysrv-google` -> sysrv Google 脚本。
  - `apimart-openai` -> APIMart OpenAI 脚本。
- 生成上下文注入要覆盖脚本读取的所有 globals。
- `custom_script_context`、生成参数快照、历史记录参数快照都要识别新 adapter。
- 自定义代码优先级保持不变：
  - 如果当前 Provider 对应模式存在自定义代码，使用自定义代码。
  - 否则使用固定共享脚本。

脚本注入要求：

- `base_url` 来自连接信息区。
- `api_key` 来自连接信息区 `api_key` 或 `api_key_env` 解析结果。
- `model` 来自连接信息区 `model`。
- `user_agent` 来自连接信息区 `user_agent`。
- `operation_prompt` 来自当前提交实例的提示词。
- `input_images` 来自当前提交实例的输入图。
- `resolved_size` 仅对需要尺寸的 adapter 注入并参与请求。
- `n` 来自当前提交实例的数量。
- `output_dir`、`output_path`、`result_json_path` 来自软件生成流程。
- 代理、证书、超时和重试参数来自 Provider 配置或软件默认值。

验收标准：

- `sysrv-google` 文生图、图生图可以通过软件生成流程进入对应脚本。
- `apimart-openai` 文生图、图生图可以通过软件生成流程进入对应脚本。
- 生成历史记录中 adapter、provider、model、调用方式、参数快照可追踪。
- 失败重试和错误记录沿用现有历史记录机制。
- 取消生成、生成中状态、保存区实例状态不因新 adapter 回退。

副作用：

- 新脚本可能返回不同响应结构，必须以脚本输出的 `result_json_path` 和 `output_paths` 为软件交接标准。
- 如果服务商本身返回 task 异步结构，`apimart-openai` 会等待轮询，单次任务耗时可能比普通 OpenAI 更长。

## Provider 三态个人标记

### 8. 标记状态扩展

调整方案：

- V0.70 的操作区 Provider 个人标记从两态扩展为三态。
- 状态值：
  - `checked`：显示 `√`。
  - `rejected`：显示 `X`。
  - `unused`：显示 `-`。
- 默认状态仍为 `X`。
- 点击状态按钮循环：
  - `X -> √ -> - -> X`
- 旧的 V0.70 本地状态兼容：
  - 已保存 `checked` 的 Provider 继续显示 `√`。
  - 已保存 `rejected` 或没有保存状态的 Provider 显示 `X`。
  - 新增 `unused` 后才显示 `-`。

显示规则：

- `√`、`X`、`-` 样式要明显区分。
- `-` 表示“当前没在用了”。
- 当前选中的 Provider 在下拉收起状态中也显示对应三态标记。
- 点击标记按钮只切换标记，不选中 Provider。
- 点击 Provider 行主体才选中 Provider。

验收标准：

- Provider 行右侧按钮可以在 `X`、`√`、`-` 三种状态间循环。
- 点击右侧按钮不改变当前 Provider。
- 点击右侧按钮不关闭下拉菜单。
- 点击行主体仍正常选择 Provider。
- 当前 Provider 收起状态显示三态标记。
- 刷新页面后本地三态标记保留。

副作用：

- 操作区 Provider 控件右侧状态按钮仍占用固定宽度，长 Provider 名称需要继续省略显示。
- 三态信息是本地个人标记，换浏览器、清理浏览器数据、换电脑后不会自动同步。

### 9. 标记隔离范围

调整方案：

- 三态 Provider 标记只保存在前端 UI 状态中。
- 不写入 Provider 配置。
- 不写入数据库。
- 不纳入备份、导出、恢复。
- 不参与 Provider 筛选。
- 不参与 Provider 排序。
- 不影响生成使用哪个 Provider。
- 不在以下位置显示：
  - 设置页 Provider 下拉。
  - 保存区实例 Provider 下拉。
  - 生图管理页 Provider 筛选。
  - 历史记录页 Provider 筛选。
  - 历史记录详情。
  - 数据安全导出和备份。

验收标准：

- 三态标记只在操作区 Provider 下拉菜单出现。
- 标记变化不会触发设置页“保存设置”脏状态。
- 标记变化不会改变 Provider 配置文件。
- 标记变化不会影响生成请求参数。

副作用：

- 该标记只是个人临时记录，不具备跨设备一致性。
- 这是符合“只给自己记录用”的取舍。

## 兼容性和数据影响

### 10. Provider 配置兼容

调整方案：

- 新增 adapter 默认值和规范化规则。
- 旧 Provider 不自动变成新 adapter。
- 新建 Provider 默认接口类型仍按现有规则，不因为新增 adapter 改变默认选择。
- `sysrv-google` 和 `apimart-openai` 需要保存各自参数，但不能污染其他 adapter。

验收标准：

- 旧配置打开不报错。
- 旧 Provider 的 adapter、base_url、api_key_env、model 不被误改。
- 新建 `sysrv-google` Provider 后保存再打开，参数不丢失。
- 新建 `apimart-openai` Provider 后保存再打开，参数不丢失。

副作用：

- Provider 配置字段会增加若干新 adapter 参数。只要仍保存在现有 Provider 配置 JSON 中，就不需要新增数据库 schema。

### 11. 历史记录和参数快照

调整方案：

- 历史记录参数快照要保留新 adapter 的关键参数。
- `sysrv-google` 历史快照中不伪造尺寸参数参与生成。
- `apimart-openai` 历史快照中保留 `resolved_size`、`n`、OpenAI 参数和 APIMart 轮询参数。
- 历史记录显示 Provider 时继续使用 Provider 显示名和历史快照中的旧 Provider 信息规则。

验收标准：

- 新 adapter 生成成功和失败都能写入历史记录。
- 历史记录“参数”复制能看到 adapter、model、提示词、输入图、尺寸或无尺寸规则、脚本参数。
- 历史记录高级查询与清理不受影响。

副作用：

- 历史记录参数快照字段内容会比旧版本多出新 adapter 参数。
