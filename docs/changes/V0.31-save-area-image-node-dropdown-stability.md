文档版本：V0.31

日期：2026-05-07

## 修改目标

V0.31 在 V0.30 基础上做保存区翻页图片稳定性收口、节点下拉交互收口、节点重命名 / 删除入口收口，以及撤销 / 重做按钮文案与样式收口。

主要目标：

- 修复保存区翻页后图片偶发不显示的问题，保留图片懒加载。
- 翻页、筛选、排序、每页数量变化后，当前页所有应该显示的图片必须稳定显示。
- 图片弹窗、左右切换、原图查看不能被图片稳定性修复改坏。
- 节点框闭合状态始终显示当前选择内容。
- 节点下拉改成可控的自定义下拉，避免原生 `select` 显示为空或显示错误。
- 任一层级节点下拉菜单中的真实节点项支持右键菜单。
- 节点重命名 / 删除入口移动到真实节点项右键菜单中。
- 节点区不再放独立“重命名”“删除”按钮。
- 节点下拉菜单中 `新建` 固定放在最上面，并与其他选项作视觉区分。
- `向前 / 向后` 按钮改名为 `撤销 / 重做`，样式与翻页按钮区分。
- 不破坏 V0.30 的节点筛选、节点移动、批量移动、过程区、JSON 恢复。

## 不做内容

- 不引入缩略图缓存。
- 不取消图片懒加载。
- 不新增节点数据结构。
- 不新增数据库 schema 字段。
- 不扩大撤销 / 重做作用范围。

- 不重拆前端 JS 模块。

## 保存区翻页图片稳定性

### 问题处理范围

处理保存区中以下场景的图片偶发空白问题：

- 点击 `上一页` 后当前页部分图片空白。
- 点击 `下一页` 后当前页部分图片空白。
- 点击 `首页`、`尾页` 后当前页部分图片空白。
- 修改搜索、标签筛选、来源筛选、方式筛选、排序、每页数量后，当前页部分图片空白。
- 图片空白后切换浏览器 tab 再切回来才恢复显示。

只处理保存区当前页应该显示的图片，不提前加载页面外大量图片。

### 懒加载保留规则

继续保留 V0.27 之后的保存区图片懒加载能力。

允许做以下增强：

- 当前页渲染完成后，主动检查当前页可见图片。
- 对当前页可见图片设置更积极的加载触发。
- 对疑似空白图片做有限次数重试。
- 对当前页可见但未完成加载的图片临时设置 `loading="eager"`，不影响页面外图片继续懒加载。

禁止做以下处理：

- 禁止一次性加载所有页图片。
- 禁止删除 `IntersectionObserver` 懒加载机制。
- 禁止为了修复空白而复制、改名或移动原图文件。

### 图片加载状态判断

在 `frontend/js/image-loader.js` 中增加或整理以下判断函数：

```javascript
function isImageReady(img) {
  return Boolean(img && img.complete && img.naturalWidth > 0);
}
```

疑似空白图片包括：

- 图片节点存在，但 `src` 为空。
- 图片节点存在，`complete = false` 且超过本轮检查等待时间。
- 图片节点存在，`complete = true` 但 `naturalWidth = 0`。
- 图片节点的 `data-lazy-image-path` 与当前 `src` 对应路径不一致。

### 当前页图片主动唤醒

保留 `resetSaveAreaImageObserver()`、`observeSaveAreaImageSlot()`、`loadLazyImageSlot()` 的职责，但增加当前页稳定检查入口：

```javascript
function stabilizeSaveAreaImages(options = {}) {
  // 渲染完成后多轮检查当前保存区图片
}

function verifySaveAreaImages(options = {}) {
  // 只检查当前 data-save-area 内的 data-lazy-image-path 图片位
}
```

`verifySaveAreaImages()` 的规则：

- 只扫描当前 `data-save-area` 内的 `[data-lazy-image-path]`。
- 只处理有真实图片路径的图片位。
- 优先检查当前视口内和接近视口的图片位。
- 对 `forceVisible = true` 的调用，当前页图片位都必须进入观察和加载流程。
- 对疑似空白图片执行 `loadLazyImageSlot(slot, true)`。
- 每个图片位同一轮渲染最多做有限次数重试，避免无限刷新 URL。

建议检查节奏：

```text
渲染后立即检查
80ms 后复查
240ms 后复查
600ms 后复查
1200ms 后最终复查
```

如果最终复查仍然失败，只显示原有图片位状态，不阻塞页面操作，并在控制台输出可排查信息。

### 图片 URL 与缓存 key

`loadLazyImageSlot(slot, retry)` 继续通过 `imageUrl(path)` 生成图片 URL。

重试时只允许追加一次短期 cache-buster：

```text
&retry=<timestamp>
```

要求：

- 正常首次加载不加 `retry`。
- 只有疑似空白或加载错误时才加 `retry`。
- 同一图片位不要因为多轮检查无限更新 `src`。
- 翻页后新 DOM 节点必须使用当前节点自己的 `data-lazy-image-path` 计算 URL，不能复用上一页旧节点状态。

### 翻页和筛选后的触发点

以下动作完成 `loadInstances()` 和 `renderManager()` 后，必须主动触发图片稳定检查：

- `setSavePage()`
- `changeSavePage()`
- `applySaveFilters()`
- `setSaveLayout()`
- `refreshInstances()`
- 标签筛选变化
- 节点筛选变化
- 撤销 / 重做完成后刷新保存区
- 单个移动、批量移动完成后刷新保存区
- 删除实例、批量删除完成后刷新保存区

实现上可以统一在 `renderManager()` 末尾调用：

```javascript
globalThis.stabilizeSaveAreaImages?.({ forceVisible: true, reason: "render-manager" });
```

在 `refreshInstances()` 末尾继续保留显式调用，用于异步刷新后的二次兜底。

### 图片弹窗与悬停预览

图片稳定性修改后必须保持：

- 点击图片仍然打开大图弹窗。
- 大图弹窗中左右按钮仍然可以切换当前实例或当前操作区的图片。
- 键盘左右方向键仍然可以切换大图。
- 鼠标滚轮缩放、拖动图片、适应窗口仍然可用。
- 鼠标悬停临时预览仍然可用。
- 空图片位不打开大图。

## 节点下拉显示与交互

### 自定义节点下拉

将保存区节点区的原生 `select` 改成自定义下拉组件。

原因：

- 原生 `select option` 不能稳定支持真实节点项右键菜单。
- 当前节点框使用透明原生 `select` 叠加显示文字，容易出现闭合状态显示为空。

实现位置：

```text
frontend/js/nodes.js
frontend/js/events.js
frontend/css/05-save-area.css
frontend/css/12-dialogs.css
```

### 节点框闭合显示

节点框闭合状态必须始终由当前节点路径状态计算显示文字。

显示规则：

- 当前选择为 `全部` 时显示 `全部`。
- 当前选择为 `其他` 时显示 `其他`。
- 当前选择为真实节点时显示该节点名称。
- 当前节点名超过 8 个汉字时，闭合状态显示前 8 个字。
- 节点框必须带 `title`，鼠标悬停能看到完整节点名。
- 不能出现内部状态已经切换，但节点框显示为空。
- 不能出现内部状态已经切换，但节点框仍显示上一个节点。

建议实现：

```javascript
function nodeSelectionLabel(entry) {
  if (entry.selection === "all") return "全部";
  if (entry.selection === "unassigned") return "其他";
  if (entry.selection === "node") return findNode(entry.node_id)?.name || "节点已不存在";
  return "全部";
}
```

节点路径经 `loadNodes()` 校正后，如果节点不存在，应按 V0.30 既有规则清理无效路径，不保留空白显示。

### 节点菜单选项顺序

每一个层级节点菜单的选项顺序固定为：

```text
新建
全部
其他
真实节点 1
真实节点 2
...
```

规则：

- `新建` 固定放在最上面。
- `新建` 使用独立视觉样式，与真实节点项区分。
- `全部`、`其他` 是特殊筛选项，不是真实节点。
- 真实节点项显示完整节点名称。
- 真实节点项可以左键选择，也可以右键打开节点操作菜单。
- `新建`、`全部`、`其他` 不支持右键菜单。
- `新建` 不能被当作真实节点参与筛选、移动或右键菜单。

### 节点菜单打开关闭

节点菜单交互规则：

- 点击节点框按钮打开或关闭当前层级菜单。
- 打开一个节点菜单时，关闭其他节点菜单。
- 点击菜单外部关闭节点菜单。
- 按 `Escape` 关闭节点菜单。
- 点击菜单内部空白区域不误触发批量保存。
- 点击弹窗、图片查看器、标签选择器内部不误触发节点菜单关闭后的额外保存行为。

节点菜单打开状态只作为前端临时 UI 状态，不写入数据库。

### 左键选择节点项

节点菜单左键选择规则沿用 V0.30 节点筛选逻辑：

- 点击 `新建`：打开节点名称输入弹窗。
- 点击 `全部`：当前层级选择全部。
- 点击 `其他`：当前层级选择其他。
- 点击真实节点：当前层级选择该节点，并显示下一层节点框。

选择后继续执行：

- `state.filters.page = 1`
- 清空当前页批量选择。
- 保存 UI 状态。
- 刷新保存区。
- 触发保存区图片稳定检查。

## 节点右键菜单

### 右键菜单范围

任一层级节点下拉菜单中的真实节点项支持右键菜单。

右键菜单只对真实节点出现：

- 对真实节点出现。
- 对 `全部` 不出现。
- 对 `其他` 不出现。
- 对 `新建` 不出现。
- 对菜单空白区域不出现。

右键菜单包含：

```text
重命名
删除
```

### 右键菜单行为

右键真实节点项时：

1. 阻止浏览器默认右键菜单。
2. 打开软件自定义节点右键菜单。
3. 菜单位置跟随鼠标位置，并保证不超出当前窗口。
4. 点击菜单外部关闭右键菜单。
5. 按 `Escape` 关闭右键菜单。

右键菜单目标节点必须保存在临时状态中：

```javascript
state.nodeContextMenu = {
  open: true,
  node_id: 123,
  x: 100,
  y: 200
}
```

该状态不持久化到 UI 状态，不写入数据库。

### 重命名真实节点

点击右键菜单中的 `重命名`：

1. 关闭右键菜单。
2. 打开节点名称输入弹窗。
3. 弹窗标题显示 `重命名节点`。
4. 输入框默认填入目标节点当前名称。
5. 校验空名称、纯空格、保留名、同父级重名。
6. 调用 `PATCH /api/nodes/<node_id>`。
7. 纳入 V0.30 既有撤销栈。
8. 成功后重新加载节点树。
9. 刷新保存区。

重命名的目标是右键点击的真实节点，不要求这个节点一定是当前选中的最深节点。

如果重命名目标节点位于当前筛选路径中：

- 当前筛选路径保持不变。
- 节点框闭合显示更新为新名称。

如果重命名目标节点不在当前筛选路径中：

- 当前筛选路径不变。
- 只更新菜单和节点树显示。

### 删除真实节点

点击右键菜单中的 `删除`：

1. 关闭右键菜单。
2. 弹出二次确认。
3. 确认文案必须包含目标节点名称。
4. 调用 `DELETE /api/nodes/<node_id>`。
5. 纳入 V0.30 既有撤销栈。
6. 删除成功后重新加载节点树。
7. 刷新保存区。

删除规则继续沿用 V0.30：

- 删除节点不删除任何实例。
- 删除节点不删除任何图片文件。
- 被删节点以及子节点下的实例整体上提到被删节点的父节点。
- 如果被删节点在根层，则这些实例的 `node_id = NULL`。
- 被删节点的子节点结构整体上提到父节点，不丢失层级顺序。

删除后的当前筛选路径处理：

- 如果删除的是当前筛选路径中的节点，当前路径回退到被删节点父级。
- 如果删除的是当前筛选路径的祖先节点，当前路径回退到被删节点父级。
- 如果删除的是当前筛选路径以外的节点，当前路径保持不变。
- 删除后 `state.filters.page = 1`。
- 删除后清空当前页批量选择。
- 删除后保存 UI 状态。

### 去掉独立按钮

删除节点区中独立的：

```text
重命名
删除
```

按钮。

相关 action 不再从节点区按钮触发，但可保留函数供右键菜单调用。

## 移动弹窗兼容

单个移动、批量移动弹窗继续使用路径式节点选择。

可以复用自定义节点下拉组件，但必须满足：

- 移动弹窗中仍然可以新建节点。
- 新建节点后仍然自动进入新节点。
- `新建` 不作为移动目标本身。
- `全部`、`其他` 的移动语义继续沿用 V0.30。
- 移动弹窗中的真实节点不需要右键菜单。
- 不允许在移动弹窗中误触发节点删除。

如果复用同一套渲染函数，需要增加参数控制：

```javascript
renderNodePathSelectors({
  enableContextMenu: false
})
```

保存区节点筛选区域使用：

```javascript
renderNodePathSelectors({
  enableContextMenu: true
})
```

## 撤销 / 重做按钮

### 文案

将保存区批量工具栏中的：

```text
向后
向前
```

改为：

```text
撤销
重做
```

对应关系：

- `undo-last-action` 显示为 `撤销`
- `redo-last-action` 显示为 `重做`

### 样式

`撤销 / 重做` 样式要和右侧翻页按钮区分。

要求：

- 仍然放在 `总数` 左边。
- 与 `首页 / 上一页 / 下一页 / 尾页` 不使用完全相同视觉样式。
- 置灰状态要清楚。
- 不改变撤销 / 重做的功能范围。

建议新增样式类：

```html
<button type="button" class="undo-redo-button" data-action="undo-last-action">撤销</button>
<button type="button" class="undo-redo-button" data-action="redo-last-action">重做</button>
```

### 作用范围

撤销 / 重做继续沿用 V0.30 的当前页面会话范围：

- 不持久化。
- 不跨浏览器刷新。
- 不撤销生成任务。
- 不撤销数据恢复。
- 不撤销设置页保存。
- 不扩大到 V0.30 文档以外的新业务范围。

节点右键菜单触发的重命名和删除继续纳入 V0.30 既有撤销栈。

## 副作用与控制

### 图片稳定性增强的副作用

可能副作用：

- 当前页图片加载检查会增加少量前端计算。
- 疑似空白图片的有限重试会增加少量本地图片读取请求。
- 对可见图片临时设置更积极加载，可能让当前页图片更早读取。

控制方式：

- 只检查当前保存区。
- 只检查当前页图片。
- 只对疑似空白图片重试。
- 限制重试次数。
- 页面外图片继续懒加载。

### 自定义节点下拉的副作用

可能副作用：

- 原生 `select` 的默认键盘行为会变化。
- 需要额外处理外部点击关闭和 `Escape` 关闭。
- 需要额外保证菜单层级不被保存区卡片遮挡。

控制方式：

- 节点框按钮支持键盘 `Enter` / `Space` 打开。
- 菜单支持 `Escape` 关闭。
- 菜单使用明确的 `z-index`。
- 点击弹窗、图片查看器、标签选择器内部不触发误关闭和误保存。

### 节点右键菜单的副作用

可能副作用：

- 用户可能右键到非当前选中的真实节点并执行删除。

控制方式：

- 删除确认文案必须包含节点名称。
- 右键菜单只对真实节点出现。
- `全部`、`其他`、`新建` 不显示右键菜单。
- 删除继续不删除实例、不删除图片文件。
- 删除继续纳入撤销栈。

### 撤销 / 重做文案的副作用

可能副作用：

- 用户需要适应新文案。

控制方式：

- action 不变。
- 位置不变。
- 作用范围不变。
- 样式与翻页按钮区分，减少误点。
