## 修改目标

V0.28 重点修复 V0.27 实际使用中的保存区过程问题，并做稳定性收口。

主要目标：

- 生成中实例保持唯一性。
- 保存区实例的 TAG 可以随时添加和删除，不需要进入编辑模式。
- 点击保存区实例之外区域时，批量保存所有正在编辑的实例。
- 翻页后当前页图片稳定显示，保留懒加载。
- 普通实例按钮改为 `复制提交`。
- 生成失败实例按钮显示为 `重新提交`。
- `复制提交` 新增一个实例。
- `重新提交` 在失败实例原位置再次生成，不新增实例。
- 使用临时数据库做大量实例和回归验证，不污染真实共享数据库。

## 生成状态数据结构

为了解决“前端生成中临时实例”和“后端提前创建的数据库实例”同时显示的问题，实例表增加生成状态字段。

`backend/database.py` 的 schema 迁移中为 `instances` 增加字段：

```sql
ALTER TABLE instances ADD COLUMN generation_status TEXT NOT NULL DEFAULT 'ready';
ALTER TABLE instances ADD COLUMN generation_task_id TEXT NOT NULL DEFAULT '';
ALTER TABLE instances ADD COLUMN generation_output_index INTEGER NOT NULL DEFAULT 1;
ALTER TABLE instances ADD COLUMN generation_error TEXT NOT NULL DEFAULT '';
ALTER TABLE instances ADD COLUMN generation_started_at TEXT NOT NULL DEFAULT '';
ALTER TABLE instances ADD COLUMN generation_finished_at TEXT NOT NULL DEFAULT '';
```

字段含义：

```text
generation_status        ready / running / failed
generation_task_id       同一次点击生成的任务标识
generation_output_index  同一任务下第几张输出，从 1 开始
generation_error         失败原因
generation_started_at    后端创建生成中实例的时间
generation_finished_at   后端成功或失败结束的时间
```

状态含义：

```text
ready    正常实例
running  生成中实例
failed   生成失败实例
```

旧数据迁移规则：

- 旧实例没有这些字段时，全部默认视为 `ready`。
- 旧实例不写入 `generation_task_id`。
- 旧实例不写入失败信息。
- 迁移失败时不能破坏原数据库，继续沿用 V0.23 的迁移前备份和失败保护规则。

序列化规则：

- `get_instance`
- `list_instances`
- `api_create_instance`
- `api_create_instances_bulk`
- `api_generate`

以上返回实例数据时都带上新增字段。

## 生成中实例唯一性

点击生成后，每个预期输出只显示一条对应的生成中实例。

预期输出数量：

```text
文生图：按 n 创建，一张输出对应一个实例
图生图：固定 1
复制提交：按当前操作区 / 全局默认参数，文生图和图生图数量都按 1
失败实例重新提交：按失败实例原来的输入重新跑，数量按 1
```

后端生成流程：

1. `api_generate` 接收请求后生成一个 `generation_task_id`。
2. 根据模式和数量预创建数据库实例。
3. 预创建实例写入：

```text
generation_status = running
generation_task_id = 本次任务 id
generation_output_index = 1..n
output_image_path = 空
generation_error = 空
```

4. 调用 Provider 或自定义脚本执行生图。
5. 每拿到一张输出图，就更新对应预创建实例：

```text
generation_status = ready
output_image_path = 实际输出图片路径
generation_finished_at = 当前时间
generation_error = 空
```

6. 如果 Provider 返回图片数量少于预期数量，剩余预创建实例改为：

```text
generation_status = failed
generation_error = Provider 返回图片数量少于预期
generation_finished_at = 当前时间
```

7. 如果整次生成失败，所有本次预创建实例改为：

```text
generation_status = failed
generation_error = 实际异常信息
generation_finished_at = 当前时间
```

8. 生成失败实例保留在保存区，不自动删除。

前端显示流程：

1. 点击生成后，前端仍然立即显示生成中实例。
2. 前端生成中实例必须带上 `generation_task_id` 和 `generation_output_index`。
3. `loadInstances()` 返回数据库中的 `running` 实例时，前端用以下键合并：

```text
generation_task_id + generation_output_index
```

4. 如果同一个键同时存在前端临时实例和数据库 `running` 实例，只显示一条。
5. 优先使用数据库实例的真实 `id`，保留前端计时起点。
6. 生成完成后，用数据库返回的 `ready` 或 `failed` 实例替换原来的生成中显示。
7. 最终保存区只保留一条正常实例或一条失败实例。

生成中实例显示规则：

- 编号位置显示读秒，精确到 `0.1 s`。
- 输出图区显示生成中状态和读秒。
- 不显示 `无输出图`。
- 不参与批量选择。
- 不显示批量选择复选框。
- 不允许进入编辑模式。
- 不允许删除输入图或输出图。
- 可以保留删除按钮；删除时只删除软件中的该条记录，不删除图片文件。

读秒规则：

- 读秒只作为前端显示。
- 不写入数据库。
- 页面刷新后，已有 `running` 实例可以从 `generation_started_at` 粗略恢复读秒。
- 生成成功、生成失败、取消显示、页面卸载后清理对应定时器。
- 全局只保留一个生成中读秒定时器，避免多个定时器残留。

## 失败实例重新提交

所有普通实例上的按钮文字从：

```text
重新提交
```

改为：

```text
复制提交
```

`复制提交` 行为：

- 从当前实例复制提示词和输入图。
- 使用当前操作区 / 全局默认 Provider。
- 使用当前操作区 / 全局默认尺寸、清晰度、宽高比、生成路径。
- 如果当前实例有输入图，按图生图提交。
- 如果当前实例没有输入图，按文生图提交。
- 文生图和图生图数量都按 `1`。
- 新增一个生成中实例。
- 生成成功后新增一个正常实例。
- 不修改原实例。

生成失败实例上的按钮显示为：

```text
重新提交
```

`重新提交` 行为：

- 只针对 `generation_status = failed` 的实例显示。
- 使用失败实例自己的提示词和输入图。
- 使用当前操作区 / 全局默认 Provider。
- 使用当前操作区 / 全局默认尺寸、清晰度、宽高比、生成路径。
- 文生图和图生图数量都按 `1`。
- 在当前失败实例原位置重新跑。
- 不新增实例。
- 重新提交时将该实例更新为：

```text
generation_status = running
generation_error = 空
output_image_path = 空
generation_started_at = 当前时间
generation_finished_at = 空
```

- 成功后将当前实例更新为 `ready`，并补上输出图路径。
- 失败后仍保留当前实例，状态为 `failed`，更新失败原因。

前端动作命名：

- 保留现有 `resubmitInstance` 时，应改清楚内部含义，避免普通实例和失败实例混用。
- 建议拆成：

```javascript
copySubmitInstance(instanceId)
retryFailedInstance(instanceId)
```

事件 action 建议：

```text
copy-submit-instance
retry-failed-instance
```

## 保存区 TAG 随时操作

保存区实例的 TAG 不再依赖编辑模式。

行为：

- 非编辑状态下可以添加 TAG。
- 非编辑状态下可以删除 TAG。
- 编辑状态下也可以添加和删除 TAG。
- 添加 TAG 时仍然可以选择已有 TAG。
- 添加 TAG 时仍然可以新建 TAG。
- 删除 TAG 只删除当前实例和该 TAG 的关联。
- 删除 TAG 不删除真实 TAG 字典中其他实例仍在使用的标签。
- 删除 TAG 不删除电脑上的图片文件。
- 提示词和图片仍然必须进入编辑模式后才能修改。

TAG 操作保存规则：

- TAG 添加和删除是独立即时保存。
- TAG 操作不进入实例草稿。
- TAG 操作不受 `取消编辑` 影响。
- 点击 `取消编辑` 只取消提示词、输入图、输出图等编辑草稿，不回滚已经即时保存的 TAG。

后端新增单实例 TAG 接口：

```text
POST   /api/instances/<id>/tags/add
POST   /api/instances/<id>/tags/remove
```

请求体：

```json
{
  "tags": ["tag1", "tag2"]
}
```

返回：

```json
{
  "item": { "id": 1, "tags": ["tag1"] },
  "tags": ["tag1", "tag2"]
}
```

实现规则：

- 后端复用现有 TAG 规范化逻辑。
- `__untagged__` 是虚拟筛选值，不能作为真实 TAG 写入。
- 单实例 TAG 接口不能修改提示词、图片路径、Provider、生成参数。
- 批量添加 TAG、批量删除 TAG 继续使用 V0.27 的批量接口，不能改坏。

前端调整：

- `render-instance.js` 中 TAG 区域始终渲染添加入口和删除入口。
- 删除 TAG 按钮不再受 `editable` 限制。
- 添加 TAG 下拉不再受 `editable` 限制。
- TAG 操作成功后刷新当前实例、全局 TAG 列表、标签筛选选项。
- 如果当前筛选条件因为 TAG 变化导致当前实例不再匹配，刷新当前页并执行避免空白页逻辑。

## 点击实例外区域批量保存

点击保存区实例之外区域时，保存所有正在编辑的实例。

触发区域：

- 保存区实例上方空白区域。
- 保存区实例下方空白区域。
- 保存区左右空白区域。
- 页面其他非实例区域。
- 顶部工具栏中不会打开弹窗或下拉菜单的普通区域。

不触发区域：

- 当前点击的实例内部。
- 弹窗内部。
- 图片查看器内部。
- 悬停大图预览内部。
- 下拉菜单内部。
- TAG 选择器内部。
- 文件选择相关按钮。
- 确认框触发按钮。
- 页面导航按钮。
- 表单输入框、文本域、按钮、链接、select。

实现规则：

1. 在 `events.js` 使用捕获阶段监听页面点击。
2. 调用 `shouldSkipBatchSave(event.target)` 判断是否跳过。
3. 如果目标不在任何 `[data-instance-card]` 内，并且不属于跳过区域，调用 `batchSaveEditingInstances()`。
4. 如果目标在另一个实例内，先保存除当前目标实例以外的其他正在编辑实例。
5. 保存失败时：

```text
失败实例继续保留编辑状态
顶部显示错误
不阻止用户点击当前目标
```

6. 保存成功的实例退出编辑状态。
7. 保存失败的实例不被强行取消编辑。

## 翻页图片稳定显示

保存区翻页、筛选、排序、每页数量变化后，当前页应该显示的图片必须稳定显示。

保留 V0.27 图片懒加载：

```html
<img loading="lazy" decoding="async">
```

新增当前页图片稳定检查：

1. 保存区渲染完成后执行一次 `requestAnimationFrame`。
2. 在下一帧检查当前保存区内所有图片节点。
3. 对当前页内可见或接近可见区域的图片执行加载唤醒。
4. 如果图片节点缺少 `src`，从 `data-image-path` 或当前实例路径重新生成 `/api/image?path=...`。
5. 如果图片节点有 `src`，但 `complete = false` 且长时间没有触发加载，重新设置一次相同路径的 `src`。
6. 重新设置 `src` 时保留路径编码规则，不追加会导致缓存混乱的随机参数。
7. 只检查当前保存区 DOM，不扫描全站所有图片。

建议新增函数：

```javascript
stabilizeSaveAreaImages()
wakeVisibleSaveImages()
imageUrlForPath(path)
```

调用位置：

- `loadInstances()` 成功后。
- `renderSaveArea()` 完成后。
- 上一页、下一页、首页、尾页后。
- 搜索、标签筛选、来源筛选、方式筛选、排序变化后。
- 每页数量变化后。
- 单列 / 双列切换后。

要求：

- 不取消懒加载。
- 不生成缩略图。
- 不复制原图。
- 不破坏图片点击大图。
- 不破坏图片左右切换。
- 不破坏图片原图查看。
- 不产生横向滚动条。

## 保存区筛选和批量选择回归

V0.28 保留 V0.27 的保存区筛选和批量管理规则。

需要确认：

- 分页继续走后端查询。
- 搜索继续走后端查询。
- 标签筛选继续走后端查询。
- `无` 标签筛选仍然只是虚拟筛选项。
- `__untagged__` 不能写入真实 TAG。
- 来源筛选继续走后端查询。
- 方式筛选继续走后端查询。
- 排序继续走后端查询。
- 批量选择只选择当前页。
- 生成中实例不能被批量选择。
- 筛选变化后清空批量选择。
- 排序变化后清空批量选择。
- 翻页后清空批量选择。
- 每页数量变化后清空批量选择。
- 单列 / 双列切换不需要清空批量选择，除非当前页重新加载。

方式筛选逻辑保持：

```text
文生图：没有输入图
图生图：有输入图
有输出：有输出图路径，且 generation_status != running
无输出：没有输出图路径，且 generation_status != running
```

`running` 实例不显示为 `无输出图`，也不应该因为输出图为空而在界面上呈现为普通无输出实例。

- 点击取消编辑不会回滚已经添加或删除的 TAG。
- 点击保存区实例下方空白区域会保存所有正在编辑实例。
- 点击下拉菜单和图片弹窗内部不会误触发批量保存。
- 上一页 / 下一页 / 首页 / 尾页多次切换后，当前页图片稳定显示。
- 浏览器 tab 不需要切走再切回来，图片也应正常显示。
- 批量选择、全选当前页、批量添加 TAG、批量删除 TAG、批量删除实例可用。
- 翻页、筛选、排序、每页数量变化后批量选择清空。

## 可能副作用和处理方式

### 数据库字段增加

新增生成状态字段会触发 schema 迁移。

处理方式：

- 迁移前依赖 V0.23 的备份保护。
- 新字段全部有默认值。
- 旧实例全部显示为正常实例。
- 导出和恢复包含新字段。

### TAG 即时保存不受取消编辑影响

TAG 添加和删除从编辑草稿中独立出来后，`取消编辑` 不会撤销 TAG 操作。

处理方式：

- 这是 V0.28 明确规则。
- 编辑保存和 TAG 操作无关。
- TAG 操作失败时显示错误，不改变本地显示。

### 生成失败实例会留在保存区

生成失败后保存区会保留一条失败实例。

处理方式：

- 失败实例显示错误状态。
- 失败实例提供 `重新提交`。
- 用户可以手动删除失败实例。
- 删除仍然只删除软件记录，不删除电脑上的图片文件。

### running 实例刷新后的读秒不完全精确

页面刷新后，前端原始 `performance.now()` 起点丢失。

处理方式：

- 刷新前的读秒按前端精确计时。
- 刷新后可用 `generation_started_at` 恢复近似读秒。
- 读秒不写入数据库，不作为历史耗时。

### 图片稳定检查会增加少量前端工作

翻页后主动检查当前页图片会增加少量 DOM 检查。

处理方式：

- 只检查当前保存区图片。
- 只在渲染完成后的下一帧执行。
- 不扫描页面外数据。
- 保留懒加载，避免全量加载。

### 批量保存点击范围扩大

点击页面其他空白区域也会触发保存正在编辑的实例。

处理方式：

- 明确排除弹窗、下拉、TAG 选择器、图片查看器、输入框和按钮。
- 保存失败时保留失败实例编辑状态。
- 不阻止用户点击当前目标。
