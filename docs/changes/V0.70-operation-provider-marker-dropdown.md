# V0.70 操作区 Provider 个人标记下拉

## 目标

当前 V0.69 已完成筛选空列、编辑态 ESC、历史记录键盘翻页、稳定 H 编号、TAG 密度和节点样式收口。本版 V0.70 目标是在生图管理页操作区 Provider 下拉菜单中增加一个仅供个人记录使用的 `√ / X` 标记按钮。

本版需求：

- 生图管理页操作区 Provider 下拉菜单中，每一行 Provider 最右边增加一个状态按钮。
- 状态按钮有两种状态：`√` 和 `X`。
- 点击 Provider 行主体才选中 Provider。
- 点击右侧 `√ / X` 状态按钮只切换该 Provider 的记录状态，不选中 Provider。
- 当前操作区已选中的 Provider，在下拉收起状态中也显示该 Provider 的 `√ / X` 状态。
- `√` 和 `X` 样式明显区分。
- 该状态只在操作区 Provider 体现。
- 其他页面、其他 Provider 下拉、保存区实例、历史记录、筛选、设置页都不体现该状态。

本版原则：

- 不改变 Provider 配置结构。
- 不改变实际生图使用的 Provider 逻辑。
- 不影响 Provider 能力体系。
- 不写入后端数据库。
- 不写入设置页 Provider 配置。
- 不纳入数据导出、备份、恢复。
- 不影响保存区实例 Provider、历史 Provider、Provider 筛选、Provider 排序。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 当前状态判断

当前操作区 Provider 控件使用原生 `select`。

原生 `select` 的限制：

- 无法在每一行右侧放独立按钮。
- 无法做到点击行内按钮时不选中该行。
- 无法对每一行的右侧按钮做 `√ / X` 独立交互。

因此，本版如果要完整实现需求，需要将“仅操作区 Provider 控件”从原生 `select` 改成自定义下拉控件。

其他 Provider 下拉不改：

- 设置页 Provider 下拉保持原生或现有实现。
- 保存区实例 Provider 下拉保持现有实现。
- 生图管理页 Provider 筛选保持现有实现。
- 历史记录页 Provider 筛选保持现有实现。

## Provider 标记规则

### 1. 标记状态

调整方案：

- 每个 Provider 有一个个人标记状态。
- 状态值为：
  - `checked`：显示 `√`。
  - `rejected`：显示 `X`。
- 默认状态为 `X`。
- 点击状态按钮在 `√` 和 `X` 之间切换。

显示规则：

- Provider 下拉菜单每行右侧显示该 Provider 的 `√ / X` 状态按钮。
- 当前选中的 Provider 在下拉收起状态中也显示 `√ / X`。
- `√` 建议使用绿色文字或浅绿色底。
- `X` 建议使用红色文字或浅红色底。
- 两种状态要能一眼区分。

验收标准：

- 每个 Provider 行右侧都有 `√ / X` 按钮。
- 默认未标记的 Provider 显示 `X`。
- 点击 `X` 后变为 `√`。
- 再点击 `√` 后变回 `X`。
- 当前已选 Provider 在收起状态中显示当前 `√ / X`。
- `√` 和 `X` 视觉区分明显。

副作用：

- 操作区 Provider 控件宽度内会多一个状态标识。
- 长 Provider 名称需要保留省略显示，不能挤压按钮。

## 交互规则

### 2. 点击行主体选中 Provider

调整方案：

- 点击 Provider 行主体区域，选中该 Provider。
- 选中 Provider 后沿用当前 `changeOperationProvider` 逻辑：
  - 更新当前 active Provider。
  - 保存当前 active Provider 到设置。
  - 按现有 Provider 能力体系刷新操作区。
  - openai-google 的尺寸 / 分辨率规则不回退。
- 选中后关闭下拉菜单。

验收标准：

- 点击 Provider 行主体可以正常切换 Provider。
- 切换后操作区当前 Provider 显示更新。
- 切换后该 Provider 的 `√ / X` 状态一起显示。
- 生成使用的 Provider 是刚刚选中的 Provider。
- 切换 Provider 的现有规则不回退。

副作用：

- 自定义下拉需要重新实现原生 `select` 的基本行为。
- 需要避免点击行主体时误触状态按钮。

### 3. 点击状态按钮不选中 Provider

调整方案：

- 点击 Provider 行右侧 `√ / X` 状态按钮时：
  - 阻止事件冒泡到行主体。
  - 只切换该 Provider 的标记状态。
  - 不调用 `changeOperationProvider`。
  - 不改变当前 active Provider。
  - 不关闭下拉菜单，方便连续标记多个 Provider。

验收标准：

- 当前 Provider 是 A，打开下拉点击 B 行右侧 `X / √` 按钮，当前 Provider 仍是 A。
- 点击状态按钮不会触发 Provider 切换。
- 点击状态按钮不会触发生成参数变化。
- 点击状态按钮不会关闭下拉菜单。
- 可以连续切换多个 Provider 的 `√ / X` 状态。

副作用：

- 需要确保按钮点击区域足够明确。
- 需要避免状态按钮点击被全局点击外部关闭逻辑提前处理。

## 保存规则

### 4. 只保存为前端 UI 状态

当前需求说明：

- 这个按钮和其他地方都没有关联。
- 只是用户自己记录用。
- 在其他地方的 Provider 都不体现。

调整方案：

- `√ / X` 状态只保存到前端 UI 状态中。
- 建议使用现有 UI 状态持久化机制，即 `localStorage`。
- 保存结构按 Provider 内部编号记录，例如：
  - `providerMarkers: { "provider_a": "checked", "provider_b": "rejected" }`
- 不写入后端配置文件。
- 不写入 Provider 配置。
- 不写入数据库。
- 不纳入备份、导出、恢复。
- 不触发设置页“保存设置”按钮变脏。

Provider 变动规则：

- Provider 显示名称修改：状态跟随内部编号保留。
- Provider 删除：对应状态自然失效。
- Provider 复制 / 新建：默认显示 `X`，不继承原 Provider 标记，除非后续明确要求。
- Provider 内部编号变化：按新编号视为新 Provider，默认 `X`。

验收标准：

- 刷新页面后，已设置的 `√ / X` 状态仍保留。
- 切换页面后再回到生图管理页，状态仍保留。
- 设置页保存 Provider 配置时，不会改变 `√ / X` 状态。
- 数据安全导出内容不包含 Provider 标记状态。
- 备份恢复不影响该本地标记状态。
- 删除 Provider 后，下拉菜单不再显示该 Provider，也不会报错。

副作用：

- 使用 `localStorage` 表示该标记是当前浏览器本地状态。
- 换浏览器、清理浏览器数据、换电脑后该标记不会自动同步。
- 这是符合“个人记录用、不进入核心数据”的取舍。

## 自定义下拉行为

### 5. 下拉打开、关闭和键盘行为

调整方案：

- 操作区 Provider 控件改为自定义下拉。
- 点击主控件打开 / 关闭下拉。
- 点击控件外部关闭下拉。
- 按 `Esc` 关闭下拉。
- 生成中实例存在时，下拉菜单不能因为自动刷新而立即消失。
- 菜单打开时，状态按钮点击不能被外部关闭逻辑误判为点击外部。
- 菜单层级不被操作区、保存区、浮窗遮挡。

键盘规则建议：

- 当前版本先保证鼠标交互完整。
- 如实现键盘支持：
  - `Enter` 或空格打开下拉。
  - `Esc` 关闭下拉。
  - 上下方向键可在 Provider 行之间移动焦点。
  - `Enter` 选中当前焦点 Provider。
- 该键盘支持不能影响保存区左右方向键翻页、历史记录左右方向键翻页。

验收标准：

- 点击主控件可以打开下拉。
- 点击外部可以关闭下拉。
- 按 `Esc` 可以关闭下拉。
- 点击状态按钮时下拉不关闭。
- 点击行主体选中 Provider 后下拉关闭。
- 生成中实例刷新时，下拉不会自动闪退。
- 下拉不会被保存区内容遮挡。

副作用：

- 自定义下拉比原生 `select` 交互复杂。
- 需要重点测试点击外部关闭、`Esc`、生成中刷新、页面重渲染。

## UI 布局

### 6. 操作区 Provider 显示收口

调整方案：

- 操作区 Provider 标题仍显示为 `Provider`。
- Provider 主控件内部建议显示：
  - Provider 显示名。
  - 必要时显示 adapter 或内部编号的既有格式。
  - 右侧显示当前 Provider 的 `√ / X` 状态。
  - 右侧保留下拉箭头。
- Provider 名称超长时省略显示。
- `√ / X` 状态按钮固定宽度，不被长 Provider 名称挤压。
- 下拉菜单中每行建议布局：
  - 左侧：Provider 显示名称。
  - 次要信息：内部编号或 adapter，沿用当前 Provider 显示规则。
  - 右侧：`√ / X` 状态按钮。
- 当前选中的 Provider 行需要有选中样式，和右侧 `√ / X` 状态样式互不混淆。

验收标准：

- 操作区布局高度不增加。
- Provider 控件不挤压标签框、路径框、选择按钮。
- 当前 Provider 的 `√ / X` 状态在收起状态可见。
- 下拉菜单中每行右侧状态按钮对齐。
- 长 Provider 名称不覆盖状态按钮。
- `√ / X` 状态样式和当前选中行样式能区分。

副作用：

- 自定义 Provider 控件可能比原生 `select` 占用更多样式代码。
- 需要检查窄窗口下是否溢出。

## 回归检查

完成实现后需要检查：

- 生图管理页可以正常打开。
- 操作区 Provider 下拉可以打开和关闭。
- 操作区 Provider 下拉每行右侧显示 `√ / X`。
- 点击 `√ / X` 只切换状态，不切换 Provider。
- 点击 Provider 行主体正常切换 Provider。
- 选中 Provider 后，收起状态显示该 Provider 的 `√ / X`。
- `√ / X` 状态刷新页面后保留。
- `√ / X` 状态切换不触发设置页“保存设置”脏状态。
- `√ / X` 状态不出现在保存区实例 Provider 下拉。
- `√ / X` 状态不出现在设置页 Provider 下拉。
- `√ / X` 状态不出现在 Provider 筛选。
- `√ / X` 状态不出现在历史记录页。
- 生图时仍使用当前选中的 Provider。
- openai、openai-google、google、other 等 Provider 能力判断不回退。
- 生成中实例刷新时 Provider 下拉不闪退。
- 点击外部关闭下拉正常。
- `Esc` 关闭下拉正常。
- 保存区普通列表模式不受影响。
- 保存区缩略图模式不受影响。
- 历史记录页键盘翻页不受影响。
- 数据安全导出、备份、恢复不受影响。

## 不做内容

- 不把 `√ / X` 状态写入 Provider 配置。
- 不把 `√ / X` 状态写入数据库。
- 不把 `√ / X` 状态纳入导出、备份、恢复。
- 不在保存区实例中显示该状态。
- 不在历史记录中显示该状态。
- 不在设置页中显示该状态。
- 不在 Provider 筛选或排序中使用该状态。
- 不改变生成请求参数。
- 不改变 Provider 能力体系。
- 不新增数据库 schema。
