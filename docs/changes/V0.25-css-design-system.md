## 修改范围

本版本主要做 CSS 与设计系统整理：

- 将 `frontend/styles.css` 按区域拆分为多个 CSS 文件。
- 保留 `frontend/styles.css` 作为 CSS 唯一入口。
- 使用 `@import` 在 `frontend/styles.css` 中按顺序引入拆分后的 CSS 文件。
- 建立统一设计变量，集中管理常用尺寸、颜色、间距、字号和状态样式。
- 保持当前整体视觉风格、布局密度、单列/双列显示效果不变。
- 保持 V0.24 的 `frontend/js/` 模块结构不变。

本版本允许的行为和位置调整：

- 修正生成中临时占位实例在翻页时的显示规则。
- `删除` 按钮回到右侧动作列，放在 `编辑` 的正下方。
- `重新提交` 按钮继续放在标签区域下方，但整体向右对齐，视觉上靠近右侧动作区。
- 数据安全页备份、导出、恢复按钮使用全局控件变量统一样式。

本版本不做以下内容：

- 不重新设计界面。
- 不改变当前整体视觉风格。
- 不引入 React、Vue、Tailwind、Bootstrap、打包器或 CSS 预处理器。
- 不改变前端 JS 模块结构。
- 不重构 Provider。
- 不改数据库 schema。
- 不改备份、导出、恢复格式。
- 不改变图片文件保存、读取、删除规则。
- 不新增除上述占位显示修正和按钮位置调整以外的业务功能。

## 横向滚动条保护

所有现有页面都不能出现横向滚动条。

全局基础规则：

```css
html,
body {
  max-width: 100%;
  overflow-x: hidden;
}

* {
  box-sizing: border-box;
}
```

各页面宽度规则：

- 顶栏不允许超过视口宽度。
- 操作区横向布局在窄屏下继续进入响应式紧凑布局。
- 保存区双列在较窄窗口下不能把实例撑出页面。
- 设置页、历史记录页、数据安全页的工具栏允许换行，不允许横向撑出。
- 图片位区域如果内容超出，优先按现有规则换行，不挤压固定按钮区域。

不要使用固定大宽度覆盖响应式规则。

## 生成中临时占位实例翻页规则

V0.25 保留 V0.24 的前端临时占位实例方案。

生成中临时占位实例只保存在：

```javascript
state.pendingInstances
```

它不是数据库真实实例。

显示规则改为：

- 每个生成请求只创建一组 pending，占位数量按当前请求决定。
- 文生图 `n > 1` 时显示 n 条 `生成中` 占位。
- 图生图固定显示 1 条 `生成中` 占位。
- 保存区无论当前在第几页，都把 `state.pendingInstances` 显示在列表最上面。
- pending 不参与真实实例分页切片。
- pending 不参与真实实例编号。
- pending 不计入保存区总数。
- pending 不受翻页影响，不因为 `上一页` / `下一页` 变成普通 `#001` 空输出实例。
- 生成成功后，只移除对应 `task_id` 的 pending。
- 生成成功后刷新真实实例列表，真实实例按当前排序规则显示；通常最新生成实例出现在第一页。
- 生成失败后，只移除对应 `task_id` 的 pending，并显示错误状态。

实现时不要在翻页过程中重新创建 pending。

保存区渲染时使用：

```javascript
const visibleInstances = [
  ...state.pendingInstances,
  ...state.instances,
];
```

但分页总数、页码、空白页保护只基于后端返回的真实实例分页信息。

如果当前页没有真实实例但仍有 pending，占位仍然显示。

如果当前页没有真实实例且没有 pending，按现有空白页保护逻辑跳转到有效页。

## 点击生成立即新增真实实例的关系

V0.23 后端已经实现点击生成后立即创建真实保存区实例。

V0.25 不改变该后端逻辑。

前端 pending 的职责只是提示当前请求正在生成：

```text
前端 pending：显示“生成中”的过程状态
后端真实实例：保存提示词、输入图、标签等数据
```

在生成完成前翻页时：

- 不要把后端尚未输出图片的真实实例伪装成新的 `#001` 过程实例。
- 不要让 pending 和真实空输出实例重复表达同一个任务。
- 保持 pending 在当前页面顶部显示，直到对应任务完成。

如果后端返回的当前页真实实例中包含同一任务的空输出实例，前端可以继续显示 pending；真实空输出实例按当前分页数据显示。生成完成刷新后以真实实例为准。

## 保存区按钮位置

保存区实例按钮分为两个区域。

右侧动作列：

```text
非编辑状态：编辑
编辑状态：保存 / 取消
删除
```

`删除` 要放在 `编辑` 的正下方。

标签区域下方动作行：

```text
重新提交
```

`重新提交` 继续放在标签区域下方，但整体向右移动。

布局要求：

- `重新提交` 视觉上靠近右侧动作区。
- `重新提交` 不挤压标签输入框。
- `重新提交` 不和图片区域重叠。
- `重新提交` 不造成横向滚动条。
- `删除` 不放在标签区域下方。
- 双列模式下保持实例宽度不变。
- 单列模式下保持现有单列布局不变。

建议实现：

```css
.instance-inline-actions {
  display: flex;
  justify-content: flex-end;
  padding-right: var(--space-8);
}
```

只在 `.instance-inline-actions` 中放 `重新提交`。

右侧 `.instance-actions` 中放：

```text
编辑 / 保存 / 取消 / 删除
```

临时占位实例不显示：

```text
编辑
保存
取消
重新提交
删除
```

## 副作用与处理

CSS 拆分最大的风险是样式顺序变化。通过 `styles.css` 统一 `@import` 顺序，并把 `13-responsive.css` 放在最后，降低覆盖顺序变化带来的风险。

`@import` 会让浏览器发起多个本地 CSS 请求。本软件是本地网页软件，不引入构建工具，因此这个成本可以接受。

变量统一可能误改视觉细节。处理方式是先保留原值，把重复值映射到变量，不做视觉重设计。

把全部 `@media` 放到 `13-responsive.css` 后，响应式覆盖更集中，但需要确保它最后加载，否则单列/双列和窄屏布局可能被普通规则覆盖。

数据安全页按钮统一会轻微改变按钮的内部 CSS 来源，但视觉尺寸、颜色和交互应保持与全局控件一致。

pending 始终显示在当前保存区顶部后，生成中期间页面可见条数可能临时超过每页数量。这是有意设计，因为 pending 不是数据库真实分页数据。

pending 不参与真实编号后，生成中占位不再显示类似 `#001` 的编号，避免用户误以为它是普通实例。

如果生成完成前用户翻页，pending 继续显示在当前页顶部；真实实例仍按后端分页结果显示。生成完成后刷新数据，真实实例按正常排序和筛选规则出现。

`删除` 回到右侧动作列后，和 V0.24 的 `重新提交 | 删除` 同行布局不同。`重新提交` 保留在标签区域下方并右对齐，避免挤压右侧编辑 / 保存 / 取消按钮。

双列模式下按钮右移可能压缩标签区域。实现时必须用 flex 右对齐或 grid 定位，不能使用会导致横向溢出的固定大 margin。

V0.25 不改变数据库 schema，因此旧数据可继续直接使用。
