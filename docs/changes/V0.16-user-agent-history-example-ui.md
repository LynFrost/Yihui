## user_agent 配置

在设置页 `连接信息` 区域新增字段：

```text
user_agent
```

配置规则：

- `user_agent` 默认值为空字符串。
- `user_agent` 可以手动填写并保存到共享配置文件。
- 旧 Provider 没有 `user_agent` 时，归一化补齐为空字符串。
- `user_agent` 放在 `base_url`、`api_key`、`api_key_env` 同一组连接信息中。
- `user_agent` 和 OpenAI API 的 `user` 参数不是同一个含义。
- `user` 继续保留为 OpenAI API 的终端用户标识。

后端调用规则：

- 如果 `user_agent` 为空，OpenAI client 不额外传入 `default_headers`。
- 如果 `user_agent` 非空，OpenAI client 使用：

```python
default_headers={"User-Agent": user_agent}
```

- 如果生成接口返回 `image_url`，软件下载图片时也使用同一个 `user_agent`：

```python
Request(image_url, headers={"User-Agent": user_agent})
```

- 如果 `user_agent` 为空，下载图片时不额外设置 `User-Agent`。
- 自定义脚本执行上下文中新增变量 `user_agent`。
- 自定义脚本是否使用 `user_agent` 由脚本本身决定，软件只负责注入变量。

## 固定调用示例

固定调用示例必须同步 `user_agent` 参数。

文生图固定示例：

```python
from openai import OpenAI
from urllib.request import Request, urlopen
import shutil

USER_AGENT = user_agent or "Mozilla/5.0 PowerShell/7.4"

client = OpenAI(
    base_url="https://img.aiapis.help/v1",
    api_key="${YOUR_API_KEY}",
    default_headers={"User-Agent": USER_AGENT},
)

prompt = operation_prompt
output_path = "output.png"  # 这里换成你的路径参数

resp = client.images.generate(
    model="gpt-image-2",
    prompt=prompt,
    size=resolved_size,
    quality="high",
    output_format="png",
    # output_compression only works for jpeg/webp
    # output_compression=80,
    background="auto",
    moderation="low",
    n=n,
    user="",
)

image_url = resp.data[0].url
request = Request(image_url, headers={"User-Agent": USER_AGENT})
with urlopen(request, timeout=60) as response:
    with open(output_path, "wb") as f:
        shutil.copyfileobj(response, f)
```

图生图固定示例：

```python
from openai import OpenAI
from urllib.request import Request, urlopen
import shutil

USER_AGENT = user_agent or "Mozilla/5.0 PowerShell/7.4"

client = OpenAI(
    base_url="https://img.aiapis.help/v1",
    api_key="${YOUR_API_KEY}",
    default_headers={"User-Agent": USER_AGENT},
)

prompt = """
把这张图改成电影感写实风格，保留主体构图，增强光影和细节。
"""

output_path = "edited.png"  # 这里换成你的路径参数

with open("input.png", "rb") as image_file:
    resp = client.images.edit(
        model="gpt-image-2",
        image=image_file,
        prompt=prompt,

        n=1,
        size="1024x1024",
        quality="high",
        output_format="png",

        # output_compression only works for jpeg/webp
        # output_compression=80,

        background="auto",
        input_fidelity="high",

        # mask=open("mask.png", "rb"),

        user="local-user-001",
    )

image_url = resp.data[0].url
request = Request(image_url, headers={"User-Agent": USER_AGENT})
with urlopen(request, timeout=60) as response:
    with open(output_path, "wb") as f:
        shutil.copyfileobj(response, f)
```

示例规则：

- 示例中的 `user_agent` 是软件注入或配置的变量名，不写死为 Provider 配置值。
- 示例中的 `"Mozilla/5.0 PowerShell/7.4"` 只作为常用 fallback，方便用户理解 AIAPIS 需要 UA 的场景。
- 软件内部真实调用逻辑以 Provider 保存的 `user_agent` 为准。
- 如果用户编辑保存过某个 Provider + 调用方式 + 生图方式 的固定示例，继续优先显示用户保存过的示例。

- 图生图 `n` 显示 `固定为 1`，禁用。
- 图生图 `image / input_images` 显示 `来自软件`，禁用。

状态结构：

```javascript
state.generationStatus = {
  inProgress: false,
  message: "",
  startedAt: "",
  error: "",
}
```

实现规则：

- 点击 `生成` 后，立即设置 `inProgress = true`。
- 生成中状态显示在操作区现有状态位置。
- 点击筛选、下拉框、切换页面、切换设置项时，生成中状态不消失。
- 生成请求成功或失败后，才设置 `inProgress = false`。

- 生成中时不禁用其他下拉框、筛选、页面切换。
- 如果生成失败，状态区域显示错误。
- 如果生成成功，状态区域显示成功，并保留最后一次成功信息直到下一次生成或用户清空操作区。

## 历史记录数据库

新增 `generation_history` 表。

表结构：

```sql
CREATE TABLE IF NOT EXISTS generation_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  status TEXT NOT NULL,
  prompt TEXT NOT NULL DEFAULT '',
  mode TEXT NOT NULL DEFAULT '',
  provider_key TEXT NOT NULL DEFAULT '',
  adapter TEXT NOT NULL DEFAULT '',
  openai_call_method TEXT NOT NULL DEFAULT '',
  generation_path TEXT NOT NULL DEFAULT '',
  resolved_size TEXT NOT NULL DEFAULT '',
  params_json TEXT NOT NULL DEFAULT '{}',
  input_image_paths_json TEXT NOT NULL DEFAULT '[]',
  output_image_paths_json TEXT NOT NULL DEFAULT '[]',
  error_message TEXT NOT NULL DEFAULT '',
  custom_script_used INTEGER NOT NULL DEFAULT 0,
  started_at TEXT NOT NULL,
  finished_at TEXT NOT NULL DEFAULT '',
  duration_ms INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX IF NOT EXISTS idx_generation_history_started_at ON generation_history(started_at);
CREATE INDEX IF NOT EXISTS idx_generation_history_status ON generation_history(status);
```

`status` 可选值：

```text
running
success
failed
```

`params_json` 至少保存：

```json
{
  "ratio": "16:9",
  "resolution_level": "4K",
  "resolved_size": "3840x2160",
  "n": 1,
  "quality": "high",
  "output_format": "png",
  "output_compression": 80,
  "background": "auto",
  "moderation": "low",
  "user": "",
  "user_agent": "",
  "model": "gpt-image-2",
  "custom_script_used": false
}
```

## 历史记录写入流程

只记录点击 `生成` 的历史。

后端 `/api/generate` 流程：

1. 成功解析 JSON 请求后，创建一条 `running` 历史记录。
2. 记录提示词、模式、Provider、Adapter、调用方式、生成路径、输入图片路径、参数快照、开始时间。
3. 如果后续校验失败，更新该记录为 `failed`。
4. 如果 Provider 调用失败，更新该记录为 `failed`。
5. 如果自定义脚本失败，更新该记录为 `failed`。
6. 如果生成成功并创建保存区实例，更新该记录为 `success`。
7. 成功时写入输出图片路径、结束时间、耗时。
8. 失败时写入错误信息、结束时间、耗时。

特殊规则：

- 请求体不是合法 JSON 时，可以不写历史记录，因为无法可靠读取生成请求。
- 提示词为空、输出目录为空、图生图输入图缺失等业务校验失败，需要写入 `failed` 历史记录。
- 历史记录失败不能影响生成主流程；如果历史记录写入异常，应记录服务端错误，但不能让已经成功的生成变成失败。
- 成功返回给前端时，可以附带 `history_id`。

## 后端 OpenAI 调用

`AIAPISGptImage2Provider` 中统一处理 `user_agent`。

实现规则：

- 新增 `user_agent` 属性，从 Provider config 读取并去除首尾空白。
- `_client()` 中，如果 `user_agent` 非空，传入：

```python
default_headers={"User-Agent": user_agent}
```

- `_client()` 中，如果 `user_agent` 为空，不传 `default_headers`。
- 下载 URL 时，`download_url` 支持可选 `user_agent`。
- `download_url` 在 `user_agent` 非空时使用 `Request`。
- 文生图和图生图保存 URL 结果时都必须走带 UA 的下载逻辑。
- base64 结果不需要下载，不受 `user_agent` 影响。

## 副作用处理

新增 `generation_history` 表会改变数据库结构，但只新增表和索引，不修改现有保存区实例表的语义。

历史记录会持续增长。V0.16 先不做删除和清空，避免误删排查记录；后续版本可以再增加历史清理功能。

`user_agent` 默认为空。AIAPIS 如果要求 UA，用户需要在 Provider 的连接信息中手动填写并保存。

`user_agent` 和 OpenAI API 的 `user` 参数容易混淆。设置页必须保留两个不同字段名：`user_agent` 用于 HTTP 请求头，`user` 用于 API 参数。

代码框自动增高会让设置页变长，但能保证代码默认可见，并避免代码框内部滚动。

生成中状态变成全局状态后，页面重绘时需要小心保留状态，避免下拉菜单和筛选操作把状态清空。

如果历史记录写入失败，不能影响已经成功的图片生成和保存区实例创建。
