# V0.51 保存区 Provider 筛选排序与历史记录显示收口

## 目标

V0.51 在 V0.50.2 稳定性修复之后，继续做小范围交互和显示收口。本版不新增大功能，不改变数据库 schema，重点优化生图管理页保存区工具栏、Provider 筛选与排序、失败实例重新生成位置、标签清除按钮位置，以及历史记录页的筛选、Provider 显示、model 显示和编号规则。

本版原则：

- 不删除电脑上的图片文件。
- 不改变生成、复制提交、重新提交、手动提交的核心流程。
- 不破坏 V0.50.2 的生成中下拉稳定、保存区翻页稳定、历史尝试合并展示。
- 保存区筛选不影响历史记录编号。
- 历史记录筛选不影响保存区编号。
- 两边编号只跟各自使用的排序规则有关。
- 历史记录里的旧 Provider 信息属于历史快照，当前 Provider 被删除后，历史页仍继续保留并显示当时的 Provider 信息。

## 修改项

### 1. 保存区工具栏布局调整

当前需求：

- 生图管理页中，将“路径替换”按钮从筛选行拿下来。
- “路径替换”放到“缩略图”按钮右边挨着。
- “缩略图”按钮和“新增”按钮的样式做一点区分。

调整方案：

- 保存区第一行筛选栏继续保留搜索、标签筛选、来源筛选、方式筛选、Provider 筛选、排序、每页数量、显示方式。
- “新增”“缩略图”“路径替换”放在批量工具栏这一行：
  - 新增
  - 缩略图
  - 路径替换
- “新增”保持更明显的操作按钮样式。
- “缩略图”使用视图切换样式，和“新增”区别开。
- “路径替换”使用普通工具按钮样式，不抢主操作视觉。

验收标准：

- “路径替换”在“缩略图”右边。
- 筛选栏宽度更宽，不再被“路径替换”占位置。
- “新增”和“缩略图”视觉上能区分用途。
- 不影响批量按钮、总数、翻页按钮位置。

### 2. 保存区新增 Provider 筛选

当前需求：

- 在“方式筛选”右边挨着，新增“Provider 筛选”。
- 所有 Provider 下拉选择菜单中，各 Provider 都按名称 A-Z 排序。

调整方案：

- 保存区筛选状态增加 `provider`，默认 `all`。
- Provider 筛选下拉选项：
  - 全部
  - 当前配置中存在的 Provider，按显示名称 A-Z 排序
  - 如果实例中存在历史 Provider key，但当前配置已删除，也要能作为筛选项显示出来，显示历史 key 或历史显示名兜底
- 后端列表查询支持按实例 `provider` 字段筛选。
- 前端只传筛选条件，不一次性加载全部实例再筛。

Provider 显示规则：

- 优先显示 Provider 的 `display_name`。
- 如果有 adapter 标记，沿用当前显示方式，例如 `AIAPIS GPT Image 2 (c)`。
- 如果当前配置中已经没有该 Provider，但实例里仍保存了 provider key，则显示保存下来的 key，不能静默替换为当前 Provider。

验收标准：

- “Provider 筛选”位于“方式筛选”右边。
- 选择 Provider 后立即刷新保存区列表。
- Provider 选项按显示名称 A-Z 排序。
- 当前配置中已删除但实例仍在使用的 Provider 仍可被识别和显示，不丢历史信息。

### 3. 保存区新增 Provider 排序

当前需求：

- 在“排序”下拉菜单中，新增“Provider 排序 A-Z”和“Provider 排序 Z-A”。

调整方案：

- 保存区排序增加：
  - `provider_asc`
  - `provider_desc`
- 排序走后端查询。
- 排序依据优先使用 Provider 显示名称。
- 如果当前配置中找不到 Provider 显示名称，则用实例保存的 provider key 兜底。
- Provider 排序会影响保存区实例编号。

验收标准：

- 排序菜单出现“Provider A-Z”和“Provider Z-A”。
- 选择后保存区立即刷新。
- 保存区编号按新排序重新计算。
- 筛选条件不影响历史记录编号。

### 4. 失败实例重新生成后进入最前面

当前需求：

- 保存区实例中，对曾经失败过的案例，点击“重新生成”进入“生成中”。
- 当这个案例再次生成成功或失败之后，不要回到以前的位置。
- 它应该给到最前面的位置，和新生成的案例一样。

调整方案：

- 失败实例重新提交仍然复用原实例，不新增实例。
- 生成中阶段继续沿用 V0.50 规则：
  - 生成中实例不参与正式分页。
  - 生成中实例不挤掉已有正式实例。
  - 原有正式编号在生成完成或失败前不变。
- 生成结束后，不管成功还是失败，都更新该实例的排序时间。
- 在“最新优先”排序下，该实例进入最前面。
- 在其他排序下，仍按当前排序规则重新计算位置和编号。

验收标准：

- 失败实例重新生成完成后，在“最新优先”下排到最前面。
- 重新生成失败后也排到最前面，方便继续处理。
- 生成中阶段不影响当前页已有正式实例编号。
- 不新增重复实例。

### 5. 标签总清除按钮移出标签框

当前需求：

- 保存区实例中，将标签框里面的总清除按键“X”拿掉。
- 当前这个按键占用标签框最右边一整列，浪费空间。
- 将这个按键放到“带入”按钮左边挨着。
- 样式和标签框里面的标签样式保持一致。

调整方案：

- 标签输入框内部不再放总清除 X。
- 在实例按钮区中，“带入”左侧新增一个小型 chip 风格按钮。
- 文案建议：
  - `清标签`
- 样式接近标签 chip，但要能看出它是可点击操作。
- 点击后仍只清除当前实例上的标签关联，不删除真实 TAG，不删除电脑图片文件。

验收标准：

- 标签框右侧不再被 X 占一列。
- “清标签”位于“带入”左边。
- 清标签动作不需要进入编辑状态。
- 批量添加标签、批量删除标签不受影响。

### 6. Provider 下拉统一排序

当前需求：

- 所有 Provider 下拉选择菜单中，各 Provider 都保持同样排序规则：按照名称 A-Z 排序。

调整方案：

- 抽出统一的 Provider 排序辅助逻辑。
- 使用范围包括：
  - 操作区 Provider 下拉
  - 保存区实例编辑状态 Provider 下拉
  - 保存区 Provider 筛选
  - 历史记录 Provider 筛选
  - 设置页 Provider 选择
  - 带入操作区时需要选择 Provider 的弹窗或 prompt
- 排序依据：
  - 当前 Provider 配置中的 `display_name`
  - 如果没有 display_name，用内部 key
  - adapter 标记只用于显示，不改变排序主体

验收标准：

- 不同页面中的 Provider 顺序一致。
- 新增 Provider 后，下拉顺序自动按名称变化。
- 当前选中值不因为排序变化丢失。

### 7. 历史记录 Provider 显示修正

当前需求：

- 历史记录页中，Provider 下拉显示不对，应和生图管理页 Provider 下拉一致。
- 历史记录页每条记录里的 Provider 显示名不对，应显示名称而不是内部编号。
- Provider 已删除时，历史页里面旧 Provider 信息继续保留。

调整方案：

- 历史记录中的 Provider 显示优先使用历史快照：
  - 历史记录 `params.provider_display_name`，如果后续补入
  - 历史记录本身保存的 `provider_key`
  - 历史记录参数快照里的 `provider_key`
- 当前 Provider 配置仍可作为显示名补充，但不能覆盖历史信息。
- 如果历史 Provider 在当前配置中仍存在，可显示当前配置中的显示名。
- 如果历史 Provider 在当前配置中已删除，仍显示历史中保存的 Provider key 或历史显示名，并可加“历史”标识，但不能显示为空。

建议显示：

- 当前仍存在：`AIAPIS GPT Image 2 (c)`
- 当前已删除但历史有 key：`old_provider_key（历史）`
- 历史有 display_name：`旧 Provider 名称（历史）`

验收标准：

- 历史 Provider 下拉不是内部编号裸显示。
- 历史记录卡片里的 Provider 使用显示名称。
- 删除当前 Provider 配置后，旧历史记录仍可看到当时 Provider 信息。

### 8. 历史记录增加 model 显示和筛选

当前需求：

- 历史记录页中，每条记录的信息中的“调用方式”后面增加“model”。
- 历史记录页筛选栏中，“调用方式”后面增加“model”。

调整方案：

- 历史记录卡片摘要中显示：
  - 调用方式
  - model
- model 从历史参数快照中读取：
  - `params.model`
  - 没有则显示“未记录”或不显示该字段
- 历史记录筛选栏新增 model 下拉。
- model 筛选走后端查询，优先基于 `params_json` 中的 model。

验收标准：

- 新历史记录能看到 model。
- 旧历史记录没有 model 时不报错。
- model 下拉选择后立即刷新历史记录。

### 9. 历史记录新增尺寸和模式筛选

当前需求：

- 历史记录页中，“筛选”栏中，“调用方式”前面增加“尺寸”、“模式”筛选按钮。

调整方案：

  - 尺寸

  - 开始日期
  - 结束日期
  - 刷新

- 模式筛选使用历史记录 `mode`：
  - 全部
  - 文生图
  - 图生图
  - 其他
- 所有下拉选择后立即刷新。

验收标准：

- 不一次性加载全部历史到前端筛选。

### 10. 历史记录去掉筛选按钮和清理按钮

当前需求：

- 历史记录页中，“筛选”通过下拉菜单点选实现，所以去掉“筛选”按钮。
- 失败记录一定需要保留，所以去掉“删除失败记录”按钮。
- 去掉“删除日期之前记录”按钮和旁边日期选择。

调整方案：

- 历史记录筛选表单不再显示“筛选”按钮。
- 下拉、日期、每页数量变更后立即刷新。
- 提示词搜索仍保留回车搜索或输入后点击刷新。
- “删除失败记录”从页面移除。
- “删除日期之前记录”和旁边清理日期输入从页面移除。
- 后端历史清理接口本版不强制删除，避免破坏已有能力和旧测试；只是前端不暴露入口。

验收标准：

- 历史页看不到“筛选”按钮。
- 历史页看不到“删除失败记录”。
- 历史页看不到“删除日期之前记录”和清理日期框。
- 失败记录仍完整保留，数据安全导出仍包含失败历史。

### 11. 历史记录卡片背景区分度提高

当前需求：

- 历史记录页中，将每一个记录的背景颜色调整得区分度更高一些。

调整方案：

- 不重做历史页 UI。
- 只调整记录卡片底色、边框或状态侧边线。
- 可以按状态增加轻微差异：
  - 成功：偏浅绿色或正常底色加绿色状态线
  - 失败：偏浅红色或红色状态线
  - 生成中：偏浅黄色或蓝色状态线
- 保持简约，不做大面积花哨背景。

验收标准：

- 不同历史记录之间边界更清楚。
- 失败记录更容易扫到。
- 不出现横向滚动条。

### 12. 历史编号与保存区编号一致但筛选互不影响

当前需求：

- 历史记录页中，将每一条记录的编号和生图管理页保存区实例编号保持严格一致。
- 如果保存区实例中由于排序原因编号发生更改，历史记录页中每条记录编号也相应更改。
- 但是排序不要相互影响。
- 两边筛选都不要影响另一边的编号，只有排序会影响编号。

最终规则：

- 保存区编号：
  - 只受保存区当前排序规则影响。
  - 不受历史记录筛选影响。
  - 不受历史记录排序影响。
- 历史记录编号：
  - 对应保存区实例时，显示该实例在“保存区当前排序规则”下的全局编号。
  - 不受保存区当前筛选影响。
  - 不受历史记录当前筛选影响。
  - 不改变历史记录自己的展示顺序。
- 如果历史记录没有对应保存区实例：
  - 显示 `—`
  - 或显示“无对应实例”
- 如果一个历史记录对应多个输出实例：
  - 显示主要实例编号，必要时显示 `#001 等`
- 如果是重试合并历史：
  - 主记录显示主实例编号。
  - 子重试记录不单独编号。

实现建议：

- 生成历史记录时，在参数快照里记录对应实例 ID 或生成任务 ID。
- 对已有历史，如果没有可靠实例 ID，则不强行猜测。
- 后端提供一个“实例在当前排序规则下的编号映射”能力。
- 历史记录页查询时带上当前保存区排序规则，用该排序规则计算编号。
- 保存区筛选条件不参与这个编号映射，避免“筛选后历史编号跟着变”的问题。

验收标准：

- 保存区排序从“最新优先”切到“最早优先”后，历史记录中对应实例编号会变化。
- 保存区筛选 Provider、标签、来源、方式后，历史记录编号不跟着筛选变化。
- 历史记录筛选状态、Provider、尺寸、模式、调用方式、model 后，保存区编号不变化。
- 没有可靠对应实例的历史记录不会误显示错误编号。

## 副作用与处理

- Provider 筛选和 Provider 排序需要后端参与，后端要读取当前配置中的 Provider 显示名；如果 Provider 已删除，用历史 key 兜底。
- 历史记录显示 Provider 名称时，当前配置可能已经变化；历史页必须优先保护历史快照，不能用当前配置覆盖旧信息。
- 历史记录 model、尺寸、模式筛选依赖历史快照；旧历史记录可能缺字段，需要显示“未记录”并允许筛选。
- 去掉历史清理按钮后，失败记录不会被误删；如后续需要清理能力，应另做版本并加更严格确认。
- 历史编号和保存区编号一致这项最容易误伤性能；必须走后端计算，不能在前端全量加载所有实例。
- 失败实例重新生成后更新排序时间，会让它在“最新优先”下前置；这是符合本版目标的行为，但会改变旧失败实例的位置。
- 工具栏新增 Provider 筛选后空间更紧，需要配合把“路径替换”下移，避免横向滚动。

## 测试重点

- 保存区工具栏：路径替换位置正确，新增/缩略图样式区分。
- 保存区筛选：Provider 筛选立即刷新，和标签、来源、方式、节点、搜索可以叠加。
- 保存区排序：Provider A-Z、Provider Z-A 正确，编号随排序变化。
- 保存区实例：清标签按钮移到带入左侧，不占标签输入框内部宽度。
- 失败实例重新生成：完成后在最新优先下进入最前面，不新增重复实例。
- Provider 下拉：操作区、保存区实例、历史筛选、设置页顺序一致。
- 历史页：Provider 下拉和记录内 Provider 显示名正确。
- 历史页：当前 Provider 删除后，旧历史仍显示旧 Provider 信息。
- 历史页：调用方式后显示 model，筛选栏也能按 model 筛选。
- 历史页：尺寸、模式、调用方式、model 下拉选择后立即刷新。
- 历史页：筛选按钮、删除失败记录、删除日期之前记录及清理日期框均不再出现。
- 历史页：记录背景区分度提高，不出现横向滚动条。
- 编号规则：保存区筛选不影响历史编号，历史筛选不影响保存区编号，只有排序影响编号。
- 回归：V0.50.2 的生成中下拉稳定、7 个生成中翻页、历史多错误合并展示不回退。
