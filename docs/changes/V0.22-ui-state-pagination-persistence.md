## 当前问题根因

V0.21 中，保存区每页数量保存在前端内存：

```javascript
state.filters.per_page
```

关闭网页后前端状态重新初始化，每页数量回到默认值 `50`，所以用户选择 `10` 后重新打开网页会丢失。

同类问题也存在于保存区筛选、排序、页码、历史记录筛选、历史记录每页数量、历史记录页码，以及操作区草稿内容。

## UI 状态持久化方式

新增浏览器本地存储：

```javascript
const UI_STATE_STORAGE_KEY = "AIImageManager.uiState.v1";
```

使用 `localStorage` 保存 UI 状态。

使用 `localStorage` 的规则：

- 保存用户当前网页状态。
- 不保存数据库内容。
- 不保存 Provider 配置。
- 不保存 API Key。
- 不保存正在生成中的任务。
- 不保存弹窗、悬停、下拉展开等瞬时状态。

实现以下函数：

```javascript
function defaultPersistedUiState()
function loadPersistedUiState()
function persistUiState()
function applyPersistedUiState(savedState)
function persistedOperationState()
function persistedSaveFilterState()
function persistedHistoryState()
```

`loadPersistedUiState()` 必须做异常保护：

- `localStorage` 不可用时返回默认状态。
- JSON 解析失败时返回默认状态。
- 字段类型不正确时忽略该字段。

`persistUiState()` 必须做异常保护：

- `localStorage` 写入失败时不影响正常使用。
- 不在页面顶部弹出错误提示。

## 启动时恢复状态

`boot()` 流程调整为：

```text
1. 加载 /api/settings
2. 初始化全局默认参数
3. 读取 localStorage UI 状态
4. 将 UI 状态覆盖到对应 state
5. 加载保存区实例
6. 加载标签
7. 渲染页面
```

恢复操作区时：

- 如果 UI 状态中有 `generation_path`，优先使用 UI 状态。
- 如果 UI 状态中没有 `generation_path`，使用 `settings.default_output_dir`。
- 如果 UI 状态中的模式不是 `text_to_image` 或 `image_to_image`，回退为 `text_to_image`。
- 如果 UI 状态中的图片路径不是数组，回退为空数组。
- 如果 UI 状态中的标签不是数组，回退为空数组。
- 如果 UI 状态中的生成数量不是正整数，回退为默认生成数量。
- 如果恢复后是图生图模式，生成数量固定为 `1`。

恢复保存区筛选时：

- `per_page` 只允许 `10`、`20`、`50`、`100`、`200`。
- `source` 只允许 `all`、`generated`、`manual`。
- `sort` 只允许现有排序选项。
- `page` 必须是大于等于 `1` 的整数。
- `tags` 必须是字符串数组。

恢复历史记录时：

- `per_page` 只允许历史记录页已有每页数量选项。
- `status` 只允许历史记录页已有状态选项。
- `page` 必须是大于等于 `1` 的整数。

## 统一避免空白页逻辑

保存区和历史记录页都必须实现统一分页保护。

新增通用函数：

```javascript
function maxPageForTotal(total, perPage)
function normalizePageForTotal(page, total, perPage)
function shouldReloadForNormalizedPage(currentPage, normalizedPage)
```

规则：

- `total = 0` 时，当前页固定为 `1`。
- `total > 0` 时，最大页码为 `Math.ceil(total / per_page)`。
- 如果当前页小于 `1`，改为 `1`。
- 如果当前页大于最大页码，改为最大页码并重新加载。
- 只要当前查询结果有数据，就不允许停留在无效空白页。

保存区加载流程：

```text
1. 使用当前 state.filters 请求 /api/instances
2. 写入 state.instances 和 state.total
3. 计算 normalizedPage
4. 如果 normalizedPage 不等于请求页码：
   - 写入 state.filters.page = normalizedPage
   - persistUiState()
   - 重新请求 /api/instances
5. 渲染保存区
```

历史记录加载流程：

```text
1. 使用当前 state.history 请求 /api/generation-history
2. 写入 state.history.items 和 state.history.total
3. 计算 normalizedPage
4. 如果 normalizedPage 不等于请求页码：
   - 写入 state.history.page = normalizedPage
   - persistUiState()
   - 重新请求 /api/generation-history
5. 渲染历史记录页
```

删除实例后：

- 继续调用现有刷新保存区逻辑。
- 刷新后如果当前页无效，自动回到最后一个有效页并重新加载。
- 不出现“有数据但当前页空白”的情况。

新增实例后：

- 保持现有新增逻辑。
- 新增后保存区刷新仍走统一分页保护。

修改每页数量后：

- 当前页重置为 `1`。
- 写入 UI 状态。
- 刷新保存区或历史记录。

修改筛选或排序后：

- 当前页重置为 `1`。
- 写入 UI 状态。
- 刷新保存区或历史记录。

翻页后：

- 写入 UI 状态。
- 刷新保存区或历史记录。

## 保存区每页数量问题修复

用户在保存区选择每页数量 `10` 后：

- 立即写入 `state.filters.per_page = 10`。
- 立即调用 `persistUiState()`。
- 关闭网页再重新打开后，从 `localStorage` 恢复为 `10`。
- 加载实例时使用 `per_page=10` 请求。
- 页面下拉框显示 `10`。

## 历史记录每页数量同步修复

用户在历史记录页选择每页数量后：

- 立即写入 `state.history.per_page`。
- 立即调用 `persistUiState()`。
- 关闭网页再重新打开后，从 `localStorage` 恢复。
- 加载历史记录时使用恢复后的每页数量请求。
- 页面下拉框显示恢复后的值。

## 操作区草稿恢复

关闭网页前，如果操作区有未生成的提示词、输入图、标签、模式、路径等，下次打开网页恢复。

点击“清空”操作区后：

- 清空提示词。
- 清空输入图。
- 清空输出图预览。
- 保留或恢复当前生成路径按现有按钮逻辑执行。
- 立即调用 `persistUiState()`，避免下次打开恢复旧提示词。

图生图模式恢复：

- 恢复输入图路径。
- 生成数量仍显示为 `1` 且置灰。

文生图模式恢复：

- 不显示输入图区内容，但保留草稿中的输入图路径不参与文生图生成。
- 如果用户切回图生图，输入图路径仍可恢复。

## 副作用与处理

如果浏览器清理站点数据，`localStorage` 状态会丢失。数据库、配置、图片文件不受影响。

如果同一个浏览器打开多个版本，可能共享同一个 `localStorage` key。V0.22 使用固定 key `AIImageManager.uiState.v1`，让 V0.22 之后的版本可以延续 UI 状态。后续如果状态结构发生不兼容变化，再升级 key。

如果恢复的图片路径对应文件已经不存在，页面沿用现有图片加载失败显示逻辑，不删除路径。

如果恢复的保存区筛选条件没有匹配数据，显示第 1 页空状态。这不是空白页错误，而是当前筛选没有结果。

如果恢复的保存区筛选条件有匹配数据，但恢复页码无效，自动跳到最后一个有效页。

如果用户正在编辑保存区实例，关闭网页不会保存未点击保存的实例编辑内容。这是 V0.22 的明确边界。

`beforeunload` 只写本地 `localStorage`，不发 API 请求，避免关闭网页时卡顿或出现浏览器拦截。
