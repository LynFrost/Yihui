## 并行生成

操作区允许在生成未完成时继续点击 `生成`。

实现规则：

- 每次点击 `生成` 都立即截取当前操作区表单快照。
- 每个生成请求使用自己的 prompt、输入图、输出路径、标签、尺寸、清晰度、数量和 Provider 参数。
- 生成按钮不再因为已有任务运行而禁用。
- 多个 `/api/generate` 请求可以并行发送，互不覆盖请求参数。
- 操作区输出图显示“最后完成的生成任务”的最后一张输出图。
- 保存区实例和历史记录以每个任务自己的结果为准。
- 生成成功后刷新保存区列表、标签和历史记录。
- 某个任务失败只影响该任务，不影响其他运行中或已完成任务。

前端状态从单任务改为多任务：

```javascript
state.generationTasks = []
```

每个任务至少包含：

```javascript
{
  id: "",
  status: "running",
  prompt: "",
  startedAt: "",
  finishedAt: "",
  durationMs: 0,
  error: "",
  outputImagePaths: []
}
```

`status` 可选：

```text
running
success
failed
```

操作区状态显示规则：

- 有运行中任务时显示：`生成中 N 个 · 已完成 S · 失败 F`
- 没有运行中任务且最近一次成功时显示：`已生成`
- 没有运行中任务且最近一次失败时显示最近错误。
- 点击筛选、下拉框、切换页面、切换设置项时，任务状态不消失。
- 点击 `清空` 清空操作区内容，但不取消正在运行的任务。

## 后端并发处理

Flask 本地服务启动时启用 threaded：

```python
app.run(host=args.host, port=args.port, debug=False, threaded=True)
```

SQLite 连接增加等待和 WAL 相关设置：

```python
sqlite3.connect(db_path, timeout=30)
PRAGMA busy_timeout = 30000
PRAGMA journal_mode = WAL
PRAGMA foreign_keys = ON
```

实现规则：

- 并发生成时，每个请求使用独立数据库连接。
- 历史记录创建、实例创建、历史记录完成更新都继续使用事务。
- 如果某个任务写库失败，只让该任务失败，不影响其他任务。
- 历史记录仍只记录点击 `生成` 的任务。

## 文生图 n>1

文生图固定示例改为遍历 `resp.data` 下载多张图。

固定示例：

```python
from openai import OpenAI
from urllib.request import Request, urlopen
import shutil

USER_AGENT = user_agent or "Mozilla/5.0 PowerShell/7.4"

client = OpenAI(
    base_url="https://img.aiapis.help/v1",
    api_key="${YOUR_API_KEY}",
    default_headers={"User-Agent": USER_AGENT},
)

prompt = operation_prompt

resp = client.images.generate(
    model="gpt-image-2",
    prompt=prompt,
    size=resolved_size,
    quality="high",
    output_format="png",
    # output_compression only works for jpeg/webp
    # output_compression=80,
    background="auto",
    moderation="low",
    n=n,
    user="",
)

for i, item in enumerate(resp.data, start=1):
    image_url = item.url
    output_path = f"output_{i}.png"

    request = Request(image_url, headers={"User-Agent": USER_AGENT})
    with urlopen(request, timeout=60) as response:
        with open(output_path, "wb") as f:
            shutil.copyfileobj(response, f)
```

软件内部生成规则：

- 文生图 `n > 1` 时，后端必须保存所有返回图片。
- 每张输出图创建一个保存区实例。
- 每个实例仍只保留 1 张输出图。
- 每个实例继承同一份提示词、输入图、标签、Provider 和生成参数。
- 操作区输出图显示最后一张输出图。
- 历史记录写入全部输出图片路径。
- 图生图继续固定 `n = 1`。

必须补充测试：

- 文生图传入 `n = 3` 时，Provider 调用参数包含 `n = 3`。
- Provider 返回 3 个 URL 时，下载 3 张图片。
- `/api/generate` 返回 3 个 `output_image_paths`。
- 保存区创建 3 个实例。
- 历史记录记录 3 个输出路径。
- 图生图提交数量时仍强制为 1。

## output_compression 联动

`output_format = png` 时，`output_compression` 必须禁用并明显置灰。

实现规则：

- 切换到 `png` 后，`output_compression` 的 DOM 属性必须为 `disabled`。
- 切换到 `jpeg` 或 `webp` 后，`output_compression` 恢复可编辑。
- 禁用时视觉上使用灰色背景、灰色文字、禁用光标。
- 切换 `output_format` 时不得丢失当前未保存的 Provider 表单内容。
- 因为 disabled input 不提交表单，保存设置时如果表单没有提交 `output_compression`，应保留已有 Provider 的 `output_compression` 值。
- 后端调用 OpenAI 时，`output_format = png` 不传 `output_compression`。
- 后端调用 OpenAI 时，`output_format = jpeg` 或 `webp` 才传 `output_compression`。

## 图片原始路径导入

所有当前可以选择图片路径的位置，支持先点击具体图片区，再通过“资源管理器复制文件后粘贴”的方式导入原始图片路径。

支持位置：

- 操作区输入图。
- 操作区输出图。
- 保存区实例编辑状态下的输入图。
- 保存区实例编辑状态下的输出图。

交互规则：

- 用户先点击某个具体图片区或加号图片位。
- 软件记录当前图片目标区域。
- 用户在 Windows 资源管理器中复制一个或多个图片文件。
- 用户回到软件按 `Ctrl+V`。
- 前端请求后端读取 Windows 系统剪贴板里的 `FileDropList`。
- 后端返回剪贴板中的原始本地绝对路径。
- 软件记录原始本地绝对路径。
- 软件不复制图片文件。
- 软件不改名图片文件。
- 软件不创建导入副本。
- 输入图区粘贴图片时追加到输入图列表。
- 输出图区粘贴图片时替换当前输出图。
- 保存区非编辑状态不允许改图；粘贴时提示先点击编辑。
- 如果剪贴板没有本地文件路径，提示 `剪贴板中没有可用的本地图片路径，请从资源管理器复制图片文件，或点击选择图片。`
- 如果剪贴板路径不是支持的图片扩展名，提示 `剪贴板中的文件不是支持的图片格式。`
- 如果剪贴板路径指向的文件不存在，提示 `图片文件不存在。`

后端新增接口：

```text
GET /api/clipboard/image-paths
```

返回：

```json
{
  "paths": ["原始本地绝对路径"]
}
```

后端规则：

- 使用 Windows 原生剪贴板读取 `FileDropList`。
- 只返回本地文件路径。
- 不读取图片二进制内容。
- 不复制图片文件。
- 不改名图片文件。
- 支持扩展名：`.png`、`.jpg`、`.jpeg`、`.webp`、`.bmp`、`.gif`。
- 返回前校验文件存在。
- 多个路径按剪贴板中的顺序返回。
- 如果剪贴板没有 `FileDropList`，返回空列表或明确错误。

## 拖拽图片处理

拖拽不作为图片导入方式。

实现规则：

- 浏览器拖拽事件通常无法提供真实本地绝对路径。
- 为了满足“不复制图片、不改名、必须记录原始绝对路径”，V0.17 不使用普通网页拖拽导入图片。
- 用户拖拽图片到图片区时，软件提示：`拖拽无法读取原始路径，请从资源管理器复制图片文件后粘贴，或点击选择图片。`
- 现有点击选择图片功能继续保留；该功能通过后端原生文件选择窗口获取真实本地绝对路径。

## 副作用处理

并行生成会增加 Provider 侧并发压力，可能更容易触发限流、超时或余额快速消耗。软件只负责并行提交和独立记录结果，不能保证服务商接受无限并发。

并行任务完成顺序可能和提交顺序不同。V0.17 以“最后完成任务”更新操作区输出图，保存区和历史记录保留完整结果。

SQLite 并发写入需要增加等待设置。V0.17 使用 `busy_timeout` 和 WAL 降低 `database is locked` 概率。

普通浏览器拖拽和普通图片粘贴无法保证获得原始本地绝对路径。V0.17 不使用这两种方式写入图片路径，只支持原生文件选择窗口和资源管理器复制文件后的剪贴板 `FileDropList`。

V0.17 不复制图片、不改名图片、不创建导入目录，因此不会额外占用图片副本磁盘空间；代价是截图、网页图片、聊天软件图片等没有本地路径的剪贴板内容不能直接导入。

设置页全宽会让代码示例区域更宽，页面信息密度更高。通过分组浅色背景保持层次。

`output_compression` disabled 时不会随表单提交，保存逻辑必须保留旧值，避免用户选择 png 后把压缩参数意外清空。
