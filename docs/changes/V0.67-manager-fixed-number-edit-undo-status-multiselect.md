# V0.67 保存区固定编号、编辑撤销和状态多选

## 目标

当前 V0.66 已完成撤销恢复修复、批量提交和批量复制工具栏。本版 V0.67 目标是继续收口生图管理页保存区的稳定性和可追踪性：

- 第三次严肃修正保存区实例输入图区“清除”按钮与操作区输入图区“清除”按钮竖直对齐。
- 生图管理页状态筛选顺序改为“全部 / 生成中 / 准备 / 失败 / 生成 / 其他”。
- 生图管理页状态筛选由单选改为多选。
- 修复失败实例 Provider 可编辑但保存后回退的问题。
- 保存区实例编辑保存纳入撤销 / 重做。
- 保存区实例 Provider 下拉框加宽，使用 Provider 标题和下拉框之间的空白。
- 保存区实例提示词框上方新增数量 `n` 下拉框。
- 保存区实例编号改为创建时固定编号，不随排序、筛选、分页变化。
- 保存区排序新增“编号 从小到大”和“编号 从大到小”。
- 历史记录页能关联到实例的记录显示实例固定编号。

本版原则：

- 固定编号必须是数据库持久字段，不能继续使用当前页临时 `display_index`。
- 固定编号一旦生成，不因删除、排序、筛选、分页、恢复显示而重排。
- 编辑保存属于数据库修改，应纳入撤销 / 重做。
- 生成任务类操作仍不纳入撤销 / 重做。
- 不删除电脑上的图片文件。
- 不破坏 V0.66 的撤销恢复修复、批量提交、批量复制。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 输入图清除按钮对齐

### 1. 保存区和操作区输入图“清除”按钮竖直对齐

当前问题：

- 该需求已经连续提出多次。
- 当前保存区实例输入图区的“清除”按钮仍然偏左。
- 视觉上没有和操作区输入图区的“清除”按钮竖直对齐。

调整方案：

- 重新梳理操作区输入图区和保存区实例输入图区的列宽来源。
- 保存区输入图区“清除”按钮不能通过手工 margin 或相对偏移凑位置。
- 操作区和保存区实例的输入图标题行应使用同一右边界基准。
- 对齐目标是两个“清除”按钮的右边界竖直一致。
- 单列模式必须严格对齐。
- 双列模式下每张实例卡内部不能破版。
- 编辑态和只读态都要检查。

验收标准：

- 操作区输入图“清除”按钮和保存区实例输入图“清除”按钮右边界误差不超过 1px。
- 保存区实例输入图“清除”按钮不再偏左。
- 无输入图、有一张输入图、多张输入图时都稳定。
- 保存区单列模式稳定。
- 保存区双列模式稳定。
- 编辑态和只读态都稳定。
- 修改后不影响 V0.65 / V0.66 的 Provider 框、标签框、路径框扩宽布局。

测试要求：

- 实现后必须用浏览器测量两个按钮的 `getBoundingClientRect().right`。
- 不能只凭肉眼判断。

副作用：

- 可能需要调整输入图区标题行或保存区实例网格列宽。
- 需要防止局部对齐修正导致其他列错位。

## 状态筛选多选

### 2. 状态下拉顺序调整

当前顺序需要调整为：

- 全部
- 生成中
- 准备
- 失败
- 生成
- 其他

调整方案：

- 生图管理页筛选区状态选项按以上顺序显示。
- “全部”位于第一项。
- “全部”代表不启用状态过滤。

验收标准：

- 状态筛选展示顺序严格为“全部 / 生成中 / 准备 / 失败 / 生成 / 其他”。
- 旧的顺序“准备 / 生成 / 失败 / 生成中 / 其他”不再出现。

### 3. 状态筛选由单选改为多选

当前问题：

- 状态筛选当前是单选。
- 用户希望可以同时筛选多个状态。

调整方案：

- 状态筛选改为和标签筛选类似的多选下拉。
- 下拉中每个状态项可以独立选中或取消。
- 已选状态在按钮内以紧凑标签显示。
- 支持清空状态筛选。
- 点击“全部”时清空其他状态选择，回到不过滤状态。
- 选择任意具体状态时，“全部”不作为真实状态同时存在。
- 多个状态之间按 OR 逻辑查询。
- 状态内部语义：
  - 生成中：`generation_status = 'running'`。
  - 准备：无输出图，且不是失败、不是生成中。
  - 失败：`generation_status = 'failed'`。
  - 生成：有输出图，且不是生成中。
  - 其他：不属于以上分类的实例。

兼容规则：

- 旧 UI 状态中如果保存的是字符串，例如 `status: "failed"`，加载时应转换为多选数组 `["failed"]`。
- 旧 UI 状态中如果保存的是 `status: "all"` 或空值，加载时转换为空数组。
- 后端需要兼容旧的单值 `status` 和新的多值 `statuses`。

验收标准：

- 可以同时选择“生成中”和“失败”。
- 同时选择多个状态时，列表显示任意匹配状态的实例。
- 点击“全部”后清空所有状态选择。
- 清空状态筛选后恢复显示全部。
- 切换状态筛选后分页回到第一页。
- 切换状态筛选后清空当前页批量选择，沿用 V0.27 规则。
- 不破坏标签筛选、Provider 筛选、尺寸筛选、模式筛选、调用方式筛选、model 筛选。

副作用：

- 前端 UI 状态结构会从单值变为数组。
- 后端查询条件会从单个状态条件变为多个状态条件 OR 组合。
- 需要避免多个状态筛选和其他筛选条件组合时查询结果不准确。

## 失败实例 Provider 保存

### 4. 修复失败实例 Provider 保存后回退

当前问题：

- 保存区失败状态实例的 Provider 下拉框可以编辑。
- 但修改 Provider 后点击保存，页面刷新后又变回旧 Provider。

根因判断：

- 当前失败实例允许显示 Provider 下拉框。
- 但同步编辑草稿时仍存在旧限制：当实例来源是 `generated` 时，不读取 `instance_provider` 下拉框。
- 失败实例通常来源仍是 `generated`，所以保存时实际提交的还是旧 Provider。

调整方案：

- 只要当前实例编辑态中存在 `instance_provider` 下拉框，就读取下拉框的值。
- Provider 是否可编辑由渲染层的 `canEditInstanceProvider` 控制。
- 草稿同步层不再额外用 `source === generated` 阻止读取。
- 保存时应更新实例主字段 `provider`。
- 如实例 `generation_params.provider_key` 存在，也应同步更新为新 Provider，避免后续提交 / 重提使用旧 Provider。

验收标准：

- 失败实例进入编辑后修改 Provider 并保存，刷新后 Provider 保持新值。
- 修改后的失败实例点击“重提”使用新 Provider。
- 准备态实例修改 Provider 并保存，刷新后 Provider 保持新值。
- 生成成功且有输出图的实例仍不能修改 Provider。
- Provider 不存在时仍沿用已有提示规则，不静默失败。

副作用：

- 更新 `generation_params.provider_key` 会改变该实例后续提交参数来源。
- 历史记录已经发生过的 Provider 信息不应被反向修改。

## 编辑保存纳入撤销 / 重做

### 5. 保存区实例编辑保存支持撤销 / 重做

当前问题：

- 保存区实例进入编辑后，修改 Provider、提示词或其他内容并点击“保存”。
- 这些修改当前不能通过“撤销 / 重做”恢复。

调整方案：

- `saveInstanceDraft` 保存前创建会话快照。
- 保存成功后，把保存前快照放入撤销栈。
- 保存失败时不写入撤销栈。
- 如果保存前后没有实际变化，不写入撤销栈。
- 自动批量保存也按同样规则处理：
  - 有实际变化并保存成功，纳入撤销。
  - 无变化，不纳入撤销。
  - 保存失败，不纳入撤销。
- 保存区编辑保存覆盖以下内容：
  - 提示词。
  - Provider。
  - 模式。
  - 输入图。
  - 输出图。
  - 标签。
  - 生成路径。
  - 尺寸。
  - 数量 `n`。
  - 可保存的生成参数。

验收标准：

- 修改实例提示词并保存后，点击撤销可以恢复旧提示词。
- 再点击重做可以恢复新提示词。
- 修改实例 Provider 并保存后，点击撤销可以恢复旧 Provider。
- 再点击重做可以恢复新 Provider。
- 修改输入图并保存后，撤销 / 重做可恢复。
- 修改输出图并保存后，撤销 / 重做可恢复。
- 修改标签并保存后，撤销 / 重做可恢复。
- 修改数量 `n` 并保存后，撤销 / 重做可恢复。
- 无变化点击保存，不增加撤销栈。
- 保存失败不增加撤销栈。

不纳入范围：

- 提交、重提、生成中、取消生成仍不纳入撤销 / 重做。
- 操作区输入内容变化仍不纳入撤销 / 重做。
- 筛选、排序、分页、每页数量仍不纳入撤销 / 重做。

副作用：

- 撤销栈会覆盖更多真实数据库编辑。
- 自动批量保存如果处理不好，可能产生过多撤销记录。
- 需要用变更检测避免无意义撤销记录。

## 保存区实例布局调整

### 6. Provider 下拉框加宽

当前问题：

- 保存区实例的 Provider 标题和 Provider 下拉框之间存在空白。
- 下拉框显示空间不足。

调整方案：

- Provider 标题位置不移动。
- 使用 Provider 标题和下拉框之间的空白，加宽 Provider 下拉框。
- 优先让下拉框向左吃掉空白，再按现有右边界规则使用剩余空间。
- 不挤压状态标识、标签框、提交 / 重提按钮。

验收标准：

- Provider 标题和下拉框之间不再有明显浪费空白。
- Provider 下拉框比当前更宽。
- 长 Provider 显示更完整。
- 不影响保存区右侧编辑 / 删除按钮列。
- 不影响单列 / 双列布局。

副作用：

- Provider 行内部布局会更紧凑。
- 需要检查长 Provider 名称、状态标识、标签框同时存在时是否溢出。

### 7. 提示词标题行新增数量 `n` 下拉框

当前需求：

- 保存区实例的提示词框上方，在“复制”按钮左边增加数量下拉框。
- 显示当前实例的数量 `n`。
- `n` 来自操作区生成参数。
- 旧实例如果没有该参数，默认都是 `1`。
- 数量下拉框只利用空白间隙，不影响当前布局。

调整方案：

- 从实例 `generation_params.n` 或 `generation_params.count` 读取数量。
- 如果不存在或非法，显示为 `1`。
- 下拉框放在提示词标题行的“复制”按钮左边。
- 下拉框宽度紧凑，避免挤压提示词标题和复制 / 清除按钮。
- 下拉选项建议为 `1` 到 `10`。
- 如果旧数据中存在大于 `10` 的合法数量，则把当前值临时加入下拉选项，避免显示丢失。
- 修改数量后点击保存，写回实例生成参数：
  - `generation_params.n`。
  - 必要时同步 `generation_params.count`。
- 数量修改纳入编辑保存撤销 / 重做。

验收标准：

- 旧实例显示数量 `1`。
- 新增准备态实例显示操作区带来的数量 `n`。
- 复制实例保留数量 `n`。
- 修改数量并保存后刷新仍保持。
- 修改数量后提交实例，生成任务使用该实例保存的数量。
- 数量下拉框不导致提示词标题行变高。
- 数量下拉框不挤压复制按钮。
- 撤销 / 重做可以恢复数量修改。

副作用：

- 保存区实例的提示词标题行会增加一个控件。
- 需要检查窄窗口、双列布局、长重试提示时是否拥挤。

## 固定实例编号

### 8. 实例编号改为创建时固定不变

当前问题：

- 保存区实例编号目前来自 `display_index`。
- `display_index` 会随排序、筛选、分页变化。
- 这不符合“实例唯一编号”的需求。

调整方案：

- 为 `instances` 表新增持久字段 `instance_number`。
- `instance_number` 为正整数，创建时分配。
- 显示时统一格式为 4 位，例如：
  - `#0001`
  - `#0002`
  - `#0010`
  - `#0100`
- 旧实例迁移规则：
  - 按 `created_at ASC, id ASC` 排序。
  - 最早实例分配 `1`，显示为 `#0001`。
  - 后续依次递增。
- 新实例创建规则：
  - 取当前数据库最大 `instance_number + 1`。
  - 删除实例后不复用已删除编号。
- 恢复旧备份或旧导出时：
  - 如果没有 `instance_number` 字段，按旧实例迁移规则补齐。
  - 如果有 `instance_number` 字段，应保留原编号。
  - 如果恢复数据中存在编号冲突，应明确修复规则并记录校验信息，不能静默产生重复编号。

验收标准：

- 保存区显示固定编号，不再使用临时 `display_index`。
- 最早创建的实例显示 `#0001`。
- 新建实例编号递增。
- 删除实例后，其他实例编号不改变。
- 排序改变后，实例位置可以变化，但编号不变。
- 筛选改变后，显示的实例编号仍是原固定编号。
- 翻页后编号不重排。
- 撤销 / 重做后编号保持一致。
- 批量复制创建的新实例获得新的固定编号。
- 提交准备态实例、重提失败实例不改变该实例编号。

副作用：

- 该需求需要数据库 schema 迁移。
- 导出、备份、恢复、会话快照都要包含 `instance_number`。
- 历史记录与保存区编号关联逻辑需要同步调整。

### 9. 排序新增编号从小到大 / 从大到小

调整方案：

- 保存区排序下拉框新增：
  - 编号 从小到大。
  - 编号 从大到小。
- 后端排序对应：
  - `instance_number ASC, id ASC`。
  - `instance_number DESC, id DESC`。
- 旧排序项继续保留。

验收标准：

- 选择“编号 从小到大”后，保存区按固定编号升序排列。
- 选择“编号 从大到小”后，保存区按固定编号降序排列。
- 排序只影响位置，不改变编号。
- 状态多选、标签筛选、Provider 筛选、尺寸筛选等筛选条件下编号排序仍准确。

副作用：

- 保存区排序选项增加，需要检查下拉框宽度和文案显示。

## 历史记录编号

### 10. 历史记录显示关联实例固定编号

当前需求：

- 历史记录页中，每个记录的编号如果能够联系到具体实例，都改成这个实例的编号。

调整方案：

- 历史记录优先通过参数快照中的实例引用关联保存区实例：
  - `primary_instance_id`。
  - `instance_ids`。
  - `target_instance_id`。
  - `retry_instance_id`。
  - `instance_id`。
- 能关联到实例时，显示该实例的固定编号，例如 `#0007`。
- 不使用输出图路径匹配实例编号，避免路径重复、路径变更、手动替换导致不准确。
- 如果关联不到具体实例，不显示空编号。
- 关联不到时使用明显区分的历史本地编号，例如：
  - `H0001`
  - `H0002`
- 历史本地编号只用于历史页显示，不等同实例编号。

验收标准：

- 历史记录能关联实例时，显示保存区同一个实例的固定编号。
- 保存区排序变化不影响历史记录中的固定编号。
- 保存区筛选变化不影响历史记录中的固定编号。
- 旧历史记录如果无法关联实例，显示 `H0001` 这类历史编号，不显示空编号。
- 多次重试合并记录中，主记录和重试记录编号显示规则一致。
- 历史 Provider、调用方式、model、参数快照不被修改。

副作用：

- 旧历史可能有一部分无法关联实例，会显示历史本地编号。
- 这是为了准确性，不用输出图路径做不可靠匹配。

## 数据安全和兼容

### 11. schema、备份、导出、恢复兼容

调整方案：

- 数据库 schema 版本需要升级。
- `instances.instance_number` 纳入：
  - 数据导出。
  - 数据备份。
  - 数据恢复。
  - 会话快照。
  - 会话恢复。
- 旧备份 / 旧导出缺少 `instance_number` 时自动补齐。

验收标准：

- 旧数据库升级后所有实例都有固定编号。
- 新建实例自动分配编号。
- 导出 JSON 中包含 `instance_number`。

- 会话撤销 / 重做恢复后编号不丢失。

副作用：

- schema 迁移会影响数据安全链路，必须重点回归。
- 编号冲突处理规则必须明确，否则恢复时可能出现重复编号。
