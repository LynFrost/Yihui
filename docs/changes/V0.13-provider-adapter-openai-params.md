## 生图管理 UI 边界

V0.13 不修改“生图管理”页面布局。

不得修改：

- 操作区列宽、控件位置、控件高度、控件间距。
- 文生图和图生图的布局切换规则。
- 提示词框、输入图、分辨率、清晰度、数量、输出图、添加标签、生成路径、清空、生成的位置。
- 保存区实例布局、实例高度规则、单列和双列布局。
- 保存区实例中图片框、提示词框、标签区、按钮区的位置和尺寸。
- 保存区实例中新增生成参数说明文字。

允许的“生图管理”页面可见变化只有现有 Provider 文字的内容变化：

```text
Provider：显示名称 (短标记)
```

短标记规则：

```text
adapter = openai  -> (c)
adapter = google  -> (g)
adapter = other   -> (o)
```

说明：

- `(c)` 表示 OpenAI / OpenAI 兼容接口。
- `(g)` 表示 Google 接口。
- `(o)` 表示其他或自定义接口。
- 只在原有 Provider 文本后追加短标记。
- 不新增控件。
- 不新增说明文字。
- 不新增一行。
- 不改变操作区或保存区任何列宽、高度、间距。
- Provider 文本仍保持单行显示。
- 如果 Provider 文本过长，按现有规则截断或省略，不允许撑开布局。

需要应用短标记的位置：

- 操作区现有 `Provider：xxx`。
- 保存区实例现有 `Provider：xxx`。
- 手动实例编辑 Provider 时，已有 Provider 选项可以显示短标记，但保存值仍保存真实 Provider key 或原有 Provider 值，不把 `(c)`、`(g)`、`(o)` 写入 Provider 名称。

当当前选中的 Provider 对应的 `adapter` 不是 `openai` 时，点击生成不改变页面布局，只在现有状态区域提示：

```text
Google adapter 暂未实现。
Other adapter 暂未实现。
```

状态提示必须使用现有状态区域，不新增区域，不改变操作区高度、宽度或列布局。

## 概念命名

V0.13 起，Provider 与 adapter 的含义固定为：

```text
Provider = 用户自己配置的代理商、渠道或接口提供方。
adapter = Provider 使用的接口调用类型。
```

Provider 示例：

```text
AIAPIS GPT Image 2
某某代理商
自定义渠道 A
```

adapter 可选值：

```text
openai
google
other
```

前端不要再向用户显示英文标签 `adapter`，统一显示为：

```text
接口类型
```

## OpenAI Image API 参数

当 `接口类型 = openai` 时，设置页显示 `OpenAI Image API 参数` 区域。

该区域列出 OpenAI Image API 能控制且当前软件需要暴露或说明的参数。

### 来自软件的参数

以下参数来自操作区，不能在设置页修改。控件置灰，并在右侧标注：

```text
来自软件
```

参数：

```text
prompt
size
n
```

说明：

```text
prompt：来自操作区提示词
size：来自操作区的长宽比 + 清晰度换算结果
n：来自操作区的生成数量
```

`size` 在设置页中只做说明，不直接编辑。说明文字：

```text
size 由操作区选择的长宽比和清晰度自动换算，例如 16:9 + 4K = 3840x2160
OpenAI 官方支持 auto，也支持满足约束的 宽x高；本软件优先使用长宽比 + 清晰度映射，避免用户手动输入错误尺寸
```

V0.13 后台不得再把假的 `resolution` 参数传给 OpenAI adapter。OpenAI adapter 只接收最终换算后的官方参数 `size`。

### 固定参数

`model` 固定为：

```text
gpt-image-2
```

设置页中显示但置灰，右侧标注：

```text
固定参数
```

保存 Provider 配置时仍保存 `model = gpt-image-2`，便于生成记录回看。

### 可编辑参数

`quality` 做成下拉选择。

可选项：

```text
low
medium
high
auto
```

默认值：

```text
high
```

`output_format` 做成下拉选择。

可选项：

```text
png
jpeg
webp
```

默认值：

```text
png
```

`output_compression` 做成数字输入或滑块。

范围：

```text
0-100
```

规则：

- 当 `output_format = png` 时，`output_compression` 置灰。
- 当 `output_format = png` 时，在控件旁提示 `仅 jpeg / webp 有效`。
- 当 `output_format = jpeg` 或 `webp` 时，允许设置。

`background` 做成下拉选择。

可选项：

```text
auto
opaque
```

默认值：

```text
auto
```

说明：

```text
gpt-image-2 当前不使用 transparent，因此不在可选项中显示。
```

`moderation` 做成下拉选择。

可选项：

```text
auto
low
```

默认值：

```text
low
```

`user` 显示为可选文本框。

默认值：

```text
空
```

说明：

```text
可选终端用户标识，用于接口侧滥用监控；本机个人使用可以留空。
```

默认值：

```text
false
```

右侧标注：

```text

```

说明：

默认值：


可选项显示：

```text
2
```


## OpenAI 代码示例

当 `接口类型 = openai` 时，设置页下面显示只读代码示例区。

标题：

```text
OpenAI Image API 最简单调用示例
```

代码示例：

```python
from openai import OpenAI
import base64

client = OpenAI(
    base_url=base_url,
    api_key=api_key,
)

prompt = operation_prompt

result = client.images.generate(
    model="gpt-image-2",
    prompt=prompt,
    size=resolved_size,
    quality="high",
    output_format="png",
    # output_compression only works for jpeg/webp
    # output_compression=80,
    background="auto",
    moderation="low",
    n=n,
    stream=False,
    partial_images=0,
    user="",
)

image_base64 = result.data[0].b64_json
image_bytes = base64.b64decode(image_base64)

with open("output.png", "wb") as f:
    f.write(image_bytes)
```

代码示例中的以下变量不要写死：

```text
base_url
api_key
operation_prompt
resolved_size
n
```

代码示例下面增加说明：

```text
prompt 来自操作区
resolved_size 由操作区的长宽比 + 清晰度换算
n 来自操作区生成数量
quality / output_format / background / moderation 来自 Provider 设置
output_compression 只在 jpeg / webp 时生效
stream / partial_images 当前暂不启用
```

## 后台生成参数

前端操作区生成请求不再向后端表达假的 API 参数 `resolution`。

V0.13 操作区提交：

```js
options: {
  ratio: state.operation.generation_aspect_ratio,
  resolution_level: state.operation.generation_clarity,
  size: state.operation.generation_size,
  n: state.operation.generation_count,
}
```

说明：

- `ratio` 是长宽比，例如 `16:9`。
- `resolution_level` 是清晰度，例如 `1K`、`2K`、`4K`、`custom`。
- `size` 只用于兼容 V0.12 的自定义尺寸和前端状态，不传给 OpenAI 前直接信任。
- `n` 是生成数量。

后端规范化流程：

```text
接收 ratio
接收 resolution_level
接收 n
如果 resolution_level 是 1K / 2K / 4K，使用 SIZE_MAP[ratio][resolution_level] 换算 resolved_size
如果 resolution_level 是 custom，沿用 V0.12 自定义尺寸校验逻辑，得到 resolved_size
调用 OpenAI Image API 时只传官方参数 size=resolved_size
调用 OpenAI Image API 时不传 resolution
```

`n` 的后端规范化继续要求大于等于 1。

OpenAI adapter 请求参数：

```python
{
    "model": "gpt-image-2",
    "prompt": prompt,
    "size": resolved_size,
    "quality": provider_config["quality"],
    "output_format": provider_config["output_format"],
    "background": provider_config["background"],
    "moderation": provider_config["moderation"],
    "n": n,
    "stream": False,
    "partial_images": 0,
}
```

当 `output_format` 是 `jpeg` 或 `webp` 时，追加：

```python
"output_compression": provider_config["output_compression"]
```

当 `user` 非空时，追加：

```python
"user": provider_config["user"]
```

当 `output_format = png` 时，不传 `output_compression`。

## 输出文件格式

OpenAI adapter 保存输出图片时，文件后缀应匹配 `output_format`：

```text
png  -> .png
jpeg -> .jpeg
webp -> .webp
```

这只影响本地输出文件路径和文件格式，不允许改变“生图管理”页面布局。

## 自动生成实例记录

保存区 UI 不显示新增生成参数。

数据库需要保存自动生成实例的生成参数，方便以后回看：

```text
provider_key
adapter
model
ratio
resolution_level
resolved_size
quality
output_format
background
moderation
n
```

推荐新增 JSON 字段，而不是新增多个独立列：

```sql
ALTER TABLE instances ADD COLUMN generation_params_json TEXT NOT NULL DEFAULT '{}';
```

原因：

- 后续 `google` 和 `other` 的参数不一定和 OpenAI 一样。
- JSON 字段更容易扩展。
- 不影响现有实例列表查询、排序、筛选。

创建自动生成实例时写入：

```json
{
  "provider_key": "aiapis_gpt_image_2",
  "adapter": "openai",
  "model": "gpt-image-2",
  "ratio": "16:9",
  "resolution_level": "4K",
  "resolved_size": "3840x2160",
  "quality": "high",
  "output_format": "png",
  "background": "auto",
  "moderation": "low",
  "n": 1
}
```

`generation_size` 继续保存 `resolved_size`，用于兼容现有尺寸显示逻辑。

手动新增实例：

- `generation_params_json` 保存 `{}`。
- 不显示生成参数。

编辑保存区实例时：

- 如果前端没有提交 `generation_params_json`，后端不要清空已有生成参数。
- 普通编辑只修改提示词、图片、标签、Provider 等现有字段。

## 多图生成实例

当 `n > 1` 且 provider 返回多张图时，沿用 V0.11 / V0.12 规则：

- 每张输出图保存成一个独立实例。
- 每个实例仍只有 1 张输出图。
- 每个实例复制同一份 `generation_params_json`。
- 操作区只显示最后一张输出图。

## 副作用与约束

设置页会明显变长，必须通过分组显示，避免字段拥挤。

`openai`、`google`、`other` 中，只有 `openai` 先能真正生成。`google` 和 `other` 必须明确提示未实现，避免用户误以为可以使用。

旧 `aiapis_gpt_image_2` adapter 必须兼容迁移，不能导致已有 Provider 丢失。

保存更多生成参数会新增数据库字段。使用 JSON 字段可以降低后续扩展成本。

`stream` 和 `partial_images` 暂不启用。不要在 V0.13 中处理流式中间图保存和显示。

`output_compression` 只对 `jpeg / webp` 有效。`png` 时必须禁用，避免误解。

未来接入 `google` adapter 时，参数不一定和 OpenAI 相同。设置页必须按接口类型动态显示不同参数区域。

V0.13 不修改“生图管理”页面布局。新增配置、参数说明、代码示例全部放在设置页；保存区不显示新增生成参数。
