# V0.53 历史记录页布局与 Provider 排序收口

## 目标

当前 V0.52 已完成历史记录页和生图管理页筛选布局重排、历史编号优化、历史错误浮窗滚动、保存区筛选增强。本版 V0.53 不新增业务功能，重点修复 V0.52 后实际使用中发现的历史记录页显示问题和 Provider 下拉排序不一致问题。

本版原则：

- 不新增数据库 schema。
- 不改变生成、保存、历史记录写入流程。
- 不改变 V0.52 已确定的筛选能力和编号规则。
- 只修复布局、显示和排序一致性问题。
- 不删除电脑上的图片文件。
- 文档确认后再执行实现；本文档落成不等于直接开始改代码。

## 修改项

### 1. 修复历史错误浮窗滚动条右侧空白

当前问题：

- 历史记录页中，错误信息浮窗已经能在内容超出窗口高度时出现滚动条。
- 但是滚动条出现后，显示区域右边出现很多空白，浪费横向空间。

调整方案：

- 保留 V0.52 的浮窗最大高度和内部滚动能力。
- 检查历史浮窗相关样式：
  - `.history-popover`
  - `.history-popover-content`
  - 错误信息浮窗内容容器
- 确保文本区域使用完整浮窗宽度。
- 避免因为以下原因产生大块右侧空白：
  - 过大的右侧 `padding`
  - 固定宽度或错误的 `max-width`
  - `scrollbar-gutter: stable` 造成长期预留过宽空间
  - 滚动容器和内容容器嵌套后宽度计算不一致
  - `white-space` / `overflow-wrap` 设置导致文本提前换行
- 如果需要预留滚动条空间，只保留浏览器滚动条实际需要的宽度，不额外留一列空白。

验收标准：

- 长错误信息浮窗仍然不会超出浏览器窗口。
- 内容过长时浮窗内部有纵向滚动条。
- 滚动条出现后，右侧不再出现明显大块空白。
- 短错误、长错误、长路径、长 JSON 的浮窗显示都不被改坏。

### 2. 去掉历史记录页左上角标题

当前需求：

- 将历史记录页中的左上角标题“历史记录”去掉，节省空间。

调整方案：

- 历史记录页内容区不再渲染 `<h1>历史记录</h1>`。
- 页面当前位置继续由顶部导航栏中的“历史记录”标签表达。
- 去掉标题后，同步压缩标题所在容器的高度和间距。

验收标准：

- 历史记录页左上角不再显示“历史记录”标题。
- 顶部筛选区整体上移。
- 不影响顶部导航栏。

### 3. 修复历史记录列表上方空白过多

当前问题：

- 历史记录页最上面的记录上面仍然有很多空白。

调整方案：

- 检查历史页顶部结构和 CSS：
  - `.history-panel`
  - `.history-top-row`
  - `.history-toolbar`
  - `.history-list`
  - `.message`
  - 分页区域相关容器
- 无错误、非加载状态下，历史页 message 区域不应占用明显高度。
- 压缩历史筛选区和历史列表之间的 `gap` / `margin`。
- 去掉因为标题、隐藏清理区、隐藏 message、换行容器造成的空白。
- 不通过负 margin 这类脆弱方式硬挤布局。

验收标准：

- 第一条历史记录和筛选区之间没有明显多余空白。
- 加载中、错误提示出现时仍然能正常显示消息。
- 页面不出现横向滚动条。

### 4. 历史记录页分页控件移动到日期行右侧

当前需求：

- 历史记录页中，将“总数”到“尾页”之间的所有按钮，放到“结束日期”同一行，靠右边放。

最终布局：

- 第一行：
  - 提示词搜索
  - 每页数量
  - 刷新
- 第二行：
  - 标签
  - 状态
  - Provider
  - 尺寸
  - 模式
  - 调用方式
  - model
- 第三行：
  - 开始日期
  - 结束日期
  - 右侧：总数 / 首页 / 上一页 / 下一页 / 尾页

调整方案：

- 将现有 `.history-right-tools` 从第一行移动到日期行。
- 日期控件靠左排列。
- 分页控件靠右排列。
- 窄屏时允许自然换行，但不能产生横向滚动条。
- 记录列表和分页/日期行之间的纵向间距继续压缩。

验收标准：

- “总数”到“尾页”在结束日期同一行。
- 分页控件靠右。
- 第一行刷新按钮紧挨每页数量。
- 历史记录列表上方空白减少。
- 首页、上一页、下一页、尾页功能不回退。

### 5. 历史记录页 Provider 下拉排序统一

当前问题：

- 历史记录页 Provider 下拉显示内容已经对了，但排序仍然不对。
- 需要和生图管理页操作区 Provider 下拉排序方式保持一致。

排序规则：

- 所有当前仍存在的 Provider：
  - 使用操作区 Provider 下拉同一个排序函数。
  - 按显示名称 A-Z 排序。
  - 如果没有显示名称，按内部 key 排序。
  - adapter 标记只参与显示，不改变排序主体。
- 历史记录中存在但当前已删除的 Provider：
  - 继续显示，不能丢历史信息。
  - 放在当前 Provider 后面。
  - 按历史显示名或 provider key A-Z 排序。
- 如果历史 Provider key 和当前 Provider key 相同：
  - 只显示一项。
  - 使用当前 Provider 的显示名称。

调整方案：

- 历史页 Provider 下拉不再直接使用后端返回顺序。
- 前端应复用操作区 Provider 排序辅助逻辑，例如 `sortedProviderEntries()` / `providerSortLabel()`。
- 后端可以继续返回历史 Provider 值，前端负责按统一规则合并和排序。

验收标准：

- 历史页 Provider 下拉顺序和操作区 Provider 下拉顺序一致。
- 已删除历史 Provider 不消失。
- 已删除历史 Provider 排在当前 Provider 后面，并按 A-Z 排序。
- 当前选中值不因为排序变化丢失。

### 6. 生图管理页筛选行 Provider 下拉排序统一

当前问题：

- 生图管理页筛选行中的 Provider 下拉菜单排序不对。
- 需要和生图管理页操作区 Provider 下拉排序方式保持一致。

调整方案：

- 保存区 Provider 筛选下拉也复用操作区 Provider 排序辅助逻辑。
- 当前 Provider 按显示名称 A-Z。
- 历史/已删除 Provider 如果作为筛选项出现，放在当前 Provider 后面并按历史显示名/key A-Z。
- 不使用对象原始插入顺序。
- 不使用后端原始返回顺序。

验收标准：

- 操作区 Provider 下拉、保存区 Provider 筛选下拉、历史页 Provider 筛选下拉三者中，当前 Provider 的排序完全一致。
- 已删除历史 Provider 不影响当前 Provider 的排序。
- 保存区 Provider 筛选选择后仍然立即刷新。

## 副作用与处理

- 去掉历史页标题后，页面内不再有大标题；当前位置依赖顶部导航栏表达，这是为了节省空间，符合本版目标。
- 分页控件移动到日期行后，窄屏下可能换行，需要重点检查不会出现横向滚动条。
- Provider 排序统一后，某些下拉选项位置会变化，这是预期显示调整，不改变数据。
- 浮窗滚动区域调整可能影响长文本换行，需要同时检查错误、参数、输出路径浮窗。
- 压缩历史页间距时，不能把错误提示、加载提示压没。
