## 修改目标

V0.36 在保存区增加一种新的显示模式：缩略图视图。

目标：

- 在保存区批量工具栏中，`新增` 按钮右边挨着增加 `缩略图` 按钮。
- 点击 `缩略图` 后，保存区实例区域切换为缩略图网格。
- 缩略图模式下，一个实例只显示一个输出图缩略图。
- 缩略图模式下，省略实例的所有其他信息，包括编号、日期、提示词、输入图、Provider、TAG、编辑、删除、复制提交等。
- 缩略图模式下，按钮文字改为 `列表`，点击后回到普通保存区显示。
- 缩略图模式下，`显示方式` 的单列/双列下拉框置灰。
- 缩略图模式下，批量选择和批量操作先置灰，不做缩略图选中。
- 缩略图模式下，图片仍然支持鼠标悬停临时预览。
- 缩略图模式下，点击图片仍然打开大图弹窗。
- 缩略图模式下，点击 `生成` 后立即新增空白缩略图位，并显示读秒；生成完成后刷新为最终缩略图。

本版重点是新增保存区缩略图视图，不改数据库，不改后端生成逻辑，不改缩略图缓存目录，不改原图路径保存方式。

- 不改变 V0.34 已有缩略图缓存接口。
- 不改变 V0.31 的翻页图片稳定显示逻辑。

- 不改变 V0.35 的提示词清除按钮位置、搜索框 `X` 位置、顶部栏固定置顶、CMD 标题版本号修复。
- 不在缩略图模式下做批量选择。
- 不在缩略图模式下显示编辑、删除、复制提交、移动等实例按钮。

## 缩略图模式入口

### 按钮位置

保存区批量工具栏当前顺序类似：

```text
全选  取消  已选 X  添加标签  删除标签  移动  删除  新增
```

V0.36 调整为：

```text
全选  取消  已选 X  添加标签  删除标签  移动  删除  新增  缩略图
```

缩略图模式开启后，按钮文字改为：

```text
列表
```

也就是：

```text
全选  取消  已选 X  添加标签  删除标签  移动  删除  新增  列表
```

要求：

- `缩略图` 按钮紧挨在 `新增` 右边。
- `缩略图` / `列表` 使用同一个按钮、同一个动作。
- 建议 `data-action="toggle-thumbnail-view"`。
- 按钮在缩略图模式下可以高亮，以便看出当前正在缩略图模式。
- `新增` 按钮仍然保留，仍然是手动新增实例。
- 按钮文字必须简短，不写成 `缩略图显示`。

## UI 状态

### 状态位置

建议在前端状态中增加：

```javascript
state.saveViewMode = "list" | "thumbnail"
```

默认值：

```javascript
"list"
```

也可以命名为：

```javascript
state.ui.save_view_mode
```

但要和当前模块结构一致，不要为了这个功能重构状态系统。

### 是否持久化

建议持久化到现有 UI 状态持久化中。

规则：

- 用户切到缩略图模式后，刷新页面仍保持缩略图模式。
- 用户切回列表模式后，刷新页面仍保持列表模式。
- 只保存显示模式，不保存任何缩略图 DOM 状态。

相关文件：

```text
frontend/js/state.js
frontend/js/persistence.js
```

### 与单列/双列的关系

缩略图模式下：

- `显示方式` 下拉框置灰。
- 单列/双列的当前值保留。
- 缩略图网格不使用单列/双列布局。
- 退出缩略图模式后，恢复原来单列/双列显示。

要求：

- 不要在进入缩略图模式时修改 `state.settings.save_layout`。
- 不要调用保存默认布局接口。
- 不要把缩略图模式写入 Provider 设置。

## 保存区渲染

### 普通模式

普通模式继续使用当前逻辑：

- `renderSaveArea`
- `renderBatchToolbar`
- `renderInstanceCard`
- `saveLayoutClass`
- `pending-section`
- `save-list is-single/is-double`

普通模式显示和交互不应因为 V0.36 改动发生变化。

### 缩略图模式

缩略图模式新增专门的渲染分支。

建议新增函数：

```javascript
function renderThumbnailSaveGrid(processInstances, formalInstances) {}
function renderInstanceThumbnailTile(instance) {}
```

渲染结构建议：

```html
<div class="save-thumbnail-grid">
  <button class="save-thumbnail-tile" data-action="open-lightbox" data-path="...">
    <img ...>
  </button>
</div>
```

或继续复用现有图片槽能力，但外层必须是缩略图专用结构，避免把普通实例卡片里的其他列带出来。

显示规则：

- 每个正式实例渲染一个缩略图 tile。
- 每个生成中实例渲染一个生成中 tile。
- tile 只展示输出图。
- 没有输出图的正式实例显示空白 tile，文字为 `无输出`。
- 生成中实例显示空白 tile，文字为当前读秒，例如 `3.2s`。
- 生成失败实例如果没有输出图，显示 `失败`。
- 不显示输入图。
- 不显示提示词。
- 不显示编号和日期。
- 不显示 Provider、TAG、尺寸、分辨率、路径。
- 不显示编辑、删除、移动、复制提交、重新提交。

### 生成中缩略图

生成中缩略图必须复用现有 pending 合并逻辑。

要求：

- 点击 `生成` 后，缩略图网格最前面立即出现一个空白缩略图位。
- 空白缩略图位显示读秒。
- 读秒精确到 0.1s。
- 读秒只作为前端显示，不写入数据库。
- 生成完成后，用最终实例刷新替换生成中缩略图位。
- 生成完成后不能同时保留生成中 tile 和正式 tile。
- 生成失败后，保留失败实例，tile 显示 `失败`。
- 生成中 tile 不参与批量选择。

这部分必须继续遵守 V0.28、V0.29、V0.30 关于生成中实例唯一性的规则。

## 缩略图图片来源

### 列表 tile 图片

缩略图 tile 中的小图优先使用 V0.34 已有缩略图缓存接口：

```text
/api/thumbnail?path=...
```

不要直接用原图作为小图地址，避免大量图片时加载过慢。

要求：

- tile 小图使用缩略图缓存。
- 图片弹窗打开大图时仍然使用原图接口：

```text
/api/image?path=...
```

- 原图路径失效时，tile 不能伪装成正常原图存在。
- 如果缩略图接口失败，tile 显示缺失状态。
- 不复制原图。

### 懒加载

缩略图模式必须继续使用懒加载。

要求：

- 当前页可见 tile 优先加载。
- 页面外 tile 不提前加载太多。
- 翻页后主动触发一次图片显示检查，沿用 V0.31 的图片稳定逻辑。
- 不能为了缩略图模式取消懒加载。

相关文件：

```text
frontend/js/image-loader.js
frontend/js/lightbox.js
frontend/js/render-save.js
frontend/js/render-instance.js
```

## 悬停预览与点击大图

缩略图模式下，图片交互规则和普通图片保持一致：

- 鼠标悬停在有输出图的缩略图上，自动弹出临时大图预览。
- 鼠标移开后，临时预览立刻消失。
- 点击有输出图的缩略图，打开大图弹窗。
- 大图弹窗继续支持左右切换、键盘左右方向键切换、关闭等既有能力。
- 空白 tile、生成中 tile、失败且无输出图 tile 不打开大图。

大图切换范围：

- 缩略图模式下，点击某个缩略图打开大图后，左右切换范围是当前缩略图网格中有输出图的实例。
- 不混入输入图。
- 不混入操作区图片。
- 不混入普通列表模式下隐藏的其他图片。

## 批量操作规则

缩略图模式下，批量选择和批量操作先置灰。

置灰范围：

- `全选`
- `取消`
- `添加标签`
- `删除标签`
- `移动`
- `删除`

不置灰：

- `新增`
- `缩略图` / `列表`
- 撤销
- 重做
- 总数
- 首页
- 上一页
- 下一页
- 尾页

要求：

- 进入缩略图模式时，清空当前页批量选择。
- 缩略图模式下不能通过点击 tile 选中实例。
- 缩略图模式下不能显示选择框。
- 退出缩略图模式后，批量操作恢复普通规则。

原因：

- 缩略图模式只做快速浏览。
- 批量选择如果也进入缩略图模式，会需要边框高亮、键盘焦点、误触处理等额外规则，V0.36 先不做。

## 筛选、排序、分页、节点

缩略图模式继续使用当前保存区查询结果。

也就是说：

- 搜索提示词仍然生效。
- 标签筛选仍然生效。
- 来源筛选仍然生效。
- 方式筛选仍然生效。
- 排序仍然生效。
- 节点筛选仍然生效。
- 分页仍然生效。
- 每页数量仍然生效。

重要解释：

缩略图模式下的“保存区所有实例改成缩略图显示”，指的是当前保存区查询结果中的实例都用缩略图形式显示，而不是一次性加载数据库里的全部实例。

原因：

- V0.27 已经要求大量实例下不能一次性把所有数据塞到前端。
- 如果缩略图模式一次加载全部实例，会造成图片请求暴增。
- 如果用户每页数量设为 200，当前页最多显示 200 个缩略图，这已经足够快速浏览。

## 与生成逻辑的关系

### 操作区点击生成

普通模式下行为不变。

缩略图模式下：

- 点击 `生成` 后，立即在缩略图网格最前面新增空白缩略图位。
- 空白缩略图位显示读秒。
- 后端生成逻辑不变。
- 生成完成后刷新当前保存区数据。
- 如果当前排序是最新优先，最终实例应自然出现在前面。
- 如果当前排序不是最新优先，最终实例位置按现有排序规则决定。

### 复制提交 / 重新提交

缩略图模式下不显示保存区实例按钮，因此不能直接从缩略图 tile 发起复制提交或重新提交。

普通模式下：

- `复制提交` 继续新增实例。
- 失败实例的 `重新提交` 继续重跑当前实例，不新增实例。
- 生成中的 pending 逻辑继续生效。

### 新增实例

缩略图模式下 `新增` 按钮保留。

点击 `新增` 后建议行为：

- 仍然调用当前手动新增实例逻辑。
- 新增完成后可以保持缩略图模式。
- 因为手动新增实例通常没有输出图，所以缩略图网格中显示一个 `无输出` tile。

如果用户需要编辑新实例，应切回 `列表` 模式后编辑。

## 可能副作用与处理

### 缩略图请求量增加

影响：

- 一页显示大量实例时，会请求更多缩略图。

处理：

- 继续使用 V0.34 缩略图缓存。
- 继续使用懒加载。
- 不一次性加载全部数据库实例。
- 翻页后只处理当前页。

### 批量操作在缩略图模式下不可用

影响：

- 用户不能在缩略图模式下直接批量添加标签、移动或删除。

处理：

- 批量按钮置灰。
- 用户切回 `列表` 模式后执行批量管理。
- 后续如确实需要，可以单独做缩略图选择模式。

### 单列/双列和缩略图模式冲突

影响：

- 如果不置灰，用户可能以为单列/双列会影响缩略图布局。

处理：

- 缩略图模式下置灰 `显示方式`。
- 保留单列/双列原值。
- 退出缩略图模式后恢复。

### 生成中实例可能重复显示

影响：

- 如果缩略图渲染没有复用 pending 合并逻辑，可能重新出现生成中 tile 和正式实例重复显示。

处理：

- 缩略图模式必须使用和普通模式相同的 `mergePendingWithInstances`。
- 正式实例中的 running 状态必须并入 process 区/缩略图 pending 区，不重复进正式列表。

### 图片弹窗切换范围可能混乱

影响：

- 缩略图模式只显示输出图，如果沿用普通实例图片集合，可能混入输入图。

处理：

- 缩略图 tile 打开大图时，传入当前缩略图网格的输出图列表。
- 左右切换只在当前缩略图网格有输出图的 tile 之间切换。

### 手动新增实例在缩略图模式下不可编辑

影响：

- 缩略图模式点击 `新增` 后只能看到 `无输出` tile，不能直接编辑提示词。

处理：

- 保留 `新增` 行为。
- 用户需要编辑时点击 `列表` 回到普通模式。
- 不在 V0.36 为缩略图 tile 增加编辑入口。

## 代码修改建议

### 前端状态与持久化

```text
frontend/js/state.js
frontend/js/persistence.js
```

增加保存区视图模式：

- 默认 `list`。
- 支持持久化和恢复。
- 恢复时只接受 `list` / `thumbnail`，非法值回退 `list`。

## 测试要求

### 静态测试

新增或更新前端静态测试，确认：

- 版本号全部为 V0.36。
- CMD 标题为 `AI Image Manager V0.36`。
- `renderBatchToolbar` 包含 `data-action="toggle-thumbnail-view"`。
- `缩略图` 按钮在 `新增` 右边。
- 缩略图模式下按钮文字可变为 `列表`。
- 缩略图模式下批量按钮 disabled。
- 缩略图模式下 `save_layout` 下拉框 disabled。
- 存在 `saveViewMode` 或等价状态。
- UI 状态持久化包含保存区视图模式。
- 存在 `save-thumbnail-grid`、`save-thumbnail-tile` 等样式。
- 缩略图 tile 使用 `/api/thumbnail` 或 `thumbnailUrl(path)`。
- 缩略图点击大图使用原图路径，不直接使用缩略图作为大图。
