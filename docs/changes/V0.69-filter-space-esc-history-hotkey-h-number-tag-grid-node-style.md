# V0.69 筛选空列、编辑 ESC、历史翻页与 H 编号、TAG 密度和节点样式收口

## 目标

当前 V0.68 已完成数量框收口、筛选清除按钮外移、历史编号类型筛选和设置页 model 脏状态修复。本版 V0.69 目标是在 V0.68 基础上继续修正几个交互和布局细节：

- 修复生图管理页状态 / 标签筛选下拉和已选内容区域右侧仍残留一列不可用空白的问题。
- 保存区实例进入编辑状态时，按 `Esc` 退出编辑状态且不保存修改。
- 历史记录页支持键盘左右方向键翻页。
- 历史记录页 `H` 编号和 `#` 编号一样，从 `H0001` 开始按稳定顺序从小到大显示，并兼容旧记录。
- 历史记录页每页数量框尺寸不变，位置移动到日期框旁边。
- 标签管理页每行 TAG 卡片数量从 4 个改为 8 个。
- 生图管理页节点下拉菜单中，可拖动节点与普通节点样式区分更明显。

本版原则：

- 不新增数据库 schema。
- 不改变 V0.67 固定实例编号 `#0001` 规则。
- 不改变 V0.68 编号类型筛选 `# / H` 语义。
- 不使用输出图路径匹配历史记录编号。
- 不破坏保存区普通列表模式、缩略图模式、节点管理、批量管理、撤销 / 重做、Provider 能力体系。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 筛选区右侧空列

### 1. 状态 / 标签筛选去掉旧预留槽位

当前问题：

- V0.68 已经将状态筛选和标签筛选的清除 `x` 从下拉菜单内部移到标题旁边。
- 但是状态或标签筛选的已选内容区域右侧仍然留出一整列空白。
- 当已选内容快碰到右边时，会提前换行，右侧空间无法被使用。

根因判断：

- 当前筛选控件仍保留旧布局中给内部清除按钮或内部操作区预留的右侧空间。
- 典型表现是筛选按钮 / chip 容器仍有较大的 `padding-right` 或固定右侧槽位。
- 因为 `x` 已经外移，这段预留空间应同步取消。

调整方案：

- 状态筛选和标签筛选的主显示区域取消旧的右侧预留槽位。
- 已选 chip 应可以使用筛选框完整宽度。
- 下拉菜单内部选项的勾选标记可以保留，但只能占用紧凑空间。
- 下拉菜单内部不能因为勾选标记保留一整列不可用空白。
- 标题旁边的小号 `x` 继续保留，不移回下拉菜单内部。

验收标准：

- 状态筛选已选内容接近右边界时，不再提前留一整列空白换行。
- 标签筛选已选内容接近右边界时，不再提前留一整列空白换行。
- 状态筛选和标签筛选标题旁边的小 `x` 仍能清空筛选。
- 点击小 `x` 不误触发下拉菜单。
- 点击筛选主区域仍能正常打开下拉菜单。
- 多选、清空、搜索标签、分页回到第一页等既有逻辑不回退。

副作用：

- 已选 chip 可用宽度变大后，窄窗口下换行行为会改变。
- 需要确认标题旁边小 `x` 与主下拉按钮的点击区域不重叠。

## 保存区编辑 ESC

### 2. 编辑态按 ESC 退出且不保存

当前需求：

- 生图管理页保存区中，某个实例进入编辑状态时，按下键盘 `Esc`。
- 作用是退出编辑状态，不保存当前未提交修改。

调整方案：

- 全局 `keydown` 中增加保存区实例编辑态 `Esc` 处理。
- 当存在正在编辑的保存区实例时：
  - `Esc` 退出编辑态。
  - 丢弃当前 DOM / 草稿中的未保存修改。
  - 恢复该实例保存前的数据展示。
- 该行为优先级应高于“取消全部选择”，避免编辑实例同时选中实例时 `Esc` 先清空选择。
- 该行为低于更高优先级弹层：
  - 图片弹窗。
  - 节点菜单 / 节点右键菜单。
  - 历史记录固定浮窗。
  - 标签管理合并弹窗。
  - 其他正在打开的模态弹窗。

验收标准：

- 实例进入编辑态，修改提示词后按 `Esc`，退出编辑且提示词不保存。
- 修改 Provider 后按 `Esc`，退出编辑且 Provider 不保存。
- 修改标签、路径、数量、输入图等内容后按 `Esc`，退出编辑且不保存。
- 按 `Esc` 退出编辑不写入撤销栈。
- 按 `Esc` 退出编辑不触发后端保存请求。
- 图片弹窗打开时 `Esc` 仍优先关闭图片弹窗。
- 历史记录固定浮窗打开时 `Esc` 仍优先关闭浮窗。
- 节点菜单打开时 `Esc` 仍优先关闭节点菜单。

副作用：

- `Esc` 处理优先级会变复杂，需要避免和已有“取消选择”“关闭浮窗”冲突。
- 用户未保存内容会被丢弃，这是本需求的明确语义。

## 历史记录键盘翻页

### 3. 历史记录页左右方向键翻页

当前需求：

- 历史记录页中，点击键盘左 / 右方向键，作用等同于上一页 / 下一页。

调整方案：

- 在历史记录页新增键盘翻页处理：
  - `ArrowLeft`：上一页。
  - `ArrowRight`：下一页。
- 只在历史记录页生效。
- 只在没有修饰键时生效。
- 到第一页继续按左键不报错、不跳转。
- 到最后一页继续按右键不报错、不跳转。
- 以下场景不触发历史翻页：
  - 焦点在输入框、文本框、选择框、日期框中。
  - 历史记录浮窗固定打开。
  - 图片弹窗打开。
  - 任意模态弹窗打开。
  - 正在输入中文等组合输入状态。

验收标准：

- 历史记录页空白区域按左键，等同点击“上一页”。
- 历史记录页空白区域按右键，等同点击“下一页”。
- 搜索框内移动光标时不触发翻页。
- 日期框内操作时不触发翻页。
- 下拉框聚焦时不触发翻页。
- 浮窗或弹窗打开时不触发翻页。
- 生图管理页保存区左右方向键翻页不回退。

副作用：

- 历史页新增全局键盘交互，需要严格避开表单输入场景。
- 需要避免和图片弹窗左右切图冲突。

## 历史 H 编号

### 4. H 编号从 H0001 开始稳定递增

当前问题：

- 历史记录页中，能关联实例的记录显示 `#0001` 这类实例固定编号。
- 不能关联实例的记录显示 `H0001` 这类历史本地编号。
- 当前 `H` 编号可能来自当前页或当前筛选结果中的临时 `display_index`。
- 这会导致旧记录在翻页、筛选、每页数量变化后，`H` 编号不够稳定。

最终规则：

- `#` 编号：
  - 继续使用保存区实例固定编号。
  - 不随历史页排序、筛选、分页变化。
- `H` 编号：
  - 只用于无法关联保存区实例的历史记录。
  - 从 `H0001` 开始。
  - 按稳定的历史记录基准顺序从小到大分配。
  - 旧历史记录也按同一规则显示。
- 建议稳定顺序：
  - 按历史记录创建时间 / 提交时间从早到晚。
  - 同时间按历史记录 `id` 从小到大。
- 不将 `H` 编号写入数据库，优先在后端查询 / 序列化时稳定计算，避免新增 schema。

调整方案：

- 后端在返回历史记录时，为无法关联实例的记录计算稳定 `history_number`。
- 显示时格式化为 `H0001`、`H0002`、`H0003`。
- 计算范围应是全部无法关联实例的历史记录，而不是当前页记录。
- 筛选、分页、每页数量变化不应导致同一条历史记录的 `H` 编号变化。
- `H` 编号类型筛选继续沿用 V0.68 语义：
  - `#`：能关联实例编号。
  - `H`：不能关联实例编号。

验收标准：

- 第一条无法关联实例的历史记录显示 `H0001`。
- 第二条无法关联实例的历史记录显示 `H0002`。
- 翻页后，同一条无法关联实例历史记录的 `H` 编号不改变。
- 改变每页数量后，同一条无法关联实例历史记录的 `H` 编号不改变。
- 使用状态 / Provider / 尺寸 / 模式 / 调用方式 / model / 标签 / 日期筛选后，同一条无法关联实例历史记录的 `H` 编号不改变。
- 选择编号筛选 `H` 后，只显示 H 编号记录，且 H 编号仍是全局稳定编号。
- 选择编号筛选 `#` 后，只显示能关联保存区实例编号的记录。
- 不修改历史记录参数快照。
- 不使用输出图路径匹配编号。

副作用：

- 后端历史查询需要额外计算 H 编号。
- 如果历史记录很多，需要注意计算方式的性能。
- 不新增 schema 的方案更安全，但实现时要避免分页后前端临时编号。

## 历史记录页布局

### 5. 每页数量框移动到日期框旁边

当前需求：

- 历史记录页中，每页数量框尺寸不变。
- 位置改到和日期框挨着。

调整方案：

- 历史记录页日期行调整为：
  - 开始日期。
  - 结束日期。
  - 每页数量。
  - 右侧分页 / 总数工具区。
- 每页数量框尺寸沿用当前样式，不扩大、不缩小。
- 总数、上一页、下一页、首页、尾页等分页控件继续靠右。
- 减少日期框与分页区之间的空白。

验收标准：

- 每页数量框紧挨结束日期框右侧。
- 每页数量框尺寸和 V0.68 一致。
- 开始日期完整显示。
- 结束日期完整显示。
- 分页按钮仍在右侧且可点击。
- 历史记录第一条与工具栏之间不新增额外纵向空隙。
- 窄窗口下不重叠、不溢出。

副作用：

- 历史工具栏同一行内容更多，需要检查窄窗口换行。
- 每页数量靠近日期框后，视觉分组会变化。

## 标签管理页密度

### 6. TAG 卡片每行从 4 个改为 8 个

当前需求：

- 标签管理页中，每行 TAG 数量由 4 个改为 8 个。

调整方案：

- 标签管理页 TAG 卡片网格从 `repeat(4, minmax(0, 1fr))` 改为 `repeat(8, minmax(0, 1fr))`。
- 不改变 TAG 管理只显示正在使用 TAG 的规则。
- 不新增 TAG。
- 不管理未使用 TAG。
- 右键菜单重命名、合并继续保留。
- 长 TAG 名称使用省略显示，并通过 `title` 或既有悬停能力查看完整名称。

验收标准：

- 桌面宽度下标签管理页每行显示 8 个 TAG 卡片。
- 搜索后仍按每行 8 个排列。
- 长 TAG 不撑破卡片。
- TAG 数量文字不溢出。
- 右键菜单仍能正常打开。
- 重命名和合并功能不回退。

副作用：

- 每张 TAG 卡片更窄，长 TAG 更容易被截断。
- 需要检查不同窗口宽度下是否过度拥挤。

## 节点下拉可拖动样式

### 7. 可拖动节点与其他节点样式区分

当前需求：

- 生图管理页节点区的节点下拉菜单中，可以拖动的节点样式和其他节点样式有所区分。

当前问题：

- 节点下拉菜单中已有拖动能力。
- 但可拖动节点和普通节点视觉差异不够明显。
- 用户不容易判断哪些节点可以拖动调整顺序。

调整方案：

- 对可拖动节点增加独立样式，例如：
  - 更明显的拖动光标。
  - 轻微背景色。
  - 左侧拖动提示线或小把手。
  - hover 时显示更明确的拖动反馈。
- 不可拖动节点保持普通样式。
- “新建节点”等特殊项不显示可拖动样式。
- 拖动中和可放置目标样式继续保留，并与“可拖动”默认样式区分。

验收标准：

- 自定义可拖动节点在下拉菜单中一眼能看出可以拖动。
- 不可拖动节点不显示拖动样式。
- 新建节点项不显示拖动样式。
- 拖动中的节点仍有拖动中样式。
- 放置目标仍有放置目标样式。
- 右键节点菜单不受影响。
- 点击下拉框以外关闭节点菜单的逻辑不回退。

副作用：

- 节点菜单视觉层级会更明显，需要避免过度花哨。
- 需要确认 hover、选中、拖动中、放置目标几种状态不互相覆盖。
