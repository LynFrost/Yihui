# V0.46 生成链路完整回归与稳定性收口

## 目标

V0.46 不新增大功能，重点对 V0.42 到 V0.45.2 期间新增和调整过的生成链路能力做完整回归验收，并只修复验收中发现的问题。

本版重点确认：

- Provider 新建、引用、历史记录和实例引用稳定。
- OpenAI 文生图、图生图共享脚本与软件默认生成逻辑一致。
- 文生图 `n > 1`、图生图多输入图、连续生成、重试、取消、历史记录都稳定。
- 保存区普通列表模式和缩略图模式下，生成中实例、批量选择、Shift 连选、批量操作不回退。
- V0.37 数据安全、V0.38 标签管理、V0.40 带入操作区不被生成链路修改破坏。

V0.46 的通过标准不是保证外部 AIAPIS 服务永远不返回 502、timeout 或断开连接，而是保证软件在这些外部波动出现时行为正确、可控、可取消、可追踪。

## 回归测试策略

### 1. 数据隔离

默认使用复制数据库或临时数据库进行回归测试。

以下操作不能直接在真实共享数据库上做破坏性验证：

- 批量删除实例
- 清理历史记录
- 恢复导入
- 标签合并或重命名压力测试
- 节点移动和批量移动压力测试

如果需要验证真实数据库兼容性，只做只读检查或先自动备份，再在明确允许的范围内验证。

### 2. 外部服务与 Mock 服务边界

真实 AIAPIS 服务可用于最终 smoke test，但不能只依赖真实服务判断软件逻辑是否正确。

以下情况优先使用 mock OpenAI 服务稳定复现：

- 502 / 503 / 504
- 429
- ConnectTimeout / ReadTimeout
- 连接断开
- 第 1 次失败、第 2 次成功
- 连续 4 次失败
- 取消后后续请求不再发起
- 返回结果后取消，不回写成功

真实 API key 不写入代码、文档、默认配置或测试文件。

## 回归范围

### 1. Provider 自动编号

检查内容：

- 新建 Provider 时自动生成内部编号。
- 内部编号从新建开始不可编辑。
- 已有 Provider 的内部编号不变化。
- 已有实例、历史记录、默认 Provider 引用不被改乱。
- 删除 Provider 后再新建，编号仍能生成唯一值。

发现问题时只修复编号生成和引用兼容，不重构 Provider 系统。

### 2. OpenAI 脚本与默认生成逻辑一致性

检查内容：

- `files/openai_text_to_image.py` 与软件文生图默认生成逻辑一致。
- `files/openai_image_to_image.py` 与软件图生图默认生成逻辑一致。
- 设置页调用示例与实际生成逻辑一致。
- `base_url`、`api_key`、`user_agent`、`quality`、`output_format`、`output_compression`、`background`、`moderation`、`user` 等设置页参数都通过注入传入。
- `operation_prompt`、`resolved_size`、`n`、输入图路径、输出路径等操作区参数都通过注入传入。
- 输出为 URL 或 base64 时都能保存到指定路径。

验收重点：

- 文生图单张可成功保存。
- 文生图 `n > 1` 时，多张图都保存成功。
- 图生图单输入图可成功保存。
- 图生图多输入图按操作区上传顺序传入，不静默丢图。

### 3. 文生图 n > 1

检查内容：

- `n > 1` 时生成多张输出图。
- 每张输出图都有对应保存区实例或明确的实例关联规则。
- 历史记录记录本次请求参数和输出路径。
- 失败重试时不会重复创建无法对应的实例。
- 取消时不会留下错误的成功实例。

### 4. 图生图多输入图

检查内容：

- 操作区依次上传的输入图按顺序传入脚本和后端生成逻辑。
- 多输入图不会只传第一张。
- 多输入图不会因为保存区实例编辑、带入操作区、复制提交而丢失顺序。
- 历史记录参数快照保留输入图路径数组。

### 5. 同 Provider 请求串行与并行提交

检查内容：

- 前端允许连续点击生成，形成多个生成中实例。
- 同一个 Provider 的真实外部请求按 V0.45.1 规则串行执行。
- 不同 Provider 的任务不被同一个锁无意义阻塞。
- 新生成中实例显示在旧生成中实例上方。
- 普通列表模式和缩略图模式下生成中排序一致。
- 生成成功后只更新保存区实例和历史记录，不回填操作区输出图。

### 6. 重试规则

检查内容：

- 可重试错误最多尝试 4 次。
- 不出现无限重试。
- 前 3 次可重试失败分别写入历史记录。
- 每条失败重试历史保留：
  - `retry_attempt`
  - `retry_delay_seconds`
  - `retryable`
  - `parent_history_id`
  - 完整失败原因
- 第 4 次仍失败时，任务结束为失败。
- 不可重试错误不进入无意义重试。

可重试错误包括：

- HTTP 429
- HTTP 502
- HTTP 503
- HTTP 504
- ConnectTimeout
- ReadTimeout
- APITimeoutError
- connection reset / disconnected
- Cloudflare `retryable=true`
- bad gateway / origin_bad_gateway / gateway timeout / service unavailable

### 7. 取消生成

检查内容：

- 生成中实例关闭网页后重新打开仍然显示取消按钮。
- 点击取消后，数据库中的 running 实例更新为取消或失败状态。
- 点击取消后不再进入下一轮重试。
- 如果请求已经发出且稍后返回成功，已取消实例不能被回写为成功。
- 取消不会删除电脑上的图片文件。
- 取消后的历史记录能看出取消原因。

### 8. 保存区普通列表模式

检查内容：

- 单列和双列显示对齐。
- 生成中实例读秒正常。
- 翻页后图片稳定显示。
- 节点筛选、标签筛选、来源筛选、方式筛选、搜索、排序、分页、每页数量稳定。
- 键盘左右方向键翻页稳定，输入框内不误触发。
- 批量选择、Shift 连选、全选、添加标签、删除标签、移动、删除稳定。
- 实例带入、复制提交、重新提交、移动、编辑、删除稳定。

### 9. 保存区缩略图模式

检查内容：

- 缩略图模式切换稳定。
- 缩略图模式下生成中实例排序与列表模式一致。
- 缩略图模式批量选择稳定。
- Shift 连选稳定。
- 全选当前页、批量标签、批量移动、批量删除稳定。
- 图片悬停预览、图片弹窗、原图查看不被破坏。
- 清理缩略图缓存功能仍可用。

### 10. 历史记录体验

检查内容：

- 搜索、状态筛选、Provider 筛选、调用方式筛选、日期筛选稳定。
- 失败原因正文最多显示最后 3 行。
- 悬停浮窗和点击固定浮窗显示完整错误。
- “指令 / 参数 / 错误”复制按钮稳定。
- 没有错误时，“错误”按钮置灰不可点。
- 翻页、筛选、刷新、切换页面后，固定浮窗自动关闭。
- 历史记录“带入操作区”稳定，不修改原历史记录和参数快照。

### 11. generation_history.tags_json 兼容

检查内容：

- V0.40 新增的 `generation_history.tags_json` 在备份、导出、恢复中不丢失。
- 旧备份缺少 `tags_json` 时恢复不报错。
- 旧历史记录没有 TAG 快照时仍能正常显示、筛选、带入。
- 新历史记录继续写入 TAG 快照。

### 12. 数据安全页

检查内容：

- 手动备份稳定。
- 自动备份策略不回退。
- 大数据导出稳定。
- 恢复预览显示实例、标签、节点、历史记录数量。
- 恢复前自动备份当前数据库。
- 恢复不删除电脑上的图片文件。
- 恢复后节点、标签、历史记录、Provider 参数快照可用。
- V0.44 重试历史记录可以正常导出和恢复。

### 13. 标签管理中心

检查内容：

- 标签搜索稳定。
- 标签重命名稳定。
- 标签合并稳定。
- 标签统计排除虚拟筛选项“无”和内部值 `__untagged__`。
- 标签管理操作同步影响保存区实例 TAG、批量 TAG、标签筛选下拉。
- 标签操作不影响电脑上的图片文件。

### 14. Provider 不存在时的兼容

检查内容：

- 历史记录或旧实例引用的 Provider 当前不存在时，不导致页面崩溃。
- 带入操作区时给出明确提示，并允许用户选择当前可用 Provider。
- 操作区参数以当前可用 Provider 能力为准。
- 历史记录参数快照可查看，但不能被误改。

### 15. 快捷操作

检查内容：

- Enter 搜索稳定。
- Ctrl+Enter 生成稳定。
- Esc 关闭弹窗稳定。
- 节点新建、重命名弹窗 Enter 确认、Esc 取消稳定。
- 保存区左右方向键翻页稳定。
- 图片弹窗左右方向键切换图片稳定，不触发保存区翻页。

## 允许修复的范围

V0.46 允许修复：

- 生成链路错误处理问题。
- 取消状态不一致问题。
- 重试历史记录缺字段问题。
- 生成中实例排序或状态显示问题。
- 文生图 `n > 1` 输出关联问题。
- 图生图多输入图传参问题。
- 旧数据兼容显示问题。
- 数据安全导出、备份、恢复遗漏 V0.40 / V0.44 新字段的问题。

V0.46 不做：

- 不新增新的 Provider 类型。
- 不新增新的批量操作类型。
- 不重新设计 UI。
- 不重构前端模块结构。
- 不重拆 CSS。
- 不主动改变数据库 schema。
- 不删除电脑上的图片文件。
- 不把真实 API key 写入任何文件。

如果发现必须修改数据库 schema 才能修复 V0.42 至 V0.45.2 的兼容问题，需要在实施前单独说明原因、迁移方式、失败回滚方式和旧数据保护方案。

## 副作用与风险

- 同 Provider 串行会降低同一 Provider 下多任务的实际吞吐，但能减少并发打爆代理服务的概率。
- 最多 4 次重试会增加 API 调用次数和费用。
- 如果服务端已经收到请求但返回 502，再重试可能实际生成多次；软件只保存最终成功返回的结果。
- 真实 AIAPIS 服务波动可能导致 smoke test 偶发失败，这类失败需要结合 mock 测试判断是否为软件逻辑问题。
- 使用真实数据库做恢复、清理、批量删除测试有数据风险，因此本版默认使用复制库或临时库。
- 如果旧历史记录没有 `tags_json`，只能按无 TAG 快照兼容显示，不能凭空恢复当时 TAG。

## 验收标准

V0.46 完成后需要给出回归结果，至少包括：

- 使用复制库或临时库完成的功能回归结论。
- mock 可重试错误验证结论。
- 取消生成验证结论。
- 文生图 `n > 1` 验证结论。
- 图生图多输入图验证结论。
- 保存区列表模式和缩略图模式验证结论。
- 数据安全导出、备份、恢复验证结论。
- 如果进行了真实 AIAPIS smoke test，需要说明成功数量、失败数量、失败原因和输出文件位置。

最终结果应明确列出：

- 已修复的问题。
- 未发现问题的检查项。
- 仍存在但确认属于外部服务波动或非本版范围的问题。
