# V0.64 生图管理页布局细节和实例状态语义收口

## 目标

当前 V0.63 已完成生图管理页对齐和原地提交的第一轮纠偏，但页面级检查仍发现操作区下对齐、左侧状态区、实例状态标识、来源筛选和右侧列对齐仍未完全符合预期。本版 V0.64 目标是不新增大功能，继续对生图管理页做细节收口：

- 操作区分辨率框、数量框、路径框、“新增”按钮下边缘严格对齐。
- 删除操作区左侧“操作区”标题和多余空行。
- 操作区左侧空白区全部用于状态信息，长信息默认显示尾部，悬停显示完整浮窗。
- 保存区 `Ctrl+Enter` 支持失败实例“重提”。
- 保存区实例标识从“手动/生成”改为“准备/失败/生成”。
- 来源筛选同步改为“生成/准备/失败”。
- 没有输出图的实例不能显示“生成”标识。
- 只有生成成功且有输出图的实例不可修改 Provider；准备和失败实例都可修改 Provider。
- 复制保存区实例时必须连同尺寸、比例、分辨率、数量等生成参数一起复制。
- 操作区尺寸控制列、输入图区清除按钮、Provider/标签/选择区域继续按保存区实例列位严格对齐。

本版原则：

- 继续基于 V0.63 的统一主网格做细节修正，不重拆前端模块。
- 状态语义以实例当前结果状态为准，不再只看数据库 `source` 字段。
- 不改变 V0.62/V0.63 的“操作区新增、保存区提交/重提原地生成”主流程。
- 不删除电脑上的图片文件。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 操作区下对齐

### 1. 分辨率、数量、路径和新增按钮下边缘对齐

当前问题：

- V0.63 中操作区已使用 8 列主网格，但分辨率框、数量框、路径框仍依赖不同容器内部的 `padding-top`、行高和堆叠布局近似对齐。
- 页面上能看到分辨率框/数量框和路径框下边缘没有严格对齐。

调整方案：

- 操作区中，分辨率框、数量框、路径框、“新增”按钮的下边缘必须严格对齐。
- 比例框、标签框、“清空”按钮的上边缘继续保持对齐。
- 不再允许用各列单独 `padding-top` 的方式近似对齐。
- 需要使用同一行高、同一底部对齐规则或统一子网格来约束。

验收标准：

- 分辨率框下边缘和路径框下边缘对齐。
- 数量框下边缘和路径框下边缘对齐。
- “新增”按钮下边缘和路径框下边缘对齐。
- 比例框上边缘和标签框上边缘对齐。
- “清空”按钮上边缘和比例框上边缘对齐。
- 窄窗口下不出现按钮文字被挤出或控件互相覆盖。

## 左侧状态信息区

### 2. 删除“操作区”标题和顶部空行

当前问题：

- V0.63 操作区左侧仍显示“操作区”文字。
- 左侧标题占据顶部空间，使操作区最上方多出一行。
- 用户希望提示词框和操作区整体边框之间不要有多余空行。

调整方案：

- 删除操作区左侧“操作区”文字标题。
- 操作区左侧不再为标题预留空行。
- 操作区左侧整块区域用于显示状态信息或操作信息。
- 提示词框与操作区边框之间不再因为左侧标题而产生多余空白。

验收标准：

- 操作区左侧不再显示“操作区”文字。
- 操作区顶部不再多出空行。
- 提示词框和操作区边框之间的上下留白明显减少。
- 删除标题后，操作区整体高度不被无意义撑高。

### 3. 左侧状态信息默认显示尾部，悬停显示完整内容

调整方案：

- 操作区左侧整块空白区都用于显示操作信息或状态提示。
- 如果信息长度超出左侧区域范围，默认不要全部显示。
- 默认显示信息尾部部分，便于看到最新错误、最新重试或最终结论。
- 鼠标悬停时显示完整浮窗。
- 浮窗可以根据内容自动放大，暂时遮挡其他区域可以接受。
- 除非当前页面可视范围放不下完整内容，否则浮窗不要出现滚动条。
- 当前页面范围确实放不下完整内容时，浮窗再出现滚动条。

验收标准：

- 长状态信息不会撑高操作区。
- 默认状态区显示尾部内容。
- 鼠标悬停能看到完整状态信息。
- 浮窗尽量完整展示内容，不轻易出现滚动条。
- 浮窗出现和消失不改变页面布局。

副作用：

- 左侧状态区默认不再从头显示完整文本。
- 长错误信息需要悬停查看完整内容。
- 浮窗可能遮挡页面其他区域，这是本版接受的交互结果。

## 操作区和保存区列位继续收口

### 4. 尺寸控制列对齐保存区输出图列

当前问题：

- 操作区比例框、分辨率框、数量框目前在尺寸控制列中。
- 用户希望这些控件的左右边缘和保存区实例的输出图框左右边缘竖直对齐。

调整方案：

- 操作区比例框、分辨率框、数量框移动到与保存区实例输出图框一致的列位。
- 这些控件的左右边缘与保存区实例输出图框左右边缘对齐。
- 原尺寸控制列腾出的横向空间分给操作区输入图区。
- 操作区输入图区获得更大宽度。
- 操作区和保存区实例的输入图“清除”按钮随输入图区新边界同步右移，并保持对齐。

验收标准：

- 操作区比例框左右边缘与保存区实例输出图框左右边缘对齐。
- 操作区分辨率框和数量框整体左右边缘与保存区实例输出图框左右边缘对齐。
- 操作区输入图区比当前更宽。
- 操作区输入图“清除”按钮和保存区实例输入图“清除”按钮对齐。
- 保存区实例输出图框本身不被挤压变形。

副作用：

- 操作区输入图区、尺寸控制区、输出图列之间的空间分配会变化。
- 必须重点检查单列、双列、窄窗口下是否出现横向滚动或内容挤压。

### 5. Provider/标签/选择区域右边对齐并右移

新增要求：

- 生图管理页操作区中，Provider 框、标签框、路径选择按钮的右边要和保存区实例中状态标识、标签框、提交/重提按钮的右边竖直对齐。
- 这些区域整体都往右挪一点，靠近操作区“清空/新增”按钮或保存区实例“编辑/删除”按钮。

调整方案：

- 操作区 Provider 框、标签框、路径选择按钮所在详情列右边界，与保存区实例状态标识、标签框、提交/重提按钮所在详情列右边界一致。
- 操作区详情列整体向右收口，靠近操作区按钮列。
- 保存区实例详情列也按同一右边界收口，靠近实例编辑/删除按钮列。
- 路径选择按钮不单独飘出对齐边界。
- 提交/重提按钮作为详情区内联按钮，其右边与操作区路径选择按钮右边对齐。

验收标准：

- 操作区 Provider 框右边和保存区实例状态标识右边竖直对齐。
- 操作区标签框右边和保存区实例标签框右边竖直对齐。
- 操作区“选择”按钮右边和保存区实例“提交/重提”按钮右边竖直对齐。
- 上述区域整体更靠近右侧按钮列。
- 不挤压到操作区“清空/新增”按钮。
- 不挤压到保存区实例“编辑/删除”按钮。

副作用：

- 详情列右移后，Provider 名称、标签列表、路径输入框可用宽度可能发生变化。
- 需要检查长 Provider 名称、长路径、多标签时是否仍能正常截断和悬停查看。

## 保存区快捷键提交/重提

### 6. `Ctrl+Enter` 支持失败实例重提

当前问题：

- V0.63 中 `Ctrl+Enter` 批量提交会跳过 `generation_status === "failed"` 的实例。
- 用户希望失败实例也能通过同一个快捷键触发“重提”。

调整方案：

- 保存区选中准备态实例时，`Ctrl+Enter` 触发“提交”。
- 保存区选中失败实例时，`Ctrl+Enter` 触发“重提”。
- 保存区选中多个实例时：
  - 准备态实例执行提交。
  - 失败实例执行重提。
  - 已有输出图的生成成功实例跳过。
  - 生成中或取消中的实例跳过。
  - Provider 缺失或参数不完整的实例跳过并提示。
- 没有选中实例时，`Ctrl+Enter` 仍然无效。

验收标准：

- 选中一个失败实例后，`Ctrl+Enter` 等同点击“重提”。
- 同时选中准备实例和失败实例时，能分别提交和重提。
- 已有输出图实例不会被误提交。
- 生成中实例不会被重复提交。
- 提示信息能显示提交、重提、跳过数量。

副作用：

- 批量重提失败实例会增加并发请求数量。
- 需要继续沿用现有生成中、取消中和服务商稳定性保护规则。

## 实例状态标识和 Provider 可编辑规则

### 7. 标识从“手动/生成”改为“准备/失败/生成”

当前问题：

- 保存区实例标识仍基于 `source` 显示：
  - `manual` 显示“手动”。
  - `generated` 显示“生成”。
- 这会导致没有输出图但 `source=generated` 的实例也显示“生成”。
- 用户希望标识表达当前实例状态，而不是历史来源字段。

调整方案：

- 保存区实例标识改为状态语义：
  - `准备`：没有输出图，且不是失败、不是生成中。
  - `失败`：`generation_status === "failed"`。
  - `生成`：有输出图，且生成成功或处于 ready 状态。
- 不再显示“手动”。
- 没有输出图的实例绝不能显示“生成”。
- 生成中实例继续显示读秒/取消中，不用“准备/失败/生成”标识替代读秒。

验收标准：

- 空输出图准备态实例显示“准备”。
- 失败实例显示“失败”。
- 有输出图且成功的实例显示“生成”。
- 没有输出图的实例不会显示“生成”。
- “手动”字样不再作为实例状态标识出现。

### 8. Provider 可编辑规则改为按状态判断

调整方案：

- 只有显示“生成”的实例不可修改 Provider。
- “准备”实例可以修改 Provider。
- “失败”实例可以修改 Provider。
- 判断 Provider 是否可编辑时，不再只看 `source === "generated"`。
- 如果实例没有输出图，即使数据库 `source` 是 `generated`，也应允许编辑 Provider。

验收标准：

- 准备实例进入编辑后，可以修改 Provider。
- 失败实例进入编辑后，可以修改 Provider。
- 生成成功且有输出图的实例进入编辑后，Provider 不可修改。
- Provider 修改保存后，再提交或重提使用修改后的 Provider。

副作用：

- 旧数据中 `source=generated` 但没有输出图的实例，用户现在会看到它们变成“准备”或“失败”，并且可修改 Provider。
- 这是为修复状态语义不准确而有意调整。

### 9. 修正没有输出图但标识为“生成”的旧实例

调整方案：

- 当前所有没有输出图但显示为“生成”的实例，都必须按新状态规则显示：
  - 如果失败，显示“失败”。
  - 如果未失败且未生成中，显示“准备”。
- 本版优先通过显示层和查询层规则修正，避免无必要批量改写数据库。
- 如果来源筛选需要准确筛选“准备/失败/生成”，后端查询层应按新状态语义计算，而不是只读 `source` 字段。
- 只有在现有数据结构无法支持筛选时，才考虑最小必要的数据修正。

验收标准：

- 刷新页面后，没有输出图的旧实例不再显示“生成”。
- 没有输出图的旧实例可以编辑 Provider。
- 数据库中的电脑图片文件路径不被删除或改写。

## 来源筛选同步改造

### 10. 来源筛选改为“生成/准备/失败”

调整方案：

- 生图管理页保存区筛选行中的“来源”筛选项从旧的“生成/手动”改为：
  - 全部
  - 生成
  - 准备
  - 失败
- 筛选语义与实例状态标识一致：
  - 生成：有输出图，且生成成功或 ready。
  - 准备：没有输出图，且不是失败、不是生成中。
  - 失败：`generation_status === "failed"`。
- 不再用 `source=manual/generated` 作为来源筛选的直接含义。
- 生成中实例是否出现在来源筛选结果中，沿用当前状态筛选规则，不强行归入“准备/失败/生成”。

验收标准：

- 来源筛选下拉显示“全部 / 生成 / 准备 / 失败”。
- 选择“生成”只显示有输出图的成功实例。
- 选择“准备”显示无输出图且非失败的准备态实例。
- 选择“失败”显示失败实例。
- 没有输出图但旧 `source=generated` 的实例不会被“生成”筛选命中。
- “手动”不再作为来源筛选项出现。

副作用：

- “来源”这个筛选名称保留，但含义从历史来源变成当前实例状态分类。
- 旧版本中按“手动/生成”理解来源筛选的习惯会改变。
- 这与当前实例标识语义统一，能减少“没有输出图却显示生成”的混乱。

## 复制实例参数完整性

### 11. 复制实例时必须保留尺寸

当前问题：

- 保存区实例点击“复制”后，新复制出来的准备态实例尺寸显示为空。
- 从当前代码看，复制动作会根据原实例重新计算生成参数，但创建准备态实例时没有显式把原实例的 `generation_size`、`generation_params.resolved_size`、`generation_params.size` 作为复制优先级锁住。
- 如果原实例尺寸只存在于某一个字段中，或重算参数时落到默认/空值，新实例的尺寸显示就会丢失。

调整方案：

- 复制保存区实例时，必须完整复制原实例的生成尺寸相关信息。
- 复制优先级应为：
  - 原实例 `generation_size`。
  - 原实例 `generation_params.resolved_size`。
  - 原实例 `generation_params.size`。
  - 根据原实例比例和分辨率可稳定推导出的尺寸。
- 新复制出来的准备态实例应写入：
  - `generation_size`。
  - `generation_params.resolved_size`。
  - `generation_params.size`。
  - `generation_params.ratio`。
  - `generation_params.resolution_level`。
  - `generation_params.n`。
- 复制动作仍然不复制输出图。
- 复制动作仍然清空 `output_image_path` 和 `output_image_paths`。
- 复制动作仍然不立即提交生成。
- 如果是 `openai-google` 这类本来不使用尺寸的 Provider，继续按该 Provider 的规则保持尺寸为空或“无”，不要硬塞不适配的尺寸。

验收标准：

- 原实例有尺寸时，复制出的准备态实例尺寸不为空。
- 原实例为 1K/2K/4K 预设尺寸时，复制出的实例保留相同尺寸、比例和分辨率。
- 原实例为自定义尺寸时，复制出的实例保留相同自定义尺寸。
- 原实例 `n > 1` 时，复制出的实例保留相同 `n`。
- 复制出的实例没有输出图。
- 复制出的实例仍是准备态，可以编辑 Provider，可以提交。
- 复制失败实例时，同样保留尺寸参数。

副作用：

- 复制逻辑会更依赖原实例保存的 `generation_params` 完整性。
- 对旧数据中尺寸字段本来就缺失的实例，无法凭空恢复准确尺寸，只能按现有可推导信息补齐。
- 需要避免为了补齐尺寸而把当前操作区的尺寸误写进复制实例。
