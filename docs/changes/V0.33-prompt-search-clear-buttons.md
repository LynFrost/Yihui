## 修改目标

V0.33 在 V0.32 基础上补齐清空输入体验：

- 搜索提示词输入框内部增加浮现的 `X` 清空按钮。
- 保存区实例进入编辑状态后，实例提示词输入框内部增加浮现的 `X` 清空按钮。
- 两处 `X` 的视觉和交互方式尽量复用操作区提示词输入框现有 `X`。

本版只处理“清空框内文字”这一类小交互，不改变搜索、保存、批量保存、分页、节点、标签、图片加载等业务逻辑。

## 搜索提示词清空按钮

### 显示位置

在保存区顶部的 `搜索提示词` 输入框内部右侧增加 `X` 清空按钮。

当前搜索提示词结构在：

```text
frontend/js/render-save.js
```

现有结构类似：

```html
<div class="toolbar-input-row">
  <input name="q" value="...">
  <button type="button" data-action="apply-prompt-search">搜索</button>
</div>
```

V0.33 调整为在输入框外包一层专用容器：

```html
<div class="toolbar-search-wrap">
  <input name="q" value="...">
  <button
    type="button"
    class="prompt-clear search-prompt-clear"
    data-action="clear-prompt-search"
    aria-label="清空搜索提示词"
  >×</button>
</div>
<button type="button" data-action="apply-prompt-search">搜索</button>
```

要求：

- `X` 位于搜索输入框内部右侧。
- 鼠标悬停在搜索输入框区域时显示。
- 搜索输入框获得焦点时显示。
- 搜索框为空时可以隐藏，也可以显示但点击无副作用；推荐为空时隐藏。
- 不遮挡搜索按钮。
- 不改变搜索按钮位置和功能。
- 不造成保存区工具栏横向溢出。

### 点击行为

点击搜索框内的 `X` 时：

1. 清空 `state.filters.q`。
2. 清空 DOM 中 `input[name="q"]` 的值。
3. 将 `state.filters.page` 设为 `1`。
4. 清空当前页批量选择。
5. 保存 UI 状态。
6. 刷新保存区实例列表。
7. 触发 V0.31 图片稳定显示检查。

推荐新增函数：

```javascript
function clearPromptSearch() {
  state.filters.q = "";
  state.filters.page = 1;
  clearCurrentPageSelection();
  persistUiState();
  refreshInstances().catch((error) => {
    if (state.page === "manager") {
      setMessage(error.message, "error");
    }
  });
}
```

如果当前实现中已有 `applySaveFilters(toolbar)` 负责清空选择、持久化和刷新，也可以通过设置输入框为空后复用 `applySaveFilters(toolbar)`，不要另写重复的刷新流程。

### 与键盘翻页关系

搜索框获得焦点时，V0.32 的保存区左右键翻页必须继续避让。

要求：

- 焦点在搜索提示词输入框中，左右方向键只移动光标。
- 点击搜索框 `X` 不触发保存区左右键翻页。
- 点击搜索框 `X` 不触发保存区批量保存。

## 保存区实例提示词清空按钮

### 显示范围

保存区实例提示词清空按钮只在实例进入编辑状态后显示。

要求：

- 编辑状态：提示词输入框内部右侧显示浮现 `X`。
- 非编辑状态：不显示清空 `X`。
- 非编辑状态继续保留当前的复制按钮。
- 非编辑状态不能直接清空实例提示词。

原因：

- 保存区实例提示词属于实例内容。
- 现有规则是提示词和图片需要进入编辑状态后修改。
- 如果非编辑状态直接清空，会绕过编辑 / 保存 / 取消规则，容易误删内容。

### 渲染方式

保存区实例提示词已经复用：

```text
frontend/js/render-operation.js
renderPromptField()
```

当前操作区提示词的清空按钮通过 `clearAction` 参数渲染：

```javascript
renderPromptField({
  name: "prompt",
  value: state.operation.prompt,
  className: "record-prompt operation-prompt",
  clearAction: "clear-operation-prompt",
})
```

V0.33 应继续复用这套机制，不新建另一套提示词框组件。

在 `frontend/js/render-instance.js` 中，实例进入编辑状态时传入：

```javascript
clearAction: editable ? "clear-instance-prompt" : "",
instanceId,
```

`renderEditablePromptField()` 中的清空按钮需要在有 `instanceId` 时带上：

```html
data-id="..."
```

要求：

- 操作区提示词清空按钮继续正常工作。
- 实例提示词清空按钮使用同一套 `.prompt-clear` 基础样式。
- 实例提示词清空按钮点击时带上实例 ID。

### 点击行为

点击编辑状态实例提示词框内的 `X` 时：

1. 找到对应实例编辑草稿。
2. 将草稿 `prompt` 设为空字符串。
3. 同步 DOM 中对应 `textarea[name="instance_prompt"]` 的值为空。
4. 调用现有自动高度函数，避免空内容后 textarea 高度异常。
5. 重新渲染当前保存区，或只更新当前 textarea 与草稿。
6. 不立即写入数据库。

推荐新增函数：

```javascript
function clearInstancePrompt(instanceId) {
  const draft = state.editing.get(String(instanceId)) || state.editing.get(Number(instanceId));
  if (!draft) {
    return;
  }
  draft.prompt = "";
  const input = document.querySelector(
    `[data-instance-card][data-id="${CSS.escape(String(instanceId))}"] [name="instance_prompt"]`,
  );
  if (input) {
    input.value = "";
    autoGrowPromptTextarea(input);
    input.focus();
  }
}
```

也可以在清空后调用 `syncInstanceDraftFromDom(instanceId)`，但要保证草稿最终为空。

### 保存 / 取消规则

实例提示词清空只影响编辑草稿：

- 点击 `保存` 后，空提示词写入数据库。
- 点击实例外部触发批量保存时，空提示词按现有规则保存。
- 点击 `取消` 后，恢复为原实例提示词。
- 如果保存失败，继续保留编辑状态，并显示错误。

提示词为空不影响保存。

### 生成中实例和失败实例

要求：

- 生成中实例不参与提示词编辑，因此不显示清空 `X`。
- 失败实例如果允许进入编辑状态，则编辑状态下可以清空提示词。
- 清空提示词不影响 `重新提交` / `复制提交` 按钮本身的显示规则。

## 事件处理

在 `frontend/js/events.js` 中增加 action 分发：

```javascript
if (action === "clear-prompt-search") {
  clearPromptSearch();
}

if (action === "clear-instance-prompt") {
  clearInstancePrompt(actionNode.dataset.id);
}
```

要求：

- 点击 `X` 时阻止不必要的事件冒泡。
- 点击 `X` 不打开图片弹窗。
- 点击 `X` 不触发标签下拉。
- 点击 `X` 不触发保存区键盘焦点异常。
- 点击实例提示词 `X` 不导致编辑状态丢失。

如果现有点击边界保存逻辑会因为点击 `X` 触发批量保存，应给 `X` 加：

```html
data-skip-batch-save="true"
```

并确认 V0.04 之后的批量保存边界逻辑会跳过它。

## 副作用与控制

### 搜索框清空按钮的副作用

可能副作用：

- `X` 可能遮挡搜索输入框右侧文字。
- 点击 `X` 会立即刷新列表，用户当前页可能回到第 1 页。
- 搜索工具栏中多一个绝对定位按钮，窄屏下可能产生视觉拥挤。

控制方式：

- 给搜索输入框增加右侧 padding。
- 清空搜索后回到第 1 页，沿用筛选变化的既有规则。
- `X` 默认隐藏，只在 hover / focus 时出现。
- 使用绝对定位，不改变工具栏布局宽度。
- 页面级测试确认无横向滚动条。

### 实例提示词清空按钮的副作用

可能副作用：

- 用户误点 `X` 后提示词框会立即变空。
- 如果点击实例外部触发批量保存，空提示词会按现有规则保存。
- `X` 和复制按钮同时存在时可能造成视觉拥挤。

控制方式：

- 只在编辑状态显示清空 `X`。
- 非编辑状态不显示清空 `X`，继续只保留复制按钮。
- 编辑状态下清空只改草稿，点击取消可恢复。
- 提示词为空继续允许保存，符合既有规则。
- 清空按钮复用现有 hover / focus 浮现样式，减少常驻干扰。

### 与 V0.32 键盘翻页的关系

可能副作用：

- 点击搜索框或实例提示词框后，保存区左右键翻页焦点状态可能被错误保留。
- 清空按钮点击可能被误判为保存区空白点击。

控制方式：

- 搜索框和实例提示词框仍然属于输入类控件，左右方向键继续被 V0.32 避让。
- 清空按钮加 `data-skip-batch-save="true"`，避免误触发批量保存。
- 页面级测试覆盖搜索框左右键和保存区左右键翻页。
