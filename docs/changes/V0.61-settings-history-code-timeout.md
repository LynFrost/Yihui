# V0.61 设置页下拉历史、代码区样式和脚本超时收口

## 目标

当前 V0.60 已完成设置页代码区页签、参数介绍、新建 Provider 空白连接信息和复制 Provider。本版 V0.61 目标是不新增生成大功能，修复设置页带下拉记录字段跨版本、跨端口丢失的问题，并统一代码区显示样式，同时将软件执行共享脚本和自定义代码的外层自动中断时间从 900 秒调整为 3600 秒。

本版原则：

- 所有带下拉记录的字段都应尽量共享持久化，不再只依赖浏览器 `localStorage`。
- 已经在 Provider 配置中出现过的字段值，应能回填到对应下拉记录。
- 不记录 `api_key` 明文历史。
- 调用示例、参数介绍、自定义代码的代码区显示样式保持一致。
- 固定“调用示例”继续只读，不恢复编辑能力。
- 3600 秒只调整软件执行共享脚本和自定义代码的外层超时，不直接改写脚本内部请求超时、下载超时和重试间隔。
- 不破坏 V0.60 的 Provider 新建、复制、参数介绍、自定义代码和共享脚本规则。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 下拉记录共享持久化

### 1. 覆盖所有带下拉记录的字段

当前问题：

- 设置页连接信息区中，`api_key_env / model / user_agent` 这些带下拉记录的字段，历史记录仍主要保存在前端本地 UI 状态中。
- 换版本、换端口、浏览器本地状态变化后，下拉记录会减少。
- V0.59/V0.60 已经将操作区路径历史改为后端共享化，但设置页连接字段历史没有同步改造。
- 当前配置中已经出现过的 `model`，例如 `gpt-image-2-standard`，如果没有进入当前端口的本地历史，就可能不会出现在下拉菜单里。

调整方案：

- 将所有带下拉记录的字段统一纳入共享历史管理。
- 本版至少覆盖：
  - 设置页连接信息区 `api_key_env`。
  - 设置页连接信息区 `model`。
  - 设置页连接信息区 `user_agent`。
  - 生图管理页操作区 `generation_path`，沿用 V0.59/V0.60 共享路径历史，并回归检查不倒退。
- 不为 `api_key` 增加历史下拉。
- 不记录 `api_key` 明文。

验收标准：

- `api_key_env` 下拉记录跨版本不减少。
- `model` 下拉记录跨版本不减少。
- `user_agent` 下拉记录跨版本不减少。
- `generation_path` 下拉记录跨版本不减少。
- `api_key` 不出现历史下拉。
- 下拉记录不会因为换端口而只剩当前端口 localStorage 中的内容。

### 2. 下拉历史来源合并

调整方案：

每个带下拉记录的字段，历史来源应合并：

- 后端共享历史配置。
- 当前所有 Provider 配置里已有的对应字段。
- 生图成功后实际使用过的对应字段。
- 当前浏览器仍能读取到的旧 `localStorage` 历史。
- 当前输入框正在使用的值。

字段来源示例：

- `api_key_env`
  - 共享字段历史。
  - 所有 Provider 的 `api_key_env`。
  - 生图成功时使用的 Provider 的 `api_key_env`。
  - 当前浏览器旧本地历史。
- `model`
  - 共享字段历史。
  - 所有 Provider 的 `model`。
  - 生图成功时使用的 Provider 的 `model`。
  - 当前浏览器旧本地历史。
- `user_agent`
  - 共享字段历史。
  - 所有 Provider 的 `user_agent`。
  - 生图成功时使用的 Provider 的 `user_agent`。
  - 当前浏览器旧本地历史。
- `generation_path`
  - 共享路径历史。
  - 成功保存实例中的 `generation_path`。
  - 生图成功时使用的路径。
  - 当前浏览器旧本地历史。

验收标准：

- 当前任一 Provider 中出现过的 `model` 都能出现在 model 下拉中。
- `gpt-image-2-standard` 如果存在于 Provider 配置中，必须出现在 model 下拉中。
- 当前任一 Provider 中出现过的 `api_key_env` 都能出现在 api_key_env 下拉中。
- 当前任一 Provider 中出现过的 `user_agent` 都能出现在 user_agent 下拉中。
- 当前输入框里的非空值也能显示在当前下拉列表里。
- 生图成功后，使用过的 `api_key_env / model / user_agent / generation_path` 会进入共享历史。

### 3. 排序、去重和数量限制

调整方案：

- 下拉记录去重。
- 空值不显示。
- 最近成功使用或最近主动选择的值靠前。
- Provider 配置中回填的值跟在共享历史后面。
- 每个字段保留合理数量上限，建议沿用 20 条。
- 长记录显示完整 `title`，下拉菜单必要时使用滚动，不撑乱设置页布局。

验收标准：

- 下拉记录不重复。
- 空字符串不出现在下拉里。
- 长 model、长 user_agent、长路径不会撑乱页面。
- 下拉菜单可滚动。
- 点击下拉菜单外仍能关闭菜单。
- 切换 Provider 后，下拉菜单不会卡在旧字段状态。

副作用：

- 下拉菜单可能比当前更长。
- 已经不用的旧 Provider 字段值也会回填出来。
- 这是“所有出现过的记录不要丢失”的自然结果。
- 只存在于其他端口 `localStorage`、当前端口读不到、也没有出现在配置或历史中的旧记录，无法凭空恢复。

## 代码区显示样式

### 4. 调用示例代码区改为黑底白字

当前问题：

- V0.60 中自定义代码代码区是黑底白字。
- 调用示例因为 `readonly` 样式覆盖，可能显示成白底黑字。
- 用户希望调用示例代码区显示样式和自定义代码一致。

调整方案：

- 设置页 `调用示例` 代码区改为黑底白字。
- 显示样式和 `自定义代码` 保持一致。
- 固定调用示例仍然只读。
- 不恢复固定调用示例编辑能力。
- `参数介绍` 代码区也建议保持黑底白字，使三个页签视觉一致。

验收标准：

- `调用示例` 代码区黑底白字。
- `自定义代码` 代码区黑底白字。
- `参数介绍` 代码区黑底白字。
- `调用示例` 内容清晰可见，不出现白屏或低对比度。
- `调用示例` 仍无法编辑。
- `自定义代码` 仍可编辑、保存、取消、复制、清空。
- `参数介绍` 仍只读且可复制。

副作用：

- 设置页整体是浅色风格，代码区黑底白字会更突出。
- 但代码区本身属于代码查看/编辑语义，统一为黑底白字更容易识别。

## 脚本执行外层超时

### 5. 自动中断时间从 900 秒改为 3600 秒

当前问题：

- 软件执行共享脚本或自定义代码的外层默认超时为 900 秒。
- 对复杂任务、多次重试、服务商慢响应场景，900 秒可能提前中断。

调整方案：

- 将软件执行共享脚本和自定义代码的外层自动中断时间从 `900` 秒改为 `3600` 秒。
- 同步相关测试和错误文案。
- 不直接改变脚本内部：
  - 单次 HTTP 请求超时。
  - 图片下载超时。
  - 重试间隔。
  - 重试次数。
- 不直接改变前端读秒规则。
- 生成中实例继续按当前规则显示读秒和取消状态。

验收标准：

- 后端脚本执行默认外层超时为 3600 秒。
- 超时错误文案显示 3600 秒。
- 相关测试不再断言 900 秒。
- 共享脚本和自定义代码都使用同一外层超时规则。
- 点击取消生成仍然有效。
- 取消中状态不因超时变长而丢失。

副作用：

- 卡住的脚本最长可能占用后台任务 1 小时，而不是 15 分钟。
- 服务商长期不返回时，生成中实例可能等待更久。
- 并发很多时，长时间挂起的任务会占用更多后台资源。
- 需要确保取消生成仍能尽快生效，避免用户只能等待 3600 秒。
- 优点是复杂任务、多次重试、慢响应更不容易被软件外层提前截断。

## 回归检查

完成实现后需要检查：

- 设置页可以正常打开。
- `api_key_env / model / user_agent` 下拉记录稳定。
- `model` 下拉包含所有 Provider 中出现过的 model。
- `model` 下拉包含 `gpt-image-2-standard`，前提是该值存在于当前配置中。
- `api_key_env` 下拉包含所有 Provider 中出现过的环境变量名。
- `user_agent` 下拉包含所有 Provider 中出现过的 User-Agent。
- 操作区路径下拉沿用共享历史，不回退。
- 换版本、换端口后，下拉记录不减少。
- 生图成功后，对应字段会写入共享历史。
- 不记录 `api_key` 明文历史。
- 调用示例、参数介绍、自定义代码均为黑底白字。
- 调用示例仍只读。
- 自定义代码仍可编辑。
- 脚本外层超时为 3600 秒。
- 取消生成仍然有效。
- V0.60 的参数介绍、新建 Provider、复制 Provider 不回退。
- V0.59 的 openai-google 参数空值、尺寸“无”、路径历史不回退。

## 不做内容

- 不记录 `api_key` 明文历史。
- 不新增新的设置字段。
- 不改变生成脚本内部请求超时、下载超时、重试次数和重试间隔。
- 不改变固定调用示例只读规则。
- 不改变 Provider 能力体系。
- 不删除电脑上的图片文件。
