# V0.62 操作区准备态和保存区提交工作流

## 目标

当前 V0.61 已完成设置页下拉历史共享、代码区样式统一和脚本执行外层超时调整。本版 V0.62 目标是调整生图管理页的主工作流：操作区不再直接生成，而是负责整理内容并新增为保存区准备态实例；保存区实例负责真正提交生成。

本版原则：

- 操作区从“直接生成区”调整为“准备实例编辑区”。
- 保存区实例从“结果列表”进一步承担“提交队列”的作用。
- 新增和提交永远针对一个实例。
- 生成数量 `n` 作为实例参数保存；如果 `n > 1`，该实例提交后应在同一个实例结果中承载多个输出图。
- 不为了新增 `n` 显示而破坏保存区实例原有布局。
- 不改变 V0.61 的下拉历史、代码区样式和 3600 秒超时规则。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 操作区布局收口

### 1. 水平对齐

调整内容：

- 生图管理页操作区中，“操作区”标题、“提示词”标题、“Provider”标题、“清除”按钮在同一水平逻辑线上对齐。
- 原“文生图”按钮、“图生图”按钮所在位置删除后，释放出的区域用于显示结果状态提示。
- 操作区中提示词框、比例框、标签框、“清空”按钮保持上边缘对齐。
- 操作区中提示词框、分辨率框、路径框、“新增”按钮保持下边缘对齐。
- “清空”按钮和“新增”按钮与保存区实例的“编辑”“删除”按钮在视觉高度上对齐。

验收标准：

- 操作区第一眼看起来不再上下错位。
- 提示词、Provider、清除、清空、新增这些关键操作之间没有明显跳行或歪斜。
- 状态提示不再挤占右侧信息显示区域，也不挤压标签框和路径框。
- 窄窗口下文字不互相覆盖，按钮不挤出父容器。

### 2. 竖直对齐

调整内容：

- 操作区提示词框左右边缘与保存区实例提示词框左右边缘对齐。
- 操作区 Provider 区域与保存区实例 Provider 区域对齐。
- 对齐以现有保存区实例卡片的列结构为主要参照，避免单独为操作区做一套不一致的网格。

验收标准：

- 操作区和保存区实例上下比较时，提示词列、Provider 列边界一致。
- 单列和双列显示不因本次对齐调整出现错位。

## 操作区模式调整

### 3. 删除“文生图 / 图生图”按钮

调整内容：

- 操作区中删除“文生图”“图生图”两个按钮。
- 操作区总是显示当前图生图模式下的输入图区域。
- 如果输入图为空，提交时自动按文生图处理。
- 如果输入图不为空，提交时自动按图生图处理。
- 操作区 UI 不再保存或依赖用户手动切换的生图方式按钮状态。

验收标准：

- 操作区始终能看到输入图框。
- 不上传输入图时，新增出来的准备态实例为文生图参数。
- 上传一张或多张输入图时，新增出来的准备态实例为图生图参数。
- 现有输入图上传、删除、粘贴、路径读取不回退。

副作用：

- 用户不再手动选择文生图或图生图，模式由输入图是否存在决定。
- 如果用户误留输入图，新增实例会被识别为图生图；需要通过清空输入图来回到文生图。

## 操作区“新增”

### 4. “生成”改为“新增”

调整内容：

- 操作区按钮“生成”改名为“新增”。
- 点击“新增”后，将当前操作区内容新增到保存区，成为准备态实例。
- 准备态实例输出图为空。
- 点击“新增”不触发生图请求。
- 新增实例进入当前所选节点，沿用当前节点规则。
- 新增实例保留当前操作区的提示词、输入图、标签、Provider、路径、尺寸、比例、分辨率、调用方式、model、生成数量 `n` 等可用参数。

生成数量规则：

- `n` 不再影响“新增”动作的实例数量。
- 无论 `n` 是 1 还是多个，点击一次“新增”只新增一个准备态实例。
- `n` 作为该准备态实例的生成参数保存。
- 当该准备态实例提交生成时，如果 `n > 1`，应由同一个实例承载多个输出图。
- 保存区实例中新增的 `n` 信息不能挤占或破坏旧实例的布局；可采用紧凑字段、悬停提示或仅在编辑状态中展示。

验收标准：

- 点击“新增”不会立即生成图片。
- 点击一次“新增”只新增一个准备态实例。
- `n > 1` 时不会新增多条准备态实例。
- 准备态实例后续提交后能按 `n` 取得多个输出结果。
- 旧实例不因为新增 `n` 参数显示而布局变形。

### 5. 删除保存区工具栏“新增”

调整内容：

- 生图管理页中，“缩略图”按钮旁边原有的“新增”按钮删除。
- 新增准备态实例统一通过操作区“新增”完成。
- 如果需要空白实例，可以清空操作区后点击“新增”，或使用快捷键 `Alt+N`。

验收标准：

- “缩略图”按钮旁边不再出现旧的保存区工具栏“新增”。
- 用户仍能创建空白准备态实例。

### 6. `Alt+N` 快捷键

调整内容：

- 生图管理页全局快捷键 `Alt+N` 触发操作区“新增”。
- 如果触发时操作区有内容，则新增包含当前内容的准备态实例。
- 如果触发时操作区没有内容，则新增空白准备态实例到保存区。
- 弹窗、图片查看、确认框等阻塞层打开时，不触发该快捷键，避免误操作。

验收标准：

- `Alt+N` 可以快速新增准备态实例。
- 操作区为空时也能新增空白实例。
- 弹窗中不会误触发新增。

副作用：

- 浏览器或系统可能占用部分 `Alt` 组合键；实现时需要尽量兼容，但不能保证所有系统环境都完全拦截成功。

## 保存区实例按钮调整

### 7. “复制提交”改为“复制”

调整内容：

- 保存区实例中的“复制提交”按钮改名为“复制”。
- “复制”不再立即提交生成。
- 点击“复制”后，在保存区复制一个内容完全相同的准备态实例。
- 新复制出来的实例输出图为空。
- 新复制实例保留原实例的提示词、输入图、标签、Provider、路径、尺寸、比例、分辨率、调用方式、model、生成数量 `n` 等参数。
- 原实例不被修改。

验收标准：

- 点击“复制”不会立即生成。
- 复制出来的是准备态实例。
- 复制出来的实例没有输出图。
- 原实例内容和状态不变。

副作用：

- 旧的“一点复制提交就生成”流程变成“两步”：先复制，再提交。
- 这会增加一次点击，但能避免误提交，也和本版保存区队列工作流一致。

### 8. 新增“提交”按钮

调整内容：

- 保存区实例中，“带入”和“复制”按钮整体左移，为“提交”按钮腾出位置。
- 准备态实例显示“提交”按钮。
- 点击“提交”后，该实例就在当前位置进入生成中状态，直到生成成功、失败或取消。
- 提交后的实例不再额外出现在当前页或所有页的最下面。
- 如果实例已有输出图，“提交”按钮置灰不可点击。
- 如果实例正在生成中或取消中，“提交”按钮不可重复点击。
- 提交时使用实例自身保存的 Provider、路径、尺寸、比例、分辨率、调用方式、model、生成数量 `n` 等参数，不使用操作区当前值覆盖。

验收标准：

- 准备态实例可以从自身位置提交。
- 提交后不出现重复的生成中占位实例。
- 已有输出图的实例不能提交。
- 提交不会改操作区当前内容。
- 提交后读秒、取消、失败重试提示沿用既有稳定规则。

### 9. 失败实例“重新提交”改为“重提”

调整内容：

- 失败实例的“重新提交”按钮改名为“重提”。
- “重提”和准备态实例的“提交”使用同样尺寸。
- “重提”和“提交”放在同样位置，减少按钮布局跳动。
- “重提”仍表示对失败实例重新提交生成。
- 失败实例重提时仍使用该实例自身保存的 Provider 和生成参数。

验收标准：

- 失败实例按钮显示为“重提”。
- “重提”和“提交”宽高一致。
- 普通准备态实例、失败实例在按钮位置上保持一致。
- 失败实例重提后仍按既有规则进入生成中，并最终更新该实例结果。

## 快捷提交

### 10. `Ctrl+Enter` 改为提交选中实例

调整内容：

- 生图管理页全局快捷键 `Ctrl+Enter` 不再触发操作区功能。
- `Ctrl+Enter` 改为触发保存区选中实例的“提交”动作。
- 如果选择了多个实例，则批量提交其中可提交的实例。
- 已有输出图的实例自动跳过。
- 正在生成中、取消中、不可提交的实例自动跳过。
- 如果没有选择实例，`Ctrl+Enter` 无效，不触发任何生成。
- 弹窗、图片查看、确认框等阻塞层打开时，不触发该快捷键。

验收标准：

- 操作区有焦点时，`Ctrl+Enter` 也不会再直接生成操作区内容。
- 选中一个准备态实例后，`Ctrl+Enter` 等同点击该实例“提交”。
- 选中多个准备态实例后，`Ctrl+Enter` 批量提交。
- 选中实例中已有输出图的部分会跳过，不报错中断全部提交。
- 没有选中实例时，`Ctrl+Enter` 不做任何动作。

副作用：

- 旧版本中习惯用 `Ctrl+Enter` 直接生成操作区内容的流程会改变。
- 批量提交多个实例可能增加并发任务数量，对服务商稳定性和本地任务队列有压力。
- 实现时需要给出清晰提示，例如“已提交 X 个，跳过 Y 个”，避免用户误以为快捷键无效。

## 数据和状态规则

### 11. 准备态实例定义

准备态实例应满足：

- 已存在于保存区数据库。
- 输出图为空。
- 未处于生成中、取消中。
- 保存完整的生成所需参数。
- 可以通过“提交”进入生成中。

准备态实例应保存：

- 提示词。
- 输入图路径列表。
- 标签。
- Provider。
- 生成路径。
- 节点。
- 比例。
- 分辨率。
- 尺寸。
- 调用方式。
- model。
- 生成数量 `n`。
- Provider 参数快照或等价的生成参数。

### 12. 提交后的排序和位置

调整规则：

- 实例提交后立即在当前位置进入生成中，不额外插入临时实例。
- 生成中期间不挤走当前页面前面的已保存实例。
- 生成完成后，是否因当前排序规则重新定位，沿用保存区既有排序逻辑。
- 如果当前筛选条件不匹配生成后的状态，刷新后可按既有筛选规则隐藏。

验收标准：

- 提交瞬间当前页不会因为新增 pending 占位而跳动。
- 当前实例从准备态变成生成中时，编号和位置变化可控。
- 生成完成后不产生重复实例。

## 不做内容

- 不恢复操作区直接生成按钮。
- 不保留“文生图 / 图生图”手动切换按钮。
- 不让 `n` 控制新增实例数量。
- 不让保存区复制动作直接提交。
- 不让 `Ctrl+Enter` 继续触发操作区生成。
- 不改变数据库 schema，除非现有实例结构无法保存 `n` 或多个输出图且必须补齐。
- 不删除电脑上的图片文件。
- 不新增 Provider 类型。
- 不重构前端模块结构。
