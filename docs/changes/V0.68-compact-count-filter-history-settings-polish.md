# V0.68 数量框、筛选清除、历史编号筛选和设置脏状态收口

## 目标

当前 V0.67 已完成保存区固定编号、编辑撤销、状态多选和历史记录关联实例编号。本版 V0.68 目标是在不改动数据库 schema 的前提下，继续收紧生图管理页、历史记录页和设置页的小控件体验：

- 保存区实例数量 `n` 改为更小的可输入框，不再使用下拉菜单。
- 保存区实例提示词标题行固定按钮位置，编辑态出现“清除”时不影响“复制”和数量框位置。
- 生图管理页状态筛选、标签筛选的清除 `x` 移到标题旁边，避免占用下拉菜单一整列。
- 保存区排序中“编号 从大到小 / 从小到大”调整到前两项。
- 保存区实例 Provider 下拉框避开右侧状态标识。
- 历史记录页状态筛选顺序调整。
- 历史记录页新增编号类型筛选，可以筛选 `#` 实例编号记录和 `H` 历史本地编号记录。
- 设置页 model 通过历史下拉菜单选择后，必须触发“保存设置”按钮可用。

本版原则：

- 不新增数据库 schema。
- 不改变 V0.67 固定实例编号规则。
- 不改变历史记录 `# / H` 编号含义。
- 不改变生成成功实例不能修改 Provider 和数量的规则。
- 不破坏 V0.67 编辑保存撤销 / 重做。
- 不破坏状态多选、标签多选、Provider / 尺寸 / 模式 / 调用方式 / model 筛选。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 保存区实例数量框

### 1. 数量框改为紧凑输入框

当前问题：

- 保存区实例数量框当前是下拉菜单。
- 下拉控件占用宽度偏多。
- 用户只需要输入数字，不需要下拉选项。

调整方案：

- 将保存区实例数量 `n` 控件从下拉框改为文本输入框。
- 宽度尽可能小，只满足常见数字显示。
- 输入框接受手动输入。
- 读取来源继续沿用 V0.67：
  - 优先读实例 `generation_params.n`。
  - 其次读实例 `generation_params.count`。
  - 旧实例缺少该字段时显示 `1`。
- 操作区新增准备态实例时，将操作区当前数量带入实例参数。
- 复制实例时必须复制数量参数。
- 失败实例重提时使用该实例自己的数量参数。
- 生成成功且已有输出图的实例，数量框置灰不可修改。
- 准备态和失败态实例允许修改数量。

提交校验规则：

- 数量框允许用户暂时输入任意字符。
- 点击“提交 / 重提”时再校验。
- 批量提交和 `Ctrl+Enter` 提交也必须走同一校验。
- 合法值为正整数。
- 空值、非数字、`0`、负数、小数都视为非法。
- 非法时不调用后端生成接口，并提示具体实例编号。
- 批量提交时建议跳过非法数量实例，继续提交其他合法实例，同时提示被跳过的编号和原因。

验收标准：

- 数量框比当前下拉框明显更窄。
- 数量框不出现下拉菜单。
- 旧实例数量显示为 `1`。
- 新增准备态实例数量来自操作区当前数量。
- 复制实例后数量不丢失。
- 修改数量并保存后刷新不丢失。
- 生成成功实例数量不可编辑。
- 准备态实例数量可编辑。
- 失败态实例数量可编辑。
- 非法数量提交时报错，不进入生成中。
- 批量提交时非法数量实例不会导致合法实例全部无法提交。
- 数量修改仍纳入 V0.67 编辑保存撤销 / 重做范围。

副作用：

- 用户可以输入非法字符，因此提交前校验比下拉版本更重要。
- 数量框变窄后，需要检查多位数是否仍能看清。
- 批量提交需要避免一个非法实例阻塞整批合法实例。

## 提示词标题行按钮固定

### 2. 清除占位 / 复制 / 数量框位置固定

当前需求：

- 保存区实例数量框放到提示词框上面的“复制”按钮右边。
- 点击编辑后，“清除”按钮出现在数量框左边。
- 不管是否点击编辑，数量框和“复制”按钮的位置都不变。

最终布局规则：

- 提示词标题行固定为：
  - 提示词标题。
  - 中间弹性空白。
  - 清除占位。
  - 复制。
  - 数量框。
- 非编辑态：
  - “清除”按钮不显示。
  - 但清除占位仍保留同样宽度。
  - “复制”和数量框位置不变。
- 编辑态：
  - 清除占位中显示“清除”按钮。
  - “复制”和数量框仍保持原位置。

调整方案：

- 标题行右侧按钮区使用固定网格或固定宽度槽位。
- 清除按钮使用独立槽位，不通过插入元素挤压复制按钮和数量框。
- 数量框宽度固定。
- 复制按钮宽度固定。
- 清除占位宽度固定。
- 长提示词标题只能压缩标题文字，不允许挤压右侧按钮区。

验收标准：

- 非编辑态和编辑态切换时，“复制”按钮位置不跳动。
- 非编辑态和编辑态切换时，数量框位置不跳动。
- 编辑态出现“清除”按钮时，不挤压提示词框宽度。
- 单列模式稳定。
- 双列模式稳定。
- 长提示词、长重试提示、失败状态同时存在时不破版。

副作用：

- 清除占位会固定占用少量宽度。
- 需要检查窄窗口下标题文字是否被过度压缩。

## 筛选清除按钮收口

### 3. 状态筛选的 `x` 移到标题旁边

当前问题：

- 生图管理页状态筛选是多选下拉。
- 当前清除 `x` 在下拉菜单内部，占用一整列宽度。
- 选项文字空间被浪费。

调整方案：

- 状态下拉菜单内部不再显示清除 `x`。
- 在“状态”标题旁边增加小号 `x`。
- 小号 `x` 只在已有状态筛选时可用。
- 点击小号 `x` 清空所有状态筛选。
- 清空后回到“全部”含义。
- 小号 `x` 不能撑高筛选行，不能明显改变当前布局。

验收标准：

- 状态下拉菜单内部不再出现占整列的 `x`。
- 状态标题旁边出现紧凑清除 `x`。
- 点击状态标题旁边 `x` 后清空状态筛选。
- 清空后分页回到第一页。
- 清空后当前选择清空，列表显示全部状态。
- 状态多选逻辑不回退。

副作用：

- 标题区域会增加一个小按钮。
- 需要避免点击标题旁边 `x` 时误触发下拉打开。

### 4. 标签筛选的 `x` 移到标题旁边

当前问题：

- 生图管理页标签筛选是多选下拉。
- 当前清除 `x` 在下拉菜单内部，占用一整列宽度。
- 标签列表空间被浪费。

调整方案：

- 标签下拉菜单内部不再显示清除 `x`。
- 在“标签”标题旁边增加小号 `x`。
- 小号 `x` 只在已有标签筛选时可用。
- 点击小号 `x` 清空所有标签筛选和标签搜索词。
- 下拉菜单宽度和现有筛选行布局保持稳定。

验收标准：

- 标签下拉菜单内部不再出现占整列的 `x`。
- 标签标题旁边出现紧凑清除 `x`。
- 点击标签标题旁边 `x` 后清空标签筛选。
- 清空标签筛选后列表恢复显示全部标签范围。
- 不破坏“无标签 / __untagged__”既有筛选语义。

副作用：

- 标签标题区域会增加一个小按钮。
- 需要避免标签标题旁边 `x` 和标签下拉打开区域冲突。

## 保存区排序和 Provider 宽度

### 5. 编号排序项调整到最前

当前需求：

- 生图管理页排序下拉框中：
  - “编号 从大到小”放到第一个。
  - “编号 从小到大”放到第二个。

调整方案：

- 只调整下拉菜单显示顺序。
- 后端排序值继续沿用 V0.67：
  - `number_desc`。
  - `number_asc`。
- 不改变默认排序，除非当前默认排序已经是编号排序。

验收标准：

- 打开排序下拉，第 1 项是“编号 从大到小”。
- 第 2 项是“编号 从小到大”。
- 选择后排序结果仍按固定实例编号排序。
- 排序只影响位置，不改变编号。

副作用：

- 用户习惯的旧排序项位置会后移。
- 需要确认持久化的旧排序值仍能正常显示。

### 6. 保存区 Provider 下拉框避开状态标识

当前问题：

- 保存区实例 Provider 下拉框右边靠近“准备 / 生成 / 失败”等状态标识。
- 当前宽度可能挤压或贴近状态标识。

调整方案：

- Provider 标题不移动。
- Provider 下拉框右边界稍微往左收。
- 留出和右侧状态标识之间的安全间距。
- 同列标签框、路径框等不因此被整体错位。

验收标准：

- Provider 下拉框不会碰到“准备 / 生成 / 失败”状态标识。
- 长 Provider 名称仍尽量显示完整。
- 状态标识不被挤变形。
- 单列模式稳定。
- 双列模式稳定。

副作用：

- Provider 下拉框宽度会略变小。
- 需要在长 Provider 名称场景下检查显示效果。

## 历史记录筛选

### 7. 历史状态筛选顺序调整

当前需求：

- 历史记录页状态筛选下拉菜单顺序改为：
  - 生成中。
  - 失败。
  - 生成。
  - 其他。

调整方案：

- 只调整历史记录页状态下拉菜单显示顺序。
- 历史记录没有“准备”状态。
- 是否保留“全部”由当前历史筛选控件既有模式决定：
  - 如果当前有“全部”，仍保留“全部”作为第一项。
  - 具体状态项顺序严格为“生成中 / 失败 / 生成 / 其他”。

验收标准：

- 历史记录页状态筛选具体状态顺序为“生成中 / 失败 / 生成 / 其他”。
- 不出现“准备”。
- 选择各状态后查询结果准确。

副作用：

- 只影响显示顺序，不应影响后端状态语义。

### 8. 历史记录新增编号类型筛选

当前需求：

- 历史记录页中，在 model 框右边新增一个编号框。
- 下拉菜单是：
  - `#`
  - `H`
- 分别筛选 `#` 编号和 `H` 编号的记录。

调整方案：

- 在历史记录筛选区 `model` 右边新增“编号”筛选。
- 下拉选项建议为：
  - 全部。
  - `#`。
  - `H`。
- `#` 表示历史记录能关联到保存区实例固定编号。
- `H` 表示历史记录无法关联到保存区实例，使用历史本地编号。
- 后端历史查询增加轻量筛选参数，例如 `number_type`：
  - `all`：不过滤。
  - `instance` 或 `#`：只返回能关联实例编号的记录。
  - `history` 或 `H`：只返回无法关联实例编号的记录。
- 筛选必须基于 V0.67 的准确关联逻辑。
- 不能通过输出图路径匹配实例编号。
- 不能为了筛选去修改历史记录内容。

验收标准：

- 编号筛选默认显示全部。
- 选择 `#` 后，只显示能显示 `#0001` 这类实例编号的历史记录。
- 选择 `H` 后，只显示 `H0001` 这类历史本地编号记录。
- 筛选后分页回到第一页。
- 编号筛选可以和状态、Provider、尺寸、模式、调用方式、model、标签、日期范围组合。
- 不影响历史记录合并重试显示。
- 不修改 Provider、调用方式、model、参数快照。

副作用：

- 后端历史查询需要增加一个筛选参数。
- 如果旧历史大量无法关联实例，选择 `H` 时记录数量可能较多。
- 需要避免在分页后才前端过滤，否则总数和页数会不准确。

## 设置页脏状态

### 9. model 历史下拉选择后触发保存设置可用

当前问题：

- 设置页中 model 通过下拉历史记录来更改之后，“保存设置”按钮仍然置灰。
- 这说明下拉选择没有触发设置脏状态。

调整方案：

- `select-setting-history` 选择历史值后，必须调用设置脏状态逻辑。
- 目标字段包括：
  - `model`。
  - `api_key_env`。
  - `user_agent`。
- 只有实际值发生变化时才标记为脏。
- 仅打开下拉、不选择、不改变值，不应标记为脏。
- 选择后下拉菜单关闭。
- “保存设置”按钮变蓝可点击。
- “取消”按钮的脏状态同步更新。

验收标准：

- model 通过下拉选择不同值后，“保存设置”按钮立即可点。
- 保存后按钮回到置灰。
- 取消后恢复到修改前值。
- api_key_env 和 user_agent 同类下拉也正常触发脏状态。
- 打开下拉但不选择，不触发脏状态。
- 选择相同值，不触发脏状态。

副作用：

- 设置页历史下拉事件会影响脏状态判断。
- 需要避免误把单纯打开菜单当作修改。
