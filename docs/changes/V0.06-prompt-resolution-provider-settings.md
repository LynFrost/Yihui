## 提示词输入稳定性

修复这些现象：

```text
操作区提示词框点击后闪一下，无法输入文字。
保存区实例提示词框进入编辑后点击闪一下，无法输入文字。
提示词可以右键粘贴但不能正常键盘输入。
```

实现规则：

- 编辑态提示词框和操作区提示词框不得使用覆盖在 `textarea` 上方的 `.prompt-overlay`。
- 编辑态完整显示使用真实 `textarea` 自身完成：
  - `textarea:focus` 时变成浮层式编辑框。
  - 浮层式 textarea 允许覆盖旁边控件。
  - 浮层式 textarea 使用更高 `z-index`。
  - 浮层式 textarea 高度按内容展开，去掉内部滚动条。
  - 鼠标离开或失焦后恢复标准高度。
- 非编辑态保存区提示词继续支持悬停完整显示：
  - 非编辑态使用只读显示层或只读 textarea 的 hover 浮层。
  - 非编辑态浮层 `pointer-events: none`。
- 输入、点击、聚焦、选中、键盘输入期间不得调用 `renderManager()`。
- `input` 事件只同步状态与高度，不重绘整个操作区或保存区。
- `click` 事件遇到 `textarea`、`input`、`select`、`button` 继续跳过批量保存。
- 中文输入法组合输入期间不得重绘，使用 `compositionstart` / `compositionend` 保护输入状态。

实现建议：

- 将 `renderPromptField()` 拆成可编辑和只读两种渲染：
  - `renderEditablePromptField()`
  - `renderReadonlyPromptField()`
- 操作区和保存区编辑态调用 `renderEditablePromptField()`。
- 保存区非编辑态调用 `renderReadonlyPromptField()`。
- 增加 `autoGrowPromptTextarea(textarea)`：
  - 设置 `textarea.style.height = "auto"`。
  - 设置 `textarea.style.height = textarea.scrollHeight + "px"`。
  - 只在 focus、input、compositionend 时作用于当前 textarea。
- 删除编辑态 `.prompt-overlay` 的渲染路径。

## 操作区状态显示

修复截图 `Snipaste_2026-05-01_16-15-55.png` 中状态文字被“清空”按钮遮挡的问题。

实现规则：

- 操作区状态文字从按钮列内部移出。
- 状态文字放在独立状态行 `.operation-status-row`。
- `.operation-status-row` 横跨 `record-detail` 与 `operation-actions` 两个区域，或横跨操作区右侧足够宽的列。
- “清空 / 生成”按钮放在 `.operation-button-row`。
- 状态文字和按钮不使用绝对定位互相覆盖。
- 状态文字过长时允许换行或省略，但不能被按钮挡住。
- 状态为空时保留稳定高度，避免生成状态出现时布局跳动。

## 尺寸与分辨率控件

尺寸控件保留 V0.05 的逻辑，但宽度减半。

新增分辨率控件：

```text
1K
2K
4K
```

规则：

- 分辨率控件放在尺寸控件右侧。
- 分辨率控件使用下拉选择，不使用弹窗。
- 选择分辨率后立即写入 `state.operation.resolution`。
- 选择分辨率后立即保存到全局默认配置 `settings.default_resolution`。
- 未选择时使用全局默认值。
- 初始默认值为 `1K`。
- 生成时请求体包含：

```json
{
  "options": {
    "size": "1024x1024",
    "resolution": "1K"
  }
}
```

后端规则：

- `backend/config.py` 的默认配置增加：

```python
"default_resolution": "1K"
```

- `normalize_config()` 只接受 `1K`、`2K`、`4K`，非法值恢复为 `1K`。
- `backend/api.py` 的 `normalize_generation_options()` 返回标准化后的 `options`，并保证 `options["resolution"]` 存在。
- `backend/image_providers/aiapis_gpt_image_2.py` 的 `_request_options()` 将 `resolution` 加入 provider 请求参数：

```python
"resolution": options.get("resolution") or self.config.get("default_resolution") or "1K"
```

- 如果代理商 API 不支持 `resolution` 并返回错误，前端显示后端错误，不创建实例。
- 后续新增 provider 适配器时，可在各自 provider 类中决定使用、忽略或转换 `resolution`。

## 操作区布局

操作区横向顺序固定如下。

文生图：

```text
模式 | 提示词 | 尺寸 | 分辨率 | 输出图 | Provider/标签/路径 | 操作
```

图生图：

```text
模式 | 提示词 | 输入图 | 尺寸 | 分辨率 | 输出图 | Provider/标签/路径 | 操作
```

规则：

- 文生图和图生图只有提示词框宽度不同。
- 文生图不显示输入图区。
- 文生图中提示词框占用原输入图区空间。
- 图生图中输入图区宽度必须能容纳 6 张标准图片位。
- 标准图片位继续使用当前尺寸。
- 尺寸框宽度为 V0.05 尺寸框宽度约一半。
- 分辨率框宽度与尺寸框一致。
- 尺寸框、分辨率框、输出图之间紧贴排列，仅保留标准 gap。
- 提示词框、输入图区、尺寸框、分辨率框、输出图之间不插入额外空白列。
- Provider/标签/路径区域和操作按钮区域不被输入图区挤压。
- 窄屏时按现有响应式规则改为纵向排列，不能出现横向溢出。

建议 CSS 列：

```css
grid-template-columns:
  88px
  minmax(220px, 1fr)
  minmax(486px, 486px)
  52px
  52px
  76px
  minmax(180px, .8fr)
  88px;
```

文生图模式通过 `grid-column` 让提示词跨过输入图区：

```css
.operation-area.mode-text_to_image .operation-prompt {
  grid-column: 2 / 4;
}
.operation-area.mode-text_to_image .operation-input-images {
  display: none;
}
```

## 标签筛选已选标签展示

保存区标签筛选框不再只显示：

```text
已选 N 个
```

改为显示已选标签 chip。

规则：

- 未选标签时显示 placeholder：

```text
标签筛选
```

- 已选标签时，在标签筛选框内显示所有已选 TAG。
- 每个 TAG 使用小 chip 样式。
- TAG 很多时允许换行。
- 标签筛选框右侧继续保留内部清空 X。
- 清空 X 点击后清空所有已选 TAG。
- 已选 TAG chip 不能遮挡清空 X。
- 标签筛选下拉菜单继续包含搜索框和所有数据库中已有 TAG。
- TAG 下拉菜单打开、搜索、选择、取消选择时不得影响操作区提示词输入状态。

副作用处理：

- 已选 TAG 很多时筛选工具栏会变高；允许工具栏自然增高。
- 工具栏增高不能覆盖总数/翻页行。
- 工具栏增高不能造成横向滚动。

## Provider 配置管理

设置页管理 `settings.providers` 中的 provider 实例。

每个 provider 配置包含：

```json
{
  "display_name": "AIAPIS GPT Image 2",
  "adapter": "aiapis_gpt_image_2",
  "base_url": "https://img.aiapis.help/v1",
  "api_key": "",
  "api_key_env": "IMG_API_KEY",
  "model": "gpt-image-2"
}
```

规则：

- `adapter` 表示实际调用哪一种 Python provider 类。
- 当前可选 adapter 至少包含：

```text
aiapis_gpt_image_2
```

- `provider key` 是配置项的唯一 ID。
- 新建 provider 时必须输入唯一 `provider key`。
- 已保存 provider 的 `provider key` 不直接编辑；需要改 key 时，新建一个 provider，再删除旧 provider。
- `display_name` 可编辑。
- `base_url`、`api_key`、`api_key_env`、`model` 可编辑。
- 设置页可以：
  - 选择当前全局 provider。
  - 新建 provider。
  - 编辑当前 provider。
  - 保存当前 provider。
  - 删除当前 provider。
- 删除 provider 需要二次确认。
- 删除 provider 只删除配置，不修改历史实例，不删除数据库记录，不删除图片文件。
- 删除当前 active provider 后：
  - 如果还有其他 provider，自动选择第一个 provider 为 active。
  - 如果没有 provider，`active_provider` 保存为空，操作区显示 `未选择 provider`，生成时返回明确错误。

后端规则：

- `backend/config.py` 的 `normalize_config()` 不再强制把已删除的默认 provider 合并回来。
- 当配置文件不存在时，仍使用 `DEFAULT_CONFIG` 初始化。
- 当配置文件存在且 `providers` 是有效 dict 时，保留用户保存的 provider 集合。
- 当 `providers` 缺失或不是 dict 时，使用 `DEFAULT_CONFIG["providers"]`。
- `active_provider` 必须是 `providers` 中存在的 key；否则自动选择第一个 key；没有 key 时为空字符串。
- 旧配置中没有 `adapter` 的 provider：
  - 如果 provider key 能匹配内置 adapter 名，`adapter` 使用该 key。
  - 否则使用 `aiapis_gpt_image_2`。

生成调用规则：

- `backend/image_generation.py` 的 `provider_from_config()` 用 active provider 配置里的 `adapter` 查找 provider class。
- 如果 adapter 不存在，返回错误：

```text
未知图片生成适配器：xxx
```

- 如果 active provider 为空，返回错误：

```text
未选择图片生成 Provider
```

前端下拉规则：

- 设置页 provider 下拉框只显示 `settings.providers` 中真实存在的 provider。
- 选项文字显示 `display_name`，没有 `display_name` 时显示 provider key。
- 选项 value 使用 provider key。
- 操作区显示当前 active provider 的 `display_name`。
- 保存区手动实例编辑 provider 时，候选项只来自 `settings.providers`。
- 手动实例 provider 候选不再同时列出 key 和 display_name 两套重复选项。
- 历史实例 provider 如果找不到当前配置，显示原 provider 字符串。

## 提示词与控件重绘边界

V0.06 中这些操作不得触发整页重绘：

```text
点击提示词框
在提示词框输入文字
中文输入法组合输入
选择提示词文字
点击尺寸框或分辨率框
打开标签筛选下拉
搜索 TAG
打开 provider 下拉
在 provider 设置字段中输入文字
```

这些操作允许重绘：

```text
切换文生图/图生图
确认尺寸
选择分辨率后保存默认值完成
保存 provider 设置完成
删除 provider 完成
筛选保存区实例
翻页
保存实例
批量保存成功或失败
```

重绘前必须同步当前可编辑 DOM：

- 操作区提示词。
- 操作区标签草稿。
- 操作区生成路径。
- 当前编辑实例提示词。
- 当前编辑实例 provider。
- 当前编辑实例标签草稿。
