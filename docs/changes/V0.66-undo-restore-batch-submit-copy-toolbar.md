# V0.66 撤销恢复修复、撤销范围核对和批量提交复制工具栏

## 目标

当前 V0.65 已完成保存区紧凑化、状态筛选统一、状态颜色强化和输入图清除按钮对齐。本版 V0.66 目标是不新增大架构，集中解决生图管理页撤销恢复失败和保存区工具栏效率问题：

- 修复保存区清空实例标签后点击“撤销”失败的问题。
- 明确当前“撤销 / 重做”覆盖范围和暂不覆盖范围。
- 继续修正保存区实例输入图区“清除”按钮和操作区输入图区“清除”按钮竖直对齐。
- 翻页操作行去掉“删除标签”按钮。
- 翻页操作行在“删除”和“缩略图”之间新增“提交”和“复制”按钮。
- “提交”按钮功能等同保存区 `Ctrl+Enter` 批量提交。
- “复制”按钮支持批量复制已选实例为准备态实例，并纳入撤销 / 重做。

本版原则：

- 先修复撤销恢复的根因，不用表面绕过错误。
- 不扩大生图任务类操作的撤销范围，避免把外部接口调用、历史记录和文件生成混入普通撤销。
- 批量复制属于数据库创建实例，应支持撤销 / 重做。
- 批量提交属于生成任务触发，不纳入撤销 / 重做。
- 不删除电脑上的图片文件。
- 不破坏 V0.65 的状态筛选、状态颜色、准备态 / 生成态 / 失败态语义。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 撤销恢复失败修复

### 1. 清空标签后撤销报错

当前问题：

- 在生图管理页保存区中，点击实例标签框下方的“X”清空所有标签。
- 再点击“撤销”时，恢复会话快照失败。
- 报错为：

```text
恢复会话快照
失败:
UNIQUE
constraint
failed:
nodes.name
```

根因判断：

- “清空标签”本身已经纳入撤销栈。
- 撤销时前端会把清空标签前的会话快照交给后端恢复。
- 后端恢复节点时，当前逻辑会先把所有节点临时按 `parent_id = NULL` 插入，再第二轮更新真实 `parent_id`。
- 数据库存在同级节点名称唯一约束：
  - 根节点同名不允许。
  - 同一个父节点下子节点同名不允许。
- 如果快照中存在不同层级但同名的节点，临时全部插成根节点时，就会误触发根节点同名唯一约束。
- 因此这不是标签清理动作的业务错误，而是会话快照恢复器的节点恢复顺序错误。

调整方案：

- 后端恢复会话快照或导入数据时，节点不能再“全部先插成根节点再更新父节点”。
- 节点恢复应按真实父子关系插入：
  - 先插入根节点。
  - 再插入父节点已存在的子节点。
  - 对多层节点递归或拓扑排序恢复。
- 插入节点时直接使用快照中的真实 `parent_id`。
- 如果节点引用的父节点不存在，继续沿用 V0.37 的恢复规则，明确处理为根节点或记录校验修复信息，不能悄悄失败。
- 如果快照本身存在同一真实层级下的重复节点名，应给出明确错误，不应恢复出不一致数据库。
- 恢复过程必须在事务中执行：
  - 恢复成功才提交。
  - 恢复失败必须回滚，避免数据库处于半恢复状态。

验收标准：

- 对实例清空全部标签后，点击“撤销”可以恢复清空前的标签。
- 再点击“重做”可以重新清空标签。
- 节点树中存在不同层级同名节点时，撤销 / 重做不再触发 `UNIQUE constraint failed: nodes.name`。
- 恢复失败时不会留下半恢复数据。
- 数据安全页恢复旧备份仍能正常处理节点。
- 节点筛选、节点移动、节点排序、节点管理不被破坏。

副作用：

- 该修复会影响会话撤销恢复和数据安全恢复的共同恢复逻辑。
- 因此实现后需要重点回归节点树、旧备份恢复、带同名子节点的恢复。

## 撤销 / 重做覆盖范围核对

### 2. 当前已覆盖范围

当前“撤销 / 重做”主要覆盖生图管理页中已经通过会话快照包裹的数据库变更：

- 节点新建。
- 节点重命名。
- 节点删除。
- 批量添加标签。
- 批量删除标签。
- 批量删除实例。
- 批量移动实例。
- 新增准备态实例。
- 复制准备态实例。
- 删除实例。
- 移动实例。
- 新增手动 / 准备态实例。
- 添加实例标签。
- 删除单个实例标签。
- 清空实例全部标签。

V0.66 新增：

- 批量复制已选实例为准备态实例，应纳入撤销 / 重做。

### 3. 当前不覆盖范围

以下操作当前不纳入生图管理页“撤销 / 重做”：

- 保存区实例进入编辑后，修改提示词、输入图、输出图、Provider、标签、路径等并点击“保存”。
- 编辑态中尚未保存的本地草稿变化。
- 节点上下拖动排序。
- 操作区内容变化，包括提示词、输入图、路径、标签、Provider、尺寸、数量等。
- 筛选、排序、分页、每页数量、缩略图 / 列表视图等 UI 状态变化。
- 提交、重提、生成中、取消生成、失败重试等生图任务类操作。
- 设置页 Provider 新建、复制、修改、删除。
- 数据安全页导出、备份、恢复。
- 路径替换。
- 标签管理中心搜索、重命名、合并。
- 历史记录筛选、清理、带入操作区。

本版建议：

- V0.66 只修复撤销恢复机制，不大范围扩展撤销 / 重做覆盖面。
- 生成任务类操作继续不纳入撤销 / 重做。
- 如果后续要扩大范围，优先考虑：
  - 保存区实例保存编辑。
  - 节点拖动排序。
  - 标签管理中心重命名 / 合并。

原因：

- 这三类是纯数据库变更，技术上更适合纳入撤销。
- 操作区输入和筛选分页更偏 UI 状态，纳入撤销反而容易和键盘操作冲突。
- 生成任务涉及外部接口、文件和历史记录，普通撤销无法真正撤回外部调用。

验收标准：

- 文档中明确列出当前覆盖和不覆盖范围。
- 用户可以据此决定后续版本是否继续扩展撤销 / 重做范围。
- V0.66 不因为本次核对而引入大范围撤销语义变化。

副作用：

- 不扩大覆盖范围意味着部分操作仍不能通过“撤销 / 重做”恢复。
- 好处是本版风险集中在恢复器修复和保存区工具栏，不扩大不可控面。

## 输入图清除按钮对齐

### 4. 保存区和操作区输入图“清除”按钮竖直对齐

当前问题：

- V0.65 已要求保存区实例输入图区“清除”按钮与操作区输入图区“清除”按钮竖直对齐。
- 当前实际仍未对齐，保存区实例中的“清除”按钮偏左。

调整方案：

- 重新检查操作区输入图区和保存区实例输入图区的标题行布局。
- 保存区输入图区“清除”按钮不能使用手工偏移靠近。
- 保存区和操作区应使用同一列宽规则或同一右边界基准。
- 对齐目标是按钮右边界竖直一致，而不是文字起点看起来接近。
- 在保存区单列模式下必须严格对齐。
- 在保存区双列模式下，实例内部布局不能破版。

验收标准：

- 操作区输入图“清除”按钮和保存区实例输入图“清除”按钮右边界竖直对齐。
- 保存区实例的“清除”按钮不再偏左。
- 无输入图、有一张输入图、多张输入图时都稳定。
- 编辑态和只读态都稳定。
- 单列模式稳定。
- 双列模式不破版。

副作用：

- 可能需要调整输入图区标题行或网格列宽。
- 需要回归 V0.65 中 Provider 框、标签框、路径框扩宽后的整体对齐。

## 翻页操作行调整

### 5. 去掉“删除标签”按钮

当前问题：

- 翻页操作行中存在“添加标签”和“删除标签”按钮。
- 本次需要去掉“删除标签”按钮，节省空间并减少误触。

调整方案：

- 从保存区翻页操作行中移除“删除标签”按钮。
- 底层批量删除标签能力可以保留，避免影响旧事件或后续恢复入口。
- 单个实例标签仍可通过实例标签区的“X”清理。
- 标签管理中心仍保留标签整理能力。

验收标准：

- 翻页操作行不再显示“删除标签”按钮。
- “添加标签”“移动”“删除”等其他按钮位置正常。
- 旧的批量删除标签 API 或函数不因按钮移除而报错。

副作用：

- 用户不能再从翻页操作行直接批量删除标签。
- 如后续仍需要批量删除标签，可另行设计更不占空间的入口。

### 6. 新增“提交”按钮

调整位置：

- 在翻页操作行中，“删除”按钮和“缩略图”按钮之间新增“提交”按钮。
- 推荐顺序为：
  - 添加标签
  - 移动
  - 删除
  - 提交
  - 复制
  - 缩略图 / 列表
  - 路径替换

功能规则：

- “提交”按钮作用等同保存区快捷键 `Ctrl+Enter`。
- 只对当前已选实例生效。
- 没有选中实例时按钮置灰。
- 对准备态实例，执行提交。
- 对失败实例，执行重提。
- 对已有输出图的生成成功实例，跳过。
- 对生成中实例，跳过。
- 提交完成后显示统计提示：
  - 已提交多少个。
  - 已重提多少个。
  - 已跳过多少个。
- 不纳入撤销 / 重做。

验收标准：

- 选中准备态实例后点击“提交”，实例在当前位置进入生成中。
- 选中失败实例后点击“提交”，触发重提。
- 选中多个实例后点击“提交”，和 `Ctrl+Enter` 行为一致。
- 有输出图实例不会被重复提交。
- 生成中实例不会重复提交。
- 没有选择实例时按钮不可点。
- 不影响已有 `Ctrl+Enter` 快捷键。

副作用：

- 用户可以更容易批量启动多个生成任务，可能让生成队列更长。
- 仍需沿用现有并发、重试和取消机制，不能因为新增按钮绕过这些规则。

### 7. 新增“复制”按钮

调整位置：

- 在翻页操作行中，“提交”按钮右边新增“复制”按钮。
- “复制”按钮位于“删除”和“缩略图”之间。

功能规则：

- “复制”按钮对当前已选实例批量复制。
- 没有选中实例时按钮置灰。
- 每个被复制的实例生成一个新的准备态实例。
- 新实例输出图为空。
- 新实例状态为准备态。
- 新实例应保留原实例的可复用内容：
  - 提示词。
  - 输入图。
  - 标签。
  - Provider。
  - 生成路径。
  - 比例。
  - 分辨率。
  - 尺寸。
  - 数量 `n`。
  - 调用方式和 model 等可用生成参数。
- 新实例不复制原实例的输出图。
- 新实例不复制原实例的失败错误状态。
- 新实例不复制生成中任务状态。
- 生成中实例应跳过或禁止复制，避免复制不稳定任务中间态。
- 批量复制应纳入撤销 / 重做。

验收标准：

- 选中一个实例点击“复制”，生成一个内容相同但输出图为空的准备态实例。
- 选中多个实例点击“复制”，每个实例各复制一个准备态实例。
- 复制出来的实例保留尺寸，不再出现尺寸为空的问题。
- 复制出来的实例保留标签、Provider、路径、输入图、比例、分辨率、数量。
- 复制出来的实例可以继续点击“提交”生成。
- 批量复制后点击“撤销”，复制出的准备态实例被移除。
- 再点击“重做”，复制出的准备态实例恢复。
- 生成中实例不会被复制为不完整状态。

副作用：

- 批量复制会快速增加实例数量，可能影响当前页分页和排序。
- 需要明确复制完成后当前选择是否清空，建议沿用现有批量操作规则，复制完成后清空选择，避免误删误提交。
- 复制多个带多张输入图的实例时，需要确认输入图路径引用完整，不复制电脑上的原图文件。
