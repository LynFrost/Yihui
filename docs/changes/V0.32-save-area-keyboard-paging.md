## 修改目标

V0.32 在 V0.31 基础上做两个小范围收口：

- 保存区获得交互焦点时，键盘左右方向键可以执行上一页 / 下一页。
- 将保存区 `新增` 按钮从原来的筛选工具栏中拿掉，移动到 `清空选择` 右边，并让它更醒目。

本版重点是交互便利性，不改保存区数据结构，不改图片加载架构，不改节点管理逻辑。

## 不做内容

V0.32 不做以下内容：

- 不修改数据库 schema。
- 不修改后端分页查询逻辑。
- 不修改保存区搜索、标签筛选、来源筛选、方式筛选、排序、每页数量的业务逻辑。
- 不修改节点筛选、节点移动、批量移动逻辑。
- 不修改 V0.31 图片稳定显示机制。
- 不修改图片弹窗左右切换逻辑。
- 不修改撤销 / 重做作用范围。
- 不新增跨页批量选择。
- 不新增新的快捷键设置页。
- 不重拆 JS 模块。

## 保存区左右方向键翻页

### 基本行为

当当前交互焦点在保存区范围内时：

- 按键盘 `ArrowLeft` 切换到上一页。
- 按键盘 `ArrowRight` 切换到下一页。
- 当前已经是第一页时，按 `ArrowLeft` 不翻页。
- 当前已经是最后一页时，按 `ArrowRight` 不翻页。

翻页必须复用现有分页函数：

```javascript
changeSavePage(-1);
changeSavePage(1);
```

不要另写一套分页逻辑。

复用现有分页函数后，必须继续继承以下既有行为：

- 翻页后清空当前页批量选择。
- 翻页后保存 UI 状态。
- 翻页后重新加载当前页实例。
- 翻页后重新渲染保存区。
- 翻页后沿用 V0.31 的图片稳定显示检查。
- 翻页后避免出现图片空白。

### 保存区交互焦点定义

本版说的“焦点在保存区”，不只等于 `document.activeElement` 在保存区内。

因为保存区中有大量卡片、空白区域、图片位和按钮区域，用户点击这些区域后，浏览器焦点可能仍然停在 `body` 或之前的按钮上。因此需要增加一个前端临时状态来记录保存区交互焦点。

建议在 `frontend/js/state.js` 中增加：

```javascript
saveAreaKeyboardFocus: false
```

该状态只表示键盘左右键是否应该交给保存区翻页使用：

- 不写入数据库。
- 不写入 UI 持久化配置。
- 刷新页面后默认 `false`。
- 离开生图管理页后应清为 `false`。

### 焦点进入保存区

以下情况应将 `state.saveAreaKeyboardFocus` 设为 `true`：

- 点击保存区实例卡片。
- 点击保存区实例之间或下方的保存区空白区域。
- 点击保存区分页区域。
- 点击保存区批量工具栏。
- 点击保存区节点筛选区域，但节点下拉菜单打开期间不触发左右键翻页。
- 通过键盘 `Tab` 聚焦到保存区内按钮或控件。

建议在 `frontend/js/events.js` 中使用捕获阶段监听：

```javascript
document.addEventListener("pointerdown", handleSaveAreaFocusPointerDown, true);
document.addEventListener("focusin", handleSaveAreaFocusIn, true);
```

判断目标是否在保存区范围内：

```javascript
target.closest("[data-save-area]")
```

如果点击目标位于弹窗、图片查看器、下拉菜单内部，不应因此开启保存区键盘翻页。

### 焦点离开保存区

以下情况应将 `state.saveAreaKeyboardFocus` 设为 `false`：

- 点击生图管理页保存区之外的区域。
- 点击操作区。
- 点击设置页、历史记录页、数据安全页。
- 打开图片弹窗。
- 打开批量操作弹窗。
- 打开确认弹窗。
- 打开会接管键盘输入的下拉菜单或输入浮层。
- 当前页面不在生图管理页。

如果用户只是点击保存区内某个实例按钮，例如编辑、保存、删除、复制提交、移动、添加 TAG，不应清除保存区交互焦点；但这些按钮自身的点击行为仍然按原逻辑执行。

## 避让规则

保存区左右键翻页必须非常谨慎，不能抢走文字编辑、弹窗、下拉菜单、图片查看器的左右键。

### 输入类控件避让

当事件目标位于以下元素中时，`ArrowLeft` / `ArrowRight` 只移动光标，不触发保存区翻页：

- `input`
- `textarea`
- `select`
- `[contenteditable="true"]`
- 搜索框
- 提示词框
- TAG 输入框
- 节点重命名输入框
- 弹窗输入框
- 自定义代码编辑框
- 调用示例编辑框

建议增加统一判断：

```javascript
function isTextEditingTarget(target) {
  return Boolean(
    target?.closest?.(
      "input, textarea, select, [contenteditable='true'], .prompt-input, .tag-search-input, .dialog input, .dialog textarea"
    )
  );
}
```

具体选择器以 V0.31 实际 DOM 类名为准，不要为了这版改动重命名大量已有类名。

### 图片弹窗避让

当图片弹窗打开时：

- `ArrowLeft` 继续用于切换上一张图片。
- `ArrowRight` 继续用于切换下一张图片。
- 不触发保存区翻页。

全局 `keydown` 处理顺序必须保证图片弹窗优先。

建议顺序：

1. `Ctrl+Enter` 生成。
2. `Escape`、弹窗、菜单关闭逻辑。
3. 图片弹窗 `ArrowLeft` / `ArrowRight` 切图逻辑。
4. 保存区 `ArrowLeft` / `ArrowRight` 翻页逻辑。

如果 `state.lightbox.path` 存在，保存区翻页逻辑不得执行。

### 下拉菜单和弹窗避让

以下任一 UI 层打开时，不触发保存区左右键翻页：

- 节点下拉菜单。
- 节点右键菜单。
- TAG 下拉菜单。
- 标签选择器。
- 批量添加标签弹窗。
- 批量删除标签弹窗。
- 批量移动弹窗。
- 删除确认弹窗。
- 数据恢复确认弹窗。
- 任意 `.modal`、`.dialog`、`.popover` 类弹层。

建议增加统一判断：

```javascript
function hasBlockingSaveAreaKeyboardLayer() {
  return Boolean(
    state.lightbox.path ||
    state.nodeMenu?.open ||
    state.nodeContextMenu?.open ||
    document.querySelector(".modal.is-open, .dialog.is-open, .popover.is-open, [data-floating-menu='open']")
  );
}
```

实际字段和选择器以 V0.31 当前代码为准。

### 修饰键避让

以下情况不触发保存区翻页：

- `Ctrl + ArrowLeft`
- `Ctrl + ArrowRight`
- `Shift + ArrowLeft`
- `Shift + ArrowRight`
- `Alt + ArrowLeft`
- `Alt + ArrowRight`
- `Meta + ArrowLeft`
- `Meta + ArrowRight`

原因：

- 系统或浏览器可能已经使用这些组合键。
- 文本输入中这些组合键常用于选择文字或移动光标。
- V0.21 的 `Ctrl+Enter` 生图逻辑不能被影响。

## 翻页边界与状态处理

### 页码边界

左右键翻页前必须读取当前分页状态：

- 当前页 `page`
- 总页数 `totalPages`

规则：

- `page <= 1` 时，`ArrowLeft` 不执行任何翻页请求。
- `page >= totalPages` 时，`ArrowRight` 不执行任何翻页请求。
- `totalPages <= 1` 时，左右键都不执行翻页请求。

不要通过触发按钮点击来实现边界判断，直接复用状态和 `changeSavePage()`。

### 翻页后的图片稳定检查

键盘翻页和点击分页按钮必须共享同一套后续流程。

因此键盘翻页不应该直接调用 `loadInstances()` 或 `renderManager()`，而是调用现有：

```javascript
changeSavePage(-1);
changeSavePage(1);
```

这样可以继续走 V0.31 已经封闭的图片稳定显示检查：

- 当前页 DOM 渲染后主动检查图片。
- 当前页可见图片优先加载。
- 疑似空白图片有限重试。
- 不取消懒加载。

### 批量选择状态

键盘翻页后必须沿用 V0.27 规则：

- 清空当前页批量选择。
- 不保留上一页的勾选状态。
- 不跨页全选。

该行为应由现有 `setSavePage()` 或 `changeSavePage()` 内部完成，V0.32 不另写清空逻辑。

### 撤销 / 重做不受影响

键盘左右键翻页不能改变 V0.30 / V0.31 的撤销 / 重做规则。

要求：

- 不新增 `Ctrl+Z`。
- 不新增 `Ctrl+Y`。
- 不修改 `撤销` 按钮 action。
- 不修改 `重做` 按钮 action。
- 不把键盘翻页写入撤销栈。

## “新增”按钮移动

### 当前问题

保存区的 `新增` 按钮当前位于筛选工具栏的动作区中。V0.32 将它移动到批量工具栏中，放在 `清空选择` 的右边，减少上方筛选行拥挤，并让新增入口更贴近保存区批量操作区域。

### 新位置

在 `frontend/js/render-save.js` 中调整渲染：

原筛选工具栏 `.toolbar-actions` 中不再渲染：

```html
<button type="button" data-action="new-manual-instance">新增</button>
```

批量工具栏中，`清空选择` 右边新增：

```html
<button type="button" class="new-instance-button" data-action="new-manual-instance">新增</button>
```

布局顺序建议为：

```text
全选当前页  清空选择  新增  批量添加标签  批量删除标签  批量移动  批量删除  撤销  重做  总数  首页  上一页  第 x / y 页  下一页  尾页
```

如果当前实际顺序略有不同，以 V0.31 批量工具栏结构为准，但必须满足：

- `新增` 紧挨 `清空选择` 右边。
- `新增` 不再出现在原筛选工具栏动作区。
- `新增` 仍然使用 `data-action="new-manual-instance"`。
- `新增` 始终可点击。
- `新增` 不依赖当前是否选中实例。
- `新增` 不受 `清空选择` 置灰状态影响。

### 样式要求

`新增` 按钮要比普通批量按钮更醒目，但不能像危险操作。

要求：

- 不使用红色。
- 不和 `批量删除` 混淆。
- 可以使用主色边框或浅色主色背景。
- 高度与同一行其他按钮一致。
- 字体大小与同一行按钮一致。
- 在窄屏下不造成横向溢出。

建议在 `frontend/css/05-save-area.css` 增加：

```css
.new-instance-button {
  border-color: var(--color-primary);
  background: var(--color-primary-soft);
  color: var(--color-primary-strong);
  font-weight: 600;
}

.new-instance-button:hover {
  background: var(--color-primary-soft-hover);
}
```

具体变量名以 V0.25 之后的 `frontend/css/00-variables.css` 为准；如果没有完全对应变量，应使用已有主色变量，不为这一个按钮新增过多颜色体系。

### 交互保持

移动按钮位置后，功能保持不变：

- 点击后新增手动实例。
- 不自动进入生成流程。
- 不删除或移动任何图片文件。
- 不影响批量选择。
- 不影响当前筛选条件。
- 不影响节点筛选路径。

如果当前筛选处于某个节点下，新增手动实例的节点归属继续沿用 V0.29 / V0.30 规则，不在 V0.32 改动。

## 副作用与控制

### 键盘事件副作用

可能副作用：

- 左右方向键可能误触发保存区翻页。
- 输入框内移动光标可能被误拦截。
- 图片弹窗左右切换可能被保存区翻页抢走。
- 下拉菜单打开时可能误翻页。

控制方式：

- 只在保存区交互焦点为 `true` 时启用。
- 输入类控件一律避让。
- 图片弹窗优先处理。
- 弹窗、下拉菜单、浮层打开时一律避让。
- 不处理带修饰键的左右方向键。

### 保存区焦点状态副作用

可能副作用：

- 用户点击保存区后，再点击页面其他区域，如果状态没有清掉，左右键可能仍然翻页。

控制方式：

- 捕获阶段监听页面点击。
- 点击保存区外部时清除 `saveAreaKeyboardFocus`。
- 切换页面时清除 `saveAreaKeyboardFocus`。
- 打开弹窗或图片查看器时暂停保存区键盘翻页。

### 新增按钮移动副作用

可能副作用：

- 用户需要适应 `新增` 的新位置。
- 批量工具栏按钮变多，窄屏下可能拥挤。

控制方式：

- `新增` 放在 `清空选择` 右边，仍然在保存区顶部工具区域。
- 样式更醒目，降低找不到入口的概率。
- 不改变 `data-action` 和实际功能。
- 使用现有响应式换行能力，避免横向溢出。
