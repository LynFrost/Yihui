## 修改目标

V0.29 在 V0.28 基础上做保存区稳定性修复，并新增保存区节点管理。

主要目标：

- 修复生成中实例翻页后读秒卡住的问题。
- 再次修复保存区翻页后图片偶发不显示的问题，保留懒加载。
- 保存区实例 TAG 弹出页支持点击外部关闭。
- 修复实例 TAG 框 X 清空后弹出页误开、旧 TAG 又恢复的问题。
- TAG 下拉选项按保存区中相同 TAG 使用数量倒序排列。
- 保存区分页总数和分页按钮移动到批量工具栏同一行右侧。
- 新增节点管理功能，支持按用户自建节点路径管理实例。
- 生成、复制提交、重新提交产生的实例进入当前所选节点。
- 保存区实例新增 `移动` 按钮。
- 保存区批量工具栏新增 `批量移动`。

## 节点数据结构

新增 `nodes` 表：

```sql
CREATE TABLE IF NOT EXISTS nodes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_id INTEGER REFERENCES nodes(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  position INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(parent_id, name)
);
```

为 `instances` 表新增字段：

```sql
ALTER TABLE instances ADD COLUMN node_id INTEGER REFERENCES nodes(id) ON DELETE SET NULL;
```

新增索引：

```sql
CREATE INDEX IF NOT EXISTS idx_nodes_parent_position ON nodes(parent_id, position, id);
CREATE INDEX IF NOT EXISTS idx_instances_node_id ON instances(node_id);
```

节点名规则：

- 同一父节点下不能重名。
- 节点名去掉前后空格后不能为空。
- 同一父节点下禁止使用以下保留名称：

```text
全部
其他
新建
```

旧实例迁移规则：

- 旧实例 `node_id` 默认为 `NULL`。
- `node_id = NULL` 的实例在根层级显示为 `其他`。
- 迁移不改变实例提示词、图片路径、TAG、历史记录、Provider 参数快照。

## 节点含义

保存区顶部新增节点管理区域。

节点管理从根层级开始，每一层显示一个下拉菜单。用户选择某个真实节点后，右侧出现下一层下拉菜单。

每个下拉菜单包含：

```text
全部
其他
新建
用户自建节点...
```

含义：

- `全部`：当前层级下的全部实例，包括当前层级自身未进入子节点的实例，以及所有子节点和更深子节点中的实例。
- `其他`：当前层级下还没有分配到下一级节点的实例。
- `新建`：在当前层级新建一个子节点。
- 用户自建节点：进入该节点，并在右侧显示下一层下拉菜单。

当前节点路径示例：

```text
全部
人像
人像 / 写实
人像 / 写实 / 女性
```

节点路径状态保存在前端 UI 状态中，关闭网页再打开后恢复。

如果恢复时某个节点已被删除：

- 保留可恢复的上级路径。
- 删除不存在节点及其后续层级。
- 自动刷新保存区。

## 节点筛选后端查询

`backend/database.py` 的 `list_instances()` 增加节点筛选参数：

```text
node_filter_type
node_id
```

取值：

```text
node_filter_type = all / unassigned / node
node_id = 当前真实节点 id 或空
```

查询规则：

1. 根层级 `全部`

```text
node_filter_type = all
node_id = 空
```

返回全部实例。

2. 根层级 `其他`

```text
node_filter_type = unassigned
node_id = 空
```

返回 `instances.node_id IS NULL` 的实例。

3. 选择真实节点后的 `全部`

```text
node_filter_type = all
node_id = 当前节点 id
```

返回当前节点及所有后代节点下的实例。用 SQLite 递归 CTE 查询：

```sql
WITH RECURSIVE subtree(id) AS (
  SELECT ?
  UNION ALL
  SELECT nodes.id
  FROM nodes
  JOIN subtree ON nodes.parent_id = subtree.id
)
SELECT instances.*
FROM instances
WHERE instances.node_id IN (SELECT id FROM subtree)
```

4. 选择真实节点后的 `其他`

```text
node_filter_type = unassigned
node_id = 当前节点 id
```

返回 `instances.node_id = 当前节点 id` 的实例。这里的“其他”表示已经分配到当前节点，但还没有分配到当前节点的子节点。

5. 选择真实节点本身

```text
node_filter_type = node
node_id = 当前节点 id
```

进入该节点路径后，默认下一层显示 `全部`，查询等同“选择真实节点后的全部”。

节点筛选必须和已有筛选叠加：

- 提示词搜索
- TAG 筛选
- 来源筛选
- 方式筛选
- 日期筛选
- 排序
- 每页数量
- 分页

筛选或节点路径变化后：

- `state.filters.page = 1`
- 清空当前页批量选择
- 保存 UI 状态
- 刷新保存区

## 节点 API

在 `backend/api.py` 中新增节点接口。

### 获取节点树

```http
GET /api/nodes
```

返回：

```json
{
  "items": [
    {
      "id": 1,
      "parent_id": null,
      "name": "人像",
      "position": 1,
      "children": []
    }
  ]
}
```

节点按：

```text
position ASC, id ASC
```

排序。

### 新建节点

```http
POST /api/nodes
```

请求：

```json
{
  "parent_id": 1,
  "name": "写实"
}
```

根层级新建时：

```json
{
  "parent_id": null,
  "name": "人像"
}
```

返回新建节点和完整节点树。

### 重命名节点

```http
PATCH /api/nodes/<node_id>
```

请求：

```json
{
  "name": "新名称"
}
```

V0.29 可以先不在 UI 暴露重命名入口，但后端可同时补齐，方便后续版本使用。

### 删除节点

```http
DELETE /api/nodes/<node_id>
```

V0.29 可以先不在 UI 暴露删除入口，避免误删节点结构。后端可先不实现删除。

如果实现删除，必须二次确认，并且只删除节点结构，不删除图片文件；该节点及子节点下实例的 `node_id` 改为被删除节点的父节点，或改为 `NULL`。V0.29 默认不做节点删除。

### 移动单个实例

```http
POST /api/instances/<instance_id>/move
```

请求：

```json
{
  "node_id": 3
}
```

移动到根层级其他：

```json
{
  "node_id": null
}
```

返回更新后的实例。

生成中实例不允许移动，返回 400：

```json
{
  "error": "生成中实例不能移动节点"
}
```

### 批量移动实例

```http
POST /api/instances/batch/move
```

请求：

```json
{
  "ids": [1, 2, 3],
  "node_id": 5
}
```

返回：

```json
{
  "updated": 3
}
```

批量移动规则：

- 只移动正常实例和失败实例。
- 跳过 `generation_status = running` 的实例。
- 不删除图片文件。
- 不改变提示词、图片路径、TAG、Provider、历史记录。

## 新实例进入当前节点

前端保存当前节点路径状态：

```javascript
state.nodeFilter = {
  path: [
    {
      node_id: 1,
      selection: "node"
    },
    {
      node_id: 3,
      selection: "all"
    }
  ]
}
```

实际实现时可以用更简单结构，但必须能表达：

- 当前真实节点路径。
- 每一层选择的是 `全部`、`其他`、`新建`、还是某个真实节点。

新实例归属规则：

- 如果当前路径中存在至少一个真实节点，则新实例的 `node_id` 使用最深的真实节点 id。
- 如果当前路径只在根层级选择 `全部` 或 `其他`，则新实例的 `node_id = NULL`。

以下操作创建或更新生成实例时都要传入 `node_id`：

- 操作区点击 `生成`
- 保存区普通实例点击 `复制提交`
- 保存区失败实例点击 `重新提交`

后端 `api_generate()` 在预创建 `running` 实例时写入 `node_id`。

失败实例 `重新提交` 的规则：

- 不新增实例。
- 原实例保留原节点不变，除非请求明确传入新的 `node_id`。
- V0.29 中重新提交使用当前所选节点，因此失败实例重新提交时应把该失败实例移动到当前节点后再跑生成。

## 生成中读秒修复

V0.28 的问题是读秒刷新基于临时实例 id。翻页后数据库 `running` 实例和前端临时实例合并显示，DOM id 可能变为真实实例 id，导致计时器找不到节点。

V0.29 改为基于稳定键刷新读秒：

```text
generation_task_id + generation_output_index
```

前端新增工具函数：

```javascript
function runningInstanceKey(item) {
  const taskId = item?.generation_task_id || item?.task_id || "";
  const outputIndex = item?.generation_output_index || item?.output_index || 1;
  return taskId ? `${taskId}:${outputIndex}` : "";
}
```

渲染生成中实例时，读秒节点写入：

```html
<strong
  data-pending-elapsed-key="task-id:1"
  data-pending-start-ms="123456.7"
>
  1.2 s
</strong>
```

输出图区的生成中状态也使用相同 key：

```html
<span
  data-pending-elapsed-key="task-id:1"
  data-pending-start-ms="123456.7"
>
  1.2 s
</span>
```

读秒刷新函数改为：

1. 查询所有 `[data-pending-elapsed-key]`。
2. 从节点读取 `data-pending-start-ms`。
3. 如果节点没有开始时间，从 `state.pendingStartedAtByKey` 中读取。
4. 如果仍然没有，则用当前时间初始化。
5. 每 100ms 刷新文字。

`state.pendingStartedAtByKey` 保存：

```javascript
state.pendingStartedAtByKey = new Map();
```

合并前端临时实例和数据库 `running` 实例时：

- 用 `runningInstanceKey()` 合并。
- 保留最早的 `started_at_ms`。
- 如果数据库实例有 `generation_started_at`，用它换算开始时间。
- 如果前端已有同 key 开始时间，优先用前端开始时间。

页面翻页、筛选、排序、每页数量变化、重新渲染保存区后：

- 必须调用 `startPendingTimer()`。
- `startPendingTimer()` 发现已有计时器时不重复创建。
- 当前页面没有生成中实例，但 `state.pendingInstances` 或数据库返回中仍有 running 时，不停止计时器。
- 只有前端没有 pending，当前页也没有 running，且没有进行中的 generation task 时，才停止计时器。

生成成功、失败、取消或页面刷新后：

- 清理对应 `state.pendingStartedAtByKey` key。
- 不留下多余定时器。

## 图片翻页稳定显示修复

V0.29 保留懒加载，但不只依赖浏览器原生 `loading="lazy"`。

新增保存区图片加载管理器，建议放在：

```text
frontend/js/image-loader.js
```

如果不新增文件，也可以继续放在 `frontend/js/actions-manager.js`，但要保持函数边界清楚。

加载规则：

1. 保存区图片节点继续带：

```html
data-lazy-image-path="本地图片路径"
```

2. 渲染后调用：

```javascript
stabilizeSaveAreaImages({ forceVisible: true });
```

3. `stabilizeSaveAreaImages()` 做以下事情：

- 重新扫描当前保存区所有 `[data-lazy-image-path]`。
- 为当前页图片重新绑定 `IntersectionObserver`。
- 对已经在可视区或接近可视区的图片立即设置 `src`。
- 对 `img.complete === false` 且没有 `src` 的图片立即设置 `src`。
- 对 `img.complete === true` 但 `naturalWidth === 0` 的图片重设 `src`。
- 对 `error` 图片允许追加轻量 cache bust 参数重试一次。

4. 监听以下事件后再次唤醒当前页图片：

```javascript
window.addEventListener("scroll", wakeVisibleSaveImages, { passive: true });
window.addEventListener("resize", wakeVisibleSaveImages);
window.addEventListener("focus", wakeVisibleSaveImages);
document.addEventListener("visibilitychange", wakeVisibleSaveImages);
```

5. 翻页动作完成后必须执行：

```javascript
await loadInstances();
renderManager();
stabilizeSaveAreaImages({ forceVisible: true });
```

6. 不允许为了修复该问题取消懒加载。

7. 图片弹窗、左右切换、悬停预览继续使用原始图片路径，不使用 cache bust 后的展示 URL 作为图片路径。

## TAG 弹出页关闭与 X 修复

### 点击外部关闭

统一关闭规则：

- 点击 `.tag-selector` 外部，关闭所有实例和操作区 TAG 选择器。
- 点击 `.tag-selector-menu` 内部不关闭。
- 点击 TAG 选项后按现有逻辑添加 TAG。
- 点击弹窗、图片查看器、路径替换、批量操作弹窗内部不触发关闭。

`events.js` 中点击处理顺序：

1. 先识别当前点击是否在 `.tag-selector` 内。
2. 如果不在 `.tag-selector` 内，执行 `closeTagSelectors()`。
3. 如果关闭了选择器，重新渲染当前页。
4. 不阻止后续目标按钮自己的正常点击，除非该点击只是为了关闭浮层。

### 实例 TAG 框 X 清空

当前实例 TAG 是即时保存，因此清空也必须即时同步后端。

为实例清空 TAG 新增接口：

```http
POST /api/instances/<instance_id>/tags/clear
```

返回：

```json
{
  "item": {},
  "tags": []
}
```

实现规则：

- 只删除当前实例与 TAG 的关联。
- 不删除 `tags` 表中的 TAG 名称。
- 不删除图片文件。
- 不影响其他实例上的同名 TAG。

前端 `clearTagSelector(scope, instanceId)` 规则：

- `scope = operation` 时，只清空操作区 TAG，保留原本逻辑。
- `scope = instance` 时，调用 `/api/instances/<id>/tags/clear`。
- 成功后更新当前实例的 `tags = []`。
- 成功后 `tag_selector_open = false`。
- 不自动打开 TAG 弹出页。
- 不把旧 TAG 从数据库重新带回来。

`clear-tag-selector` 按钮点击后必须 `event.stopPropagation()` 或在 action 处理中显式避免再次触发 `open-tag-selector`。

## TAG 选项排序

后端 `list_tags()` 改为返回按使用数量排序。

排序规则：

```sql
ORDER BY usage_count DESC, tags.name COLLATE NOCASE ASC
```

只统计保存区真实实例上的 TAG 关联：

- 包含正常实例。
- 包含失败实例。
- 不包含生成中实例。
- 不包含虚拟筛选项 `__untagged__`。

API 可以保持返回：

```json
{
  "items": ["常用TAG", "较少TAG"]
}
```

如需前端显示数量，可额外返回：

```json
{
  "items": ["常用TAG", "较少TAG"],
  "counts": {
    "常用TAG": 12,
    "较少TAG": 3
  }
}
```

V0.29 只要求排序，不要求显示数量。

该排序影响：

- 保存区标签筛选下拉。
- 操作区添加标签下拉。
- 保存区实例添加标签下拉。
- 批量添加标签弹窗。
- 批量删除标签弹窗。

## 前端状态持久化

`frontend/js/persistence.js` 中新增保存：

```javascript
node_filter_path
```

示例：

```json
[
  {"node_id": 1, "selection": "node"},
  {"node_id": 3, "selection": "all"}
]
```

恢复规则：

- 如果节点树中存在该节点，恢复。
- 如果某个节点不存在，截断到上一级可用路径。

- 移动弹窗打开状态。

## 风险与处理

### 数据库 schema 升级风险

V0.29 新增 `nodes` 表和 `instances.node_id` 字段，会改变共享数据库结构。

处理：

- 迁移前自动备份。
- 迁移失败不写 schema_version。
- 旧实例默认 `node_id = NULL`。
- 旧版本 V0.28 不认识节点功能，升级后建议继续使用 V0.29 管理数据。

### 节点筛选性能风险

节点 `全部` 需要递归查询后代节点。

处理：

- 增加 `idx_nodes_parent_position`。
- 增加 `idx_instances_node_id`。
- 保存区继续分页。
- 不把全部实例拉到前端筛选。

### 读秒状态风险

翻页和后端 running 合并会改变实例 id。

处理：

- 读秒统一按 `generation_task_id + generation_output_index`。
- DOM 节点保存 `data-pending-elapsed-key`。
- 计时器扫描 DOM 节点刷新，不依赖单个临时实例 id。

### 图片加载风险

快速翻页后浏览器原生 lazy load 可能不立即触发。

处理：

- 使用 `IntersectionObserver`。
- 翻页后主动唤醒当前页图片。
- 浏览器 tab focus 和 visibilitychange 时再次检查。
- 不取消懒加载。

### TAG 即时保存风险

TAG 已经允许非编辑状态操作，清空 TAG 如果只改前端会被后端旧数据覆盖。

处理：

- 实例 TAG 清空必须调用后端接口。
- 清空后关闭弹出页。
- 清空只删除当前实例关联，不删除 TAG 名称和图片文件。

### UI 拥挤风险

节点管理、批量移动、分页工具都在保存区顶部增加控件。

处理：

- 保存区顶部允许换行。
- 分页组靠右。
- 节点路径单独占一行或在窄屏自动换行。
- 不出现横向滚动条。
