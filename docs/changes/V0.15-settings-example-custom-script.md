## 生图管理 UI 影响边界

V0.15 允许修改“生图管理”页以下内容：

- 操作区切换为图生图时，数量输入框固定显示 `1`，禁用并置灰。

V0.15 不得修改“生图管理”页以下布局：

- 文生图和图生图的提示词、输入图、尺寸、清晰度、输出图、标签、生成路径、按钮位置。
- 保存区实例卡片宽度、高度规则、单列和双列布局规则。
- 保存区实例中图片框、提示词框、标签区、按钮区的位置和尺寸。

## 设置页参数置灰

设置页 `OpenAI API 参数` 区域中，所有不可编辑参数必须有清晰的禁用状态。

实现规则：

- 禁用输入框使用灰色背景、灰色文字和禁用鼠标样式。
- 禁用下拉框使用同样灰色禁用样式。
- 不可编辑参数的输入框内显示来源文字，例如 `来自软件` 或固定值。
- 不在参数右侧额外显示 `来自软件` 说明。

来自软件的参数：

```text
prompt
size
n
保存路径
image / input_images
```

其中：

- `prompt` 来自操作区提示词。
- `size` 来自操作区长宽比 + 清晰度换算后的 `resolved_size`。
- `n` 来自操作区数量；图生图时固定为 `1`。
- `保存路径` 来自操作区生成路径。
- `image / input_images` 来自操作区输入图；只在图生图参数表中显示。

## 调用方式与生图方式

`OpenAI API 参数` 区域第一行放两个控件：

```text
调用方式    生图方式
```

`调用方式` 可选值：

```text
gpt-image-2
response
```

`生图方式` 可选值：

```text
文生图
图生图
```

实现规则：

- `生图方式` 放在 `调用方式` 右边。
- `生图方式` 只影响设置页参数表和调用示例展示。
- 真正点击生成时，仍以“生图管理”页操作区当前的 `文生图 / 图生图` 为准。
- Provider 配置中保存 `openai_example_mode`，可选值为 `text_to_image`、`image_to_image`。
- 旧 Provider 没有 `openai_example_mode` 时，默认补齐为 `text_to_image`。
- `调用方式 = response` 时，同样显示 `生图方式` 控件，并根据文生图 / 图生图切换参数表和示例区域；具体 response 示例内容可以先用占位模板。

当：


参数规则：

- `prompt` 禁用，输入框内显示 `来自软件`。
- `size` 禁用，输入框内显示 `来自软件`。
- `n` 禁用，输入框内显示 `来自软件`。
- `保存路径` 禁用，输入框内显示 `来自软件`。
- `quality` 下拉选项：`low`、`medium`、`high`、`auto`，默认 `high`。
- `output_format` 下拉选项：`png`、`jpeg`、`webp`，默认 `png`。
- `output_compression` 数字输入范围 `0-100`。
- 当 `output_format = png` 时，`output_compression` 禁用并置灰。
- 当 `output_format = jpeg` 或 `webp` 时，`output_compression` 可编辑。
- `background` 下拉选项：`auto`、`opaque`，默认 `auto`。
- `moderation` 下拉选项：`auto`、`low`，默认 `low`。
- `user` 可选文本框，默认留空。

## 操作区图生图数量固定

当操作区模式为：

```text
图生图
```

数量框行为：

- 显示 `1`。
- 禁用输入。
- 使用置灰样式。
- 不允许编辑。
- 不保存 `1` 为全局默认数量。

当操作区切回：

```text
文生图
```

数量框行为：

- 恢复切换前的文生图数量。
- 如果没有临时记忆值，使用全局默认数量。
- 文生图数量修改后继续保存为全局默认数量。

后端生成规则：

- `mode = image_to_image` 时，强制 `n = 1`。
- `mode = text_to_image` 时，继续使用操作区传入的 `n`。
- 保存生成参数时，图生图实例保存 `n = 1`。

## 自定义脚本执行变量

执行自定义代码前，软件生成并注入以下 Python 变量：

```python
base_url
api_key
operation_prompt
resolved_size
n
output_dir
output_path
result_json_path
input_images
mode
quality
output_format
output_compression
background
moderation
user
```

变量规则：

- `base_url` 来自 Provider 连接信息。
- `api_key` 优先使用 Provider 的 `api_key`，如果为空则读取 `api_key_env` 指向的环境变量。
- `operation_prompt` 来自操作区提示词。
- `resolved_size` 来自操作区尺寸换算结果。
- `n` 来自操作区数量；图生图时强制为 `1`。
- `output_dir` 来自操作区生成路径。
- `output_path` 必须由软件生成。
- `result_json_path` 必须由软件生成。
- `input_images` 来自操作区输入图路径列表。
- `mode` 是当前操作区模式，值为 `text_to_image` 或 `image_to_image`。
- `quality`、`output_format`、`output_compression`、`background`、`moderation`、`user` 来自 Provider 设置。

## 自定义脚本输出规则

`output_path` 必须来自软件。

自定义脚本必须把至少一张最终图片写入软件提供的 `output_path`，或者在 `result_json_path` 中声明输出路径。

多图输出规则：

- 脚本可以根据 `n` 生成 1 张或多张图片。
- 多图输出时，脚本可以基于软件提供的 `output_path` 派生路径，例如：

```python
output_path
output_path_2
output_path_3
```

- 软件不需要提前注入 `output_path_2`、`output_path_3` 变量；脚本可以自己基于 `output_path` 的文件名派生。
- 脚本必须把所有最终输出路径写入 `result_json_path`。

`result_json_path` 格式：

```json
{
  "output_paths": [
    "D:/AI/out/one.png",
    "D:/AI/out/two.png"
  ]
}
```

软件读取规则：

- 如果 `result_json_path` 存在，优先读取其中的 `output_paths`。
- 如果 `result_json_path` 不存在，检查 `output_path` 是否存在。
- 如果两者都没有，判定生成失败。
- `output_paths` 中每个路径都必须存在。
- `output_paths` 中每个路径都必须在 `output_dir` 目录下。
- `output_paths` 中每个路径都必须是图片扩展名。
- 不接受脚本保存到任意其他目录的结果。

允许的图片扩展名：

```text
.png
.jpg
.jpeg
.webp
```

如果返回多张图：

- 沿用现有保存规则。
- 保存区拆成多个实例。
- 每个实例一张输出图。
- 输入图、提示词、标签、Provider、生成参数继承。

## 自定义脚本执行方式

自定义代码必须使用独立 Python 子进程执行。

执行规则：

- 不在 Flask 主进程中直接 `exec` 用户代码。
- 运行前将用户代码写入临时脚本文件。
- 运行前将参数写入临时 JSON 文件。
- 临时脚本加载参数 JSON 后执行用户代码。
- 捕获标准输出和标准错误。
- 设置超时时间，建议默认 `180` 秒。
- 超时后终止子进程。
- 执行结束后删除临时脚本文件和临时参数文件。
- `result_json_path` 可以保留到读取完成后删除。

如果脚本失败：

- 不创建保存区实例。
- 不写入数据库。
- 不吞掉错误。
- 在操作区现有状态区域显示错误。

错误类型包括：

- 子进程退出码非 0。
- 脚本超时。
- 缺少输出图片。
- 输出路径不在 `output_dir` 下。
- 输出文件扩展名不是图片格式。
- `result_json_path` 不是合法 JSON。
- `output_paths` 不是列表。

## 自定义脚本安全说明

自定义脚本等于运行本机 Python。

它可以：

- 读取本机文件。
- 写入本机文件。
- 调用网络。
- 覆盖文件。
- 安装或调用本机已有 Python 包。

软件只做以下保护：

- 独立子进程执行。
- 超时终止。
- 错误捕获。
- 输出路径检查。
- 只接受 `output_dir` 下的输出图片。

软件不做完整安全沙箱。

设置页自定义代码区域必须显示醒目提示，提醒用户谨慎使用。

## 后端生成流程

点击生成时：

1. 后端读取当前 Provider 配置。
2. 后端根据当前操作区 `mode` 决定实际生图方式。
3. 后端根据 Provider 的 `openai_call_method` 和当前 `mode` 查找对应自定义代码。
4. 如果自定义代码非空，走自定义脚本执行。
5. 如果自定义代码为空，走现有软件内置 Provider 调用。

注意：

- 设置页的 `openai_example_mode` 只影响设置页展示，不决定实际生成模式。
- 实际生成模式必须来自操作区提交的 `mode`。
- 图生图时，后端必须强制 `n = 1`。
- 自定义脚本执行成功后，仍返回 `ImageGenerationResult(output_paths=[...])`。
- 保存区实例创建逻辑继续沿用现有 `output_paths` 多图拆分规则。

## 副作用处理

自定义代码功能会明显提高复杂度。它从“展示示例”扩展为“用户脚本参与生成”，后续排错可能更多取决于用户脚本本身。

自定义代码只要非空就启用。为避免误用，自定义代码 tab 必须显示醒目启用提示，并提供 `清空自定义代码` 按钮。

自定义脚本能读写本机文件和访问网络。软件不提供完整沙箱，只提供子进程隔离、超时、错误捕获和输出路径检查。

图生图数量固定为 `1` 会改变操作区行为。必须保证切回文生图后不丢失文生图数量默认值。

固定示例可以编辑保存后，用户看到的示例可能和软件内置默认示例不同。需要按 Provider + 调用方式 + 生图方式保存，避免一个 Provider 的示例影响另一个 Provider。

response 的文生图和图生图示例 V0.15 先做结构和占位，不强行补齐未讨论清楚的完整调用代码。
