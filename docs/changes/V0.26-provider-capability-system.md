## 修改目标

V0.26 只做 Provider 能力体系收口，不做大范围 UI 调整。

目标是把现有 Provider 相关规则整理清楚：

- Provider 是用户自己命名的代理商配置，例如 `AIAPIS GPT Image 2`。
- adapter 是接口类型，只能是 `openai`、`google`、`other`。
- 调用方式是接口类型下面的具体调用方式。当前 OpenAI adapter 下有 `gpt-image-2` 和 `response`。
- 能力判断采用方案 A：同一个 adapter 和同一个调用方式使用同一套参数规则，不为每个 Provider 单独维护能力开关。
- 如果某个 OpenAI 兼容 Provider 实际不支持其中某些参数，界面仍然显示这些参数；请求时由代理商接口忽略，或由代理商接口返回错误。

本版本重点是把规则集中，减少散落在设置页、操作区、后端生成、历史记录里的重复判断。

## 不做内容

V0.26 不做以下内容：

- 不重新设计界面。
- 不改变当前生图管理页整体布局。
- 不改变当前设置页主要布局。
- 不把 JS 模块重新合并回 `frontend/app.js`。
- 不把 CSS 模块重新合并回 `frontend/styles.css`。
- 不引入 React、Vue、打包器、Tailwind、Bootstrap。

- 不实现 Other 自定义接口调用。

- 不改变数据安全页的备份、导出、恢复格式。
- 不删除或移动电脑上的图片文件。

## 名词规则

Provider：

- 用户自己创建和命名的代理商配置。
- 内部编号对应 provider key。
- 显示名称对应 display_name。
- 生图管理页操作区选择的 Provider 才是真正用于生成的 Provider。
- 设置页选择 Provider 只是为了编辑配置，不同步到操作区生成 Provider。

adapter：

- 接口类型。
- 当前允许值为 `openai`、`google`、`other`。
- 生图管理页继续用 Provider 显示文字后面的 `(c)`、`(g)`、`(o)` 显示 adapter，避免额外占用布局。

调用方式：

- adapter 下面的具体调用方式。
- 当前只对 `openai` 有调用方式。
- `gpt-image-2` 是当前主要生成路径。
- `response` 保留当前已有逻辑。

能力：

- 能力只由 adapter 和调用方式决定。
- 不由 Provider 名称决定。
- 不因为 Provider 是 AIAPIS、其他代理商或用户自定义名称而改变前端参数显示。

生成路径：

- 生成路径不放进 Provider 配置。
- 生成路径来自操作区和全局默认值。
- 后端生成、自定义脚本、历史记录只把生成路径作为本次生成上下文使用。

## 前端 Provider 能力集中

在 `frontend/js/providers.js` 中集中定义 adapter 和调用方式能力。

建议新增 `ADAPTER_CAPABILITIES`：

```javascript
export const ADAPTER_CAPABILITIES = {
  openai: {
    label: "openai",
    marker: "(c)",
    implemented: true,
    settingsKind: "openai",
    callMethods: {
      "gpt-image-2": {
        label: "gpt-image-2",
        supportsTextToImage: true,
        supportsImageToImage: true,
        supportsCount: true,
        imageToImageCount: 1,
        supportsCustomScript: true,
      },
      response: {
        label: "response",
        supportsTextToImage: true,
        supportsImageToImage: false,
        supportsCount: false,
        imageToImageCount: 1,
        supportsCustomScript: true,
      },
    },
  },
  google: {
    label: "google",
    marker: "(g)",
    implemented: false,
    message: "Google adapter 暂未实现。",
    settingsKind: "placeholder",
    callMethods: {},
  },
  other: {
    label: "other",
    marker: "(o)",
    implemented: false,
    message: "Other adapter 暂未实现。",
    settingsKind: "placeholder",
    callMethods: {},
  },
};
```

字段含义：

- `implemented` 表示内置生成逻辑是否已实现。
- `settingsKind` 决定设置页显示 OpenAI 参数区还是占位说明。
- `callMethods` 只描述当前 adapter 下已有调用方式。
- `supportsCount` 表示文生图是否允许数量参数生效。
- `imageToImageCount` 表示图生图固定数量，当前为 1。
- `supportsCustomScript` 只表示自定义脚本入口继续显示和保存，不表示所有 adapter 都已内置可生成。

同时新增或整理以下 helper：

```javascript
export function normalizeProviderAdapter(adapter) {}
export function providerCapability(provider) {}
export function providerCallMethodCapability(provider) {}
export function providerAdapterMarker(adapter) {}
export function isProviderImplemented(provider) {}
export function providerUnavailableMessage(provider) {}
```

这些 helper 供设置页、操作区和历史记录显示使用，避免各文件重复写 `adapter === "google"`、`adapter === "other"` 这种判断。

## 前端设置页规则

设置页继续是编辑 Provider 配置的地方。

设置页顶部 Provider 下拉框只决定当前正在编辑哪个 Provider，不改变生图管理页操作区使用的 Provider。

Provider 基础字段保持：

```text
display_name
provider key
adapter
```

连接信息保持：

```text
base_url
api_key
api_key_env
user_agent
```

adapter 下拉框保持：

```text
openai
google
other
```

当 adapter 为 `openai` 时：

- 显示 OpenAI API 参数区。
- 显示调用方式选择。
- 调用方式可选 `gpt-image-2` 和 `response`。
- 显示生图方式选择。
- 显示调用示例和自定义代码区域。
- 参数置灰逻辑保持现有规则。
- `output_format = png` 时，`output_compression` 置灰。
- `output_format = jpeg` 或 `webp` 时，`output_compression` 可编辑。

当 adapter 为 `google` 时：

- 不显示 OpenAI 专用参数为可执行配置。
- 显示占位说明：`Google adapter 暂未实现。`
- 允许保存 Provider 配置。
- 点击生成时后端仍返回 `Google adapter 暂未实现。`

当 adapter 为 `other` 时：

- 不显示 OpenAI 专用参数为可执行配置。
- 显示占位说明：`Other adapter 暂未实现。`
- 允许保存 Provider 配置。
- 点击生成时后端仍返回 `Other adapter 暂未实现。`

不要为某个具体 Provider 增加额外能力开关，例如：

```text
支持文生图
支持图生图
支持多图
支持 png
支持 webp
```

这些不进入单个 Provider 表单。

## 操作区规则

生图管理页操作区 Provider 下拉框才决定实际生成使用的 Provider。

切换操作区 Provider 后：

- 立即保存为全局默认 Provider。
- 设置页当前正在编辑的 Provider 不跟着同步。
- Provider 显示继续使用显示名称加 adapter 标记，例如 `AIAPIS GPT Image 2 (c)`。

操作区参数不按具体 Provider 名称隐藏。

OpenAI adapter 下：

- 文生图显示文生图所需控件。
- 图生图显示输入图区域。
- 文生图数量 `n` 使用操作区数量。
- 图生图数量固定为 1，并置灰。
- 尺寸由长宽比和清晰度换算得到。
- 自定义分辨率继续按现有规则进入 `resolved_size`。

Google adapter 下：

- 操作区可以选中该 Provider。
- 点击生成时提示 `Google adapter 暂未实现。`
- 不新增额外布局。

Other adapter 下：

- 操作区可以选中该 Provider。
- 点击生成时提示 `Other adapter 暂未实现。`
- 不新增额外布局。

Response 调用方式下：

- 文生图保持当前已有生成逻辑。
- 图生图保持当前未实现提示：`Responses API 图生图暂未实现。`
- 不在 V0.26 强行实现 Responses API 图生图。

- base_url 保持不变。
- api_key 保持不变。
- user_agent 保持不变。

## 后端生成规则

`backend/image_generation.py` 继续按 adapter 选择 Provider 类：

```text
openai -> AIAPISGptImage2Provider
google -> GooglePlaceholderProvider
other -> OtherPlaceholderProvider
```

建议把未实现 adapter 的错误收口到统一函数，避免 `api.py` 和 `image_generation.py` 各写一份不一致判断。

OpenAI adapter 下：

- `gpt-image-2` 文生图调用 `client.images.generate`。
- `gpt-image-2` 图生图调用 `client.images.edit`。
- `response` 文生图调用 `client.responses.create`。
- `response` 图生图继续返回 `Responses API 图生图暂未实现。`
- `output_compression` 只在 `jpeg`、`webp` 时传入。
- `png` 时不传 `output_compression`。
- `user_agent` 如果填写，则同时用于 OpenAI client default_headers 和图片 URL 下载请求。

图生图数量规则：

- 后端继续强制图生图 `n = 1`。
- 即使前端传入大于 1 的数量，后端也改为 1。

文生图多图规则：

- 文生图 `n > 1` 时，后端保存返回的多张图。
- 每张输出图仍保存为一个独立实例。
- 操作区显示最后一张或当前已有逻辑中的代表图。

自定义脚本规则：

- 自定义脚本功能保持 V0.25 行为。
- 自定义脚本继续接收同一组操作区参数和 Provider 参数。
- 自定义脚本上下文继续包含 `output_dir`，最终输出路径必须来自软件传入的生成目录。
- V0.26 不扩大 `google`、`other` 的内置生成能力。

## 历史记录和实例参数快照

历史记录要继续保存点击生成当时的文字数据和参数快照。

V0.26 不新增数据库字段，优先使用现有字段：

```text
generation_history.provider_key
generation_history.adapter
generation_history.openai_call_method
generation_history.resolved_size
generation_history.params_json
instances.generation_params_json
```

`params_json` 和 `generation_params_json` 中要确保包含：

```text
provider_key
adapter
openai_call_method
model
ratio
resolution_level
resolved_size
quality
output_format
output_compression
background
moderation
user
user_agent
n
custom_script_used
```

旧历史记录和旧实例可能缺少部分字段。

前端显示历史记录和实例参数时必须防御式读取：

- 缺少字段时显示空字符串或不显示该段。
- 不因为旧记录缺少 `adapter`、`openai_call_method`、`user_agent` 导致页面报错。
- 不要求旧记录补写新字段。

如果实现中发现现有 `generation_params_from_options()` 或 `history_params_snapshot()` 已经保存其中大部分字段，只补缺口，不重复造新结构。

- 设置页 adapter 为 `openai` 时显示 OpenAI 参数。
- 设置页 adapter 为 `google` 时显示未实现占位。
- 设置页 adapter 为 `other` 时显示未实现占位。
- `output_format = png` 时 `output_compression` 置灰。
- `output_format = jpeg` 或 `webp` 时 `output_compression` 可编辑。
- 文生图数量可以编辑。
- 图生图数量固定为 1 并置灰。
- `openai + gpt-image-2 + 文生图` 操作不被能力整理破坏。
- `openai + gpt-image-2 + 图生图` 操作不被能力整理破坏。
- `openai + response + 文生图` 操作不被能力整理破坏。
- `openai + response + 图生图` 显示未实现错误。
- `google` 点击生成显示未实现错误。
- `other` 点击生成显示未实现错误。
- 历史记录页可以显示新记录。
- 历史记录页可以显示旧记录。

## 副作用与处理

采用方案 A 后，软件不会为每个 Provider 单独判断参数支持情况。好处是简单稳定，缺点是某个 OpenAI 兼容代理商如果不支持某些参数，界面仍然会显示这些参数，最终可能由接口忽略或返回错误。

Provider 和 adapter 的概念会更严格。Provider 是代理商配置名称，adapter 才是 `openai`、`google`、`other`。实现时不能把用户创建的 Provider 名字误当成 adapter。

设置页选择 Provider 只是编辑配置，操作区选择 Provider 才是生成使用的 Provider。这一点如果实现错，会造成用户在设置页切换 Provider 后不小心改变生成 Provider。

把能力判断集中到 `providers.js` 后，前端其他模块要通过 helper 读取能力。这样后续维护更清楚，但本次需要小心替换旧的散落判断，避免漏改导致某些页面显示不一致。

后端如果也集中未实现 adapter 判断，要保证错误文案不变，否则已有测试和用户记忆里的提示会变。

`google` 和 `other` 继续允许保存配置，但不能让用户误以为已经可以生成。点击生成时必须明确提示未实现。

`response` 调用方式目前只有文生图可用，图生图仍未实现。设置页可以保留生图方式选择，但实际生成时必须给出清楚错误。

历史记录和实例参数快照会更完整，但旧记录缺少字段是正常情况。前端和后端读取旧记录时必须兼容空字段。

V0.26 不新增数据库字段，因此不需要数据库迁移；只需要把 `app_version` 元数据更新为 `V0.26`。

自定义脚本保持 V0.25 行为。不要因为能力整理改变自定义脚本的输入变量，也不要改变输出路径必须来自软件生成目录的规则。

数据安全功能不能受影响。备份、导出、恢复仍然操作共享目录下的数据库和配置，不删除电脑上的图片文件。
