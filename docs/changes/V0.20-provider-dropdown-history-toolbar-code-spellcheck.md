## 设置页调用示例去掉双横线

设置页调用示例代码框中，不显示浏览器拼写或语法检查产生的双横线。

实现规则：

- 固定调用示例代码框 `fixed_code_example` 增加以下属性：

```html
spellcheck="false"
autocapitalize="off"
autocomplete="off"
autocorrect="off"
```

- 自定义代码框 `custom_script` 增加同样属性。
- 代码框仍保持 V0.19 的默认直接显示、默认可编辑。
- 不改变调用示例内容。
- 不改变调用示例的保存、取消、复制、自定义代码启用逻辑。

## 操作区 Provider 下拉选择

生图管理页操作区中，当前只显示小字 `Provider：xxx` 的位置改为可下拉选择。

实现规则：

- 操作区 Provider 使用下拉框。
- 下拉框选项来自设置页同一份 `state.settings.providers`。
- 选项显示文字使用现有 Provider 显示逻辑，包含 adapter 标记：

```text
显示名称 (c)
显示名称 (g)
显示名称 (o)
```

- 选项 value 使用 Provider 内部编号。
- 当前选中项使用 `state.settings.active_provider`。
- 如果没有 Provider，显示空选项或不可用状态，并保持生成时的现有错误提示。
- 下拉框位置保持在 V0.19 操作区原来的 Provider 小字位置，不明显增加操作区高度。
- 样式与操作区已有输入框、下拉框协调，字体可以保持小号，避免占用过多空间。

## 操作区切换 Provider 后立即保存为全局默认

操作区切换 Provider 后，立即保存为全局默认 Provider。

实现规则：

- 监听操作区 Provider 下拉框变化。
- 用户选择 Provider 后：
  - 更新 `state.settings.active_provider`。
  - 调用设置保存接口，将新的 `active_provider` 写入共享配置。
  - 操作区立即重新渲染，显示新的 Provider。
  - 设置页再次打开时，也显示同一个 Provider。
- 保存成功后可以轻量显示状态，例如 `已切换 Provider`。
- 保存失败时：
  - 顶部显示错误。
  - 保留当前页面，不阻止用户继续操作。
  - 如果需要回退，回退到保存前的 `active_provider`，避免界面和配置不一致。

生成逻辑：

- 点击生成时继续使用当时的 `state.settings.active_provider`。
- 已经提交中的生成任务不受之后 Provider 切换影响。
- 如果切换到 `google` 或 `other`，生成时继续按当前逻辑提示该 adapter 暂未实现。

## 历史记录页顶部进一步压缩

历史记录页顶部压缩为同一行，右侧控件紧凑排列。

目标布局：

```text
历史记录    状态    每页数量        筛选    刷新    总数 18 · 第 1 / 1 页    上一页    下一页
```

实现规则：

- `历史记录` 标题、状态下拉框、每页数量下拉框、`筛选`、`刷新`、总数页码、`上一页`、`下一页` 全部处于同一个顶部行容器。
- `筛选` 和 `刷新` 放在总数页码左边。
- `总数 18 · 第 1 / 1 页` 紧挨着 `上一页`、`下一页`。
- `筛选 / 刷新 / 总数页码 / 上一页 / 下一页` 这一组整体靠右。
- 不再单独使用 V0.19 中独立的分页行。
- 顶部加载状态和错误信息仍可显示在顶部行下方。

窄屏规则：

- 宽度不足时允许自然换行。
- 换行后顺序仍保持：

```text
历史记录 / 状态 / 每页数量 / 筛选 / 刷新 / 总数页码 / 上一页 / 下一页
```

- 不允许页面产生横向滚动。

## 副作用与处理

设置页代码框禁用拼写检查后，浏览器不再为代码内容提供拼写提示。代码示例本身不需要拼写检查，因此这个副作用可以接受。

操作区 Provider 改为下拉后，切换会立刻影响下一次生成使用的接口配置，包括 base_url、api_key、adapter、调用方式和参数。通过立即保存 `active_provider`，保证操作区和设置页一致。

如果用户在生成任务进行中切换 Provider，已经提交的任务必须继续使用提交时的 Provider。后续新任务使用新 Provider。

如果切换到 `google` 或 `other`，生成按钮可能提示 adapter 未实现。这是当前设计内行为，不能让用户误以为 google 或 other 已经可以生成。

历史记录顶部压缩后，在较窄窗口中可能换行。通过 flex-wrap 或等效响应式布局处理，不允许横向溢出。

历史记录页本次只调整顶部工具行，不改变 V0.19 的单条历史记录三栏布局。
