# V0.45.1 取消生成与重试稳定性修复

## 目标

V0.45.1 只在 V0.45 上修复两个稳定性问题：

- 网页关闭后再打开，已有生成中实例仍然可以取消。
- 连续生成时减少 AIAPIS / 代理服务直接断开连接后反复失败循环的问题。

## 根因

### 1. 重开网页后取消失效

V0.45 中，前端只有内存里的 `pendingInstances` 会按生成中过程卡片渲染。关闭网页后，内存状态丢失，再打开时只能从数据库读到 `generation_status = running` 的实例，但这些实例没有被当成可取消过程实例处理。

### 2. 点击取消后仍可能再请求一次

后端取消状态只在重试等待 `sleep` 期间检查。若用户点击取消时刚好接近下一轮请求开始，下一轮请求仍可能发出去，导致“取消后又生成最后一次”的现象。

### 3. 连续生成更容易触发服务器断开

连续提交多个生成任务时，多个请求会并行打到同一个 Provider。AIAPIS / Cloudflare 在这种情况下更容易出现 502、连接断开、无响应等可重试错误。V0.44 的无限重试会让失败任务持续重试，形成更明显的失败循环。

## 变更内容

### 1. 数据库 running 实例可取消

- 前端将 `instance.pending` 或 `generation_status = running` 都视为生成中实例。
- 重开网页后，数据库里的生成中实例仍显示生成中读秒/状态和“取消”按钮。

### 2. 取消接口同步更新数据库状态

- `/api/generate/cancel` 接收任务编号后，写入取消标记。
- 同时把数据库中对应 `generation_task_id` 的 running 实例标记为 failed，错误信息为“生成已取消”。
- 这样即使网页刷新，也能看到该任务已经取消。

### 3. 重试下一轮请求前检查取消

- 每次真正发起外部生成请求前检查取消状态。
- 如果请求途中点击取消，请求返回错误后会先按取消处理，不再进入下一轮重试等待。
- 请求获得结果后、写回 ready 前再次检查取消状态。
- 如果已取消，不再把实例改成成功。

### 4. 同 Provider 重试流程串行化

- 保留前端连续提交多个任务的能力。
- 保存区仍会出现多个生成中实例。
- 后端对同一个 Provider 的完整生成与重试流程加锁排队，降低连续并发请求把代理服务打断的概率。
- 如果一个任务遇到 `retry_after` 或默认等待，后面的同 Provider 任务也会排队等待，避免立刻继续撞同一个服务端错误窗口。

### 5. 可重试错误不再无限循环

- 默认最多尝试 4 次。
- 前 3 次可重试失败仍然分别写入历史记录，保留失败原因和等待秒数。
- 第 4 次仍失败时，将当前生成实例标记为失败，并结束本次任务。
- 这样可以避免服务端持续不可用时，任务长时间卡在生成中并不断循环。

## 不做内容

- 不改 Provider 配置结构。
- 不改 OpenAI 脚本参数。
- 不改数据库 schema。
- 不删除电脑上的图片文件。
- 不把并行提交功能改回单任务锁。

## 副作用与风险

- 同一个 Provider 下，多个生成任务会排队执行完整重试流程，吞吐会比完全并发慢一些。
- 这样做是为了换取 AIAPIS 这类代理服务的稳定性。
- 如果不同 Provider 后续同时使用，锁按 Provider 区分，不会互相阻塞。
- 已经发出去的单次 HTTP 请求无法从 Python 端真正中断，只能阻止下一轮重试和阻止结果回写。
- 如果服务端连续 4 次都返回 502、超时或连接断开，软件会把本次任务结束为失败。用户可以稍后手动重新提交。

## 验收重点

- 生成中实例在关闭网页后重新打开，仍显示取消按钮。
- 点击取消后，实例状态变为失败/已取消。
- 点击取消后不会再进入下一轮重试请求。
- 连续生成时仍可连续提交，但同 Provider 的完整重试流程按顺序执行。
- 服务端持续失败时，不会无限循环重试。
