## 尺寸下拉

当前分辨率为 `1K`、`2K`、`4K` 时，尺寸下拉根据当前分辨率从 `SIZE_MAP` 生成选项：

```text
1024x1024 (1:1)
1280x1024 (5:4)
864x1536 (9:16)
...
```

选择某个尺寸选项后：

- 更新 `state.operation.generation_size`。
- 更新 `state.operation.custom_generation_size`。
- 关闭尺寸下拉。
- 保存为全局默认尺寸。

当前分辨率为自定义模式时：

- 尺寸下拉不使用 `SIZE_MAP` 生成预设列表。
- 只显示自定义尺寸输入。
- 自定义尺寸仍只接受 `数字x数字` 格式，例如 `1234x567`。

## 分辨率与数量控件

V0.10 的分辨率按钮区域拆成左右两半：

```text
左半：分辨率档位
右半：生成数量
```

两半加起来的总宽度等于 V0.10 的分辨率按钮宽度。

分辨率档位：

- 可选：`1K`、`2K`、`4K`、`自定义`。
- 选中 `1K`、`2K`、`4K` 时，按钮显示对应文字。
- 选中 `自定义` 时，按钮显示空白。
- 选中 `1K`、`2K`、`4K` 时，下拉菜单中不显示输入框。
- 选中或切换到 `自定义` 时，下拉菜单中显示自定义分辨率输入框。

自定义分辨率：

- 输入值保存到 `state.operation.custom_resolution`。
- 生成时作为 `options.resolution` 传给后端。
- 如果自定义模式下输入为空，点击生成时提示错误，不发起生成请求。
- 按钮可使用 `title` 或 `aria-label` 保存可访问说明，但可见文字保持空白。

数量：

- 使用右半输入框或按钮式输入框。
- 可见文字只显示数字，不显示“数量”两个字。
- 默认值为 `1`。
- 只允许正整数。
- 不设置通用最大值；具体上限由 provider 或 API 返回错误决定。
- 数量保存为全局默认值。

## 分辨率切换联动尺寸

从一个预设分辨率切到另一个预设分辨率时：

- 如果当前尺寸能匹配 `SIZE_MAP` 中的某个比例，切换后保持同一比例。
- 示例：当前为 `1536x864 (16:9)` 和 `1K`，切到 `2K` 后尺寸变为 `2048x1152 (16:9)`。
- 示例：当前为 `768x1024 (3:4)` 和 `1K`，切到 `4K` 后尺寸变为 `2448x3264 (3:4)`。

如果当前尺寸是自定义尺寸：

- 切换 `1K`、`2K`、`4K` 不强行改掉自定义尺寸。
- 尺寸继续显示为 `原尺寸 (自定义)`。

切换到自定义分辨率时：

- 不自动修改当前尺寸。
- 分辨率按钮显示空白。
- 下拉内显示自定义分辨率输入框。

从自定义分辨率切回 `1K`、`2K`、`4K` 时：

- 如果当前尺寸能匹配目标分辨率下的某个预设比例，则显示对应比例。
- 如果不能匹配，则继续作为自定义尺寸显示。

## 操作区状态

`OPERATION_DEFAULTS` 增加：

```js
generation_count: 1,
custom_resolution: "",
```

保留：

```js
generation_size
resolution
```

`resolution` 字段含义：

- `1K`、`2K`、`4K`：预设分辨率。
- `custom`：自定义分辨率模式。

生成请求中的实际分辨率值通过辅助函数取得：

```js
function activeGenerationResolution() {
  return state.operation.resolution === "custom"
    ? state.operation.custom_resolution.trim()
    : state.operation.resolution;
}
```

`operationPayload()` 传参：

```js
options: {
  size: state.operation.generation_size,
  resolution: activeGenerationResolution(),
  count: state.operation.generation_count,
}
```

## 设置与默认值

全局默认值继续通过 `PUT /api/settings` 保存。

配置中保留并扩展：

```json
{
  "default_resolution": "1K",
  "default_count": 1
}
```

新增：

```json
{
  "default_custom_resolution": ""
}
```

规则：

- 当用户选择 `1K`、`2K`、`4K`，`default_resolution` 保存对应值。
- 当用户选择自定义，`default_resolution` 保存为 `custom`，`default_custom_resolution` 保存输入的自定义分辨率。
- 当用户修改数量，`default_count` 保存正整数。
- 后端配置归一化不再把分辨率限制死为 `1K`、`2K`、`4K`；只对 `default_resolution` 的模式值做校验。

默认值解析：

- 前端启动时，如果 `default_resolution` 是 `1K`、`2K`、`4K`，操作区分辨率模式使用对应值。
- 前端启动时，如果 `default_resolution` 是 `custom`，操作区分辨率模式使用 `custom`，输入框填入 `default_custom_resolution`。
- 后端在生成请求缺少 `options.resolution` 时，如果 `default_resolution` 是 `custom`，使用 `default_custom_resolution` 作为实际分辨率值。
- 后端不要把字符串 `custom` 传给 provider。

## 后端参数归一化

`normalize_generation_options()` 处理：

- `size` 必须是 `数字x数字` 格式。
- `resolution` 必须是非空字符串。
- `count` 必须是正整数。
- 归一化后的 `options["count"]` 为正整数。

错误提示：

- 尺寸格式错误：`尺寸格式必须是数字x数字`。
- 自定义分辨率为空：`请输入自定义分辨率`。
- 数量格式错误：`生成数量必须是正整数`。

后端不在通用层设置数量最大值。

## Provider 结果结构

把 `ImageGenerationResult` 从单路径扩展为多路径：

```python
@dataclass
class ImageGenerationResult:
    output_paths: list[str]
    provider: str

    @property
    def output_path(self) -> str:
        return self.output_paths[-1] if self.output_paths else ""
```

保留 `output_path` 属性用于兼容现有代码。

`AIAPISGptImage2Provider`：

- `_request_options()` 使用 `options["count"]` 映射到当前 API 的 `n` 参数。
- `_save_result()` 遍历 `response.data`。
- 每个返回项保存成一个本地图片文件。
- 返回 `ImageGenerationResult(output_paths=[...], provider=self.name)`。
- 如果 API 只返回 1 张，则 `output_paths` 只有 1 项。
- 如果 API 返回数量少于 `count`，只保存实际返回的图片，不补空实例。

## 自动保存多实例

`POST /api/generate` 处理生成结果：

- 调用 provider 后取得 `result.output_paths`。
- 如果 `output_paths` 为空，返回错误。
- 对 `output_paths` 按返回顺序逐个创建实例。
- 每个实例只写入 1 个 `output_image_path`。
- 每个实例复制同一份：
  - `prompt`
  - `mode`
  - `source = generated`
  - `provider`
  - `generation_path`
  - `generation_size`
  - `input_image_paths`
  - `tags`

返回 JSON：

```json
{
  "item": { "最后一张输出图对应的实例": true },
  "items": [],
  "output_image_paths": []
}
```

兼容规则：

- `item` 返回最后一个创建的实例，保持前端旧逻辑可用。
- `items` 返回本次创建的全部实例。
- `output_image_paths` 返回本次生成保存的全部图片路径。

排序说明：

- 实例按 provider 返回顺序创建。
- 在默认 `最新优先` 排序下，最后创建的实例通常显示在最前面。

## 操作区生成后显示

生成成功后：

- `state.operation.output_image_path` 设置为 `output_image_paths` 的最后一项。
- 操作区只显示最后一张输出图。
- 调用 `loadInstances()` 刷新保存区。
- 自动保存的多个实例各自只有 1 张输出图。

- 手动实例仍可没有输出图。
- 编辑状态下仍然只针对当前实例的单张输出图进行添加、替换、删除。

## 副作用处理

生成数量：

- `count > 1` 会产生多次输出保存，API 调用费用和等待时间可能增加。
- 软件不设置通用最大值，避免和不同 provider 的能力冲突。
- provider/API 如果限制数量，错误直接显示给用户。

实例数量：

- 一次生成多张图会增加多个实例。
- 保存区分页、筛选、排序沿用现有逻辑。
- 标签和提示词相同的多实例会自然聚集在一起。

操作区输出图：

- 操作区只显示最后一张，避免改变操作区布局。
- 其他输出图通过保存区新增实例查看。

历史数据：

- 旧实例仍然只有一个 `output_image_path`，无需迁移。
- 不新增数据库表，因此不会影响旧数据库启动。

自定义分辨率：

- 自定义分辨率的实际有效性由 provider/API 决定。
- 前端和后端只校验非空字符串，不判断它是否被某个 API 支持。

尺寸联动：

- 预设尺寸会跟随 `1K`、`2K`、`4K` 切换。
- 自定义尺寸不跟随切换，避免覆盖用户手工输入。
