# V0.50.2 生成中下拉稳定、操作区布局、翻页卡顿与历史尝试合并

## 目标

V0.50.2 是 V0.50.1 之后的稳定性补丁，继续在当前 V0.50 版本上修复实际使用中发现的问题。本版不新增大功能，不改变数据库 schema，重点解决生成中轮询对操作区交互的干扰、操作区右侧信息栏偶发挤占空间、多个生成中实例后保存区翻页卡住，以及历史记录多次尝试的展示方式。

本版原则：

- 不删除电脑上的图片文件。
- 不改变 Provider 能力体系。
- 不改变生成、复制提交、重新提交的核心流程。
- 不改变历史记录已有数据结构，优先用现有字段做展示合并。
- 修复后必须做页面级复现测试，尤其是生成中状态下的 Provider 下拉、保存区翻页、历史记录展示。

## 修改项

### 1. 生成中时下拉菜单不再自动消失

当前问题：

- 生图管理页操作区中，如果当前有正在“生成中”的实例，点击 Provider 下拉菜单后，菜单会很快自动消失。
- V0.50.1 已经做过轮询延迟重绘，但这个问题仍然存在，说明当前策略没有完全覆盖原生 select 展开状态。

调整方案：

- 生成中轮询刷新时，不再直接整页重绘 `renderManager()`。
- 轮询只更新必须更新的保存区运行中实例、生成状态、读秒相关状态。
- 操作区当前正在交互的控件不被重建，包括：
  - Provider 下拉
  - 路径下拉
  - TAG 下拉
  - 节点下拉
  - 尺寸、清晰度、数量相关控件
  - 搜索、筛选、排序、每页数量等下拉控件
- 下拉菜单只在以下情况关闭：
  - 用户选择某个选项
  - 用户点击菜单以外区域
  - 用户按 ESC
  - 用户切换页面

验收标准：

- 有 1 个或多个生成中实例时，打开 Provider 菜单保持打开，不会被轮询自动关闭。
- 有 7 个生成中实例时，打开 Provider、路径、TAG、节点、筛选类下拉都不会自动消失。
- 用户点选或点击外部后，下拉仍然能正常关闭。

### 2. 操作区右侧信息显示不挤占其他空间

当前问题：

- 操作区右边信息显示区最右侧偶发出现一列空白。
- 该空白会挤占操作区宽度，导致标签框和路径框变窄。

调整方案：

- 检查操作区 grid 列定义和信息栏宽度，避免信息栏因为内容、滚动条、隐藏溢出或预留列造成横向挤压。
- 信息显示区应使用固定或更小的独立宽度，不参与抢占标签和路径区域的可用空间。
- 信息内容超出时继续沿用“只显示最后几句，悬停显示完整内容”的规则。
- 浮窗可以覆盖其他区域，但不能改变操作区布局宽度。

验收标准：

- 操作区右侧不出现无意义空白列。
- 标签框、路径框宽度不因信息栏内容变化而明显变窄。
- 长错误信息、多个生成任务状态、空信息状态三种情况下布局都稳定。

### 3. 多个生成中实例后保存区翻页不卡住

当前问题：

- 提交 7 个生成中实例后，保存区翻页按钮出现点不动或疑似卡住。

可能原因：

- 生成中轮询、保存区整页重绘、图片稳定检查、读秒定时器同时工作，导致点击翻页时 DOM 被频繁替换。
- 翻页请求和轮询请求并发，后返回的旧请求覆盖了新页状态。
- 多个生成中实例导致保存区过程实例区域不断变化，翻页点击被重绘打断。

调整方案：

- 保存区翻页动作优先级高于生成中轮询。
- 点击首页、上一页、下一页、尾页时，暂停或延后本轮运行中轮询重绘。
- 给保存区列表请求增加顺序保护：旧请求返回时不能覆盖新请求结果。
- 翻页按钮点击后立即保持按钮响应，不被读秒或图片检查阻塞。
- 继续保留图片稳定显示检查，但不能让它阻塞翻页按钮。

验收标准：

- 同时存在 7 个生成中实例时，首页、上一页、下一页、尾页都能响应。
- 连续快速点击翻页，不会卡在旧页或空白页。
- 翻页后当前页图片仍稳定显示。
- 生成中读秒继续正常走。

### 4. 历史记录同一实例多次尝试合并展示

当前问题：

- 历史记录页中，同一个生成任务的多次失败重试会显示成多条独立记录，排查时不够集中。
- 需要将同一个实例或同一个生成任务的多次尝试合并起来展示。
- 合并后显示多个提交时间、多个错误。
- 原来的“错误”按钮改成“错误1、错误2、……、错误n”，并按尝试顺序往后排。

合并规则：

- 优先按现有历史记录参数中的 `parent_history_id` 合并。
- `parent_history_id` 指向的主记录作为合并组主记录。
- 带有 `retry_attempt` 的失败记录作为该主记录的尝试记录。
- 如果旧历史记录没有 `parent_history_id` 或无法可靠判断属于同一个任务，则不强行合并，避免误合并不同实例。
- 不新增数据库字段，不迁移旧数据。

展示规则：

- 合并组仍占用历史记录列表中的一条主记录位置。
- 主记录显示原有提示词、参数、Provider、调用方式、状态等信息。
- 合并组中显示多个提交时间，按尝试顺序展示。
- 合并组中显示多个错误摘要，每个错误最多显示后 3 行，保留浮窗完整显示。
- 错误复制按钮从“错误”改为：
  - 错误1
  - 错误2
  - 错误3
  - 直到错误n
- 点击“错误n”复制对应第 n 次错误的完整内容。
- 原有“指令”“参数”复制按钮继续保留。
- “带入”仍针对主记录执行，沿用 V0.50.1 规则：不修改操作区 Provider 和路径。

后端查询规则：

- 历史记录查询仍尽量走后端分页和筛选。
- 后端返回合并后的展示记录，避免前端一次性加载全部历史记录后再合并。
- `total` 应按合并后的主记录数量计算，避免分页数量混乱。
- 状态筛选、Provider 筛选、调用方式筛选、日期筛选、提示词搜索仍然可用。

验收标准：

- 同一主记录的失败重试显示为一组。
- 一组中多个错误按钮依次显示为“错误1、错误2、……、错误n”。
- 每个错误按钮复制对应错误完整内容。
- 错误框仍只显示最后 3 行，浮窗完整显示不丢。
- 旧历史记录没有可靠关联字段时保持原样显示，不误合并。

## 副作用与处理

- 生成中轮询减少整页重绘后，操作区某些状态可能不会每 1.5 秒整块刷新；读秒和保存区生成状态仍保持更新，这是可接受的。
- 保存区翻页优先后，轮询结果可能延后一轮显示，但可以避免翻页按钮被重绘打断。
- 历史记录按合并组分页后，页面上的记录数量可能和原始数据库行数不同；这是展示层变化，不删除历史数据。
- 旧历史记录如果没有 `parent_history_id`，不会被强行合并；这是为了避免误判。
- 错误按钮增多后，历史记录单条记录的横向空间会更紧，需要按钮自动换行或收缩，不能撑出横向滚动条。

## 测试重点

- 页面级测试：存在生成中实例时，Provider 下拉持续打开，不被轮询关闭。
- 页面级测试：存在 7 个生成中实例时，保存区首页、上一页、下一页、尾页可点击。
- 页面级测试：操作区右侧信息栏无空白列，不挤压标签框和路径框。
- 页面级测试：历史记录同一任务多次失败重试合并显示，错误按钮按“错误1、错误2、……”出现。
- 回归测试：保存区图片稳定显示、生成中读秒、取消中读秒、带入不改 Provider/路径、设置页取消按钮、Delete 快捷删除都不回退。
- 自动测试：补充前端静态测试和后端历史记录合并查询测试。
