## 下拉框关闭方式

尺寸下拉和分辨率下拉都不显示关闭按钮。

实现规则：

- 分辨率下拉保持 V0.08 的按钮式下拉，不增加关闭按钮。
- 尺寸下拉移除当前的 `关闭` 按钮。
- 点击下拉框以外区域关闭当前下拉。
- 按 `Escape` 关闭尺寸下拉和分辨率下拉。
- 打开尺寸下拉时关闭分辨率下拉。
- 打开分辨率下拉时关闭尺寸下拉。
- 点击尺寸下拉内部的预设、自定义输入框、确认按钮时，不触发点外关闭。
- 点击分辨率下拉内部的 `1K / 2K / 4K` 时，选择当前值并关闭下拉。

实施位置：

```text
frontend/app.js
```

在 `renderSizePicker()` 中删除：

```html
<button type="button" class="size-close" data-action="close-size-picker">关闭</button>
```

保留 `close-size-picker` action 处理不影响功能，但不再由界面渲染入口触发。也可以同步删除该 action 分支；如果删除，测试中不得再要求存在 `close-size-picker`。

实施位置：

```text
frontend/styles.css
```

删除 `.size-close` 的专用样式，或保留空闲样式但不得影响界面。

## 提示词输入框下划线

禁用浏览器对提示词 textarea 的拼写检查和自动纠错，去掉输入文字下面不需要的双横线。

实现规则：

- 操作区提示词框禁用拼写检查。
- 保存区实例提示词框禁用拼写检查。
- 编辑状态和非编辑状态的提示词 textarea 都应用同一规则。
- 不改变提示词框的输入、复制、聚焦浮层、悬停浮层逻辑。

实施位置：

```text
frontend/app.js
```

在 `renderEditablePromptField()` 渲染 textarea 时增加属性：

```html
spellcheck="false"
autocapitalize="off"
autocomplete="off"
autocorrect="off"
```

结果结构：

```html
<textarea
  name="..."
  rows="3"
  spellcheck="false"
  autocapitalize="off"
  autocomplete="off"
  autocorrect="off"
>...</textarea>
```

在 `renderReadonlyPromptField()` 渲染 readonly textarea 时同样增加：

```html
spellcheck="false"
autocapitalize="off"
autocomplete="off"
autocorrect="off"
```

副作用：

- 英文拼写检查也会被关闭。
- 如果下划线来自系统输入法正在组词的临时标记，浏览器属性不能完全禁止，只能避免浏览器拼写检查产生的标记。

## 操作区输入图清除按钮

操作区输入图标题右侧新增 `清除` 按钮，用于清空当前操作区所有输入图路径。

实现规则：

- 只在图生图模式显示输入图区和 `清除` 按钮。
- 文生图模式继续保留输入图区占位宽度，但不显示标题、不显示图片位、不显示 `清除` 按钮。
- 点击 `清除` 只清空 `state.operation.input_image_paths`。
- 不删除电脑上的原始图片文件。
- 点击后保留当前提示词、输出图、标签、生成路径、尺寸、分辨率、Provider。
- 点击后重新渲染操作区，输入图区只剩添加图片位。

实施位置：

```text
frontend/app.js
```

在 `renderOperationInputImagesBlock()` 的图生图分支中，把标题从：

```html
<span>输入图</span>
```

改为复用或等价渲染：

```js
${renderImageFieldHeader("输入图", {
  editable: true,
  action: "clear-operation-input-images",
  buttonLabel: "清除",
})}
```

新增函数：

```js
function clearOperationInputImages() {
  syncOperationFromDom();
  state.operation.input_image_paths = [];
  renderManager();
}
```

在点击 action 分支中增加：

```js
if (action === "clear-operation-input-images") {
  clearOperationInputImages();
}
```

`renderImageFieldHeader()` 当前依赖 `instanceId` 输出 `data-id`。操作区没有实例 id 时，按钮应允许不输出 `data-id`：

```js
const idAttr = instanceId === "" ? "" : ` data-id="${escapeHtml(instanceId)}"`;
```

按钮结构：

```html
<button
  type="button"
  class="image-field-clear"
  data-action="clear-operation-input-images"
>
  清除
</button>
```

## 保存区实例输入图清除按钮

保存区实例输入图标题右侧显示 `清除` 按钮，但只在编辑模式显示和生效。

实现规则：

- 非编辑状态不显示 `清除` 按钮。
- 编辑状态显示 `清除` 按钮。
- 点击后清空该实例编辑草稿的 `input_image_paths`。
- 不删除电脑上的原始图片文件。
- 点击后不退出编辑模式。
- 点击后不立刻保存到数据库，需要用户点击该实例的 `保存`。
- 点击 `取消` 后恢复原保存数据。

实施位置：

```text
frontend/app.js
```

当前保存区实例已经通过 `renderImageFieldHeader("输入图", ...)` 在编辑模式显示清理按钮。V0.09 统一改成 `清除`：

```js
${renderImageFieldHeader("输入图", {
  editable,
  action: "clear-instance-input-images",
  instanceId,
  buttonLabel: "清除",
})}
```

保留现有：

```js
clearInstanceInputImages(instanceId)
```

和点击 action：

```js
if (action === "clear-instance-input-images") {
  clearInstanceInputImages(actionNode.dataset.id);
}
```

## 尺寸、分辨率、模式按钮、操作按钮水平对齐

尺寸和分辨率按钮分别与左侧模式按钮、右侧操作按钮形成两行水平对齐。

对齐目标：

```text
文生图  ...  尺寸      ...  清空
图生图  ...  分辨率    ...  生成
```

实现规则：

- `文生图`、尺寸按钮、`清空` 的上边缘和高度保持一致。
- `图生图`、分辨率按钮、`生成` 的上边缘和高度保持一致。
- 尺寸和分辨率按钮仍在同一个窄列上下排列。
- 尺寸和分辨率按钮高度与模式按钮、操作按钮高度统一。
- 尺寸和分辨率按钮之间的纵向间距与模式按钮之间、操作按钮之间的纵向间距一致。
- 不改变输出图、标签、生成路径、状态列的逻辑。
- 不恢复横向溢出。

实施位置：

```text
frontend/styles.css
```

使用统一变量控制两行按钮高度和间距：

```css
:root {
  --operation-button-height: 34px;
  --operation-button-gap: 8px;
  --generation-option-height: var(--operation-button-height);
}
```

模式按钮列：

```css
.mode-row {
  display: grid;
  gap: var(--operation-button-gap);
}

.mode-button {
  min-height: var(--operation-button-height);
}
```

尺寸/分辨率列：

```css
.record-generation-options {
  display: grid;
  grid-template-rows: var(--operation-button-height) var(--operation-button-height);
  gap: var(--operation-button-gap);
  align-content: start;
}

.size-current,
.resolution-current {
  height: var(--operation-button-height);
  min-height: var(--operation-button-height);
}
```

操作按钮列：

```css
.operation-button-row {
  display: grid;
  gap: var(--operation-button-gap);
}

.operation-button-row button {
  min-height: var(--operation-button-height);
}
```

如果当前 `.operation-actions` 使用 `padding-top: 22px` 对齐标题下方第一行按钮，尺寸/分辨率列不需要额外 padding；它们自然从字段标题隐藏后的顶部开始。浏览器验证时以三列按钮的真实上边缘为准微调：

- 优先调整 `.operation-actions` 的 `padding-top`。
- 不通过给单个按钮加 margin 来对齐。
- 不改变 grid 列顺序。

## 副作用处理

下拉关闭按钮移除：

- 用户不能再通过下拉内部按钮关闭尺寸下拉。
- 点外部和 `Escape` 仍可关闭，交互和分辨率一致。
- 自定义尺寸输入时，点击输入框或确认按钮不能被误判为点外关闭。

提示词拼写检查关闭：

- 浏览器不会再提示英文拼写错误。
- 提示词中英文混合、参数、模型词更干净。
- 系统输入法组合文字的临时标记可能仍短暂出现。

输入图清除：

- 操作区清除是即时状态变更，但只影响当前操作区，不影响保存区、不影响本地文件。
- 保存区清除只影响编辑草稿，必须点击保存才写入数据库。
- 保存区非编辑状态不显示清除按钮，避免误删记录中的图片路径。

按钮对齐：

- 尺寸、分辨率、模式、操作按钮高度统一后，操作区高度可能微调。
- 如果窄屏下宽度不足，应继续通过响应式列宽压缩处理，不能出现横向滚动条。
- 尺寸文本较长时继续单行省略，不能把尺寸列撑宽。
