## 布局目标

只调整保存区单列显示时的实例布局。保存区双列显示保持 V0.09 的紧凑布局不变。

操作区当前布局基准：

```text
模式 | 提示词 | 输入图 | 尺寸/分辨率 | 输出图 | Provider/标签/路径 | 清空/生成 | 状态
```

保存区单列目标布局：

```text
编号 | 提示词 | 输入图扩展区 | 输出图 | Provider/标签扩展区 | 编辑/保存/删除
```

对齐规则：

- 保存区单列的 `编号` 左边界、宽度对齐操作区 `模式`。
- 保存区单列的 `提示词` 左边界、右边界、宽度对齐操作区 `提示词`。
- 保存区单列的 `输入图扩展区` 左边界对齐操作区 `输入图`。
- 保存区单列的 `输入图扩展区` 吃掉操作区 `尺寸/分辨率` 的空间。
- 保存区单列的 `输出图` 左边界、宽度对齐操作区 `输出图`。
- 保存区单列的 `Provider/标签扩展区` 左边界对齐操作区 `Provider/标签/路径`。
- 保存区单列没有状态列，操作区状态列对应的空间给到 `Provider/标签扩展区`。
- 保存区单列的 `编辑/保存/删除` 按钮列贴着实例右边框，不对齐操作区 `清空/生成` 按钮列。
- 保存区双列的 `.instance-card.image-record` 原布局不变。

## 桌面宽度 CSS 结构

建议把操作区列宽抽成 CSS 变量，避免操作区和单列保存区再次漂移。

实施位置：

```text
frontend/styles.css
```

新增或调整根变量：

```css
:root {
  --op-meta-col: 88px;
  --op-prompt-col: minmax(620px, 720px);
  --op-input-col: minmax(280px, 1fr);
  --op-size-col: 92px;
  --op-output-col: 76px;
  --op-detail-col: minmax(170px, .75fr);
  --op-action-col: 88px;
  --op-status-col: minmax(96px, 120px);
  --op-grid-gap: 6px;
}
```

操作区使用这些变量：

```css
.operation-area.image-record,
.operation-area.mode-text_to_image {
  grid-template-columns:
    var(--op-meta-col)
    var(--op-prompt-col)
    var(--op-input-col)
    var(--op-size-col)
    var(--op-output-col)
    var(--op-detail-col)
    var(--op-action-col)
    var(--op-status-col);
  gap: var(--op-grid-gap);
}
```

保存区单列使用同一批变量，但最后两列顺序改为 `状态宽度 + 按钮宽度`：

```css
.save-list.is-single .instance-card.image-record {
  grid-template-columns:
    var(--op-meta-col)
    var(--op-prompt-col)
    var(--op-input-col)
    var(--op-size-col)
    var(--op-output-col)
    var(--op-detail-col)
    var(--op-status-col)
    var(--op-action-col);
  gap: var(--op-grid-gap);
}
```

这样可以保证：

- 单列保存区的前 5 个列边界与操作区一致。
- 单列保存区输入图可以跨过操作区的尺寸/分辨率列。
- 单列保存区 Provider/标签可以获得操作区状态列的宽度。
- 单列保存区按钮在最后一列，贴右边。

## 单列保存区元素定位

只给 `.save-list.is-single` 下的实例增加定位规则，不影响双列。

实施位置：

```text
frontend/styles.css
```

```css
.save-list.is-single .instance-card .instance-card-header {
  grid-column: 1;
}

.save-list.is-single .instance-card .instance-prompt {
  grid-column: 2;
}

.save-list.is-single .instance-card .record-input-images {
  grid-column: 3 / 5;
}

.save-list.is-single .instance-card .record-output-image {
  grid-column: 5;
}

.save-list.is-single .instance-card .record-detail {
  grid-column: 6 / 8;
}

.save-list.is-single .instance-card .instance-actions {
  grid-column: 8;
}
```

说明：

- `record-input-images` 使用 `grid-column: 3 / 5`，表示输入图区从操作区输入图列开始，跨过尺寸/分辨率列。
- `record-output-image` 使用 `grid-column: 5`，保证输出图仍对齐操作区输出图。
- `record-detail` 使用 `grid-column: 6 / 8`，表示 Provider/标签从操作区 Provider 列开始，吃掉状态列对应空间。
- `instance-actions` 使用 `grid-column: 8`，按钮列成为保存区实例最右列。

## 窄屏响应式

在较窄窗口下，单列保存区要和操作区同比例缩窄。

V0.09 已有操作区响应式断点：

```css
@media (max-width: 1540px) {
  ...
}

@media (max-width: 1120px) {
  ...
}

@media (max-width: 760px) {
  ...
}
```

V0.10 应改为在断点中覆盖 CSS 变量，而不是分别写两套互相漂移的 grid。

`max-width: 1540px`：

```css
@media (max-width: 1540px) {
  :root {
    --op-meta-col: 80px;
    --op-prompt-col: minmax(420px, 1.2fr);
    --op-input-col: minmax(228px, .75fr);
    --op-size-col: 84px;
    --op-output-col: 70px;
    --op-detail-col: minmax(150px, .65fr);
    --op-action-col: 80px;
    --op-status-col: minmax(92px, 108px);
  }
}
```

`max-width: 1120px`：

```css
@media (max-width: 1120px) {
  :root {
    --op-meta-col: 70px;
    --op-prompt-col: minmax(250px, 1.1fr);
    --op-input-col: minmax(240px, .8fr);
    --op-size-col: 64px;
    --op-output-col: 64px;
    --op-detail-col: minmax(100px, .5fr);
    --op-action-col: 64px;
    --op-status-col: 60px;
  }
}
```

`max-width: 760px`：

- 保留 V0.09 的移动端单列堆叠逻辑。
- 操作区和保存区实例都改成 `grid-template-columns: 1fr`。
- 所有子区域 `grid-column: auto`。
- 不强求移动端竖直列对齐，因为移动端已经是纵向堆叠。

## 双列保存区不变

不要修改基础双列实例布局：

```css
.instance-card.image-record {
  grid-template-columns: 78px minmax(0, 1.1fr) minmax(0, 1fr) 76px minmax(0, .85fr) 64px;
}
```

不要把 `.save-list.is-single` 的规则写成全局 `.instance-card` 规则。

必须保持：

```css
.save-list.is-double {
  grid-template-columns: repeat(2, minmax(0, 1fr));
}
```

双列模式下：

- 提示词框宽度不跟操作区对齐。
- 输入图区不吃掉尺寸/分辨率空间。
- Provider/标签不吃掉状态空间。
- 操作按钮不移动到新的单列专用布局。

## 副作用处理

单列实例宽度分配：

- 单列实例会更接近操作区的视觉结构。
- 输入图区变宽，可容纳更多输入图。
- Provider/标签区域变宽，标签多时更不容易换行。
- 保存区按钮贴右，不再与操作区清空/生成按钮列对齐，这是本版本的预期行为。

横向空间：

- 单列保存区会复用操作区列宽，宽屏下对齐更稳定。
- 窄屏下必须通过同一组 CSS 变量同比例缩窄。
- 页面不能出现横向滚动条。

维护成本：

- 抽出 CSS 变量后，后续如果操作区列宽改变，单列保存区会自动跟着改。
- 如果未来操作区新增或删除列，需要同步检查单列保存区的列顺序和 `grid-column` 跨列规则。

实例高度：

- 本版本只改横向列宽和竖直对齐，不改图片换行规则。
- 如果输入图更多，因为输入图区更宽，单列实例可能比 V0.09 更少换行。
- 双列模式高度表现不变。
