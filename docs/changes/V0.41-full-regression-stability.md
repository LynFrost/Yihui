## 版本目录

以当前 `AI生图软件/软件版本_V0.40/` 为基础，完整复制为：

```text
AI生图软件/软件版本_V0.41/
```

注意：

- V0.41 必须基于当前已经完成并核对过的 V0.40。
- 当前 V0.40 已包含保存区实例和历史记录“带入操作区”能力。
- 当前 V0.40 已新增 `generation_history.tags_json` 历史记录 TAG 快照字段。

V0.41 只修改 `AI生图软件/软件版本_V0.41/` 下的软件代码，以及本文件。不要修改 V0.01 至 V0.40 版本目录。

`AI生图软件/软件版本_V0.41/VERSION` 写入：

```

前端版本号改为：

```

`frontend/index.html` 中静态资源版本参数改为：

<link rel="stylesheet" href="/static/styles.css?v=V0.41">

`app.py`、`backend/api.py`、`backend/database.py`、`Open-AIImageManager.cmd` 中显示或返回的软件版本同步改为 `V0.41`。

```bat
title AI Image Manager V0.41
```

`Open-AIImageManager.cmd` 的启动方式、端口逻辑、Python 检测逻辑保持不变。

## 修改目标

V0.41 的目标是不新增大功能，对 V0.40 之后的完整软件做全量回归验收和稳定性修复。

本版重点：

- 全面检查所有页面是否能正常打开、切换、渲染。
- 全面检查保存区普通列表模式和缩略图模式。
- 全面检查保存区筛选、排序、分页、每页数量、节点、标签、批量操作。
- 全面检查 V0.40 新增的保存区实例“带入”和历史记录“带入操作区”。
- 全面检查 V0.40 新增的 `generation_history.tags_json` 在备份、导出、恢复中不丢失。
- 检查旧备份恢复时缺少 `tags_json` 不报错。
- 检查历史记录高级查询和清理。
- 检查数据安全页导出、备份、恢复、恢复预览。
- 检查标签管理中心。
- 检查缩略图缓存、缩略图视图、图片弹窗原图显示。
- 检查 Provider 能力体系、Provider 切换、历史 Provider 不存在时的提示。
- 检查快捷键和弹窗关闭行为。
- 只修复回归验收中发现的问题。

本版不做：

- 不新增大功能。
- 不重构前端模块结构。
- 不重拆 CSS。
- 不改变当前整体 UI 设计。
- 不新增 Provider 类型。
- 不做批量 Provider 修改。
- 不改变数据库 schema，除非发现 V0.40 `tags_json` 迁移存在必须修复的问题。
- 不删除电脑上的图片文件。
- 不直接使用真实共享数据库做破坏性回归测试。

## 回归测试数据安全原则

V0.41 的破坏性回归测试必须统一使用复制数据库或临时数据库。

破坏性操作包括：

- 批量删除实例。
- 删除历史记录。
- 清理失败历史记录。
- 删除某日期之前的历史记录。
- 标签重命名。
- 标签合并。
- 节点删除。
- 单个移动。
- 批量移动。
- 数据恢复。
- 恢复预览之后的正式恢复。
- 清理缩略图缓存。

规则：

- 不直接在真实共享数据库上执行上述破坏性操作。
- 如果需要验证真实数据量下的表现，先复制数据库到临时目录，再对复制库测试。
- 测试库可以复用真实图片路径，但测试操作不能删除电脑上的图片文件。
- 测试完成后可以删除临时数据库和测试缓存。
- 不能删除原图、输入图、输出图。
- 不能清空真实备份目录。
- 不能用真实库测试恢复覆盖。

建议临时测试路径：

```text
AI生图软件/tmp/V0.41-regression/
```

如果实现时使用临时目录，测试结束后清理该目录。

## V0.40 `tags_json` 验收

必须检查：

- 新建数据库中 `generation_history` 包含 `tags_json`。
- 旧数据库升级后自动新增 `tags_json`。
- V0.40 之后点击生成写入 TAG 快照。
- 旧历史记录 `tags_json` 默认为 `[]`。
- `tags_json` 过滤空字符串和 `__untagged__`。
- 历史记录接口返回 `tags` 数组。
- 数据导出包含 `generation_history.tags_json`。
- zip-jsonl 导出包含 `tags_json`。
- JSON 恢复旧备份缺少 `tags_json` 不报错。
- zip-jsonl 恢复旧备份缺少 `tags_json` 不报错。
- 恢复新备份时 `tags_json` 保留。

说明：

- V0.41 原则上不改变 schema。
- 当前 schema version 继续沿用 V0.40 的 `4`。
- 只有发现 `tags_json` 迁移存在必须修复的问题时，才允许讨论 schema 修复。

## 发现问题时的修复原则

如果回归中发现问题：

1. 先确认是否可复现。
2. 尽量写最小回归测试。
3. 只修复该问题本身。
4. 不顺手重构。
5. 不扩大 UI 改动。
6. 不改变数据库 schema，除非问题明确与 V0.40 `tags_json` 迁移有关且无法用兼容逻辑修复。
7. 修复后重新运行相关测试和完整 `pytest`。
8. 修复后清理测试缓存和临时数据库。

## 副作用与风险

本版可能带来的影响：

- V0.41 会做大量页面级验收，如果直接使用真实共享数据库执行破坏性操作，会有数据风险，因此必须统一使用复制/临时数据库。
- 如果复制库引用真实图片路径，测试图片显示和缩略图生成会读取真实图片，但不能删除或移动真实图片。
- 数据恢复测试会覆盖数据库，所以只能在临时库中执行。
- 历史记录清理测试会删除历史记录，所以只能在临时库中执行。
- 批量删除实例测试会删除数据库记录，所以只能在临时库中执行。
- 标签重命名和合并会改变数据库 TAG，所以只能在临时库中执行。
- 如果修复键盘快捷键或弹窗关闭问题，可能影响事件分发，需要重点回归输入框光标移动、图片弹窗左右切换、保存区左右翻页。
- 如果修复图片懒加载问题，可能影响缩略图模式和大图弹窗，需要重点回归图片显示。
- 如果修复 `tags_json` 备份恢复问题，可能影响数据安全导出/恢复，需要重点回归旧备份兼容。

必须避免：

- 不能删除电脑上的图片文件。
- 不能直接覆盖真实共享数据库。
- 不能破坏 V0.40 带入操作区能力。
- 不能破坏 V0.40 历史 TAG 快照。
- 不能破坏 V0.39 历史查询与清理。
- 不能破坏 V0.38 标签管理中心。
- 不能破坏 V0.37 数据安全导出、备份、恢复。
- 不能破坏 V0.36 保存区缩略图视图。
- 不能破坏 V0.34 缩略图缓存。
