## Provider 内部编号自动生成

### 当前问题

V0.41 设置页中新建 Provider 时会生成 `new_provider` 一类的临时内部编号，并且新建阶段仍允许用户修改内部编号。

用户实际不希望手动给 Provider 分配内部编号。

### V0.42 修改

设置页中新建 Provider 时，软件自动生成唯一内部编号，例如：

```text
provider_001
provider_002
provider_003
```

规则：

- 新建 Provider 时自动生成内部编号。
- 内部编号继续显示在设置页中。
- 内部编号从一开始就是不可编辑状态。
- 已保存 Provider 的内部编号继续不可编辑。
- 已有旧 Provider 的内部编号保持原样，不迁移、不重命名。
- 显示名称仍然由用户填写。
- 删除 Provider 后，新建 Provider 可以继续使用下一个可用编号；不要求填补中间空号。

建议生成逻辑：

```text
从 provider_001 开始递增
如果该 key 已存在，继续尝试 provider_002
直到找到不存在的 key
```


## OpenAI 脚本统一

### 需要修改的共享脚本

基于 V0.41 的当前软件逻辑，修改以下两个文件：

```text
AI生图软件/files/openai_text_to_image.py
AI生图软件/files/openai_image_to_image.py
```

### 总体要求

两个脚本都必须是参数注入式脚本。

脚本中不能写死真实值：

- 不能写死真实 `base_url`
- 不能写死真实 `api_key`
- 不能写死真实提示词
- 不能写死真实输出目录
- 不能写死真实输入图路径
- 不能写死用户测试用的 API Key

脚本中可以出现变量名和默认空值处理，但不能把实际敏感值落到文件里。

### 注入参数

两个脚本都需要体现设置页参数：

```python
base_url
api_key
user_agent
quality
output_format
output_compression
background
moderation
user
```

两个脚本都需要体现操作区参数：

```python
operation_prompt
resolved_size
n
output_dir
output_path
input_images
mode
```

图生图脚本额外体现：

```python
input_fidelity
mask_path
```

其中：

- `output_path` 必须来自软件注入。
- `output_dir` 必须来自软件注入。
- 文生图 `n` 来自操作区生成数量。
- 图生图在当前操作区规则下仍默认 `n = 1`，但脚本结构允许注入 `n`。

### 输出兼容

脚本必须兼容两种返回：

```python
item.url
item.b64_json
```

处理规则：

- 如果有 `b64_json`，直接 base64 解码保存。
- 如果有 `url`，用 `User-Agent` 请求下载后保存。
- 如果都没有，抛出明确错误。
- 保存结果必须位于软件指定输出目录内。
- 如果输出多张图，需要写入 `result_json_path`，内容包含：

```json
{
  "output_paths": [
    "第一张图路径",
    "第二张图路径"
  ]
}
```

这样自定义脚本执行器可以读取多输出路径。

### 文生图脚本要求

`openai_text_to_image.py` 应调用：

```python
client.images.generate(...)
```

参数来自注入：

```python
model="gpt-image-2"
prompt=operation_prompt
size=resolved_size
quality=quality
output_format=output_format
background=background
moderation=moderation
n=n
user=user
```

`output_format` 为 `jpeg` 或 `webp` 时才传：

```python
output_compression=output_compression
```

`output_format` 为 `png` 时不传 `output_compression`。

如果返回多张图：

- 第一张优先保存到软件注入的 `output_path`。
- 后续图片保存到同一输出目录，文件名基于 `output_path` 自动追加序号。
- 写入 `result_json_path`，声明全部输出路径。

### 图生图脚本要求

`openai_image_to_image.py` 应调用：

```python
client.images.edit(...)
```

参数来自注入：

```python
model="gpt-image-2"
image=打开后的输入图文件对象或文件对象列表
prompt=operation_prompt
n=n
size=resolved_size
quality=quality
output_format=output_format
background=background
user=user
```

`output_format` 为 `jpeg` 或 `webp` 时才传：

```python
output_compression=output_compression
```

如果存在 `input_fidelity`，传入：

```python
input_fidelity=input_fidelity
```

如果存在 `mask_path`，传入：

```python
mask=open(mask_path, "rb")
```

多输入图规则：

- 操作区依次上传的图片按顺序保存在 `input_images` 中。
- `input_images[0]` 对应图 1。
- `input_images[1]` 对应图 2。
- 以此类推。
- 脚本以同样顺序打开并传入接口。
- 如果接口不支持多图，错误应原样反馈到软件，不静默丢弃后面的图片。

文件关闭规则：

- 所有打开的输入图片文件必须在请求结束后关闭。
- mask 文件如果打开，也必须关闭。

## 设置页调用示例

### 当前问题

V0.41 设置页中的调用示例是前端写死的字符串，后端真实生成逻辑由 Provider 类执行。示例和真实逻辑存在继续分叉的风险。

### V0.42 修改

V0.42 中，设置页 `接口类型 = openai` 且 `调用方式 = gpt-image-2` 时：

- 文生图调用示例使用 `AI生图软件/files/openai_text_to_image.py` 的内容。
- 图生图调用示例使用 `AI生图软件/files/openai_image_to_image.py` 的内容。
- 设置页切换 `生图方式` 后立即显示对应脚本。
- 示例只显示参数变量，不显示真实 API Key。
- 自定义代码 tab 继续保留。
- 如果用户自定义代码有内容，仍按现有规则优先使用自定义代码。

建议实现方式：

- 将两个脚本内容同步到 V0.42 前端默认示例字符串中。
- 或者后端新增只读接口读取共享脚本内容，再由设置页显示。

本版推荐：

```text
后端读取共享脚本内容，前端设置页显示后端返回的调用示例。
```

理由：

- 避免同一段脚本在 `files/` 和前端字符串里维护两份。
- 修改脚本后设置页示例自然同步。
- 更容易保证“示例就是实际逻辑”。

## 实际生成逻辑与脚本一致

### 当前逻辑

V0.41 默认 OpenAI 生成路径：

```text
backend/image_providers/aiapis_gpt_image_2.py
```

自定义脚本路径：

```text
backend/custom_script_runner.py
```

### V0.42 修改

V0.42 需要保证默认 OpenAI 生成逻辑和两个脚本保持一致：

- client 初始化支持 `default_headers={"User-Agent": user_agent}`。
- 文生图支持 url 和 base64 输出。
- 图生图支持 url 和 base64 输出。
- 文生图 `n > 1` 时保存多张图。
- 图生图可以传入多张输入图。
- `output_format = png` 时不传 `output_compression`。
- `output_format = jpeg / webp` 时才传 `output_compression`。
- 输出路径仍由软件生成并控制。

推荐做法：

- 保留后端 Provider 类作为软件默认生成入口。
- 将 Provider 类中的参数组织、图片保存、多图处理逻辑与脚本完全对齐。
- 不强制默认生成每次都启动外部 Python 脚本，避免性能、错误定位和安全边界变差。
- 设置页示例脚本作为“等价参考实现”，自定义脚本仍走 `custom_script_runner.py`。

涉及文件：

```text
AI生图软件/软件版本_V0.42/backend/image_providers/aiapis_gpt_image_2.py
AI生图软件/软件版本_V0.42/backend/api.py
AI生图软件/软件版本_V0.42/backend/custom_script_runner.py
AI生图软件/软件版本_V0.42/tests/test_image_generation.py
AI生图软件/软件版本_V0.42/tests/test_custom_script_runner.py
```

验收要求：

- 默认 OpenAI 文生图和脚本参数一致。
- 默认 OpenAI 图生图和脚本参数一致。
- 自定义脚本仍可覆盖默认逻辑。
- 生成历史参数快照继续记录 Provider、调用方式、尺寸、清晰度、输出格式等信息。

## 副作用与风险

### Provider 内部编号风险

- 如果对已有 Provider 进行自动重命名，会导致历史记录和实例引用错乱。
- 因此 V0.42 只对新建 Provider 使用自动编号，旧 Provider 保持原样。

### LOGO 风险

- LOGO 图片较大，如果直接原图加载，可能影响页面加载速度。
- 可以在 V0.42 静态目录中保留原图，但 CSS 必须限制显示尺寸。
- 如加载明显变慢，可以后续版本再做压缩版 LOGO。

### 脚本统一风险

- 设置页示例和后端真实逻辑必须同步，否则用户会误以为示例就是实际执行。
- 本版通过共享脚本和 Provider 逻辑对齐降低分叉风险。

### API Key 风险

- 用户提供的测试 API Key 不能落盘。
- 所有真实测试必须使用临时注入。
- 测试完成后检查代码、文档、测试文件中没有该 Key。

### 图生图多图风险

- OpenAI 兼容接口不一定都支持多图图生图。
- V0.42 的目标是不静默丢图，并在接口不支持时明确报错。
- 如果测试接口支持多图，则软件需要跑通多图。
- 如果测试接口不支持多图，则需要自动测试证明软件按顺序传参，并在真实请求失败时给出明确错误。

### 输出格式风险

- 不同代理商可能返回 `url` 或 `b64_json`。
- 只处理其中一种会导致生成失败。
- V0.42 必须两种都兼容。

### 真实生图测试风险

- 真实测试会消耗接口额度。
- 真实测试会产生输出图片。
- 真实测试可能受网络、接口限流、模型可用性影响。
- 如果接口短时间不可用，需要保留 mock 测试证明软件逻辑正确，并记录真实接口失败原因。

## 完成标准

V0.42 完成时必须满足：

- V0.42 版本目录存在并可启动。
- 设置页新建 Provider 自动分配内部编号。
- 内部编号不可编辑。
- 标题区显示 LOGO、作者名和 V0.42。
- `AI生图软件/files/openai_text_to_image.py` 为参数注入脚本。
- `AI生图软件/files/openai_image_to_image.py` 为参数注入脚本。
- 设置页文生图和图生图分别显示对应脚本。
- 默认 OpenAI 生成功能与脚本逻辑一致。
- 文生图和图生图通过软件页面操作验证。
- 不把真实 API Key 写入任何文件。
- 自动测试通过。
- 页面级核对通过。
- 多余过程文件已清理。
