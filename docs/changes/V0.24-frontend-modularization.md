## 修改范围

本版本主要做前端 JS 模块化：

- 将 `frontend/app.js` 拆分成多个原生 ES Module 文件。
- 不引入 React、Vue、打包器、TypeScript、构建命令。
- 保持本地网页软件的轻量结构。
- 保持现有后端 API 路径不变。
- 保持现有数据库 schema 版本和 V0.23 数据安全后端能力不变。

本版本允许的功能和交互调整：

- 点击操作区 `生成` 后，保存区立即显示前端临时 `生成中` 占位实例。
- 点击保存区实例 `重新提交` 后，保存区立即显示前端临时 `生成中` 占位实例。
- 保存区实例的 `重新提交` 放到 `删除` 左边，并移动到添加标签区域下方。
- 保存区分页增加 `首页`、`尾页`。
- 历史记录分页增加 `首页`、`尾页`。

本版本不做以下内容：

- 不重构 Provider 后端。
- 不重构数据库。
- 不改变 OpenAI / custom script / google / other adapter 的现有生成逻辑。
- 不改变设置页参数含义。
- 不改变数据安全页后端备份、导出、恢复格式。
- 不新增 JSON 导入。
- 不改变图片文件保存、读取、删除规则。
- 不调整除上述按钮位置和分页按钮以外的 UI 样式。

  setMessage: () => {},

export function registerRuntime(nextRuntime) {
  Object.assign(runtime, nextRuntime);
}

## 模块依赖规则

依赖方向固定为：

```text
constants/utils/state/api
  -> providers/tags/lightbox/persistence
  -> render-*
  -> actions-*
  -> events
  -> app.js
```

允许 action 模块通过 `runtime.js` 调用渲染函数。

不允许 render 模块 import action 模块。

不允许 state 模块 import render 或 action 模块。

不允许多个模块各自维护一份独立 state。

`state` 必须只有一个来源：

```javascript
import { state } from "./state.js";
```

所有模块共享同一个 `state` 对象。

## 生成中临时占位实例

前端新增状态：

```javascript
state.pendingInstances = [];
```

临时占位实例结构：

```javascript
{
  id: "pending-task-id-1",
  pending: true,
  task_id: "task-id",
  display_index: "",
  prompt: "",
  mode: "text_to_image",
  source: "generated",
  provider: "",
  created_at: "",
  input_image_paths: [],
  output_image_path: "",
  tags: [],
  generation_size: "",
  generation_params: {},
  pending_label: "生成中"
}
```

点击操作区 `生成` 后流程：

```text
1. 前端同步操作区表单状态。
2. 前端构造 payload。
3. 前端创建 generation task。
4. 前端按照 mode 和 n 创建 pendingInstances。
5. renderManagerIfActive()，保存区立刻显示生成中占位。
6. 调用 POST /api/generate。
7. 请求成功后移除当前 task 的 pendingInstances。
8. loadInstances() / loadTags() / loadGenerationHistory()。
9. 保存区显示真实数据库实例和输出图。
10. 请求失败后移除当前 task 的 pendingInstances。
11. loadInstances() / loadGenerationHistory()。
12. 如果后端已预创建空输出实例，则显示真实空输出实例。
13. 如果后端基础校验失败未创建实例，则占位消失并显示错误。
```

文生图：

```text
n > 1 时创建 n 条临时占位。
```

图生图：

```text
固定创建 1 条临时占位。
```

保存区实例 `重新提交`：

```text
固定创建 1 条临时占位。
重新提交仍使用当前操作区 / 全局默认 Provider、尺寸、清晰度、生成路径。
重新提交不修改原实例。
```

临时占位显示规则：

- 显示在保存区列表最上方。
- 样式沿用保存区实例卡片。
- 输出图区显示 `生成中`。
- 不计入数据库总数。
- 不参与分页总数计算。
- 不参与真实实例编号。
- 不允许编辑。
- 不允许删除。
- 不允许重新提交。
- 不允许补图。
- 多个并行生成任务的占位按 task_id 分组管理。
- 某个生成任务完成或失败时，只移除该 task_id 对应占位，不影响其他生成中的占位。

临时占位和筛选关系：

- 临时占位显示在当前保存区列表顶部。
- 临时占位不改变当前筛选条件。
- 真实实例刷新后继续遵守当前筛选、排序和分页规则。
- 如果当前筛选条件排除了新生成实例，真实刷新后该实例可能不在当前列表中显示。

## 副作用与处理

ES Module 拆分后，函数不再天然处于同一个全局作用域。所有跨文件使用的函数必须显式 `export` / `import`。

模块循环依赖会导致页面加载时报错。通过 `runtime.js` 让 action 模块调用入口渲染函数，避免 render 和 action 直接互相 import。

浏览器会按模块 URL 缓存 JS 文件。V0.24 必须更新入口脚本版本参数为 `V0.24`；如果后续发现子模块缓存导致旧代码残留，再在 Flask 静态响应或模块 import URL 上增加版本控制。

临时占位不是数据库真实实例。它不能编辑、删除、重新提交，也不计入总数和分页。

如果后端基础校验失败，临时占位会短暂出现后消失，并显示错误。这是前端占位方案的正常结果。

如果当前筛选条件排除新生成实例，真实刷新后该实例可能不显示在当前列表中；临时占位只用于表达“当前任务已提交并正在生成”。

多任务并行生成时，必须按 task_id 清理临时占位。不能在某个任务完成时清空全部 pendingInstances。

把 `重新提交` 和 `删除` 移到标签区域下方会让实例详情区增加一行按钮。除此之外不调整实例布局、颜色、间距和其它 UI 样式。

保存区和历史记录增加 `首页`、`尾页` 会使分页区域按钮数量增加。窄屏下沿用现有响应式布局纵向排列，不额外设计新样式。

前端静态测试需要从单文件断言改成多文件合并断言。否则模块化完成后，测试会因为找不到字符串而误判失败。

V0.24 不改变数据库 schema，因此旧数据可继续直接使用。
