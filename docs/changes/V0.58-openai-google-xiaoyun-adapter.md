# V0.58 openai-google 小云脚本接口接入

## 目标

当前 V0.57 已完成自定义脚本外层超时提升和 Provider 代理设置。本版 V0.58 目标是基于共享目录中的两份小云 Google B2 生图脚本，新增一个独立接口类型 `openai-google`，让软件可以通过该接口类型完成文生图和图生图。

参考脚本：

- `AI生图软件/files/google_b2_text_to_image_xiaoyun.py`
- `AI生图软件/files/google_b2_image_to_image_xiaoyun.py`

本版原则：

- 新增 `openai-google` 接口类型，不替换现有 `openai`。
- 不影响现有 `openai / google / other` Provider 的保存、显示和生成流程。
- 连接信息区保持现有结构和布局。
- Google API 参数区根据脚本实际参数调整。
- 调用示例区根据两份小云脚本调整。
- 脚本进入软件生成流程后，所有实际值都必须来自软件注入，不允许在脚本里写死真实请求值。
- 保留 V0.57 的代理设置和注入能力。
- 不删除电脑上的图片文件。
- 文档确认后再执行实现；本文档落成不等于直接开始改代码。

## 接口类型定位

### 1. 新增接口类型 `openai-google`

当前判断：

- 两份小云脚本请求的是 `chat/completions`。
- 请求体使用 OpenAI 风格的 `messages[].content` 多模态格式。
- 图生图通过 `image_url.url = data:image/...;base64,...` 传入参考图。
- 响应中可能返回图片 URL、data URL 或纯 base64。
- 这不是当前 `openai` Images API，也不是当前占位的原生 `google` adapter。

调整方案：

- 新增 adapter：`openai-google`。
- 前端 Provider 类型下拉增加 `openai-google`。
- 后端配置规范化支持 `openai-google`。
- 后端 Provider 能力表中将 `openai-google` 标记为已实现。
- 前端能力表中将 `openai-google` 标记为已实现。
- `openai-google` 支持：
  - 文生图。
  - 图生图。
  - 多输入图。
  - 自定义脚本覆盖。
  - V0.57 的代理设置。

验收标准：

- 设置页接口类型下拉可以选择 `openai-google`。
- 选择 `openai-google` 后不会显示“暂未实现”。
- 选择 `openai-google` 后点击生成走小云 Google B2 共享脚本流程。
- 现有 `openai` Provider 的参数区、调用示例和生成流程不变化。

## 设置页调整

### 2. 连接信息区保持不变

当前要求：

- 设置页选择 `openai-google` 后，连接信息区的内容不变。

保留字段：

- `base_url`
- `api_key`
- `api_key_env`
- `model`
- `user_agent`
- `代理模式`
- `自定义代理`
- `允许不受信任代理证书`

默认建议：

- `base_url` 默认可使用 `https://www.xiaoyunapi.com/v1`
- `api_key_env` 默认可使用 `XIAOYUN_API_KEY`
- `model` 默认可使用 `gemini-3.1-flash-image-preview`

处理规则：

- `api_key` 优先。
- `api_key` 为空时，读取 `api_key_env` 对应环境变量。
- `model` 从连接信息区注入脚本的 `model`。
- `base_url` 要能兼容以下写法：
  - `https://www.xiaoyunapi.com`
  - `https://www.xiaoyunapi.com/`
  - `https://www.xiaoyunapi.com/v1`
  - `https://www.xiaoyunapi.com/v1/`
- 最终请求路径应稳定指向 `/v1/chat/completions` 或等价路径，避免重复 `/v1/v1`。

验收标准：

- 切换到 `openai-google` 后连接信息区布局不乱。
- 保存后 `base_url / api_key / api_key_env / model / user_agent / 代理设置` 不丢失。
- 切换回现有 `openai` 后连接信息区仍保持原有行为。

### 3. 参数区标题改为 Google API 参数

当前要求：

- 选择 `openai-google` 后，参数区标题改为 `Google API 参数`。
- 参数区参数根据脚本里的参数调整。

参数区内容：

- `生图方式`
  - 文生图。
  - 图生图。
- 软件注入参数，只展示不可直接编辑：
  - `prompt`
  - `input_images`，仅图生图显示。
  - `保存路径`
- 可配置 Google 请求参数：
  - `role`
  - `max_tokens`
  - `temperature`
  - `top_p`
  - `stream`
  - `stop`
  - `presence_penalty`
  - `frequency_penalty`
  - `logit_bias`
  - `user`
  - `response_format`
  - `seen`
  - `tools`
  - `tool_choice`

默认建议：

- `role = user`
- `max_tokens = 4096`
- `stream = false`
- 其他可选参数默认留空或 `None`

重要规则：

- `stream` 可以显示，但默认必须为 `false`。
- 当前脚本按完整 JSON 响应解析图片，若启用 stream，可能无法按现有逻辑提取图片。
- `n` 不作为核心 Google API 参数依赖。软件如需要生成多张，优先沿用现有多实例/多任务流程，而不是强依赖接口内单次返回多图。

验收标准：

- `openai-google` 下参数区标题显示 `Google API 参数`。
- 参数区不再显示不适合该接口的 OpenAI Images 参数，例如 `quality / output_format / background / moderation`。
- 参数区每个参数保存后能进入 Provider 配置。
- 切换文生图/图生图时，示例区和参数区同步变化。
- 其他接口类型的参数区标题和参数不变化。

### 5. 脚本全部参数来自软件注入

当前问题：

参考脚本中存在演示值：

- `prompt = "画10只皮卡丘"`
- `image_path = "...png"`
- `api_key = os.environ.get("XIAOYUN_API_KEY", "YOUR_API_KEY")`
- `model = "gemini-3.1-flash-image-preview"`
- `output_path = "...result.png"`

接入软件后，这些值不能硬编码。

注入规则：

- `api_key`
  - 来自 Provider 的 `api_key`。
  - 若为空，再读取 `api_key_env` 对应环境变量。
- `base_url`
  - 来自 Provider 连接信息区。
- `model`
  - 来自 Provider 连接信息区 `model`。
- `operation_prompt`
  - 来自生图管理页操作区提示词。
- `input_images`
  - 来自操作区输入图列表。
  - 图生图支持多张图片。
  - 图片按操作区上传顺序写入 content，依次为图 1、图 2 等。
- `output_dir / output_path`
  - 来自软件生成流程。
  - 脚本必须将最终图片保存到指定路径。
- `role / max_tokens / temperature / top_p / stream / stop / presence_penalty / frequency_penalty / logit_bias / user / response_format / seen / tools / tool_choice`
  - 来自 Provider 的 Google API 参数区。
- `user_agent`
  - 来自连接信息区。
- `proxy_mode / use_system_proxy / system_proxy / allow_untrusted_proxy_certificate`
  - 沿用 V0.57 的代理注入。

验收标准：

- 共享脚本中不写死真实 API Key。
- 共享脚本中不写死真实提示词。
- 共享脚本中不写死固定输入图路径。
- 共享脚本中不写死固定输出路径。
- 通过软件点击生成时，脚本收到当前操作区和当前 Provider 的实际参数。

### 6. 响应图片提取与保存

当前脚本能力：

- 递归遍历响应 JSON 中的所有字符串。
- 支持提取：
  - `data:image/...;base64,...`
  - 图片 URL。
  - 纯 base64 图片内容。
- 最终保存为本地图片文件。

调整方案：

- 保留并强化该宽松提取策略。
- 如果返回图片 URL：
  - 下载图片并保存到软件指定输出路径。
  - 下载过程要支持 `user_agent`。
  - 下载过程要尊重 V0.57 代理设置。
- 如果返回 base64 或 data URL：
  - 解码并保存到软件指定输出路径。
- 如果没有找到图片：
  - 抛出包含响应 JSON 摘要的错误，方便排查。

验收标准：

- 响应为 data URL 时能保存图片。
- 响应为图片 URL 时能下载并保存图片。
- 响应为纯 base64 时能保存图片。
- 找不到图片时，错误信息写入历史记录。
- 图片弹窗、保存区缩略图、历史输出路径不回退。

## 副作用与处理

- 新增 adapter 会影响前后端能力表、配置规范化、设置页渲染、生成入口，必须同步修改，否则会出现前端可选但后端无法生成的问题。
- `openai-google` 和现有 `google` 名称接近，界面上必须清楚显示为 `openai-google`，避免误认为是原生 Google adapter。
- 小云接口使用 `chat/completions`，参数和 OpenAI Images API 不同，不能复用 `quality / output_format / background / moderation` 那套参数区。
- 参考脚本当前使用 `http.client.HTTPSConnection`，它不会自动使用 V0.57 的代理注入；接入软件流程时必须改造为支持系统代理、自定义代理和不走代理。
- `base_url` 拼接如果处理不严谨，容易出现 `/v1/v1/chat/completions` 或缺少 `/v1` 的问题。
- `stream = true` 可能导致当前图片提取逻辑无法工作，因此默认必须为 `false`，并在参数区避免误导。
- 多张输入图会增加请求体大小，可能导致供应商拒绝或超时；失败原因必须保留到历史记录。
- 响应 JSON 结构如果变化，图片提取可能失败；错误中需要保留响应摘要以便排查。
- 这版会增加一个共享脚本路径，清理过程文件时不能误删用户提供的原始参考脚本。
