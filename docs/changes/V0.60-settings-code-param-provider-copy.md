# V0.60 设置页代码区、参数介绍和 Provider 新建复制收口

## 目标

当前 V0.59 已完成 `openai-google` 固定调用示例只读、参数空值、路径历史和尺寸显示收口。本版 V0.60 目标是不新增生成大功能，继续优化设置页空间利用、代码区可读性、参数说明能力，以及 Provider 新建和复制流程。

本版原则：

- 不改变 V0.59 的共享脚本生成规则。
- 固定“调用示例”继续只读，不重新开放编辑。
- 真正改变运行逻辑的内容仍统一放在“自定义代码”。
- 参数介绍只作为说明文本，不参与保存、不参与生成、不改变 Provider 配置。
- 新建 Provider 默认从空白连接信息开始，避免自动带入默认连接参数。
- 复制 Provider 复制当前 Provider 的全部配置，但生成新的内部编号。
- 不破坏现有 Provider 能力体系、保存设置、取消脏状态、自定义代码、代理设置和生成流程。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 设置页代码区布局

### 1. 代码区页签和操作按钮同行显示

当前问题：

- “调用示例 / 自定义代码”页签在一行。
- “复制 / 编辑 / 保存 / 取消 / 清空自定义代码”等按钮在下面的代码面板中另起一行。
- 代码区占用纵向空间较多。

调整方案：

- 将代码区顶部整理为一行：
  - 左侧：页签按钮。
  - 右侧：当前页签对应的操作按钮。
- 页签包括：
  - `调用示例`
  - `自定义代码`
  - `参数介绍`
- 当前页签对应按钮：
  - `调用示例`：只显示 `复制`。
  - `自定义代码`：显示 `编辑 / 保存 / 取消 / 复制 / 清空自定义代码`。
  - `参数介绍`：显示 `复制`。
- 按钮都放在页签右边同一行，尽量减少代码区高度。

验收标准：

- `调用示例 / 自定义代码 / 参数介绍` 和对应操作按钮位于同一行。
- 切换页签后，右侧操作按钮随当前页签变化。
- 按钮过多时不挤乱设置页主体布局。
- 窄窗口下不出现文字互相覆盖。
- 原有复制、自定义代码保存、取消、清空逻辑不回退。

### 2. 调用示例只读但必须清晰可见

当前问题：

- 调用示例代码处于非编辑状态时，代码框显示效果异常，可能出现一片白或内容看不清。
- 但 V0.59 已确认固定调用示例只读，不应恢复编辑能力。

调整方案：

- 固定调用示例仍然只读。
- 代码框视觉上保持正常可读的编辑器样式：
  - 文字清晰可见。
  - 背景和文字对比正常。
  - 保持等宽字体和滚动能力。
  - 不因为 `readonly` 状态变成不可读样式。
- 不允许用户修改固定调用示例。

验收标准：

- 调用示例页签下可以清楚看到共享脚本内容。
- 代码框不是空白、白字或低对比度。
- 固定调用示例仍无法编辑。
- 复制固定调用示例仍可用。
- 自定义代码的编辑状态不被破坏。

## 参数介绍页签

### 3. 新增参数介绍页签

当前需求：

- 在“调用示例”和“自定义代码”按钮右边新增“参数介绍”按钮。
- 点击后，下方代码框内容切换为参数介绍。
- 参数介绍需要列出所有参数、参数介绍、参数默认、参数范围、参数一般怎么选。
- 为了显示正常，代码框可以保持编辑器视觉状态。

调整方案：

- 在代码区页签中新增 `参数介绍`。
- 点击 `参数介绍` 后：
  - 下方同一代码框区域显示参数介绍文本。
  - 内容只读。
  - 保持代码框的正常可读样式。
  - 右侧操作按钮显示 `复制`。
- 参数介绍文本根据当前 Provider 状态生成：
  - 接口类型。
  - 调用方式。
  - 生图方式。
- 参数介绍不写入 Provider 配置。
- 参数介绍不作为自定义代码执行。

验收标准：

- 点击 `参数介绍` 后，代码框内容切换为参数说明。
- 再点击 `调用示例`，内容恢复为对应共享脚本。
- 再点击 `自定义代码`，内容恢复为当前自定义代码。
- 参数介绍可复制。
- 参数介绍不会被保存进 `custom_scripts` 或 `code_examples`。

### 4. 参数介绍覆盖范围

需要覆盖：

- `openai` + `gpt-image-2`
  - 文生图。
  - 图生图。
- `openai` + `response`
  - 如果当前仍未完善实际示例，需要在参数介绍里明确当前调用方式状态。
- `openai-google`
  - 文生图。
  - 图生图。
  - 图生图需要说明 `input_images` 按操作区图片顺序注入。
- `google`
  - 如果仍为未实现接口，参数介绍显示当前接口类型暂未接入生图参数。
- `other`
  - 如果仍为未实现接口，参数介绍显示当前接口类型用于后续自定义接口，暂未接入生图参数。

参数介绍每项应包含：

- 参数名。
- 参数含义。
- 默认值。
- 参数范围。
- 一般怎么选。

重要规则：

- 参数介绍是软件内置说明，不代表运行时自动校验全部范围。
- 参数最终可接受范围以接口官网和服务商兼容实现为准。
- 参数介绍不在设置页参数区额外增加备注说明。

验收标准：

- 当前接口类型切换后，参数介绍同步变化。
- 当前调用方式切换后，参数介绍同步变化。
- 当前生图方式切换后，参数介绍同步变化。
- `openai-google` 图生图参数介绍包含 `input_images`。
- `openai-google` 文生图参数介绍不把 `input_images` 当作必需参数。

副作用：

- 参数介绍文本会带来维护成本。
- 后续接口参数变更时，需要同步更新参数介绍内容，避免说明和实际代码脱节。

## 新建 Provider

### 5. 新建 Provider 默认空白连接信息

当前问题：

- 点击“新建 Provider”后，显示名称会自动填为 `新 Provider`。
- 接口类型为 `openai`，但连接信息会带入默认 `base_url / api_key_env / model`。
- 用户希望新建时从空白配置开始。

调整方案：

- 点击 `新建 Provider` 后：
  - 接口类型自动选择 `openai`。
  - 显示名称为空。
  - 连接信息区全部为空：
    - `base_url`
    - `api_key`
    - `api_key_env`
    - `model`
    - `user_agent`
    - `自定义代理`
  - 内部编号仍自动生成且不可编辑。
- 其他非连接信息的 OpenAI 参数可以继续使用软件默认值，例如：
  - 调用方式。
  - 生图方式。
  - quality。
  - output_format。
  - background。
  - moderation。
  - 代理模式。
- 保存后，空白连接信息应保持空白。
- 生成时如果缺少必需连接信息，再按现有规则报错。

验收标准：

- 点击 `新建 Provider` 后，显示名称为空。
- 点击 `新建 Provider` 后，接口类型为 `openai`。
- 点击 `新建 Provider` 后，连接信息区字段为空。
- 保存新 Provider 后，连接信息字段不会自动变回默认值。
- 空白 Provider 直接生成时会给出清楚错误，不会静默使用旧 Provider 参数。
- 取消未保存修改后，新建草稿消失并恢复原设置。

副作用：

- 新建 Provider 不再开箱即带默认 OpenAI 地址和模型。
- 用户必须主动填写连接信息后才能生成。
- 这是更清晰的空白新建行为，但会比以前多一步填写动作。

## 复制 Provider

### 6. 新增复制 Provider 按钮

当前需求：

- 在设置页 `新建 Provider` 按钮左边增加一个 `复制` 按钮。
- 点击后复制当前所有内容，新建一个 Provider。

调整方案：

- 设置页顶部操作区新增 `复制` 按钮，位置在 `新建 Provider` 左边。
- 点击 `复制` 后：
  - 基于当前设置页正在编辑的 Provider 创建副本。
  - 生成新的内部编号。
  - 复制当前 Provider 的所有配置内容，包括：
    - 显示名称。
    - 接口类型。
    - 连接信息。
    - 代理设置。
    - OpenAI 参数。
    - openai-google 参数。
    - 自定义代码。
  - 显示名称建议在原显示名称后追加 ` 副本`。
  - 如果原显示名称为空，则副本显示名称也允许为空，或使用 `副本`；实现时优先避免强制填入无意义名称。
  - 复制后进入未保存脏状态。
  - 用户需要点击 `保存设置` 后才真正写入配置。
  - 不自动切换操作区当前 Provider。

验收标准：

- 有当前 Provider 时，点击 `复制` 会生成一个新的 Provider 草稿。
- 新 Provider 内部编号和原 Provider 不同。
- 新 Provider 的配置内容和原 Provider 一致。
- 自定义代码能被复制。
- `api_key` 等敏感字段也按“复制当前所有内容”规则复制。
- 复制后保存设置，Provider 列表中出现新 Provider。
- 复制后取消设置，副本草稿消失。
- 复制不会改变生图管理页当前 active Provider。

副作用：

- 复制会复制 `api_key` 等敏感字段，这是“复制当前所有内容”的自然结果。
- 如果用户只是想复制参数但不复制密钥，需要复制后手动清空。
- 复制自定义代码后，副本 Provider 会立即具备相同自定义运行逻辑。

## 回归检查

完成实现后需要检查：

- 设置页可以正常打开。
- Provider 下拉切换稳定。
- 新建 Provider、复制 Provider、保存设置、取消修改、删除 Provider 都正常。
- 新建 Provider 默认 `openai`，显示名称和连接信息为空。
- 新建 Provider 保存后连接信息仍为空。
- 复制 Provider 后内容完整复制，内部编号唯一。
- 复制 Provider 后不会改变操作区当前 Provider。
- 调用示例只读可见。
- 自定义代码可编辑、保存、取消、复制、清空。
- 参数介绍可显示、可复制，不参与保存和生成。
- `openai`、`openai-google` 的调用示例仍读取共享脚本。
- `openai-google` 的 V0.59 参数空值、尺寸“无”、路径历史不回退。
- 现有生成、历史记录、保存区、数据安全页不受设置页调整影响。

## 不做内容

- 不新增新的接口类型。
- 不改变生成脚本请求语义。
- 不把参数介绍作为运行代码执行。
- 不在参数区额外增加说明文字。
- 不改变接口官网规定的参数范围。
- 不删除电脑上的图片文件。
