## 修改范围

本版本只做数据安全相关能力：

- 数据库和配置备份。
- 启动自动备份。
- JSON 导出。
- 备份恢复。
- 数据库 schema 版本记录。
- 备份列表查看。
- 历史记录固定编号。
- 保存区实例重新提交。
- 点击生成后立即创建保存区实例。

本版本不做以下内容：

- 不做前端模块化。
- 不做 Provider 重构。
- 不大改现有生图管理页 UI。
- 不复制、不删除、不移动电脑上的原始图片文件。
- 不做 JSON 导入。
- 不做备份合并导入。

备份文件保存到：

```text

```

文件名格式：

```text
AIImageManager_backup_{type}_V0.23_YYYYMMDD_HHMMSS.zip
```

示例：

```text

AIImageManager_backup_auto_V0.23_20260505_090001.zip
AIImageManager_backup_pre_restore_V0.23_20260505_160412.zip
AIImageManager_backup_pre_migration_V0.23_20260505_160500.zip
```

`type` 只允许：

```text
manual
auto
pre_restore
pre_migration
```

备份 zip 内部结构：

```text
AIImageManager.data.sqlite
AIImageManager.config.json
backup_metadata.json
```

`backup_metadata.json` 内容：

```json
{
  "app_name": "AIImageManager",
  "app_version": "V0.23",
  "backup_type": "manual",
  "created_at": "2026-05-05T15:30:12",
  "schema_version": 1,
  "database_file": "AIImageManager.data.sqlite",
  "config_file": "AIImageManager.config.json",
  "image_files_included": false
}
```

说明：

- 备份包含数据库和配置。
- 备份包含明文 API Key，因为配置文件本身按本机使用逻辑明文保存。
- 备份不包含图片文件。
- 备份不删除图片文件。

## 备份实现方式

新增后端模块：

```text
backend/backup.py
```

实现函数：

```python
def create_backup(db_file: Path, config_file: Path, backup_dir: Path, app_version: str, backup_type: str) -> dict
def list_backups(backup_dir: Path) -> list[dict]
def open_backup_folder(backup_dir: Path) -> None
def prune_auto_backups(backup_dir: Path, keep: int) -> None
def backup_metadata(zip_path: Path) -> dict
```

创建数据库备份时必须使用 SQLite backup API，不直接复制正在使用的 sqlite 文件。

原因：

- 当前 SQLite 使用 WAL 模式。
- 直接复制 `.sqlite` 可能漏掉 WAL 中尚未 checkpoint 的数据。
- SQLite backup API 能生成一致快照。

备份流程：

```text
1. 创建 backup 目录。
2. 使用 sqlite3 backup API 将当前数据库备份到临时 sqlite 文件。
3. 复制当前 config JSON 到临时文件。
4. 写入 backup_metadata.json。
5. 打包为临时 zip。
6. zip 完成后再原子移动为正式备份文件。
7. 删除临时目录。
```

如果备份失败：

- 不修改数据库。
- 不修改配置。
- 返回错误给前端。
- 不生成半成品 zip。

## 启动自动备份

每天首次启动自动备份一次。

判断方式：

```text
扫描 AI生图软件/backup/ 下当天是否已经存在 backup_type=auto 的备份。
```

如果当天没有自动备份：

```text
创建 AIImageManager_backup_auto_V0.23_YYYYMMDD_HHMMSS.zip
```

自动备份保留最近 30 份。

只清理 `backup_type=auto` 的旧备份。

不要清理：

```text
manual
pre_restore
pre_migration
```

启动自动备份失败时：

- 软件继续启动。
- 在后端日志打印错误。
- 数据安全页显示最近自动备份状态。
- 不影响生图管理页使用。

## 数据库 schema 版本记录

新增数据库表：

```sql
CREATE TABLE IF NOT EXISTS app_metadata (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

写入：

```text
schema_version = 1
app_version = V0.23
last_migration_at = 当前时间
```

V0.22 及更早版本数据库没有 `app_metadata` 表。

V0.23 启动时：

```text
1. 检查数据库是否存在。
2. 如果数据库存在且没有 schema_version，识别为旧库。
3. 迁移前创建 pre_migration 备份。
4. 在临时数据库副本中执行迁移。
5. 对临时数据库执行 PRAGMA integrity_check。
6. 校验通过后替换当前数据库。
7. 校验失败时保留原数据库，启动失败并显示明确错误。
```

迁移失败不能破坏原数据库。

迁移不能删除任何用户数据。

迁移不能删除图片文件。

V0.23 schema 迁移只新增 `app_metadata` 表，不修改现有实例、标签、历史记录字段。

## 备份恢复

V0.23 只支持整库替换恢复。

不做合并导入。

原因：

- 实例 id 可能冲突。
- 标签 id 可能冲突。
- 历史记录 id 可能冲突。
- Provider key 可能冲突。
- 合并导入需要冲突解决规则，容易破坏数据安全基线。

恢复入口：

```text
数据安全页 -> 备份列表 -> 选择备份 -> 恢复所选备份
```

同时提供：

```text
选择备份文件
```

用于选择 `AIImageManager_backup_*.zip`。

恢复前必须二次确认：

```text
恢复会替换当前数据库和设置。恢复前会自动备份当前数据。不会删除任何图片文件。确认恢复？
```

恢复流程：

```text
1. 前端确认用户已二次确认。
2. 后端校验备份 zip 存在。
3. 后端读取 backup_metadata.json。
4. 校验 app_name。
5. 校验 zip 中存在数据库和配置文件。
6. 恢复前创建 pre_restore 备份。
7. 解压到临时目录。
8. 对备份数据库执行 PRAGMA integrity_check。
9. 对备份配置执行 normalize_config。
10. 校验通过后关闭当前数据库连接。
11. 替换 AI生图软件/data/AIImageManager.data.sqlite。
12. 替换 AI生图软件/config/AIImageManager.config.json。
13. 重新加载配置。
14. 返回恢复成功。
15. 前端提示用户刷新页面。
```

恢复失败时：

- 保留当前数据库。
- 保留当前配置。
- 保留恢复前自动备份。
- 返回错误信息。
- 不删除图片文件。

恢复期间：

- 禁止同时执行另一个恢复。
- 禁止开始新的生成任务。
- 如果当前浏览器存在进行中的生成任务，前端禁用恢复按钮。
- 如果后端检测到恢复正在进行，生成、实例保存、设置保存等写操作返回 `409`。

## 历史记录固定编号

历史记录页编号不再使用：

```javascript
String(index + 1).padStart(3, "0")
```

历史记录编号使用数据库 `generation_history.id`。

显示格式改为：

```text
记录 1
记录 2
记录 18
```

不要显示为：

```text
#001
#002
```

规则：

- 最早创建的历史记录编号为 `记录 1`。
- 后续历史记录按数据库 id 递增。
- 翻页后编号不重新从 1 开始。
- 状态筛选后编号仍保持原始历史记录编号。
- 历史记录编号不需要和保存区实例编号对应。

后端 `list_generation_history()` 保持当前排序 `started_at DESC, id DESC`。

前端渲染时使用：

```javascript
record.id
```

## 保存区实例重新提交

保存区实例操作按钮中，在 `删除` 左边新增：

```text
重新提交
```

按钮顺序：

```text
编辑 / 保存 / 取消 / 重新提交 / 删除
```

重新提交规则：

```text
读取当前实例提示词。
读取当前实例输入图。
读取当前实例标签。
如果输入图数量 > 0，按图生图提交。
如果输入图数量 = 0，按文生图提交。
文生图和图生图的生成数量都固定为 1。
Provider 使用当前操作区 / 全局默认 Provider。
长宽比、清晰度、尺寸使用当前操作区 / 全局默认值。
生成路径使用当前操作区 / 全局默认生成路径。
不修改原实例。
不覆盖原实例输出图。
不修改操作区草稿。
```

重新提交后走同一个生成接口。

重新提交成功后新增实例。

重新提交失败后保留已经立即创建的空输出实例。

重新提交如果当前实例正在编辑：

- 先读取编辑中的草稿内容。
- 按草稿内容提交。
- 不自动保存草稿到原实例。

## 点击生成立即保存实例

操作区点击 `生成` 后，不再等到生成成功才创建保存区实例。

后端 `/api/generate` 流程调整为：

```text
1. 接收生成请求。
2. 校验基础参数。
3. 计算 mode、prompt、input_image_paths、tags、output_dir、options。
4. 计算最终生成数量 n。
5. 图生图强制 n = 1。
6. 创建 generation_history running 记录。
7. 按 n 创建保存区实例，output_image_path 为空。
8. 调用 Provider 或自定义脚本生成图片。
9. 生成成功后按顺序把 output_path 写回已创建实例。
10. 如果返回图片数量超过已创建实例数量，额外新增实例保存多出的图片。
11. 如果返回图片数量少于已创建实例数量，剩余实例保持无输出图。
12. 写入历史记录 success 或 failed。
13. 返回实例列表和输出路径。
```

基础参数校验失败时不创建保存区实例。

基础参数包括：

```text
mode 合法
prompt 可提交给后端
图生图输入图存在
输出目录存在或可用
生成数量是正整数
尺寸参数合法
Provider 存在
```

API 调用失败时：

- 已创建的保存区实例保留。
- 输出图为空。
- 历史记录标记为 failed。
- 错误信息写入历史记录。
- 前端状态显示失败原因。

文生图 `n > 1` 时：

- 点击生成后立即创建 n 个空输出实例。
- 生成成功后逐个填入输出图。
- 保存区实例数量和生成数量保持一致。

图生图时：

- 生成数量固定为 1。
- 点击生成后立即创建 1 个空输出实例。

所有立即创建的实例都保存：

```text
prompt
mode
source = generated
provider
generation_path
generation_size
generation_params_json
input_image_paths
tags
output_image_path = ""
```

为支持生成成功后填图，数据库层新增函数：

```python
def update_instance_output_image(conn, instance_id: int, output_image_path: str) -> None
```

只更新：

```text
output_image_path
updated_at
```

不要删除输入图。

不要删除标签。

不要修改提示词。

## 数据安全和生成并发

备份和 JSON 导出允许在生成过程中执行。

原因：

- 备份使用 SQLite 一致性快照。
- 导出读取当前已提交数据。

恢复不允许和生成并发执行。

实现后端保护：

```python
DATA_RESTORE_LOCK
restore_in_progress
active_generation_count
```

生成开始时：

```text
如果 restore_in_progress，返回 409。
active_generation_count += 1。
```

生成结束时：

```text
active_generation_count -= 1。
```

恢复开始时：

```text
如果 active_generation_count > 0，返回 409。
如果 restore_in_progress，返回 409。
restore_in_progress = True。
```

恢复结束时：

```text
restore_in_progress = False。
```

前端如果当前页面有进行中的生成任务，禁用恢复按钮。

后端仍必须做并发保护，不能只依赖前端。

## 文件和图片安全规则

备份、导出、恢复、重新提交、立即保存实例都不能删除电脑上的图片文件。

数据库恢复只替换：

```text
AI生图软件/data/AIImageManager.data.sqlite
AI生图软件/config/AIImageManager.config.json
```

不得删除或修改：

```text
AI生图软件/generated/
用户自选生成目录
实例中记录的任意图片路径
输入图原始文件
输出图原始文件
```

JSON 导出中的图片只保存路径字符串。

备份 zip 中不包含图片文件。

## 副作用与处理

备份 zip 包含明文 API Key。软件是本机自用，这符合当前安全边界；不要把备份 zip 发给别人。

自动备份会占用磁盘空间。只自动清理 `auto` 类型备份，保留最近 30 份。

手动备份不会被自动删除。如果手动备份很多，需要用户自己清理。

恢复会替换当前数据库和设置。恢复前必须自动创建 `pre_restore` 备份。

恢复后浏览器里的 localStorage UI 状态可能和恢复后的数据库不一致。恢复成功后前端提示刷新页面，并在刷新后按现有分页保护重新加载数据。

启动迁移失败时，软件不能继续用半迁移数据库启动。必须保留原数据库，并显示迁移失败错误。

点击生成立即创建实例后，生成失败也会留下无输出图实例。这是 V0.23 的有意设计，用来保证提示词、输入图、标签不会因为 API 失败丢失。

点击生成 `n > 1` 时，如果生成失败，会留下 n 个无输出图实例。这是用户确认的行为。

重新提交使用当前操作区 / 全局默认参数，不复刻原实例历史参数。旧实例的 Provider、尺寸、清晰度只作为历史信息保留。

历史记录编号改为 `记录 id` 后，不再显示每页内的 `#001`。这会改变历史记录页视觉文本，但不影响生图管理页实例编号。

JSON 导出不是备份恢复格式。V0.23 只支持 zip 恢复。

## 测试要求

新增后端测试：

- 手动备份会创建 zip。
- 备份 zip 包含数据库、配置、metadata。
- 备份 metadata 包含版本号、备份类型、schema_version。
- 备份使用 SQLite 快照后可打开并通过 `PRAGMA integrity_check`。
- 自动备份每天只创建一次。
- 自动备份只保留最近 30 份。
- 自动清理不删除 manual、pre_restore、pre_migration 备份。
- JSON 导出包含 instances、input_images、tags、instance_tags、generation_history、settings。
