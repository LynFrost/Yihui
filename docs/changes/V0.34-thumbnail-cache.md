## 修改目标

V0.34 在 V0.33 基础上增加缩略图缓存，用来优化大量图片场景下保存区、操作区、实例卡片小图的显示速度。

核心目标：

- 缩略图缓存放在共享目录 `AI生图软件/cache/thumbnails/`。
- 原图仍然只保存本地路径，不复制原图。
- 缩略图只是可删除、可重建的派生缓存。
- 当前页可见图片优先生成或读取缩略图。
- 不提前处理全部图片。
- 图片弹窗查看大图仍然读取原图。
- 原图路径失效时，不能用缩略图伪装成原图正常存在。
- 增加清理缩略图缓存按钮。
- 缩略图生成不能卡死页面。
- 不破坏懒加载、节点筛选、翻页图片稳定、图片弹窗、键盘翻页。
- 不破坏 V0.33 的搜索框清空按钮和实例提示词清空按钮。

本版重点是图片显示性能优化，不改保存区布局，不新增大功能。

## 缩略图缓存目录

新增共享缓存目录：

```text
AI生图软件/cache/thumbnails/
```

目录性质：

- 该目录只保存缩略图缓存。
- 缩略图可以随时删除。
- 删除缩略图不影响数据库。
- 删除缩略图不影响原图。
- 删除缩略图后，当前页可见图片再次加载时自动按需重建。

启动软件或首次请求缩略图时，如果目录不存在，后端自动创建。

缓存目录不要放在任何版本目录内部，原因是：

- V0.34 之后升级版本时，缓存可以继续复用。
- 缓存和真实数据分离。
- 删除某个软件版本目录时不会误删缓存。

## 缩略图文件命名

缩略图缓存文件名不要直接使用原图文件名，避免路径过长、特殊字符和重名冲突。

推荐缓存 key 使用以下内容计算哈希：

```text
原图绝对路径
原图文件大小
原图最后修改时间
缩略图规格版本
```

示例：

```text
sha256(abs_path + file_size + mtime_ns + thumb_version).webp
```

要求：

- 同一路径原图没有变化时，复用同一个缩略图。
- 原图被替换、修改、覆盖后，自动生成新的缩略图。
- 缩略图规格以后变化时，可以通过 `thumb_version` 让旧缓存自动失效。
- 不需要清理已经过期但无人使用的旧缩略图；用户可以通过清理缓存按钮统一删除。

## 缩略图规格

V0.34 推荐固定缩略图规格：

```text
最长边：384px
格式：webp
质量：80
```

如果运行环境对 `webp` 支持出现问题，可以退回 `jpeg`。但 V0.34 文档以 `webp` 为默认方案。

要求：

- 缩略图保持原始长宽比。
- 小图区域仍按现有 CSS 裁切和适配规则显示。
- 不改变保存区实例卡片图片位尺寸。
- 不改变操作区图片位尺寸。
- 不改变单列 / 双列布局。

## 后端接口

### 原图接口保持不变

现有原图接口继续保留：

```text
GET /api/image?path=...
```

该接口继续用于：

- 图片弹窗大图。
- 图片弹窗左右切换。
- 图片弹窗缩放。
- 需要读取原图的场景。

V0.34 不把弹窗大图切换为缩略图。

### 新增缩略图接口

新增接口：

```text
GET /api/thumbnail?path=...
```

行为：

1. 读取 `path` 参数。
2. 检查 `path` 是否存在并且是文件。
3. 如果原图不存在，返回 `404`，不要返回旧缩略图。
4. 根据原图路径、文件大小、修改时间、缩略图规格计算缓存文件名。
5. 如果缩略图已存在，直接 `send_file` 返回缩略图。
6. 如果缩略图不存在，生成缩略图后返回。
7. 生成失败时返回明确错误，不影响原图文件。

返回要求：

- 成功时返回缩略图图片文件。
- 原图不存在时返回 `404` 和 JSON 错误，错误文字可用 `图片未找到`。
- 图片格式不支持或生成失败时返回 `500` 和 JSON 错误。

### 并发生成保护

如果同一张图在短时间内被多个 `<img>` 同时请求，后端不能生成多个互相覆盖的半成品。

推荐实现：

- 先生成到临时文件。
- 生成完成后再原子替换为正式缩略图文件。
- 如果正式文件已经被其他请求生成完成，当前请求直接返回正式文件。

示例流程：

```text
thumb.webp.tmp.<pid> -> thumb.webp
```

要求：

- 不返回未写完的缩略图。
- 不因为并发请求导致损坏缩略图。
- 不阻塞其他图片的缩略图请求。

## 清理缩略图缓存

新增接口：

```text
POST /api/thumbnails/clear
```

行为：

- 删除 `AI生图软件/cache/thumbnails/` 下的缩略图缓存文件。
- 不删除目录本身也可以；如果删除目录，下一次请求时必须自动重建目录。
- 不删除原图。
- 不修改数据库。
- 不修改历史记录。
- 不修改备份。
- 不修改导出文件。

返回示例：

```json
{
  "deleted_count": 128,
  "deleted_bytes": 3456789,
  "size_label": "3.3 MB"
}
```

如果部分文件删除失败：

- 返回失败数量。
- 顶部显示错误或警告。
- 不影响已经删除成功的文件。

## 重建缩略图缓存按钮结论

V0.34 不新增 `重建全部缩略图缓存` 按钮。

原因：

- 全量重建会扫描全部实例和全部图片，和“当前页可见图片优先，不提前处理全部图片”的目标冲突。
- 数据量大时，全量重建容易让用户以为软件卡死。
- 缩略图缓存本来就是派生缓存，清理后按需重建更稳。

V0.34 的处理方式：

- 数据安全页只提供 `清理缩略图缓存`。
- 清理后，保存区当前页可见图片再次显示时自动重新生成缩略图。
- 以后如果确实需要，可以新增 `重建当前页缩略图`，但不在 V0.34 做。

## 前端图片 URL

现有原图 URL 函数：

```javascript
function imageUrl(path) {
  ...
}
```

V0.34 新增缩略图 URL 函数：

```javascript
function thumbnailUrl(path) {
  return `/api/thumbnail?path=${encodeURIComponent(path)}`;
}
```

要求：

- `imageUrl(path)` 继续表示原图。
- `thumbnailUrl(path)` 只用于小图显示。
- 不要把 `imageUrl(path)` 改成缩略图，避免弹窗被误改。
- 图片位上继续保留 `data-image-path` 原图路径。
- 图片位上继续保留 `data-lazy-image-path` 原图路径，懒加载判断仍以原图路径作为身份。

## 保存区和操作区小图

以下小图显示优先使用缩略图：

- 操作区输入图。
- 操作区输出图。
- 保存区实例输入图。
- 保存区实例输出图。
- 保存区悬停临时预览中的小图，如果当前实现复用图片位，也使用缩略图。

图片弹窗不使用缩略图。

渲染要求：

```html
<div
  class="image-slot image-slot-filled"
  data-image-path="原图路径"
  data-lazy-image-path="原图路径"
>
  <img src="/api/thumbnail?path=..." loading="lazy" decoding="async">
</div>
```

注意：

- `data-image-path` 必须是原图路径。
- 点击图片打开大图时，必须用 `data-image-path` 调用原图接口。
- 缩略图加载失败不能把 `data-image-path` 改成缩略图路径。

## 懒加载稳定检查

V0.34 必须沿用现有 `frontend/js/image-loader.js` 的懒加载和稳定显示机制。

需要调整的点：

- `loadLazyImageSlot` 设置 `<img src>` 时，使用 `thumbnailUrl(path)`。
- `imageSrcMatchesPath` 不能继续只用 `src.includes(encodeURIComponent(path))` 简单判断，必须兼容缩略图接口。
- 翻页后仍然调用 `stabilizeSaveAreaImages`。
- 错误重试仍然保留。
- `retry` 参数追加在缩略图 URL 后，避免浏览器缓存坏图。

推荐新增工具函数：

```javascript
function imageDisplayUrl(path, options = {}) {
  const base = thumbnailUrl(path);
  return options.retry ? `${base}&retry=${Date.now()}` : base;
}
```

同时保留原图函数：

```javascript
function originalImageUrl(path) {
  return imageUrl(path);
}
```

如果当前代码继续使用 `imageUrl` 作为原图函数名，则不要重命名，只新增 `thumbnailUrl`。

## 原图路径失效处理

必须满足：

- 原图不存在时，缩略图接口返回失败。
- 即使旧缩略图文件还在，也不能显示为正常图片。
- 小图可以显示加载失败状态。
- 点击大图时，原图接口同样失败并显示现有错误。

这条规则的原因：

缩略图只能说明“曾经生成过缓存”，不能说明“原图现在仍然存在”。软件的数据真实性必须以原图路径是否有效为准。

## 浏览器缓存

缩略图文件名已经包含原图大小和修改时间，因此一般不需要频繁追加随机参数。

要求：

- 正常加载时使用稳定缩略图 URL。
- 重试加载时才追加 `retry`。
- 原图改变后，因为缓存 key 变化，缩略图 URL 对应的新文件也变化。
- 清理缩略图缓存后，同一路径再次请求会重新生成。

## 数据安全与备份影响

缩略图缓存不属于核心数据。

要求：

- 手动备份不包含 `AI生图软件/cache/thumbnails/`。
- 自动备份不包含 `AI生图软件/cache/thumbnails/`。
- JSON 导出不包含缩略图缓存。
- 恢复备份不恢复缩略图缓存。
- 清理缩略图缓存不触发数据库备份。
- 清理缩略图缓存不修改 schema 版本。

数据安全页可以显示缓存目录，但不要把缓存误称为备份数据。

## 对生图管理页的影响

生图管理页布局不做调整。

不会改变：

- 操作区布局。
- 保存区实例布局。
- 单列 / 双列显示。
- 节点区布局。
- 筛选区布局。
- 分页区布局。
- 图片位尺寸。
- 图片弹窗布局。

会改变：

- 小图 `<img>` 的 `src` 从原图接口变为缩略图接口。
- 第一次显示某张图时，后端可能需要生成缩略图。
- 第二次显示同一张未变化的图时，读取缓存会更快。
- 清理缩略图缓存后，下一次显示会重新生成。

## 对 V0.33 清空按钮的影响

V0.34 不改 V0.33 的清空按钮逻辑。

必须继续满足：

- 搜索提示词输入框内部 `X` 可以清空搜索。
- 搜索清空后分页回到第 1 页。
- 搜索清空后当前页批量选择清空。
- 保存区实例编辑状态提示词框内部 `X` 可以清空当前编辑框内容。
- 非编辑状态实例提示词不显示清空 `X`。
- 清空按钮不触发图片弹窗。
- 清空按钮不触发保存区左右键翻页。

## 对 V0.32 键盘翻页的影响

V0.34 不改 V0.32 键盘翻页逻辑。

必须继续满足：

- 焦点在保存区时，左右方向键可以上一页 / 下一页。
- 焦点在输入框、textarea、搜索框、提示词框、TAG 输入框、弹窗输入框时，左右方向键只移动光标。
- 图片弹窗打开时，左右方向键仍用于图片切换。
- 键盘翻页后仍触发保存区图片稳定显示检查。
- 键盘翻页后当前页批量选择继续清空。

## 错误提示

缩略图生成失败时，不应该让页面静默空白。

要求：

- 图片位可以保持现有失败样式或显示破图状态。
- 控制台可以输出缩略图加载失败信息。
- 数据安全页清理失败时，顶部消息显示失败原因。
- 原图不存在时，错误文案不要写成“缩略图不存在”，而应表达“图片未找到”。

## 性能要求

V0.34 的缩略图生成必须按需进行。

要求：

- 实例列表 API 不生成缩略图。
- 翻页查询 API 不生成缩略图。
- 筛选查询 API 不生成缩略图。
- 只有浏览器真正请求某张小图时，后端才生成或读取缩略图。
- 当前页可见图片优先加载。
- 页面外图片继续由懒加载控制，不提前请求太多。
- 生成缩略图不能阻塞前端点击、翻页、筛选、键盘翻页。

## 可能副作用与处理

### 第一次加载某张图会多一次生成耗时

原因：

第一次请求缩略图时，后端需要读取原图并生成缓存。

处理：

- 只对当前页可见图片按需生成。
- 后续再次打开同一张图读取缓存。
- 不做全量重建，避免一次性耗时。

### 需要新增 Pillow 依赖

原因：

后端生成缩略图需要可靠图片处理能力。

处理：

- `requirements.txt` 增加 `Pillow>=10.0.0`。
- 如果依赖安装失败，缩略图接口返回明确错误，原图接口不受影响。

### 缩略图缓存会占用磁盘空间

原因：

缓存目录会随图片数量增加。

处理：

- 数据安全页显示缓存数量和大小。
- 提供 `清理缩略图缓存` 按钮。
- 缩略图是派生缓存，可以安全删除。

### 原图失效但旧缩略图还存在

风险：

如果直接返回旧缩略图，会让用户误以为原图仍存在。

处理：

- 缩略图接口每次先检查原图是否存在。
- 原图不存在时直接返回 `404`。
- 不使用旧缩略图伪装正常。

### 图片稳定显示逻辑可能需要适配新 URL

原因：

V0.31 之后的稳定检查会判断图片 `src` 是否匹配路径。缩略图接口引入后，匹配方式需要兼容。

处理：

- 保留 `data-lazy-image-path` 原图路径。
- 新增缩略图 URL 识别逻辑。
- 翻页后继续执行 `stabilizeSaveAreaImages`。
- 不能因为接入缩略图缓存而回退图片稳定修复。

### 清理缓存时正在加载图片

风险：

用户清理缓存时，某些图片请求可能正好在读取缓存文件。

处理：

- 删除失败的文件记录为失败数量。
- 后续请求会自动重新生成。
- 不影响数据库和原图。
