# V0.63 生图管理页对齐和原地提交纠偏

## 目标

当前 V0.62 已完成操作区“新增准备态实例”和保存区实例“提交/复制/重提”的主工作流调整，但页面级验收发现部分 V0.62 要求没有完全实现。本版 V0.63 目标是不新增大功能，专门修复 V0.62 遗留偏差：

- 操作区和保存区实例的提示词、输入图、Provider、按钮没有严格对齐。
- 操作区状态提示没有放到原“文生图/图生图”按钮释放出的区域。
- 保存区准备态实例点击“提交”后，生成中实例仍被挪到保存区底部。
- 失败实例缺少“复制”按钮。
- 实例点击“编辑”后，“删除”按钮位置发生下移。

本版原则：

- 这是一版纠偏修复，不扩大 V0.62 工作流范围。
- 对齐不能再只靠局部微调，必须统一操作区和保存区单列实例的主网格。
- 准备态实例和失败实例的提交/重提必须在原实例位置进入生成中。
- 不改变 V0.62 的“操作区新增、保存区提交”主流程。
- 不删除电脑上的图片文件。
- 本文档落成后不直接执行实现，确认后再进入代码修改。

## 操作区和保存区实例严格对齐

### 1. 统一主网格

当前问题：

- V0.62 中操作区仍使用独立的 7 列结构：
  - `meta / prompt / input / size / detail / actions / status`
- 保存区单列实例使用 8 列结构：
  - `meta / prompt / input / size / output / detail / status / actions`
- 两者列数和列位不同，导致提示词框、输入图、Provider、操作按钮无法严格对齐。

调整方案：

- 操作区改为和保存区单列实例一致的 8 列基准。
- 操作区、保存区单列实例共用同一组列宽变量和 gap。
- 操作区不再单独使用一套无法和实例对齐的 7 列网格。
- 保存区双列模式可以保留自身紧凑布局，但单列模式必须作为对齐基准。

验收标准：

- 操作区提示词框左右边缘与保存区实例提示词框左右边缘严格对齐。
- 操作区输入图区域左右边缘与保存区实例输入图区域左右边缘严格对齐。
- 操作区 Provider 区域与保存区实例 Provider 区域严格对齐。
- 操作区按钮列与保存区实例按钮列严格对齐。
- 单列模式下上下比较不出现明显错位。
- 双列模式不因本次改动出现布局破裂、文字重叠或横向滚动。

### 2. 水平对齐

调整方案：

- 操作区中，“操作区”标题、“提示词”标题、“Provider”标题、“清除”按钮在同一水平逻辑线上对齐。
- 操作区中提示词框、比例框、标签框、“清空”按钮上边缘对齐。
- 操作区中提示词框、分辨率框、路径框、“新增”按钮下边缘对齐。
- V0.62 已删除“文生图/图生图”按钮，因此这里的“原文生图/原图生图按钮位置”只作为旧布局参照，不恢复这两个按钮。

验收标准：

- 操作区第一行标题和清除按钮不再错位。
- 提示词框、比例框、标签框、“清空”按钮上边缘一致。
- 提示词框、分辨率框、路径框、“新增”按钮下边缘一致。
- “清空/新增”按钮与保存区实例“编辑/删除”按钮列对齐。

### 3. 输入图和清除按钮对齐

调整方案：

- 操作区“输入图”标题与保存区实例“输入图”标题对齐。
- 操作区输入图区域中的“清除”按钮与保存区实例输入图区域中的“清除”按钮对齐。
- 操作区输入图框继续常驻显示。
- 输入图为空时仍自动按文生图新增准备态实例；输入图不为空时仍自动按图生图新增准备态实例。

验收标准：

- 操作区“输入图”文字和保存区实例“输入图”文字在同一列、同一水平规则下显示。
- 操作区“清除”按钮和保存区实例“清除”按钮位置一致。
- 清除输入图后，操作区布局不跳动。

副作用：

- 统一输入图列后，操作区可用宽度会更接近保存区实例，部分窄窗口下输入图区域可能比 V0.62 更紧。
- 需要重点检查输入图多图、拖拽、粘贴、删除、悬停预览。

## 操作区状态提示位置

### 4. 状态提示放到原模式按钮区域

当前问题：

- V0.62 中状态提示仍在操作区右侧独立状态列中。
- 这没有利用删除“文生图/图生图”按钮后释放出的区域，也容易继续挤压右侧布局。

调整方案：

- 操作区结果状态提示移动到原“文生图/图生图”按钮释放出的左侧区域。
- 状态提示区域与“操作区”标题同属操作区 meta 区域。
- 可见状态文本保持紧凑。
- 完整状态内容继续通过悬停浮窗显示。
- 右侧不再额外占用独立状态列挤压 Provider、路径、标签和按钮区域。

验收标准：

- “清空”按钮右边不再承担主要结果状态提示。
- 操作区右侧没有多余状态列挤占空间。
- 状态短文本能在左侧区域看到。
- 状态完整文本仍可通过悬停浮窗查看。
- 有生成中、成功、失败、重试信息时，操作区布局不跳动。

副作用：

- 状态短文本的可见宽度会变小。
- 因此必须保留完整浮窗，避免错误信息看不全。

## 保存区原地提交

### 5. 准备态实例提交后不进入底部 pending 区

当前问题：

- V0.62 前端虽然有原地标记生成中的逻辑，但保存区渲染仍会把所有 `generation_status === "running"` 的真实实例抽出来放到 `pending-section`。
- 结果是准备态实例点击“提交”后，仍然会被挪到保存区底部。

调整方案：

- 对已有数据库实例 ID 的准备态实例，点击“提交”后必须留在当前列表中的原位置渲染。
- 保存区底部 `pending-section` 只用于没有稳定数据库实例 ID 的临时生成占位。
- 由准备态实例提交产生的 running 实例，不进入底部 `pending-section`。
- 前端刷新运行中实例时，不得因为 `generation_status === "running"` 就无条件抽离正式列表。
- 生成中读秒、取消中、失败重试提示仍显示在原实例卡片上。

验收标准：

- 准备态实例点击“提交”后，实例就在当前位置显示生成中。
- 不会在保存区底部额外出现同一个生成中实例。
- 不会因为提交导致当前页前面的实例被挤走。
- 刷新页面后，仍然能在合理位置看到该生成中实例，并且可以取消。
- 生成成功或失败后，不产生重复实例。

### 6. 后端不改写 `created_at`

当前问题：

- 后端准备已有实例生成时，会把实例 `created_at` 改成生成开始时间。
- 这会影响“最新优先/最早优先”等基于创建时间的排序，使原实例提交后位置发生变化。

调整方案：

- 已有实例进入生成中时，不改写原实例 `created_at`。
- 只更新生成相关字段，例如：
  - `generation_status`
  - `generation_task_id`
  - `generation_output_index`
  - `generation_error`
  - `generation_started_at`
  - `generation_finished_at`
  - `updated_at`
  - `generation_params_json`
  - 输出图字段
- 提交时间、重提时间、历史记录时间应继续依赖 `generation_started_at` 或历史记录，不用 `created_at` 表达。

验收标准：

- 准备态实例提交前后，实例原始创建时间不变。
- 当前排序为“最新优先”时，提交动作本身不会因为改写 `created_at` 把实例推到最前或底部。
- 历史记录仍能正确记录本次提交时间。
- 数据安全导出、备份、恢复中的创建时间不被提交动作污染。

副作用：

- 生成中的“开始生成时间”和实例“创建时间”会明确分离。
- 旧代码中如果有地方误用 `created_at` 表示提交时间，需要改为读取 `generation_started_at` 或历史记录时间。

### 7. 失败实例“重提”也保持原地

调整方案：

- 失败实例点击“重提”后，和准备态实例点击“提交”一样，在原位置进入生成中。
- “重提”不进入底部 `pending-section`。
- “重提”不改写原实例 `created_at`。
- 重提完成后，仍更新同一个实例，不生成重复实例。

验收标准：

- 失败实例点击“重提”后不跑到底部。
- 重提生成中读秒、取消中、失败重试提示显示在原实例卡片上。
- 重提成功后，同一个实例显示新输出图。
- 重提失败后，同一个实例显示失败状态。

## 保存区实例按钮纠偏

### 8. 失败实例补齐“复制”

当前问题：

- V0.62 中普通实例有“带入 / 复制 / 提交”，但失败实例只有“带入 / 重提”，缺少“复制”。

调整方案：

- 失败实例也显示“带入 / 复制 / 重提”。
- 失败实例的“复制”与普通实例的“复制”行为一致：
  - 复制为一个准备态实例。
  - 输出图为空。
  - 不立即提交。
  - 保留提示词、输入图、标签、Provider、路径、尺寸、比例、分辨率、调用方式、model、生成数量 `n` 等参数。
- 失败实例原内容不被修改。

验收标准：

- 失败实例能看到“带入 / 复制 / 重提”三个按钮。
- 点击失败实例“复制”不会触发生成。
- 复制出的实例是准备态实例。
- 复制出的实例没有输出图。

副作用：

- 失败实例按钮数量增加，需要固定按钮尺寸和间距，避免挤压标签或 Provider。

### 9. “提交”和“重提”同位置同尺寸

调整方案：

- 准备态实例的“提交”和失败实例的“重提”使用同样宽度、高度和位置。
- 失败实例、准备态实例、普通实例的右侧内联按钮区不因状态不同发生明显跳动。

验收标准：

- “提交”和“重提”视觉尺寸一致。
- 两个按钮出现在同一列位。
- 切换实例状态后按钮区不明显跳动。

### 10. 编辑态按钮固定槽位

当前问题：

- 实例点击“编辑”后，右侧操作列从“编辑 / 删除”变成“保存 / 取消 / 删除”。
- 因为中间多出“取消”，导致“删除”按钮向下移动。

调整方案：

- 实例右侧操作列固定三行槽位。
- 非编辑态：
  - 第一行显示“编辑”。
  - 第二行保留空位。
  - 第三行显示“删除”。
- 编辑态：
  - 第一行显示“保存”。
  - 第二行显示“取消”。
  - 第三行显示“删除”。
- pending 生成中态可以继续只显示“取消/取消中”，但不能影响普通实例和编辑态实例的按钮槽位规则。

验收标准：

- 点击“编辑”前后，“编辑/保存”按钮位置不变。
- 点击“编辑”前后，“删除”按钮位置不变。
- 编辑态中“取消”出现在中间预留槽位。
- 按钮列高度不导致实例卡片整体错位。

副作用：

- 非编辑态中间会有一个不可见空位。
- 这是为了保证编辑前后按钮位置稳定，属于有意保留的空间。

- 操作区状态提示位于原模式按钮释放区域。
- 操作区右侧不再因状态提示多出空白列。
- 准备态实例点击“提交”后在原位置进入生成中。
- 准备态实例提交后不在底部出现重复 pending 卡片。

## 不做内容

- 不恢复操作区直接生成。
- 不恢复“文生图 / 图生图”按钮。
- 不改变 V0.62 的准备态实例工作流。
- 不改变 `n` 作为单实例生成参数的规则。
- 不新增 Provider 类型。
- 不新增大功能。
- 不删除电脑上的图片文件。
- 不重构前端模块结构。
