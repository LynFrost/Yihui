## 操作区尺寸与分辨率合并

修复截图 `AI生图软件/docs/bugs_v0.06/Snipaste_2026-05-01_17-57-48.png` 中尺寸和分辨率控件互相挤压、视觉上叠起来的问题。

实现规则：

- 尺寸和分辨率不再各占一个横向 grid 列。
- 新增一个统一容器，例如：

```html
<div class="field record-generation-options">
  ...
</div>
```

- `record-generation-options` 只占一个横向宽度区间。
- 容器内部上下排列两个控件：
  - 上：尺寸。
  - 下：分辨率。
- 尺寸和分辨率控件都降低高度，不能继续使用 `var(--record-main-height)`。
- 单个控件建议高度：

```css
--generation-option-height: 38px;
```

- 整个 `record-generation-options` 的总高度不得超过操作区主高度太多，避免撑高整行。
- 尺寸按钮 `1024x1024` 必须完整显示，不能被裁切，不能和分辨率重叠。
- 分辨率下拉 `1K / 2K / 4K` 必须完整显示。
- 尺寸弹出的预设面板继续可用，层级必须高于输出图、输入图、右侧标签区。

实现建议：

- 保留 `renderSizePicker()` 的尺寸选择逻辑。
- 保留 `renderResolutionPicker()` 的分辨率选择逻辑。
- 新增 `renderGenerationOptions()`，由它包住尺寸和分辨率：

```js
function renderGenerationOptions() {
  return `
    <div class="field record-generation-options">
      ${renderSizePicker()}
      ${renderResolutionPicker()}
    </div>
  `;
}
```

- `renderOperationArea()` 中用 `renderGenerationOptions()` 替换原来的：

```js
${renderSizePicker()}
${renderResolutionPicker()}
```

## 操作区固定横向列

文生图和图生图使用完全一致的横向列结构。

横向顺序固定为：

```text
模式 | 提示词 | 输入图区占位 | 尺寸/分辨率 | 输出图 | Provider/标签/路径 | 操作
```

规则：

- 文生图和图生图的提示词框宽度必须完全一致。
- 文生图模式下，输入图区保留宽度，但完全无内容。
- 文生图模式下不要显示“输入图”标题、空白图片位、加号、边框或提示文字。
- 文生图模式下输入图区只作为布局占位存在，不参与鼠标交互。
- 文生图模式下不要让提示词框跨过输入图区。
- 图生图模式下输入图区正常显示标题、图片位和加号。
- 图生图模式下输入图区宽度要比 V0.06 更宽。
- 输出图、右侧 Provider/标签/路径、操作按钮在文生图和图生图切换时横向位置保持不变。

建议 CSS grid：

```css
.operation-area.image-record {
  grid-template-columns:
    88px
    minmax(260px, 520px)
    minmax(560px, 1fr)
    92px
    76px
    minmax(180px, .8fr)
    88px;
}
```

列含义：

```text
88px                模式
minmax(260px,520px) 提示词
minmax(560px,1fr)   输入图区或空占位
92px                尺寸/分辨率上下组合
76px                输出图
minmax(180px,.8fr)  Provider/标签/路径
88px                操作按钮
```

如果实际页面宽度不足，允许微调列宽，但必须满足：

- 不出现横向滚动条。
- 提示词框和其浮层宽度一致。
- 图生图输入图区至少能容纳 7 张标准图片位时优先；如果页面宽度不足，至少不能少于 V0.06 的 6 张。
- 右侧 Provider/标签/路径区域不能被挤压到不可用。
- 操作按钮不能被遮挡。

## 文生图输入图区占位

`renderOperationInputImagesBlock()` 在文生图模式下仍返回占位节点，但节点内部为空。

实现规则：

- 文生图模式下返回类似：

```html
<div class="field record-input-images operation-input-images operation-input-placeholder" aria-hidden="true"></div>
```

- 占位节点保留 grid 列宽。
- 占位节点不显示任何内容。
- 占位节点不显示边框、背景、标题、图片位和加号。
- 占位节点不响应点击。

CSS：

```css
.operation-input-placeholder {
  visibility: hidden;
  pointer-events: none;
}

.operation-area.mode-text_to_image .operation-input-placeholder {
  display: block;
}
```

不得继续使用：

```css
.operation-area.mode-text_to_image .operation-input-placeholder {
  display: none;
}
```

## 提示词框与浮层宽度一致

修复操作区提示词框宽度大于聚焦浮层宽度时，点击右侧区域导致浮层一闪就消失的问题。

实现规则：

- 操作区提示词框正常显示宽度与聚焦后的真实 textarea 浮层宽度必须一致。
- 编辑态提示词浮层不得使用固定宽度 `620px`。
- 删除或覆盖 V0.06 中类似规则：

```css
.prompt-field.is-editable textarea:focus {
  width: min(620px, calc(100vw - 32px));
}
```

- 改为：

```css
.prompt-field.is-editable textarea:focus {
  width: 100%;
}
```

- 浮层仍然可以随内容高度向下展开。
- 浮层仍然允许覆盖下面或旁边控件。
- 点击提示词框任意位置都必须保持 textarea 聚焦，不得闪退。
- 中文输入法组合输入期间不得触发重绘。

## 输入图区加宽

在尺寸和分辨率合并后，将释放出的横向空间优先分配给输入图区。

规则：

- 图生图模式下输入图区宽度大于 V0.06 的 `486px`。
- 输入图区横向空间用于容纳更多标准图片位。
- 标准图片位尺寸继续使用现有 `76px` 宽度和 `var(--record-main-height)` 高度。
- 输入图超过一行容量时，仍然按现有规则换行。
- 输入图区变宽不得挤压输出图、Provider/标签/路径、操作按钮。

## 副作用处理

文生图空白占位：

- 文生图模式下中间会保留一块完全空白区域。
- 这是为了让文生图和图生图提示词宽度一致、输出图位置一致。
- 空白区域不得显示控件，不得影响鼠标点击提示词、尺寸、输出图等真实控件。

尺寸/分辨率变矮：

- 点击区域变小后仍需保证可点击。
- 控件高度不得低于 `34px`。
- 字体、padding、行高要保证 `1024x1024` 和 `4K` 都能完整显示。

尺寸弹窗：

- 尺寸弹窗仍从尺寸按钮下方出现。
- 弹窗不能被分辨率下拉、输出图或右侧区域遮挡。
- 点击尺寸预设、自定义尺寸、关闭按钮逻辑保持不变。

响应式布局：

- 窄屏下继续使用现有单列响应式规则。
- 单列模式下尺寸和分辨率仍上下排列。
- 单列模式下文生图输入图区占位可以不占可见高度。
