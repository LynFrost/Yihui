# V0.59 openai-google 示例、参数空值、路径历史和尺寸显示收口

## 目标

当前 V0.58 已完成 `openai-google` 小云脚本接口接入。本版 V0.59 目标是不新增大功能，对 `openai-google` 的设置页体验、调用示例规则、参数空值表达、操作区路径历史、路径显示和尺寸适用规则做稳定性收口。

本版原则：

- 不改变 V0.58 已接入的 `openai-google` 文生图、图生图共享脚本生成流程。
- 不把 `openai-google` 的 `resolved_size` 强行塞进小云请求 payload。
- 所有接口的固定调用示例统一回归共享脚本，只读展示。
- 真正会改变运行逻辑的内容统一放到“自定义代码”。
- 路径历史要跨版本、跨端口稳定，不再只依赖浏览器本地状态。
- 不破坏现有 `openai`、`google`、`other` Provider 的设置和生成流程。
- 不破坏 V0.58 的代理设置、超时重试、脚本注入、多输入图和图片保存逻辑。
- 本文档只描述变更计划，落成文档不等于直接执行实现。

## 调用示例规则

### 1. 固定调用示例始终读取共享脚本

当前问题：

- 设置页中固定“调用示例”既可以显示共享脚本，也可能被 Provider 配置里曾经保存过的 `code_examples` 覆盖。
- 这会让用户难以判断当前看到的是共享标准脚本，还是以前保存过的示例文本。
- 对 `openai-google` 来说，文生图和图生图脚本本身确实不同，但前半段公共逻辑很多，看起来容易误以为完全一样。

调整方案：

- 所有接口类型的固定“调用示例”都始终读取共享脚本。
- Provider 配置里的旧 `code_examples` 不再覆盖固定调用示例。
- 保存 Provider 设置时，不再把固定调用示例写回 Provider 配置。
- 文生图、图生图切换时，固定调用示例按当前接口类型和生图方式读取对应共享脚本。
- 不额外增加“当前是文生图脚本 / 图生图脚本”的标题提示。
- 不额外突出两份脚本的差异；只要实际读取的脚本确实不同即可。

验收标准：

- `openai` 文生图显示 `openai_text_to_image.py` 共享脚本。
- `openai` 图生图显示 `openai_image_to_image.py` 共享脚本。
- `openai-google` 文生图显示 `google_b2_text_to_image_xiaoyun.py` 共享脚本。
- `openai-google` 图生图显示 `google_b2_image_to_image_xiaoyun.py` 共享脚本。
- Provider 配置中的旧 `code_examples` 不再影响固定调用示例显示。
- 切换 Provider、接口类型、生图方式后，固定调用示例不会串到另一个方式的脚本。

### 2. “调用示例”只读，只保留复制

调整方案：

- “调用示例”页签中的代码框改为只读。
- “调用示例”只保留“复制”按钮。
- 移除固定调用示例里的“编辑 / 保存 / 取消”操作。
- “自定义代码”页签继续保留编辑、保存、取消、复制、清空等操作。
- 生成逻辑保持：
  - 有自定义代码时，优先使用自定义代码。
  - 无自定义代码时，使用共享脚本。

验收标准：

- 固定“调用示例”不能被编辑。
- 固定“调用示例”可以复制。
- 自定义代码仍可编辑、保存、清空和复制。
- 自定义代码存在时，生成仍使用自定义代码。
- 自定义代码为空时，生成使用共享脚本。

副作用：

- 以前手动编辑并保存过的固定调用示例不会再作为固定示例显示。
- 如果用户需要让自己的代码参与实际生成，应迁移到“自定义代码”。

## openai-google 参数空值表达

### 3. 可选参数显示特殊 `None`

当前问题：

- `openai-google` 参数区中很多参数可以不填。
- 参数为空时，当前脚本会跳过这些字段，因此仍然可以生图成功。
- 用户需要明确知道：这些空参数不是漏传，而是主动“不发送该参数”。

调整方案：

- 所有可以默认空着的 `openai-google` 参数，在 UI 上显示为特殊样式的 `None`。
- 这个 `None` 是空值占位，不是普通字符串。
- 实际保存和提交时，`None` 应转换为空值。
- 脚本收到空值后，不把该参数写入小云请求 payload。
- 用户手动输入真实内容后，按用户输入值保存和注入。

需要支持 `None` 空值表达的参数包括：

- `temperature`
- `top_p`
- `stop`
- `presence_penalty`
- `frequency_penalty`
- `logit_bias`
- `user`
- `response_format`
- `seen`
- `tools`
- `tool_choice`
- `user_agent`

默认参数：

- `role` 默认 `user`。
- `max_tokens` 默认 `4096`。
- `stream` 固定 `false`。

重要规则：

- 参数在逻辑上区分“必填 / 默认 / 可选 / 高级可选”。
- UI 上不额外增加“必填 / 默认 / 可选 / 高级可选”的备注说明。
- 参数可接受输入范围以接口官网为准，本文档不重复列出。
- 如果可选参数留在 `None` 状态，不报错。
- 如果用户填写 JSON 型高级参数，应保持现有脚本的 JSON 解析和透传逻辑。

验收标准：

- 可选参数为空时显示特殊样式 `None`。
- `None` 不作为字符串 `"None"` 注入脚本。
- 可选参数为空时，生成请求不发送该字段。
- 必需参数缺失时仍应报错。
- 设置保存、切换 Provider、刷新页面后，`None` 显示和实际空值语义保持一致。

### 4. 文生图和图生图区分

文生图参数：

- `base_url`
- `api_key / api_key_env`
- `model`
- `user_agent`
- `prompt`
- `保存路径`
- `role`
- `max_tokens`
- `stream`
- 其他可选 Google API 参数

图生图额外参数：

- `input_images`

图生图规则：

- `input_images` 由操作区输入图列表注入。
- 支持多张不同图片。
- 图片按操作区上传顺序注入，依次对应图 1、图 2 等。
- 提示词中如果提到图 1、图 2，应和操作区图片顺序对应。

验收标准：

- `openai-google` 文生图参数区不显示 `input_images`。
- `openai-google` 图生图参数区显示软件注入的 `input_images`。
- 图生图没有输入图时不能提交成功。
- 多输入图顺序不被打乱。

## openai-google 尺寸规则

### 5. openai-google 不传尺寸参数

当前判断：

- 操作区的分辨率和尺寸会进入软件内部 payload、实例记录和历史记录。
- 但小云 `chat/completions` 生图接口并没有在当前接入脚本中明确使用 OpenAI Images 风格的 `size` 字段。
- 当前软件尺寸格式是类似 `1024x1024` 的像素格式，不能确认小云该接口支持直接接收。

调整方案：

- `openai-google` 生成时，不把 `resolved_size` 直接塞进小云请求 payload。
- 不为了“看起来传了尺寸”而发送服务商可能不识别的字段。
- `openai-google` 生成结果的保存区实例和历史记录中，尺寸记为空尺寸。
- 避免在保存区和历史记录中显示一个实际没有传给接口的尺寸。

验收标准：

- `openai-google` 共享脚本文生图请求 payload 不包含 `resolved_size` 或直接尺寸字段。
- `openai-google` 共享脚本图生图请求 payload 不包含 `resolved_size` 或直接尺寸字段。
- `openai-google` 生成后的保存区实例尺寸为空。
- `openai-google` 生成后的历史记录尺寸为空。
- 尺寸筛选中，`openai-google` 记录应按空尺寸规则处理。

副作用：

- `openai-google` 生成记录会归到“无 / 空尺寸”。
- 这是对实际请求更准确的表达，但会和普通 `openai` 的尺寸记录表现不同。

### 6. openai-google 操作区尺寸控件显示为“无”

调整方案：

- 当前 Provider 是 `openai-google` 时：
  - 操作区分辨率框自动显示“无”，并置灰不可选。
  - 操作区尺寸框自动显示“无”，并置灰不可选。
- 切换到 `openai-google` 时，不永久覆盖用户之前在普通接口下选择的分辨率和尺寸。
- 切回普通 `openai` Provider 后，恢复用户之前的分辨率和尺寸选择。

验收标准：

- 选择 `openai-google` Provider 后，分辨率框显示“无”且不可选。
- 选择 `openai-google` Provider 后，尺寸框显示“无”且不可选。
- `openai-google` 下无法通过操作区改分辨率和尺寸。
- 切回普通 `openai` Provider 后，分辨率和尺寸恢复为切换前的值。
- 不影响普通接口的 1K / 2K / 4K / 自定义尺寸选择。

## 自定义尺寸显示

### 7. 自定义分辨率时尺寸框显示真实尺寸

当前问题：

- 在普通接口中，分辨率选择“自定义”时，尺寸框显示“自定义”几个字。
- 用户更需要看到当前真实尺寸，例如 `1536x1024`。

调整方案：

- 非 `openai-google` 场景下，分辨率选择“自定义”时：
  - 尺寸框显示当前真实尺寸。
  - 不再显示“自定义”几个字。
  - 尺寸框大小不变。
  - 如果显示不下，只显示一部分。
  - 鼠标悬停可以看到完整尺寸。

验收标准：

- 自定义尺寸为 `1536x1024` 时，尺寸框显示 `1536x1024` 或其可见截断内容。
- 尺寸框不因为内容变长而撑大。
- 悬停能看到完整尺寸。
- 点击尺寸框仍可进入既有尺寸选择或自定义尺寸操作。
- 1K / 2K / 4K 的显示规则不回退。

## 路径历史

### 8. 路径历史改为共享持久化

当前问题：

- 操作区路径历史主要来自浏览器本地 UI 状态。
- 换版本、换端口、换浏览器地址后，路径下拉可能变少。
- 成功实例中已有的路径没有稳定回填到路径历史。

调整方案：

- 路径历史不能只依赖浏览器 `localStorage`。
- 新增或复用后端共享持久化来源保存路径历史。
- 路径历史来源合并：
  - 后端共享路径历史。
  - 已成功保存实例中的 `generation_path`。
  - 当前浏览器仍可读取到的旧 `localStorage` 路径历史。
- 合并时去重。
- 最近成功使用的路径仍排在靠前位置。
- 数量上限沿用现有合理限制，避免无限增长。
- 失败生成不应污染“成功路径历史”。

验收标准：

- 同一共享数据目录下，换版本后路径历史不减少。
- 同一共享数据目录下，换端口后路径历史不减少。
- 已有成功实例中的生成路径能回填到路径下拉。
- 当前浏览器旧 localStorage 中仍存在的路径能合并进共享路径历史。
- 新成功生图的路径会写入共享路径历史。
- 不把空路径写入路径历史。

副作用：

- 只存在于其他端口 localStorage、且从未成功生图、也没有被写入共享数据的旧路径，无法凭空恢复。
- 改版后新增和成功使用过的路径应进入共享历史。

### 9. 路径框优先显示后半段

当前问题：

- 操作区路径框内容过长时，容易只看到路径前半段。
- 路径后半段通常更能区分具体目录。

调整方案：

- 操作区路径输入框仍保存完整路径。
- 当路径无法完整显示时，默认显示后半段。
- 路径下拉菜单继续完整显示每个路径。
- 路径下拉菜单尽量根据路径长度自动扩宽，避免横向滚动条。

验收标准：

- 路径框值仍是完整路径。
- 路径过长时，用户优先看到后半段。
- 手动输入路径不受影响。
- 从下拉菜单选择路径不受影响。
- 路径下拉菜单不因长路径破坏操作区布局。

## 回归检查

完成实现后需要检查：

- 设置页所有接口类型可以正常切换。
- `openai` 固定调用示例只读并读取共享脚本。
- `openai-google` 固定调用示例只读并读取共享脚本。
- 自定义代码仍能覆盖共享脚本运行。
- `openai-google` 文生图、图生图仍能生成并保存图片。
- `openai-google` 图生图多输入图顺序不乱。
- `openai-google` 可选参数 `None` 不会作为字符串传入脚本。
- `openai-google` 必需参数缺失时报错清楚。
- `openai-google` 分辨率和尺寸控件显示“无”且不可选。
- 普通接口自定义尺寸显示真实尺寸。
- 普通接口尺寸、分辨率、数量不回退。
- 路径历史跨版本、跨端口稳定。
- 路径框长路径优先显示后半段。
- 保存区筛选、历史记录筛选、数据导出、备份、恢复不因空尺寸回退。
- V0.58 的代理设置、超时重试、清理过程文件规则不回退。

## 不做内容

- 不把 `resolved_size` 直接写入小云请求 payload。
- 不新增缩略图缓存或图片缓存功能。
- 不新增批量 Provider 修改。
- 不改变小云接口参数官网规定的可接受输入范围。
- 不在 UI 上新增参数说明文字或参数范围说明。
- 不改变现有 `openai` 共享脚本的请求语义。
- 不删除电脑上的图片文件。
