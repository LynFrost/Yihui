## Provider 作用域拆分

V0.21 将 Provider 分成两个明确概念：

```text
操作区 Provider：决定生图实际使用哪个 Provider
设置页 Provider：只决定当前正在编辑哪个 Provider 配置
```

实现规则：

- 操作区 Provider 继续使用 V0.20 的下拉框。
- 操作区 Provider 继续保存到共享配置里的 `active_provider`。
- 点击生成时，只使用 `active_provider` 对应的 Provider。
- 设置页 Provider 下拉只切换当前正在编辑的 Provider。
- 设置页 Provider 下拉不修改 `active_provider`。
- 设置页 Provider 下拉不影响操作区当前选中的 Provider。
- 设置页保存当前 Provider 配置时，不把该 Provider 自动设为 `active_provider`。

## 设置页编辑 Provider 状态

新增前端状态保存设置页当前编辑对象，例如：

```javascript
state.settingsEditingProvider
```

实现规则：

- 初次打开设置页时，如果 `settingsEditingProvider` 为空，默认显示：
  - `active_provider` 对应 Provider；如果不存在，则显示 Provider 列表第一个。
- 设置页下拉选择 Provider 时，只更新 `settingsEditingProvider`。
- `activeProviderName()` 继续表示操作区生图 Provider。
- 设置页渲染当前 Provider 时，使用 `settingsEditingProvider`。
- 设置页表单中的隐藏或显式 `provider` 字段也使用 `settingsEditingProvider`，不再使用 `active_provider`。
- 保存设置后，继续停留在当前 `settingsEditingProvider`。
- 操作区切换 Provider 后，如果设置页当前没有编辑对象，可以用新 active Provider 作为默认编辑对象；如果设置页已经在编辑某个 Provider，不强行同步。

## 设置页保存行为

设置页保存只保存当前编辑 Provider 的配置。

实现规则：

- 保存时读取 `settingsEditingProvider` 作为当前编辑 Provider key。
- 保存 display_name、adapter、base_url、api_key、api_key_env、user_agent、OpenAI 参数、调用示例、自定义代码等。
- 不修改 `settings.active_provider`。
- 如果编辑的 Provider 正好是操作区当前 `active_provider`，那么配置内容变化会影响下一次生成。
- 如果编辑的 Provider 不是操作区当前 `active_provider`，保存后不会影响下一次生成使用哪个 Provider。

## 新建 Provider 行为

新建 Provider 只影响设置页当前编辑对象。

实现规则：

- 点击 `新建 Provider` 后，创建新的 Provider 草稿。
- 设置页下拉切换到新 Provider。
- `settingsEditingProvider` 设置为新 Provider key。
- 不修改 `active_provider`。
- 操作区 Provider 下拉不自动切换到新 Provider。
- 新 Provider 保存后，才出现在操作区 Provider 下拉选项中。

## 删除 Provider 行为

删除 Provider 时，需要保护操作区当前生图 Provider。

实现规则：

- 如果删除的 Provider 不是 `active_provider`：
  - 允许删除。
  - 删除后设置页切换到剩余 Provider 的第一个；如果没有剩余 Provider，则显示空状态。
  - 不修改 `active_provider`，除非 `active_provider` 指向的 Provider 已不存在。
- 如果删除的 Provider 正是 `active_provider`：
  - 阻止删除。
  - 显示提示：`当前 Provider 正在操作区使用，请先到生图管理页切换 Provider 后再删除。`
  - 不自动切换 `active_provider`。
  - 不删除 Provider。

这样保证只有操作区 Provider 下拉才决定生图 Provider。

## 操作区 Provider 行为

操作区 Provider 下拉继续是唯一生图选择入口。

实现规则：

- 操作区下拉选择 Provider 后，立即保存为全局默认 Provider。
- 保存成功后更新 `active_provider`。
- 生成按钮读取最新 `active_provider`。
- 设置页当前编辑 Provider 不随操作区切换强制改变。
- 已经提交中的生成任务继续使用提交时捕获的 Provider，不受后续切换影响。

## Ctrl+Enter 生图

在生图管理页全局支持快捷键：

```text
Ctrl + Enter = 点击操作区生成按钮
```

实现规则：

- 只在 `state.page === "manager"` 时生效。
- 用户焦点在操作区、保存区、提示词框、路径框、标签框、图片位等位置时，都可以触发。
- 触发后调用与点击操作区 `生成` 按钮相同的逻辑。
- 支持连续手动按多次，从而提交多个并行生成任务。
- 忽略长按导致的重复键盘事件：

```javascript
if (event.repeat) return;
```

- 触发后 `event.preventDefault()`，避免浏览器或输入框执行额外行为。

不触发场景：

- 当前不在生图管理页。
- 当前有大图弹窗打开。
- 当前有路径批量替换弹窗打开。
- 当前有其他需要用户确认或编辑的覆盖层打开。
- 当前正在输入法组合输入中。

## 副作用与处理

设置页选择 Provider 不再影响生图 Provider。用户如果在设置页切换 Provider 后回到生图管理页，操作区 Provider 仍保持原选择，这是 V0.21 的目标行为。

设置页保存非当前操作区 Provider 的配置后，下一次生成不会切到该 Provider。只有操作区下拉选择后才会切换。

阻止删除当前操作区 Provider 会多一步操作，但可以避免删除后生图 Provider 被自动切换，保持“只有操作区下拉才生效”的规则。

`Ctrl+Enter` 会提高生成效率，也可能带来误触风险。通过限制在生图管理页、忽略长按重复、弹窗时不触发，降低误触。

如果用户正在保存区编辑实例，按 `Ctrl+Enter` 仍会触发操作区生成。这符合“生图管理页全局快捷键”的要求。
