## 修改目标

V0.39 的目标是增强历史记录查询和清理能力，让历史记录很多之后仍然容易定位、排查和整理。

本版重点：

- 历史记录页增加提示词搜索。
- 历史记录页支持按状态筛选。
- 历史记录页支持按 Provider 筛选。
- 历史记录页支持按调用方式筛选。
- 历史记录页支持按日期范围筛选。
- 历史记录查询继续走后端分页和后端筛选，不把全部历史记录一次性加载到前端。
- 增加历史记录清理功能。
- 清理历史记录必须二次确认。
- 清理历史记录不能删除保存区实例。
- 清理历史记录不能删除电脑上的图片文件。
- 历史记录里的 Provider、调用方式、参数快照不能因为筛选或清理功能丢失。

本版不做：

- 不重构历史记录页面整体布局。
- 不改变保存区实例结构。
- 不删除保存区实例。
- 不删除任何电脑上的图片文件。
- 不做按当前筛选结果任意批量删除。
- 不破坏 V0.38 标签管理中心。
- 不破坏保存区普通列表模式、缩略图模式、节点管理、批量管理。

## 查询功能

### 后端查询参数

扩展：

```text
GET /api/generation-history
```

新增或继续支持以下查询参数：

```text
q
status
provider
call_method
start_date
end_date
page
per_page
```

参数含义：

- `q`：提示词搜索，匹配 `generation_history.prompt`。
- `status`：状态筛选。
- `provider`：Provider 筛选，匹配 `generation_history.provider_key`。
- `call_method`：调用方式筛选，匹配 `generation_history.openai_call_method`。
- `start_date`：开始日期，按 `started_at >= 当天 00:00:00`。
- `end_date`：结束日期，包含当天整天，后端按 `< 次日 00:00:00` 查询。
- `page`：页码。
- `per_page`：每页数量。

### 状态筛选

状态筛选显示：

```text
全部 / 生成中 / 成功 / 失败 / 其他
```

后端规则：

- `all`：不过滤状态。
- `running`：`status = 'running'`。
- `success`：`status = 'success'`。
- `failed`：`status = 'failed'`。
- `other`：`status NOT IN ('running', 'success', 'failed')`。

说明：

- 当前软件常用状态仍然是 `running`、`success`、`failed`。
- `other` 用于兼容未来状态、旧数据或恢复导入数据。
- 历史记录卡片中仍然显示真实原始状态，不把其他状态强行改成固定文案。

### Provider 筛选

Provider 筛选使用历史记录中实际出现过的 `provider_key`。

不要使用当前设置页 Provider 列表作为历史记录筛选来源。

原因：

- 历史记录是过去生成行为的记录。
- 当前设置页 Provider 可能已经被改名、删除或新增。
- 历史记录中的 Provider 快照不能因为当前设置变化而消失。

Provider 选项显示：

```text
全部 / 历史记录中出现过的 Provider
```

空 Provider 可显示为：

```text
未记录
```

但请求值必须清楚区分：

- `all`：不过滤。
- `__empty__`：筛选空 Provider。
- 其他值：匹配具体 `provider_key`。

### 调用方式筛选

调用方式筛选使用历史记录中实际出现过的 `openai_call_method`。

选项显示：

```text
全部 / gpt-image-2 / response / 自定义或历史值 / 未记录
```

请求值规则：

- `all`：不过滤。
- `__empty__`：筛选空调用方式。
- 其他值：匹配具体 `openai_call_method`。

调用方式筛选只筛选历史记录，不改变 Provider 设置页的调用方式。

### 日期范围

历史记录日期范围按 `started_at` 查询。

规则：

- 只填 `start_date`：显示从该日期 00:00:00 之后开始的记录。
- 只填 `end_date`：显示该日期结束前的记录。
- 同时填写：显示两个日期之间的记录，包含结束日期当天。
- 如果 `start_date > end_date`，前端或后端应提示错误，不执行查询。

日期输入格式使用浏览器原生：

```text
YYYY-MM-DD
```

## 筛选选项接口

新增：

```text
GET /api/generation-history/filter-options
```

返回：

```json
{
  "providers": ["AIAPIS GPT Image 2", "__empty__"],
  "call_methods": ["gpt-image-2", "response", "__empty__"],
  "statuses": ["running", "success", "failed", "other"]
}
```

说明：

- `providers` 来自 `generation_history.provider_key` 的 distinct 值。
- `call_methods` 来自 `generation_history.openai_call_method` 的 distinct 值。
- 空值用 `__empty__` 表示，前端显示为 `未记录`。
- 选项按不区分大小写排序。
- 不需要把当前设置页 Provider 自动加入历史筛选选项。

## 历史记录清理

本版先做两个明确安全的清理动作：

```text
删除失败记录
删除某日期之前的记录
```

不做：

- 不做“删除当前筛选结果”。
- 不做“删除成功记录”独立按钮。
- 不做“清空全部历史记录”按钮。

### 删除失败记录

新增后端接口：

```text
POST /api/generation-history/cleanup/failed
```

规则：

- 只删除 `generation_history.status = 'failed'` 的记录。
- 不删除保存区实例。
- 不删除电脑上的图片文件。
- 不修改 Provider 设置。
- 不修改标签、节点、缩略图缓存。

前端点击前必须确认。

推荐确认文案：

```text
将删除 X 条失败历史记录。此操作不会删除保存区实例，也不会删除电脑上的图片文件。确定继续？
```

### 删除某日期之前的记录

新增后端接口：

```text
POST /api/generation-history/cleanup/before-date
```

请求：

```json
{
  "before_date": "2026-05-01"
}
```

规则：

- 删除 `started_at < before_date 00:00:00` 的历史记录。
- 默认不删除 `status = 'running'` 的记录。
- 不删除保存区实例。
- 不删除电脑上的图片文件。
- 不修改 Provider 设置。
- 不修改标签、节点、缩略图缓存。

为什么默认不删 `running`：

- `running` 记录可能对应仍在进行的生成任务。
- 即使页面刷新后任务状态不再活跃，也不应该由日期清理误删正在生成的历史记录。
- 如果以后需要清理卡住的 `running`，应单独设计规则。

推荐确认文案：

```text
将删除 X 条 2026-05-01 之前的非生成中历史记录。此操作不会删除保存区实例，也不会删除电脑上的图片文件。确定继续？
```

### 清理预览

为了让确认文案显示准确数量，新增预览接口：

```text
POST /api/generation-history/cleanup/preview
```

请求示例：

```json
{
  "type": "failed"
}
```

或：

```json
{
  "type": "before_date",
  "before_date": "2026-05-01"
}
```

返回：

```json
{
  "matched_count": 28,
  "will_delete_instances": false,
  "will_delete_image_files": false
}
```

前端必须先请求预览，再二次确认，再执行清理。

## 后端查询实现规则

`list_generation_history(conn, filters)` 扩展筛选条件。

建议使用参数化 SQL，不拼接用户输入。

查询条件：

- `q` 使用 `prompt LIKE ?`。
- `status` 按状态规则处理。
- `provider` 区分 `all`、`__empty__`、具体值。
- `call_method` 区分 `all`、`__empty__`、具体值。
- `start_date` 和 `end_date` 转换为 ISO 字符串比较。

索引建议：

当前已有：

```text
idx_generation_history_started_at
idx_generation_history_status
```

V0.39 建议新增：

```sql
CREATE INDEX IF NOT EXISTS idx_generation_history_provider ON generation_history(provider_key);
CREATE INDEX IF NOT EXISTS idx_generation_history_call_method ON generation_history(openai_call_method);
```

提示词搜索使用 `LIKE`，当前先不做全文索引。

原因：

- 本版目标是增强查询和清理，不引入 FTS 表。
- 如果后续提示词数量极大、搜索仍慢，再单独设计全文索引。

## 数据安全兼容

V0.37 的备份、导出、恢复增强必须保持有效。

历史记录清理后：

- 数据安全页摘要中的 `generation_history_count` 必须反映清理后的数量。
- 导出的 `generation_history` 只包含清理后仍存在的历史记录。
- 恢复旧备份后，历史记录筛选选项应根据恢复后的数据重新生成。
- 清理操作不删除图片文件，因此备份、导出、恢复仍然只处理数据库和配置，不处理原图文件。

历史记录页自身在清理后：

- 重新加载历史记录列表。
- 重新加载 Provider 和调用方式筛选选项。
- 如果当前页因为清理变成空白页，自动回到最后一个有效页或第 1 页。
- 不能出现清理后停留在空白页的情况。

## 副作用与风险

本版可能带来的影响：

- 历史记录顶部筛选项会变多，需要紧凑布局，否则会挤压页面。
- Provider 和调用方式来自历史记录实际值，可能显示当前设置页已经不存在的旧值，这是预期行为。
- 清理失败记录后，保存区中的失败实例仍然存在，历史记录和保存区实例不再一一对应，这是预期行为。
- 删除日期之前记录后，数据安全页导出和备份中的历史记录数量会减少，这是预期行为。
- 日期范围如果按字符串处理不严谨，可能漏掉结束日期当天的晚间记录，必须按 `< 次日 00:00:00` 处理。
- 提示词搜索使用 `LIKE`，数据极大时可能没有全文索引快，但本版先不引入 FTS，避免增加迁移复杂度。
- 清理历史记录属于不可逆数据库操作，必须二次确认，并且建议用户可先用 V0.39 数据安全页手动备份。

必须避免：

- 不能删除保存区实例。
- 不能删除电脑上的图片文件。
- 不能修改历史记录里仍然保留的 Provider、调用方式、参数快照。
- 不能破坏 V0.38 标签管理中心。
- 不能破坏 V0.37 数据安全备份、导出、恢复。
- 不能破坏保存区普通列表模式、缩略图模式、节点管理、批量管理。
