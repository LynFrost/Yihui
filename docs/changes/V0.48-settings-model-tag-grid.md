# V0.48 设置页密度、模型字段与标签管理四列

## 版本目标

V0.48 在 V0.47 的基础上做界面密度和 Provider 模型字段收口，不改生成主流程，不改数据库 schema，不调整数据安全、历史记录、缩略图、节点、批量管理等既有能力。

## 修改内容

1. 设置页 API 参数区固定每行 4 个参数。
   - `OpenAI API 参数` 区域由原来的三列改为四列。
   - 横屏、竖屏都保持每行 4 个参数。
   - 不因为屏幕变窄自动降成 2 列或 1 列。
   - 字段过长时通过紧凑布局、截断或控件自身收缩处理，尽量避免页面出现横向滚动条。

2. 设置页连接信息区新增模型字段。
   - 第二行左侧原来的 `api_key_env` 框拆成两个半宽字段：
     - `api_key_env`
     - `model`
   - `model` 字段可手动填写和保存。
   - `model` 默认继续使用旧值或 `gpt-image-2`，旧 Provider 不会因为缺少字段而坏掉。
   - `model` 保存到当前 Provider 配置，并在生图时继续通过现有参数注入给脚本里的 `model`。

3. 标签管理页固定每行 4 个 TAG 卡片。
   - 标签管理页主列表从每行 1 个 TAG 改为每行 4 个 TAG 卡片。
   - 横屏、竖屏都保持每行 4 个卡片。
   - 每个卡片继续显示 TAG 名称、实例数量、重命名、合并。
   - 长 TAG 名称截断显示，并保留 `title` 悬停查看完整名称。
   - 标签管理仍然只管理正在使用的真实 TAG，不显示未使用 TAG，不把“无”或 `__untagged__` 当作真实 TAG。

## 不修改内容

- 不改数据库 schema。
- 不新增 Provider 类型。
- 不改生成、复制提交、重新提交的调用流程。
- 不改 OpenAI 脚本的核心请求逻辑。
- 不改历史记录、数据安全、缩略图缓存、缩略图视图、节点管理、批量管理。
- 不改变标签管理的后端查询、重命名、合并规则。

## 兼容与副作用

- API 参数区固定四列后，窄屏下单个字段会更窄，长参数名可能更紧凑；这是本版为了节省纵向空间接受的取舍。
- 标签管理页固定四列后，窄屏下每个 TAG 卡片也会更窄，长 TAG 名称需要截断；完整名称通过悬停查看。
- `model` 变成可编辑后，如果填写了服务商不支持的模型名，生成会由服务商返回错误；软件只负责保存和注入该字段，不自动猜测模型。
- 旧配置中没有 `model` 的 Provider 会继续回落到 `gpt-image-2`。

## 验证重点

- 设置页能正常打开，API 参数区 CSS 明确为四列。
- 连接信息区第二行包含 `api_key_env` 和 `model` 两个半宽字段。
- 保存 Provider 后，`model` 不再被固定覆盖为 `gpt-image-2`，而是保存用户填写值。
- `/api/generate` 的参数快照和脚本注入继续能拿到 Provider 的 `model`。
- 标签管理页主列表 CSS 明确为四列卡片。
- TAG 搜索、刷新、重命名、合并仍然可用。
- 全量测试通过。
