# V0.50 保存区生成中、Provider 来源与设置页稳定性

## 目标

V0.50 不新增大功能，重点修复 V0.49 使用中发现的保存区过程显示、Provider 来源、设置页新 Provider 保存、下拉菜单和细节交互问题。

本版原则：

- 不改变现有页面结构和主要视觉风格。
- 不改变数据库 schema。
- 不删除电脑上的图片文件。
- 不破坏 V0.49 已有的缩略图缓存、缩略图视图、节点管理、标签管理、历史记录、数据安全、生成重试等能力。

## 修改项

### 1. 保存区提示词悬停浮窗宽度一致

- 保存区实例提示词框鼠标悬停时，浮窗内文字换行应尽量和原提示词框一致。
- 去掉浮窗右侧多余留白，避免最右侧空出一列造成每行字数减少。
- 仍保留悬停完整显示能力。

### 2. 生成中实例不影响已保存实例分页和编号

- 点击生成、复制提交、重新提交、手动实例提交后，生成中实例即时显示。
- 生成中实例不参与保存区正式分页。
- 生成中实例不占用每页数量。
- 生成中实例不改变已有实例编号。
- 原本的 `001` 在生成完成或失败前仍然保持 `001`。
- 生成中实例显示在当前保存区页面底部，不挤掉当前页顶部或尾部的已保存实例。
- 生成成功或失败后，才刷新正式保存区列表，并按现有排序规则重新进入列表。

### 3. 保存区提交使用对应实例 Provider

- 操作区普通生成继续使用操作区当前 Provider。
- 保存区实例“复制提交”使用该保存区实例自己的 Provider。
- 失败实例“重新提交”使用该失败实例自己的 Provider。
- 手动实例“提交”使用该手动实例自己的 Provider。
- 如果实例自己的 Provider 不存在，需要明确提示，不能静默改用操作区 Provider。
- 保存区提交不应改变操作区当前 Provider，也不应改写全局默认 Provider。

### 4. 生成中取消状态显示为取消中

- 对生成中实例点击“取消”后，实例上立即显示“取消中”。
- 取消按钮进入禁用状态，避免重复点击。
- “取消中”状态持续到后端确认取消或任务状态刷新完成。
- 如果取消请求失败，显示错误，并恢复可继续取消的状态。

### 5. Shift 连选不再闪选页面文字

- 保存区实例 Shift 连选时，不应出现页面文字被一闪而过选中的现象。
- 只限制选择触发区的浏览器原生文本选择。
- 不影响提示词输入框、搜索框、TAG 输入框等文本内容的正常选中复制。

### 6. 设置页新 Provider 首次保存不丢内容

- 新建 Provider 后，首次填写连接信息、参数、调用示例等内容并点击保存，应一次保存成功。
- 不能出现第一次保存回到初始值、第二次保存才成功的情况。
- 新建 Provider 的内部编号继续自动生成且不可编辑。

### 7. 设置页保存按钮脏状态

- 新建 Provider 后，“保存设置”按钮变为可点击的蓝色状态。
- 保存成功后，“保存设置”按钮回到置灰不可点击状态。
- 之后只有当设置页内容再次发生修改时，“保存设置”按钮才重新变蓝。
- 该规则覆盖连接信息、API 参数、调用示例、自定义脚本等设置页可编辑内容。

### 8. 操作区路径下拉菜单宽度自适应

- 操作区路径下拉菜单尽量完整显示路径。
- 下拉菜单可根据路径长度向左或向右扩宽。
- 在接近浏览器可视区边界前，尽量不出现横向滚动条。
- 如果路径过长且已接近可视区边界，才允许滚动条作为兜底。

## 副作用与处理

- 生成中实例放到页面底部后，不会再抢占保存区顶部位置；用户需要在当前页底部查看正在生成的任务。这样可以避免生成过程干扰翻页查看和编号稳定。
- 保存区提交改为使用实例自己的 Provider 后，如果实例 Provider 已被删除，提交会被阻止并提示原因。这比静默使用当前 Provider 更安全。
- 设置页保存按钮置灰后，未修改内容时无法重复点击保存；如果确实需要保存，必须先修改字段。
- 路径下拉菜单变宽后可能遮挡旁边控件，但它是临时浮层，优先保证路径可读。

## 验收重点

- 新提交生成中实例时，当前页已保存实例数量、顺序、编号不变。
- 生成中实例显示在当前页底部，生成完成或失败后再进入正式列表。
- 保存区复制提交、重新提交、手动提交均使用实例自己的 Provider。
- 取消生成后能看到“取消中”。
- 设置页新建 Provider 后第一次保存不丢字段。
- 设置页保存按钮蓝色/置灰状态正确。
- 操作区路径下拉菜单尽量无横向滚动条。
- Shift 连选不再闪选页面文字。
