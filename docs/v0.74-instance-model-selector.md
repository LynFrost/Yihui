# V0.74 需求：生图记录卡片模型选择与紧凑布局

- **目标版本**：V0.74
- **目标分支**：`feature/v0.74`
- **状态**：需求待确认，本文档确认前不开始代码开发
- **范围**：生图管理页面的单条记录卡片；不调整其他页面和既有生图能力

## 1. 背景与目标

当前生图记录卡片展示输出图片、Provider、标签输入框及「带入 / 复制 / 提交 / 删除」等操作。需要在不明显改变原有卡片布局的前提下，增加当前 Provider 的模型选择和模型候选管理能力。

本次以**最小布局改动**为原则：输出图片尺寸和位置不变，既有按钮的功能不变，尽量不增加卡片高度。

## 2. 卡片布局要求

### 2.1 Provider 行

1. 保留现有 Provider 文本和状态标记。
2. Provider 信息整体只向右微调必要距离，避免 Provider 文本左侧与输出图片产生视觉干涉。
3. 不通过大幅调整卡片主体或缩小输出图片来腾出空间。

### 2.2 model 行

1. 在 Provider 行正下方增加一行模型选择控件。
2. 行内显示小写文本 **`model`**，其左边缘与上方 Provider 文本左边缘对齐。
3. 文本右侧放置紧凑的下拉框；初始宽度建议约 **150–180px**，根据现有卡片可用空间适度收缩，不占满整行。
4. 当前选择显示模型 ID；过长时截断显示，完整模型 ID 应可通过展开列表查看。
5. 不移动或缩小输出图片；模型控件不得覆盖输出图片。

### 2.3 标签输入框和操作按钮

1. 将现有标签输入框从独立的上方位置移入现有操作按钮所在行，放在「带入」按钮左侧的空隙中。
2. 标签输入框使用该行剩余空间，必要时缩小宽度；不得挪到输出图片下方，也不得挤占输出图片的尺寸。
3. 「带入 / 复制 / 提交 / 删除」继续保持原有功能和操作顺序。
4. 标签输入框与按钮尽量保持在同一行，避免因增加模型行而再额外增加一行标签区域。
5. 本次不改标签的新增、展示、保存和删除业务逻辑，只调整输入框的位置与尺寸。

### 2.4 卡片高度与响应式

- 尽量保持卡片原有高度；不因标签输入框单独占行而增加高度。
- 允许模型行导致卡片内容重新分配，但不得压缩输出图片。
- 可用宽度不足时，优先压缩标签输入框和模型下拉框的宽度；避免 Provider、模型控件、标签输入框与按钮互相覆盖。
- 除必要的间距和对齐外，不重排其他卡片元素。

## 3. 模型下拉框与菜单

### 3.1 下拉框外观

- 下拉框风格与现有意绘表单控件一致，尺寸紧凑。
- 当前模型显示在控件中，点击后展开候选列表。
- 「＋添加模型」入口放在**展开的下拉菜单内部**，而不是下拉框右侧单独放置按钮。
- 列表内每个模型均可被选择；待验证和已验证模型应有清楚但克制的状态区分。

### 3.2 候选项展示

每个 Provider 单独维护模型候选列表。菜单中的模型项至少应显示：

- 模型 ID；
- 验证状态：`待验证` 或 `已验证`；
- 删除入口。

当前模型应有选中状态。列表较长时，菜单可滚动，不得撑大记录卡片。

### 3.3 添加模型

1. 用户在展开的下拉菜单内点击「＋添加模型」。
2. 弹出轻量输入界面，输入模型 ID 并确认。
3. 对输入值去除首尾空白；空值不允许添加；同一个 Provider 下的重复模型 ID 不重复创建。
4. 新模型添加后立即持久化为 **待验证候选**，即使首次调用失败也不自动删除。
5. 新增动作本身不强制更换当前模型；用户从列表选中新模型后，才将其设为该 Provider 当前使用的模型。
6. 取消添加不应改变当前模型或已有候选项。

### 3.4 删除模型

1. 每个候选项都提供删除入口，待验证和已验证模型均可删除。
2. 删除前进行轻量确认，避免误操作。
3. 如果要删除的模型正是该 Provider 当前使用的模型，必须先切换到另一个已有模型；不能删除后让 Provider 的当前模型为空。
4. 删除候选项只影响该 Provider 的模型列表，不影响其他 Provider，也不改写已经生成的历史记录。
5. 删除后立即持久化；刷新或重启后不应重新出现已删除项（除非该模型仍是必须保留的当前配置项，此情况应由删除前的切换规则避免）。

## 4. 模型选择与生图行为

1. 模型选择属于 **Provider 级设置**，不是单条历史图片独立的模型设置。
2. 用户选中模型后，将其保存为该 Provider 的当前模型；后续使用该 Provider 发起的生图请求应使用这个模型。
3. 同一个 Provider 在不同记录卡片上的模型选择显示应保持一致；切换模型后，其他卡片应同步显示当前选择。
4. 不同 Provider 的当前模型和候选列表完全隔离。
5. 更改当前模型不改写旧记录的 Provider、模型、提示词、输入图、输出图和生成结果。
6. 请求必须使用当前 Provider 配置的既有调用适配器和请求流程；本需求不引入新的供应商调用协议，也不绕过现有生图链路。

## 5. 模型验证状态与持久化

### 5.1 状态规则

- **待验证**：模型刚添加但尚未有成功生图记录。
- **已验证**：使用该 Provider 的该模型完成生图，且结果已被现有流程认定为成功并成功保存。
- 仅仅添加模型、选择模型、请求已发出或收到 HTTP 200，不足以标记为已验证。
- 失败、取消、超时或未能保存有效结果，不得将模型标记为已验证；模型候选项仍保留，便于修正配置后再次尝试。
- 验证状态以 Provider 与模型 ID 的组合为准，不能把一个 Provider 的成功状态套用到另一个 Provider。

### 5.2 成功后常驻

1. 当模型首次成功生图后，将该候选项标记为「已验证」并持久化。
2. 后续启动软件时，已验证模型仍出现在对应 Provider 的下拉列表中。
3. 已验证模型不因切换当前模型而被移除。
4. 验证状态更新应复用现有生图成功判定与持久化路径，避免前端单方面将失败请求标记为成功。

### 5.3 配置存储

1. 使用意绘现有 Provider 配置和持久化机制扩展模型候选列表，不新增与现有配置体系割裂的独立存储。
2. 当前模型仍以 Provider 的现有模型配置字段为准；候选列表及其验证状态按 Provider 保存。
3. 若旧配置没有模型候选列表，启动时应兼容旧配置，并将当前已配置模型纳入该 Provider 的候选项，不能因为升级而丢失或清空现有模型。
4. 对旧模型是否标记为「已验证」，仅在现有历史数据能够可靠地匹配 Provider 和模型且确认成功时才可据此标记；无法可靠确认时保留模型，但不要伪造验证成功。
5. 设置保存、应用重启，以及现有备份/导出/恢复流程（如包含该 Provider 配置）均应正确保留模型候选列表和验证状态。
6. 迁移和保存不得写入、输出或泄露真实 API Key；不改变真实 Key 的现有存储方式。

## 6. 兼容性与范围边界

- 保持现有 Provider 配置、当前模型和生图记录兼容。
- 不改写历史图片及历史生成参数。
- 不改变现有标签业务逻辑、按钮行为、图片尺寸、筛选排序、分页和其他页面。
- 不修改各 Provider 的 API Key、Base URL、适配器、模型调用协议或生成参数规则；本次只增加模型选择和候选管理。
- 不因模型候选功能而把跨 Provider 的模型历史混用。
- 本次仅提交与上述需求直接相关的改动，不顺带进行无关的格式或命名整理。

## 7. 验收标准

### 布局

- [ ] Provider 行仅作小幅右移，视觉上不与输出图片干涉。
- [ ] `model` 行在 Provider 正下方，左边缘对齐；控件宽度紧凑，不占满整行。
- [ ] 「＋添加模型」位于下拉菜单内部。
- [ ] 标签输入框位于「带入」左侧，与操作按钮同一行；不在输出图片下方。
- [ ] 输出图片的尺寸和位置不变；卡片高度尽量保持原状。
- [ ] 不同窗口宽度下，标签输入框、模型控件和按钮不发生明显重叠。

### 模型管理

- [ ] 每个 Provider 只展示自己的模型候选列表。
- [ ] 能添加非空模型 ID；重复模型不会产生重复项。
- [ ] 新增模型以「待验证」状态保存；取消添加不影响当前配置。
- [ ] 用户选中模型后，该 Provider 的当前模型持久化更新，后续生图使用所选模型。
- [ ] 生图成功并保存结果后，所用模型变为「已验证」并在重启后保留。
- [ ] 生图失败、取消、超时或结果保存失败，不会错误地标记为「已验证」，候选项仍保留。
- [ ] 可以删除待验证和已验证模型；删除当前模型时必须先切换到其他模型。
- [ ] 同一 Provider 的其他卡片同步显示当前模型；其他 Provider 不受影响。
- [ ] 旧配置升级后当前模型不丢失；旧历史记录不被改写。
- [ ] 现有生图、标签、带入、复制、提交、删除等功能回归测试通过。

## 8. 开发顺序建议

1. 先调整记录卡片布局：Provider、model 行、标签输入框与操作按钮行。
2. 实现下拉菜单、添加与删除交互。
3. 实现按 Provider 持久化模型候选列表和当前模型。
4. 将模型验证状态接入现有生图成功链路。
5. 完成旧配置兼容、异常场景和 UI/生图回归测试。

**本文件只记录已讨论的需求与验收标准，不代表代码已经开发或测试。开发前应先由需求方审阅确认。**
